# 행동을 열거한 잘못

2026-11-14. 사용자의 물음: "왜 행동을 저작 후보로 추적 중이게 됐을까요?"
구현([37](37-뼈대와-이어-돌린-실측.md), [39](39-모르는-행동의-일반-경로.md))이 설계에서 벗어난 것을 짚은 물음이다. 경위와 바로잡을 방향을 적는다.

## 1. 무엇이 벗어났는가

| 설계 | 구현이 한 것 |
| --- | --- |
| 행동은 자유다. 유한한 것은 **세계의 항목**이다 | **동작의 목록**(15개)을 만들고 동작마다 코드를 썼다 |
| 판단은 "무슨 일이 일어났는가"를 명확한 기준으로 가린다 | 코드가 "일어날 수 있는 일"의 후보를 미리 만들고 판단은 그 가운데서 고른다 |
| 행동의 유형은 **열어 볼 정보와 고칠 수 있는 정보**를 정한다 (권한) | 유형이 아니라 동작이 **무슨 일이 일어나는지**를 정한다 |

- 그 결과 "코드가 아는 동작"과 "모르는 동작"이 갈렸고, 모르는 동작을 위해 다시 후보의 목록을 만들었다.
- 39의 남은 문제 1번("후보의 종류가 곧 자유도의 한계다")은 문제의 발견이 아니라 **이 잘못의 증상**이다. 목록을 늘려서 풀 일이 아니다.

## 2. 왜 그렇게 됐는가

1. **"닫힌 판단"을 잘못 넓혔다.** 닫아야 하는 것은 답의 **꼴과 값**이다(어느 개체의, 어느 항목이, 어느 값으로). 나는 그것을 "일어날 수 있는 **결과**를 코드가 전부 늘어놓는다"로 옮겼다.
2. **뻔한 경우부터 만들었다.** 잠긴 문을 "연다"의 코드로 처리했다. 그런데 잠긴 문이 열리지 않는 것은 "연다"라는 동작의 성질이 아니라 **문이라는 항목에 걸린 조건**이다. 의자로 쳐도, 어깨로 밀어도 같은 조건이 걸린다. 조건을 항목에 두지 않고 동작에 두었다.
3. **쏠림.** 구 기록에서 LLM이 지어낸 연산이 버려진 것을 보고 "LLM에게 연산을 쓰게 하지 않는다"로 갔고, 거기서 "코드가 결과를 다 안다"까지 갔다. 되풀이하던 잘못(한쪽으로 쏠렸다 반대로 쏠림)이다.
4. **가늘게 끝까지 만드는 순서**가 이것을 가렸다. 동작 서넛으로 장면이 돌자 구조가 맞는 것처럼 보였다.

## 3. 바로잡을 방향 [제안]

**열거하는 것은 행동이 아니라 항목이다.**

```
해석   선언 → 무엇을 하려는가(자유로운 글), 유형(18), 대상
준비   유형이 정한 "열어 볼 정보"를 꺼낸다. "고칠 수 있는 항목"의 목록을 만든다
판단   일어난 일을 항목의 변화로 적는다:  (개체, 항목, 값) — 셋 다 사전이 정한 목록에서
코드   변화마다 그 항목의 조건을 검사한다. 걸리면 반영하지 않고, 걸린 까닭이 PC가 지각하는 결과가 된다
       통과한 변화에서 규칙이 귀결을 계산한다
```

| | 지금의 구현 | 바로잡은 뒤 |
| --- | --- | --- |
| 닫히는 것 | 결과의 후보 (코드가 동작마다 만든다) | 변화의 꼴: 개체는 장면에서, 항목은 그 개체의 정의에서, 값은 그 항목의 등급에서 |
| "잠긴 문은 안 열린다" | "연다"의 코드 | `열림(통로) = 참`이 되려면 `잠김 = 거짓`이어야 한다는 **항목의 조건**. 어떤 행동으로 열려 해도 걸린다 |
| 새 행동 | 코드를 더 써야 한다 | 쓸 것이 없다. 항목이 있으면 된다 |
| 새 상태(젖음, 불) | 후보의 목록에 더한다 | 사전에 항목과 조건·규칙을 더한다. 그러면 모든 행동이 그것을 바꿀 수 있다 |
| 자유도의 한계 | 동작과 후보의 목록 | 항목의 사전. 사전에 없는 변화는 "저작되지 않은 것의 목록"으로 간다 |

**구현에서 남기는 것**

- 세계에 쓰는 것은 검사를 거친 것뿐이다. PC가 지닌 것은 장부가 안다. 목록에 없는 대상의 처리. 플레이어에게 보이는 글은 코드가 쓴다.
- 사람을 상대로 한 판정([38](38-판정의-값.md) §5)은 이미 이 방향이다. 판단은 "무엇에 닿는가"라는 **항목**을 고른다.

**치르는 값**

- 판단 없이 끝나는 턴이 준다. 지금은 코드가 동작을 알아서 뻔한 턴을 건너뛰었다. 바로잡으면 대부분의 턴이 판단을 한 번 부른다. 실측으로는 턴당 약 2초, 2원이 더 든다. 여유 안이다.
- 구 기록의 문제(지어낸 연산이 버려짐)가 돌아올 수 있다. 막는 길: 변화의 셋을 전부 닫힌 목록에서 고르게 하고, 걸린 변화는 버리는 것이 아니라 **걸린 까닭을 결과로 쓴다.**

## 4. 설계 문서에 남아 있던 씨앗

- [32](32-항목표.md) §13에 "유형마다: 열어 볼 정보 / 고칠 수 있는 정보 / **뻔한 귀결**"이라고 적었다. "뻔한 귀결"이 유형에 달려 있다는 이 줄이 동작별 코드로 이어졌다. 뻔한 귀결은 유형이 아니라 **항목의 조건과 규칙**에서 나온다. 32를 고친다.

## 5. 남은 문제들도 같은 뿌리인가 (사용자의 물음, 2026-11-14)

[37](37-뼈대와-이어-돌린-실측.md) §4와 [39](39-모르는-행동의-일반-경로.md) §4에 적은 문제를 하나씩 다시 보았다.

| 적어 둔 문제 | 실제로 한 일 | 같은 뿌리인가 |
| --- | --- | --- |
| 부분이 개체가 아니다 (자물쇠) | 세계를 "행동의 대상이 되는 것들의 납작한 목록"으로 다뤘다. 목록에 없으면 판단에 물어 다른 것으로 이었다 | **같다.** 구성요소는 항목표에 있는 항목이다. 대상의 목록을 땜질할 일이 아니었다 |
| 없는 것을 채우지 못한다 (들보) | 확정의 사다리를 **"뒤진다"라는 동작의 코드 안에** 넣었다. 그래서 서랍은 채워지고 들보는 채워지지 않았다 | **같다.** 사다리는 장소와 용기의 항목("있을 법한 것")에 달린 것이다. 어떤 행동으로 닿든 같아야 한다 |
| 물건을 상대로 한 난이도가 너그럽다 | 난이도를 행동마다 판단에게 물었다 | **같다.** 높이, 견고함이라는 항목에서 나와야 한다. 사람 상대에서는 이미 그렇게 고쳤고 흔들림이 사라졌다 |
| 난이도가 흔들린다 | 위와 같다 | **같다** |
| 사람의 몸을 건드리는 일이 없다 | "대상이 사람이면 다루지 못한다"고 막았다. 싸움의 코드가 없어서다 | **같다.** 사람에게도 위치, 부상, 상태라는 항목이 있다. 싸움은 그 항목의 변화다 |
| 인물이 스스로 움직이지 않는다 | 인물의 반응을 "태도 하나와 말"로 받았고, 세계에서 하는 일은 코드가 늘어놓은 목록("문을 열어 준다")에서 골랐다 | **같다.** 턴을 "PC의 동작"을 축으로 세워서 인물이 들어설 자리가 없었다. 인물의 행동도 같은 항목의 변화여야 한다 |
| 서술이 인물을 움직인다 (막아선다) | 태도가 이름표일 뿐 위치의 변화가 아니었다. 빈 곳을 서술이 채웠다 | **같다** |
| 정도가 귀결에 쓰이지 않는다 | 결과가 "후보를 반영한다 / 안 한다" 둘뿐이었다 | **같다.** 항목에 등급이 있으면 정도는 등급을 몇 칸 움직이는가가 된다 |
| 판단 없이 끝난 턴이 많았다 | 코드가 동작을 알아서 건너뛴 것 | 같은 잘못이 만든 수치다 |
| 살펴서 얻은 등급이 풀이로 쓰였다 (기분: 경계) | 항목의 값을 그대로 서술에 넘겼다 | **반쯤.** 행동을 열거한 탓은 아니다. 그러나 "항목이 겉으로 어떻게 드러나는가"가 사전에 없어서 생겼다 |
| 서술이 작은 세부를 지어낸다 | | **다르다.** 서술 모델의 버릇이다. 다만 재질과 생김새가 항목으로 없어서 줄 것이 모자랐던 것은 한몫했다 |

열한 가지 가운데 아홉이 같은 뿌리다.

### 뿌리의 뿌리

- "행동을 열거했다"보다 한 겹 아래가 있다. **세계의 사전이 빈 채로 턴을 먼저 만들었다.**
- [27](27-전체-설계도.md)에서 사전을 "가장 큰 빈자리"라고 적어 놓고, [35](35-구현-순서와-미결.md)에서는 "내용은 쓰는 만큼만, 가늘게 끝까지"를 원칙으로 세웠다. 그 순서대로 턴을 만들자, 사전이 대 줘야 할 것(조건, 규칙, 구성요소, 있을 법한 것, 난이도의 근거, 드러나는 꼴)을 전부 **그때그때 코드로 지어냈고**, 지어낼 자리가 동작이었다.
- 사용자가 전에 짚은 "틀만 만지고 내용을 설계하지 않는다"와 같은 잘못이다.

### 그래서 바꿀 것

| | 35에 적은 것 | 고친다 |
| --- | --- | --- |
| 순서 | 뼈대(턴) → 가는 한 줄 → 꿰는 것 → 사람 → 진행 | **사전의 한 조각을 먼저.** 객잔 장면이 건드리는 항목을 조건·규칙·드러나는 꼴까지 써 놓고, 그 위에 턴을 올린다 |
| 턴 | 동작마다의 코드 | 동작을 모르는 기계 하나. 행동하는 이가 PC든 인물이든 같은 길: 변화를 내고, 조건을 검사하고, 규칙이 귀결을 낸다 |
| 통과 기준 | 장면이 끝까지 돈다 | **코드를 한 줄도 더 쓰지 않고** 사전에 항목 하나(예: 젖음)를 더했을 때, 그것이 모든 행동에서 작동한다 |
