# 사용자 재설계 자료와 Claude 독자안의 대조

2026-11-12. 사용자가 전달한 재설계 자료(프로젝트명 INDAIM, 17개 문서, 약 89만 바이트)를
[08](08-Claude-독자-구상.md)·[09](09-장부-설계.md)·[10](10-턴-처리-흐름.md)과 대조한다.
읽기 규칙은 [00](00-배경과-협업-원칙.md)을 따른다.

## 1. 읽은 범위

자료는 문서마다 사용자 원문과 GPT의 정리·제안을 구분해 두었다. 이번 대조는 **사용자 원문만**을 근거로 했다.

| 구분 | 문서 | 읽은 정도 |
| --- | --- | --- |
| 사용자 원문 | 전체 청사진 (U01~U09) | 전문 |
| 사용자 원문 | 추가 구상: 과업·계획·행동선언 | 전문 |
| 사용자 승인 기록 | 14개 영역 설계 독립성 판단 | 전문 |
| 사용자 원문 | 물건 사용자 구상 | 전문 |
| 사용자 승인 정책 | 시간 설계실 P01~P08, T-01~T-03 | 요약부와 운영 전제 (정책별 논의 본문은 읽지 않음) |
| 사용자 원문 | 장소 및 공간 C01~C12 | 사용자 발언 전문 (GPT 통합안 본문은 읽지 않음) |
| 사용자 원문 | 환경 및 현상 구상 1~3 | 사용자 발언 전문 (GPT 시안 본문은 읽지 않음) |
| GPT 조사·제안 | 행동 가능성 조사, 세계상태 비교조사, 외부게임 확장조사, 현행엔진 재조사, 판정구조 추출, 물건 조사·시안 등 9개 | **목차만 확인. 본문은 읽지 않음** |

- GPT 조사 자료를 읽지 않은 이유: 구 프로젝트와 GPT의 과적합이 섞여 있다는 사전 고지에 따라,
  사용자 본인의 생각과 먼저 대조하는 것이 순서라고 판단했다. 필요한 영역을 설계할 때 해당 조사를 읽는다.
- 자료 원본은 세션의 임시 공간에만 있고 **레포지토리에는 넣지 않았다.** (사용자 결정 대기)

## 2. 자료의 성격

- 사용자의 재설계는 세계 정보를 **14개 영역**으로 나눠, 설계 독립성이 높은 순서로 영역별 "설계실"을 여는 방식이다.
  순서: 시간 → 장소 및 공간 → 물건 → 환경 및 현상 → 신체 및 건강 → 정보 → 심리 및 판단 → 관계 → 감각 → 사회규범 → 세력 → 사건 → 과업 → 행동선언.
- 진행 상태: 시간은 기초 정책 8개 승인. 장소·물건·환경은 사용자 구상과 GPT 시안이 있고 미승인. 나머지 10개 영역은 미착수.
- 사용자는 전체를 네 범주로 본다: **세계 사전**(공통 + 시나리오) / **세계 시뮬레이션** / **LLM 층위로의 전달** / **플레이어가 받는 묘사**.
  자료가 다룬 것은 거의 전부 첫 범주와 둘째 범주의 일부다. 셋째·넷째 범주는 아직 다뤄지지 않았다.

## 3. 일치하는 것

| 주제 | 사용자 자료 | Claude 독자안 |
| --- | --- | --- |
| 전체 구획 | 세계 사전 / 시뮬레이션 / LLM 전달 / 묘사 | 정의·시나리오 / 장부 / 문맥 조립 / 서술 |
| 두 층위 | 원본 데이터와 세션에서 시뮬레이션되는 세계 | 정의·시나리오 → 세션 개설 → 장부 |
| 영역은 모듈이 아님 | 14개 영역은 탐색 분류이며 실행 모듈로 고정하지 않는다 | 형식은 하나, 어휘만 늘어난다 |
| 코드와 LLM의 분담 | 최고 해상도 시뮬레이션은 불가. LLM이 일관성 안에서 창작할 만큼의 정보를 주되, 지시되지 않은 사실을 지어내는 일은 최소화 | 장부 정리는 코드, 직관과 산문은 LLM |
| 과도한 물리 시스템화 경계 | 세부 물리를 시스템화해 프롬프트로 넘기면 과적합과 개연성 붕괴가 올 수 있다. LLM의 직관이 지름길일 수 있다 (C08) | 지각 계산이 과하면 물리 엔진이 된다 (09 약점) |
| 진실과 앎의 분리 | 정보 영역: 인지, 오해, 믿음의 정도, 진위 불일치, 출처, 전파, 기억 | 시야: 낡음, 틀림, 출처, 확신 |
| 세계 시간 | 플레이어의 선언과 그에 따른 진행 위에서만 흐른다. 중간 개입으로 선언 행동이 중단될 수 있다. 모든 변화가 중단을 요구하지는 않는다 | 선언을 시간축에 올리고 PC가 지각하는 첫 중단 사건까지 진행 |
| 역사는 시간 밖에 | 시간 영역은 현재 시각만 소유, 역사는 다른 곳 | 사건 기록 |
| 복원은 진행과 다름 | 과거 상태 복원은 일반 시간 진행과 구분 | 되감기 = 사건 기록을 N번까지만 쌓기 |
| 확정된 것만 반영 | 환경에 전달되는 명령은 이미 성공·확정된 것. 받는 쪽은 실현 여부를 재판단하지 않는다 | LLM은 제안, 코드가 검사 후 기록 |
| 자율 세계 | 세계는 자율성을 갖고 움직이며 과하게 수동적이어서는 안 된다 | 시계, 인물의 자기 목표 |
| NPC의 계획 | 계획 영역: PC와 NPC의 계획을 생성·수정·폐기 | 계획은 개체, 시계로 진행 |
| 서사에 대한 인식 | LLM은 작가로서 부족하고 매번 재계획시키는 것은 비싸다 | LLM에게 작가 역할을 맡기지 않는다 |

독립적으로 출발한 두 안이 뼈대에서 같다. 이 부분은 확신을 높여도 된다.

## 4. 어긋나는 것

### 4.1 미저작 공간의 생성 — 직접 충돌

- 자료(C06): "미저작 공간의 '창작'은 배제하겠습니다. 대신 필요한 경우 가져다 쓸 수 있는 여러 **장소 조각**들을 만들어놓고, 가져다 붙이는 기능을 사용할 수 있겠습니다."
- 자료(물건 U02): 물건은 "미리 배치되지 않았더라도 랜덤 혹은 llm 선정에 의해 존재하는 것으로 처리할 수 있으며 묘사에 등장한 물건을 활용하는 것도 가능".
- Claude P5: 세부는 필요할 때 생성되어 정본이 된다 (영역 구분 없음).
- 판단: 사용자의 구분이 더 정교하다. **생성의 자유도는 영역마다 달라야 한다.**
  공간은 다른 모든 것이 얹히는 뼈대여서 즉석 창작의 위험이 크고, 물건은 작다.
  P5를 "영역별 생성 정책"으로 고쳐야 한다. 다만 이 대화에서 사용자가 P5를 수용했으므로, 자료의 입장이 지금도 유효한지 확인이 필요하다.

### 4.2 사건 — 사전저작 틀 대 시계

- 자료(U03): 발동 조건을 충족한 사건 중 마스터가 골라 발생, 여러 국면과 경우의 수, **빈칸에 물건·NPC를 채워 재활용하는 틀**.
  단 "사건 시스템의 목적에 따라 구조 자체를 다르게 설계할 권한"을 명시적으로 부여.
- 이 대화: 사건 템플릿은 저작 부담 때문에 버렸다고 진술. P6(세력의 계획 + 연출가)을 조건부 수용.
- Claude 독자안의 빈틈: 시계는 세력의 **방향**을 주지만, 그 순간 벌어지는 **장면의 내용**은 주지 않는다.
  "습격이 시작된다"는 나오지만 그 습격이 어떻게 흥미롭게 전개되는지는 없다.
- 종합 후보: 사건 틀을 **시나리오마다 쓰는 것이 아니라 엔진의 공용 항목**으로 둔다(매복, 추격, 협상, 발각, 배신 등).
  시계의 단계가 완료되면 맞는 틀에 현재 세계의 인물·물건이 채워진다.
  저작 부담은 엔진에 한 번만 들고, 사용자가 말한 "빈칸 채움과 재활용"이 그대로 산다. **미확정.**

### 4.3 설계의 진행 방식 — 영역별 대 형식 우선

- 자료: 14개 영역을 하나씩 깊게 설계한다. 영역마다 풍부한 고유 구조가 생긴다
  (물건 16범주, 의복의 피복 부위와 중첩 순서, 용기의 수용량과 개구부, 장소의 분류 헤드와 계승 …).
- Claude: 하나의 형식(사실 + 정의)을 먼저 정하고 영역은 어휘로 채운다.
- 판단: 서로 배타적이지 않으나 **순서가 중요하다.**
  영역별로 먼저 깊이 들어가면 영역마다 다른 구조가 생기고, 이를 나중에 합치는 비용이 구 프로젝트의 "덧붙이기"와 같은 문제를 낳는다.
  시간 설계실 기록의 "시간 정보의 분산 소유", "영역 간 요구사항 전달"이 이미 그 조율 비용의 징후다.
  반대로 Claude의 09 문서는 **영역의 깊이를 과소평가**했다. 기제 몇 개로 의복 중첩이나 용기의 내용물을 표현할 수 있는지 검증하지 않았다.
- 권고: 14개 영역을 **구조의 단위가 아니라 어휘의 점검표**로 쓴다.
  각 영역의 사용자 구상을 하나의 형식으로 실제로 적어 보고, 적히지 않는 것이 나오면 형식이나 기제를 고친다.
  사용자의 영역별 통찰이 형식의 시험 문제가 된다.

### 4.4 인간 GM

- 자료(공통 지침으로 인용됨): "인간 GM의 감독 아래 AI가 세계를 운영하고 서사를 진행하는 디스코드 기반 TRPG 보조 GM 시스템". U03에도 "마스터가 고른 사건".
- 이 대화: 마스터 = 디스코드 봇.
- 사람이 실시간으로 개입하는지에 따라 턴 구조, 연출가, 오류 처리가 달라진다. **확인 필요.**

## 5. 사용자 자료에만 있는 것 (독자안에 반영할 후보)

| --- | --- | --- |
| 원형과 실물 | 물건 자체의 원본 데이터와 세션 세계의 실물(보관, 묶음, 소유, 손상). 종류는 이름으로 구분. 수량은 개수를 넘어 ml, g 등 | 09의 개체에 **원형–실물 구분과 단위 있는 수량**이 없다. 추가 필요 |

| 현상의 관할 | 현상의 진행은 환경이, 그 결과의 적용은 각 대상의 영역이. 날씨는 시나리오 가이드의 범위 안에서 자율 변화 | 기제와 지침의 분담 사례 |
| 과업 | 강제도 보상도 없는 방향 추천. 선택지 탐색과 장기 목표 설정을 돕는다 | 독자안에 없다. 자유도 100%의 부작용(무엇을 할지 모름)에 대한 답 |
| 사회규범과 역할 | 사회적 역할, 기대되는 언행, 관습. 인물이 상황에 맞는 인간적 행위를 하도록 돕는다 | 독자안에 없다. 인물 호출의 입력으로 중요 |
| 인격 항목 | 말투, 습관, 욕구, 선호, 권리와 의무, 유대, 신뢰, 일과, 첫인상 … | 인물 어휘의 입력 |
| 정보의 추론 관계 | 정보가 다른 정보의 증거나 추론의 기반·목적지가 된다. 가능한 경로로만 전파 | 시야에 증거–결론 관계가 없다. 추리물에 필요 |
| 행동선언 유형 | 메타, 관찰, 이동, 조작, 소유, 제작, 신체, 공격, 방어, 환경, 의사소통, 은폐, 관계, 협력, 계획, 특수능력. 유형에 따라 열어 볼 정보와 고칠 정보를 구별 | 심판의 행동 틀과 문맥 조립의 선별 기준으로 쓸 수 있다 |

## 6. Claude 독자안에만 있는 것

자료가 아직 셋째·넷째 범주(LLM 전달, 묘사)에 이르지 않았기 때문에 대조 대상이 없다. 배제가 아니라 미도달로 읽는다.

- LLM 역할의 분리(심판, 인물, 서술자)와 문맥에 의한 정보 격리
- 인물마다 별도 호출, 대사는 그 인물이 직접 작성
- 판정은 지각을, 마음은 반응을 정한다
- 연출가 (완급 조절자)
- 사건 기록 기반의 되감기·재현, 가상 플레이어와 자동 검사, 시나리오 검사기
- 기억은 요약이 아니라 선별

## 7. 독자안 수정 후보

대조 결과 09·10 문서에 반영할 것. 사용자 확인 후 반영한다.

1. P5를 **영역별 생성 정책**으로 고친다 (공간: 조각 조립 / 물건: 생성 허용 / 그 외: 영역마다 정함). — 4.1 확인 후
2. 개체에 **원형–실물**과 **단위 있는 수량**을 넣는다.
3. 사실의 시간을 **불명확한 값과 상대 관계**까지 표현하게 한다.
