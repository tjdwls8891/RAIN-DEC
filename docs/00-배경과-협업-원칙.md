# 배경과 협업 원칙

## 배경 (사용자 진술, 2026-11-12)

- 이 작업은 기존 프로젝트 하나를 **전면 재설계 및 재개발**하는 것이다.
- 구 프로젝트는 사용자가 "실패한 프로젝트"로 규정한다.
  - 오랜 기간, 아쉬운 점과 추가하고 싶은 기능을 **덧붙이는 방식**으로 개발되었다.
  - 목표치의 약 7할을 구현했으나 **수정 비용이 커졌다.**
- 목표: 그간 쌓은 통찰과 구체화된 목표를 바탕으로 **최적화되고 강력한 엔진**을 다시 만든다.

## 진행 방식 (사용자 지정)

1. 먼저 사용자의 생각과 바람을 듣는다.
2. 세부 계획과 구 프로젝트 파일은 **시기에 맞게 단계적으로** 전달받는다.
   - 이유: Claude가 구 프로젝트의 형태에 **과적합**되는 것을 막기 위함.
3. 대화 단계에서부터 설계·원칙·철학을 기록한다.
4. 기록은 항상 **GitHub 레포지토리에 파일로** 남긴다.

## 소통 원칙 (사용자 지정)

- 답변은 **필요한 만큼의 설명과 질문**으로 구성한다.
- 내용이 부족해 소통이 변질되는 것을 경계하되, 과하게 늘려 쓰지 않는다.

## Claude의 작업 태도 (해석)

- 구 프로젝트 자료를 받기 전에는 그 구조를 추측하거나 전제하지 않는다.
- 구 프로젝트 자료를 받은 뒤에도, 그것은 "무엇을 원했는가 / 무엇이 아팠는가"의 증거로 읽고
  "어떻게 만들 것인가"의 기본값으로 삼지 않는다.
- 설계 결정은 구현 형태보다 목표와 원칙에서 먼저 도출한다.
