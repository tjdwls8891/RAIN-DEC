# 형식 시험 2: 나머지 열두 영역

2026-11-12. [12](12-형식-시험-물건과-장소.md)에 이어, 14개 영역 중 남은 열두 영역을 장부 형식으로 적어 보았다.
이로써 14개 영역 전부를 한 번씩 시험했다.

- 시험에 쓴 형식: [09](09-장부-설계.md) + [12](12-형식-시험-물건과-장소.md) §4의 개정 사항.
- 근거로 삼은 요구: `자료/INDAIM/`의 사용자 원문(전체 청사진 U02~U08, 추가 구상 U01, 시간 정책 P01~P08, 환경 구상 1~3)과 이 대화.
- 시간과 환경을 뺀 열 영역은 사용자 구상이 몇 문장뿐이다. **Claude가 요구를 추정해 적은 부분이 많다.** 사용자 검증이 필요하다.
- **종이 위의 시험이다.** 형식으로 "적을 수 있는가"만 확인했다. LLM이 이 형식의 제안을 안정적으로 내는지, 비용 안에 드는지는 확인하지 않았다.

## 1. 결론

- **열두 영역 모두 적혔다.** 여섯 요소의 틀을 바꿔야 하는 영역은 없었다.
- **기제의 증가가 멈췄다.** 물건·장소에서 넷이 늘었으나 이번 열두 영역에서는 **하나**(전이)만 늘었다.
  기존 기제 중 다섯은 다른 것의 조합으로 환원되어, 기본 기제는 **일곱**으로 정리된다 (§4).
- 형식을 고쳐야 할 것이 **넷** 나왔다 (§3). 그중 "명제를 담는 것"의 일반화가 가장 크다.
- 진짜 위험은 형식이 아니라 다른 곳에 있다: **조건 언어**, **공용 사전의 분량**, **종이 시험의 한계** (§5).

## 2. 영역별 결과

### 2.1 시간 — 됨 (고침 2)

```
시각(사건#412) = 3일차 21:40
시각(사건#398) = 3일차 밤 무렵            # 뭉뚱그린 시간: 범위로 저장
앞섬(사건#398 → 사건#401) = 직전          # 값 없이 알려진 선후 관계
```

- 단일 시간축과 내부 단일값, 달력은 파생 표현: 엔진 코드의 일. 형식과 충돌 없음.
- 시점·지속·구간: 사실의 "언제부터 – 언제까지".
- 현재 시각만 시간이 소유하고 역사는 밖에: 사건 기록이 역사다. 시간 정보의 분산 소유: 시간이 각 사실에 딸리므로 자연히 그렇게 된다.
- 단조 진행과 목표 시점 지정: 목표 시점까지 예약된 일을 순서대로 처리.
- **고침:** 값의 종류에 **범위를 허용하는 시간**. **사건을 사실의 주체로** 쓸 수 있어야 한다.

### 2.2 환경 및 현상 — 됨 (기제 1 추가)

```
날씨(강남_일대) = 비                      # 분류 헤드에 두고 장소들이 계승. 실내는 덮어씀
정의: 날씨
  전이: 맑음→흐림 낮음, 흐림→비 보통, …   # 시나리오 가이드가 범위를 정한다
개체: 화재#1
  위치(화재#1 → 객잔_주방) = 안에        세기 = 중간
  같은 장소의 타는 물건에: 탐 상태 부착
```

- 기온·날씨는 가이드 범위 안에서 자율 변화: **전이 기제** (상태에서 상태로 옮겨 가는 표).
- 화재 등은 외부의 확정 명령으로 발생·변화·종료: 제안 → 검사 → 기록. 받는 쪽은 실현 여부를 재판단하지 않는다.
- 진행 중인 화재가 옆 건물로 번지는 것은 환경의 자율 판단: 심판이 두 건물의 사실을 근거로 시점을 정하고, 결과를 **예약**한다.
- 현상의 진행은 환경이, 결과의 적용은 대상 쪽이: 현상의 정의에 딸린 규칙이 대상의 상태를 바꾼다. 판정이 필요한 것(화상)은 심판으로.
- 비가 그쳐도 젖은 물건: 상태는 물건에 붙어 있고 따로 마른다.

### 2.3 신체 및 건강 — 됨 (추가 없음)

```
근력(강호민) = 14        숙련(강호민, 검술) = 상
허기(강호민) = 높음      피로(강호민) = 보통
개체: 부상#7
  위치(부상#7 → 강호민) = 왼팔         종류 = 자상     심각도 = 깊음
  출혈 = 진행 중                        처치 = 붕대
개체: 감염#2  (시계: 잠복 → 발현 → 악화)
```

- 능력치, 숙련, 상태 게이지와 상태 간 상호작용: 기존 형식 그대로.
- **부상은 개체다.** 부위, 종류, 심각도, 처치, 회복 진행을 따로 가진다. 부위는 의복의 피복 부위와 같은 어휘를 쓴다.
- 질병·중독·감염의 발현 지연과 단계: 시계 + 예약.
- "왼팔 부상이 이 행동에 불리한가"는 코드가 모른다. 심판이 부상 사실을 보정 요인으로 든다.
- 사람이 아닌 몸(짐승, 괴물)은 부위 어휘를 바꾼 **몸의 틀**로.
- 물건·장소와 성격이 가장 다른 영역인데 추가가 없었다. 형식이 버틴다는 가장 강한 신호다.

### 2.4 감각 — 됨 (추가 없음)

- 감각 능력(시력, 청력)과 그것을 낮추는 상태(어둠, 이명): 사실.
- 조도와 소음: 장소의 사실.
- 지각 판단: 명백한 경우는 코드, 경계 사례는 심판, 결과는 기록 (12 문서 §3.4).
- 숨겨진 것의 발견: 겉보기 "숨겨짐" + 관찰 행동 + 판정 → 시야에 추가.
- 오인(어둠 속에서 잘못 봄): 시야의 사실이 진실과 다르고 확신이 낮다.
- 사건의 지각에는 **어떤 감각으로**가 붙는다 (보았다 / 소리만 들었다).

### 2.5 정보 — 됨 (형식 일반화 1)

```
개체: 소문#4
  담긴 것: «위치(범인) = 보트창고»   확신: 낮음        # 명제. 참인지는 별개
개체: 편지#9
  담긴 것: «혈연(주모 ↔ 흑풍채 두목) = 남매»
뒷받침(단서#2 → 명제#31) = 강함                        # 증거와 결론
평판: 마을 사람들의 시야에 «강호민 = 수상한 외지인»
```

- 인지, 오해, 믿음의 정도, 진위 불일치, 출처, 기억: 시야가 이미 다룬다.
- **인물에게 속하지 않은 정보**: 소문, 문서, 기록, 단서도 명제를 담는다.
  시야를 "마음이 아는 것"에서 **"명제를 담는 모든 것"**으로 일반화한다. 마음, 집단, 문서, 소문이 같은 장치다.
  - 편지를 읽는다 = 편지에 담긴 명제가 읽은 이의 시야로 복사된다 (출처: 편지).
  - 소문이 퍼진다 = 명제가 집단의 시야로, 때로 변형되어 복사된다.
  - 평판 = 어떤 집단의 시야에 담긴, 그 인물에 대한 명제.
- 증거와 추론: 명제에 식별자를 주어 "이 단서가 저 결론을 뒷받침한다"를 사실로 적는다.
- 전파는 가능한 경로로만: 같은 자리의 대화, 문서의 전달, 집단 안에서의 시간에 걸친 확산(예약).
- **주권과의 접점:** 엔진은 **PC를 대신해 추론하지 않는다.** PC의 시야에는 지각한 것만 들어가고, 결론은 유저가 낸다.
  NPC의 추론은 그 인물의 호출이 자기 시야로 한다.

### 2.6 심리 및 판단 — 됨 (추가 없음)

```
성격(주모) = "셈이 빠르고 의심이 많다. 약한 사람에게는 무르다."     # 서술문
말투(주모) = "반말 섞인 장삿말. 화나면 말수가 준다."
분노(주모 → 강호민) = 높음                                          # 대상이 있는 감정
두려움(주모) = «흑풍채와의 관계가 드러나는 것»
```

- 성격, 말투, 습관, 가치관, 선호: 서술문. 읽는 것은 LLM뿐이므로 해석의 폭이 허용된다.
- 감정, 욕구: 게이지. 시간이 지나면 가라앉는다. 대상을 가질 수 있다.
- 목표: 계획 개체. 두려움: 명제를 가리키는 사실.
- **의사결정은 자료가 아니라 호출이다.** 주요 인물은 인물 호출이 정한다. 감정 변화는 인물 호출이 제안하고 코드가 폭을 검사한다.
- 단역과 화면 밖 인물은 일과(전이·예약)와 계획(시계)으로 거칠게 움직인다.
- PC의 심리는 추적하지 않는다. 판정으로 붙는 상태("겁에 질림")만 있고, 그것은 불이익만 준다 (P2).

### 2.7 관계 — 됨 (추가 없음)

- 주관적 관계(호감, 신뢰): 방향이 있는 게이지. A가 B를 믿는 것과 B가 A를 믿는 것은 다른 사실.
- 객관적 관계(혈연, 고용, 사제): 관계 사실. 대칭 여부는 정의가 정한다.
- 관계에 대한 오해(친구라 믿지만 첩자): 시야.
- 관계의 이력: 두 사람이 함께 겪은 사건을 골라낸다. 오래된 관계는 요약 서술로 저장.

### 2.8 사회규범 — 됨 (추가 없음)

```
역할(주모 @ 만리객잔) = 주인
정의: 역할·객잔 주인
  기대: "손님을 맞고 셈을 받는다. 소란은 직접 말린다."
규범: 무림인 집단의 시야에 «선배에게 먼저 포권한다»
출입(객잔_주방) = 일하는 사람만
```

- 역할: 인물이 역할을 가지면 그 역할의 기대와 권한을 **계승**한다.
- **규범은 집단이 아는 것이다.** 집단의 시야에 담긴다. 그래서 외지인은 관습을 모르고, 모르고 어길 수 있다.
- 위반의 감지와 반응: 그것을 본 인물의 호출이 판단한다. 결과는 평판과 관계의 변화로 기록.

### 2.9 세력 — 됨 (열린 문제 1)

- 구성원과 직책(관계 사실), 자원(양), 영역(지배 관계), 세력 간 관계(게이지), 공유 지식(집단 시야), 목표와 계획(시계).
- 화면 밖 진행: 시계가 돌고, 단계가 완료되면 사건 틀이 찍혀 나온다.
- **열린 문제:** PC가 세력의 계획을 부쉈을 때 **새 계획을 누가 세우는가.**
  세력의 지식과 목표로 다음 계획을 정하는 호출이 필요하다. 드물게 일어나므로 비용은 작지만,
  "LLM은 작가로서 부족하다"는 우려가 다시 걸리는 지점이다. 계획의 틀에서 고르게 하는 것이 후보다.

### 2.10 사건 — 됨 (추가 없음)

```
틀: 매복
  빈칸: 매복자(세력의 무리), 표적(인물), 길목(장소)
  발동 조건: 적대(매복자의 세력 → 표적) 높음, 표적의 경로를 앎
  국면(시계): 잠복 → 포위 → 습격 → 추격 또는 철수
  방치 시: 표적이 지나가지 않으면 철수
  반복: 세력당 3회
```

- 사건 틀 = **틀 + 시계 + 조건**. 새 요소가 필요 없다.
- 발동 조건을 충족한 것 중 고르는 일: 연출가.
- 플레이어가 이탈하면: 틀마다 "방치 시" 진행이 있다. 이탈을 따로 처리하지 않는다.
- 조건은 규칙·적용 대상·변수 조건과 **같은 조건 언어**를 쓴다.

### 2.11 과업 — 됨 (추가 없음)

- 과업은 **PC의 시야에 담긴 개체**다. PC가 아는 "해 볼 만한 일"이다. 강제도 보상도 없다.
- 생성: 틀에서, 또는 PC가 알게 된 계획·단서에서. 상태판에 보여 준다.
- 유저가 선언한 장기 목표는 PC의 계획 개체로 둔다. 유저가 정한 것이므로 주권과 충돌하지 않는다.

### 2.12 행동선언 — 됨 (구조적 이득 1)

```
정의: 행동유형·관찰
  열어 볼 것: 대상의 겉보기 사실, 장소의 조도, 행위자의 감각
  고칠 수 있는 것: 행위자의 시야
  기본 소요: 짧음
```

- 사용자가 든 16개 유형은 어휘(정의)가 된다. 유형마다 **열어 볼 정보**와 **고칠 수 있는 속성**을 적는다.
- 열어 볼 정보 → 문맥 조립의 선별 기준.
- 고칠 수 있는 속성 → **쓰기 권한.** 관찰 행동의 결과로 세계의 사실을 바꾸는 제안은 코드가 거부한다.
  사용자 구상의 "유형에 따라 수정하거나 열어 볼 정보를 구별"이 구조적 보장이 된다.
- 복합 선언(이동하며 숨기): 행동 틀 여럿, 유형 여럿.
- 조건부 선언("칼을 뽑으면 달아난다"): PC에 딸린 임시 규칙.

## 3. 형식에 대한 추가 개정 사항

12 문서 §4의 아홉 가지에 더한다.

10. 값의 종류에 **범위를 허용하는 시간**을 더한다.
11. **사건**을 사실의 주체로 쓸 수 있게 한다 (사건 사이의 선후 관계).
12. 시야를 **"명제를 담는 것"**으로 일반화한다: 마음, 집단, 문서, 소문, 기록. 명제는 식별자를 가질 수 있다.
13. 조건을 쓰는 모든 곳(규칙, 발동, 적용 대상, 변수)이 **하나의 조건 언어**를 쓴다.

그리고 형식이 아닌 운영 규칙 둘:

- 엔진은 PC를 대신해 추론하지 않는다.
- 행동 유형의 정의가 제안의 쓰기 권한을 정한다.

## 4. 기제의 정리

지금까지 나온 기제 열하나 가운데 다섯은 다른 것으로 환원된다.

| 처음 든 기제 | 환원 |
| --- | --- |
| 관계 척도 | 대상이 있는 게이지 |
| 추격 거리 | 게이지 |
| 소모 자원 | 단위 있는 양 + 규칙 |
| 성장 궤도 | 게이지 + 임계 규칙 |
| 비밀과 단서 | 명제를 담는 개체 + 시야 |

남는 **기본 기제는 일곱**이다.

| 기제 | 하는 일 | 쓰이는 곳의 예 |
| --- | --- | --- |
| 게이지 | 등급·수치가 조건에 따라 오르내린다 | 피로, 분노, 신뢰, 상함, 화재의 세기 |
| 시계 | 단계가 순서대로 진행된다 | 세력의 계획, 감염, 사건의 국면 |
| 전이 | 상태가 표에 따라 다른 상태로 옮겨 간다 | 날씨, 단역의 일과 |
| 예약 | 정해진 시점에 일이 일어난다 | 약효의 끝, 불이 옮겨붙는 시점, 소문의 확산 |
| 위치 제약 | 자리 수, 용량, 허용 종류 | 양손, 의복의 층, 용기, 탈것의 좌석 |
| 변환 | 재료가 결과로 바뀐다 | 제작, 조리, 장전 |
| 계승 | 없는 사실은 가장 가까운 위에서 가져온다 | 원형, 분류 헤드, 역할, 집단 시야 |

- 14개 영역을 다 돌고 나서 일곱이다. 처음 두 영역에서 넷이 늘었고 뒤의 열두 영역에서 하나가 늘었다.
- 장르 고유 요소(내공, 헌터 등급, 감염, 단서)는 이 일곱의 조합으로 정의될 것으로 본다. 장르별 시험은 아직 하지 않았다.

## 5. 위험

### 조건 언어가 설계의 중심이 되었다

- 규칙, 사건의 발동, 상태의 적용 대상, 변수의 조건이 모두 조건을 쓴다. 이 언어의 표현력이 엔진이 할 수 있는 일의 한계다.
- 표현력을 높이면 프로그래밍 언어가 되어 저작 난이도 제약을 깬다. 낮추면 자연어 지침으로 넘치고 해석의 유일성이 깨진다.
- 다음에 가장 먼저 설계해야 할 대상이다.

### 저작 부담이 시나리오에서 공용 사전으로 옮겨 갔다

- "엔진은 모든 장르를 안다"는 공용 정의, 원형, 틀이 수백 개 필요하다는 뜻이다.
- 시나리오 저작은 가벼워지지만 사전을 쓰는 일은 크다. 한 번만 하면 된다는 점이 다르다.
- 대응 후보: 플레이할 첫 시나리오에 필요한 만큼만 쓰고 키워 간다. 초안은 LLM이 쓰고 검사기가 거른다.

### 서술문의 비중

- 심리, 관계, 사회규범은 내용 대부분이 서술문이다. 코드는 이것을 읽지 못한다.
- 문제는 해석이 아니라 **선별**이다. 어떤 서술문을 이번 호출에 넣을지는 표지와 관계로 정해야 한다.

### 종이 위의 시험이다

- 확인한 것은 "적을 수 있다"뿐이다. 다음은 확인하지 않았다.
  - 심판과 인물 호출이 이 형식의 제안을 안정적으로 내는가.
  - 문맥 조립이 필요한 사실을 빠뜨리지 않고 고르는가.
  - 전체가 턴당 50원, 15초 안에 드는가.
- 이것은 작동하는 최소 구현으로만 확인할 수 있다.

### 요구를 추정했다

- 시간과 환경을 뺀 영역은 사용자 구상이 짧아, 예시의 상당 부분이 Claude의 추정이다.
  빠진 요구가 있으면 그 영역의 판정은 바뀔 수 있다.
