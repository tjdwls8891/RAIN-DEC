## 2. 구현의 원칙

| 원칙 | 까닭 |
| --- | --- |
| **모르는 것부터 잰다** | 설계 전체가 재 보지 않은 가정 위에 있다: 15초, 50원, 닫힌 판단을 LLM이 잘 따르는가. 틀렸다면 일찍 알아야 한다 |
| **가늘게 끝까지, 그 뒤에 넓게** | 한 장면이 선언에서 서술까지 도는 것을 먼저 만든다. 영역을 하나씩 다 채우고 잇지 않는다 |
| **내용은 쓰는 만큼만** | 사전의 내용(재질, 상태, 장면의 유형)은 첫 시나리오가 실제로 건드리는 것부터 쓴다. 나머지는 채움과 편입으로 자란다 |
| **단계마다 통과 기준** | 기준에 못 미치면 넓히지 않고 설계로 돌아온다 |
| **가짜 LLM으로 먼저** | 코드의 흐름은 가짜 답으로 시험한다. 실제 호출은 재는 데에 쓴다 |

## 3. 구현 순서

| 단계 | 만드는 것 | 통과 기준 | 필요한 것 |
| --- | --- | --- | --- |
| **0. 재기** | 호출 셋(해석, 닫힌 판단, 서술)을 따로 떼어 실제 모델로 잰다. 구 기록의 장면 몇 개를 입력으로 쓴다 | 대기와 값의 어림이 나온다. 닫힌 물음을 꼴대로 답하는가. 서술이 주권을 넘는 비율 | **API 열쇠** |
| **1. 뼈대** | 장부를 항목표에 맞춘다(상태, 특성, 수량, 시간). 턴의 일곱 단계를 가짜 LLM으로 | 객잔 장면에서 뻔한 행동이 판단 없이 끝까지 돈다. 늘 참이어야 하는 것의 검사가 턴마다 돈다 | 없음 |
| **2. 가는 한 줄** | 객잔 시나리오를 실제 LLM으로, 글자 화면에서. 행동 유형 서넛(살피기, 옮겨 가기, 물건 다루기, 말하기) | 20턴을 사람이 해 볼 수 있다. 대기와 값이 잰 어림과 맞는다 | API 열쇠 |
| **3. 꿰는 것** | 턴 끝의 경과 계산, 감각 모으기, 확정의 사다리와 채움, 판정(버튼, 정도, 강제) | 추위의 예와 도자기 병의 예([26](26-코드-권위의-세계.md))가 돈다. 발견 선언이 허용선대로 갈린다 | 판정의 값(§5) |
| **4. 사람** | 인물의 가이드 네 층, 주목과 정산, 인식 단계, 기만과 설득 | 구 기록의 "무릎을 보자는 형사" 장면에서 순응과 누설을 센다. 인물을 움직이는 세 방식을 가른다 | |
| **5. 진행** | 조직, 계획(틀에서 고르기, 재수립), 사건(국면과 경우, 장면의 유형), 과업 | 가상 플레이어 50턴에서 계획이 나아가고, 막히면 고쳐지고, 사건이 되풀이 한도 안에 있다 | 계획의 틀과 장면의 유형 몇 개 |
| **6. 화면** | 디스코드: 스레드, 버튼, 흘러나오는 서술, 상태판, 세션의 저장과 이어 하기, 되감기 | 사용자가 휴대전화로 한 세션을 끝까지 한다 | 디스코드 열쇠 |
| **7. 첫 시나리오** | 사용자의 시나리오 하나를 새 양식으로. 사전의 내용을 그것이 건드리는 만큼. 저작 도구(검사기, 되읽기) | 저작에 든 시간을 잰다. 저작되지 않은 것의 목록이 감당할 만한가 | 구 시나리오 자료 |
| **8. 다지기** | 실패 대응 전부, 캐시, 가상 플레이어의 성향 넓히기, 채운 것의 검토 흐름 | 과부하와 차단을 일부러 일으켜도 세션이 살아 있다 | |

- 0과 1은 서로 기다리지 않는다. 1은 지금 시작할 수 있고, 0은 열쇠가 들어오는 대로 한다.
- 6(화면)을 뒤에 둔 까닭: 디스코드는 익숙한 기술이고 설계의 위험이 그곳에 있지 않다. 다만 사용자가 지금 휴대전화만 쓸 수 있다면 **6을 2 바로 뒤로 당긴다**(§6의 1).
- 7에서 구 시나리오 자료를 받는다. 내용은 요구로 읽고 형식은 가져오지 않는다.

## 4. 시험 계획

층은 [34](34-운영.md) §6에 있다. 단계마다 무엇이 붙는가:

| 단계 | 붙는 시험 |
| --- | --- |
| 0 | 호출의 시험 묶음 첫 판 (구 기록의 장면에서 뽑은 입력) |
| 1 | 규칙의 시험, 늘 참이어야 하는 것, 격리의 시험 |
| 2 | 되풀이 시험(녹화한 답), 턴마다의 계측 |
| 3 | 상태 규칙마다의 시험. 판정의 분포(만 번 굴려 정도의 비율을 본다) |
| 4 | 순응과 누설을 세는 호출의 시험 |
| 5 | 가상 플레이어 |
| 7 | 검사기가 시나리오를 통과시키는가. 돌려 보기 |

**재 볼 물음** (답에 따라 설계가 바뀌는 것):

| 물음 | 답이 나쁘면 |
| --- | --- |
| 해석 → 판단 → 서술의 시작이 15초 안에 드는가 | 해석과 판단을 합친다, 서술의 사고를 끈다, 모델을 낮춘다 |
| 한 턴이 50원 안에 드는가 | 판단에 주는 것을 줄인다, 저절로 되는 캐시가 먹는지 본다 |
| 닫힌 물음이 한 턴에 몇 개인가, LLM이 다 꼴대로 답하는가 | 물음을 나눠 부른다, 물음을 항목으로 더 바꾼다 |
| 판단 없이 끝나는 턴이 얼마나 되는가 | 낮으면 뻔한 귀결의 목록을 늘린다 |
| 서술이 재료에 없는 것을 얼마나 지어내는가 | 많으면 보류 중인 "지어낸 세부의 기록"을 정해야 한다 |
| 판단이 인물을 움직일 때 순응하고 누설하는가 | 결정의 순간에 인물을 따로 부른다 |
| 채운 항목이 턴마다 몇 개 생기는가 | 많으면 사전의 내용이 모자란 것이다. 어느 영역인지 본다 |

## 5. 미결 목록

### 가. 사용자가 보류한 것 (다시 꺼낼 때까지 정하지 않는다)

| 것 | 걸리는 곳 |
| --- | --- |
| 서술이 지어낸 세부를 어떻게 기록하는가 | 서술, 장부 |
| 두 층위의 뜻 | 마스터의 층위 |
| 사건 기록의 방식과 예약 (화면 밖의 진행) | 진행, 되감기 |
| 무른 사실 | 장부 |
| 세계의 신호가 어디서 오는가 | 서술 |
| 만난 이력 | 관계 |

- 구현은 이것들 없이 시작할 수 있다. 3~5단계에서 걸리면 그때 꺼낸다.

### 나. 사용자와 함께 연구할 것

| 것 | 언제까지 |
| --- | --- |
| 판정의 값: 능력치의 폭, 난이도의 단계, 정도 여섯의 경계 | 3단계 앞 |
| 두 능력치를 묶는 판정 | 3단계 앞 |
| 2d50보다 나은 판정이 있는가 | 3단계 앞 |
| 인물의 가이드를 실제로 어떻게 쓰는가 (사람 일반의 가이드의 첫 판) | 4단계 앞 |

### 다. 재 보고 정할 것

§4의 "재 볼 물음" 일곱과:

| 것 |
| --- |
| 해석과 판단을 한 호출로 합치는가 |
| 인물의 말을 판단이 쓰는가 서술이 쓰는가 |
| 인물을 움직이는 세 방식 가운데 무엇인가 |
| 만들어 두는 캐시를 쓰는가 |
| 되읽기를 턴마다 내는가 |
| 역할마다 어느 모델인가 |

### 라. 4단계 (내용. 구현과 함께)

[32](32-항목표.md) §16의 열 가지. 첫 시나리오가 건드리는 것부터.

### 마. 설계가 얇은 곳 (Claude의 판단)

정해졌다고 적었지만 실제로 돌려 보면 가장 먼저 흔들릴 것으로 보는 곳이다.

| 곳 | 까닭 |
| --- | --- |
| "판단 물음을 항목 채우기로 바꾼다" | 가설이다. 항목으로 바꿀 수 없는 판단(이 충격이 병을 깰 만한가)이 얼마나 남는지 모른다 |
| 장면의 유형 | 사건의 총량 문제에 대한 답으로 냈으나 목록도 한 예도 아직 없다 |
| 감각 모으기의 경계 | 옆방의 소리, 어둠 속의 윤곽. 항목으로 푼다고만 적었다 |
| 상태끼리의 상호작용 | 젖음과 추위, 출혈과 피로. 규칙이 서로 물리면 수가 빠르게 는다 |
| 저작량 | 항목 약 170개에 사전의 내용까지. 한 사람이 감당할 수 있는지는 7단계에서야 안다 |

## 6. 필요한 판단
