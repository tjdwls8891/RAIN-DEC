# 운영 (3단계)

2026-11-14. 다섯 덩어리 가운데 "마. 운영"이다. 세션, 되감기, 캐시, 비용과 대기, 실패, 시험, 저작 도구, 과금, 다인 플레이.
표시가 없는 것은 **[제안]**이다.

## 1. 세션

| 것 | 내용 |
| --- | --- |
| 여는 일 | 시나리오를 고른다 → 변수를 정한다(열쇠가 있는 곳, 범인) → 세계의 장부를 만든다 → PC를 만든다 → 시작 |
| 자리 | 디스코드의 스레드 하나에 세션 하나 |
| 저장되는 것 | ① 사건의 기록(턴마다 확정된 변화, 덧붙이기만 한다) ② 가끔 찍는 장부의 사본 ③ 플레이어에게 나간 글 ④ 호출의 기록(비용, 시간, 실패) |
| 쉬기와 이어 하기 | 턴이 끝난 뒤에는 언제든 떠날 수 있다. 돌아오면 **지난 줄거리**(PC가 아는 것으로만)와 상태판을 보이고 잇는다 |
| 턴 도중에 꺼졌을 때 | 턴의 일지를 본다. 끝난 단계는 다시 하지 않고 이어서 한다. 굴린 눈도 일지에 있다 |
| 한 번에 한 턴 | 처리 중에 온 글은 받지 않고 알린다 |
| 닫기 | 결말([33](33-묘사와-경험.md) §9)이나 플레이어의 뜻으로. 닫은 세션의 기록은 남는다 |

- 세계의 현재는 "시작 때의 장부 + 사건의 기록"이다. 어느 턴으로든 되돌려 볼 수 있다(최소 구현에서 확인된 성질).
- 세션 기록에는 플레이어를 식별할 수 있는 것이 들어간다. 저장소에 올리지 않고 따로 둔다.

## 2. 되감기

| 것 | 내용 | 정도 |
| --- | --- | --- |
| 무엇인가 | 지난 턴의 끝으로 세계를 되돌린다 | |
| 주사위 | 되감으면 다시 굴린다 | 확정 |
| 판단 | 되감으면 다시 한다. 같은 답이 나온다는 보장이 없다 | |
| 채운 항목 | **남긴다.** 그 뒷골목이 바람막이가 아니라는 것은 세계의 성질이고, 턴에 일어난 일이 아니다 | 제안 |
| 사전에서 골라 확정된 실물 | 되감긴 턴에서 생긴 것은 사라진다. 서랍 속은 다시 정해진다 | 제안 (아래) |
| 화면 | 되감긴 턴의 글은 지우지 않고 "되감김" 표시를 단다 | 제안 |
| 얼마나 | 제한을 두지 않는다. 시나리오가 줄일 수 있다 | 제안 |

- "보여 준 것은 철회되지 않는다"와의 관계: 그 원칙은 **이어지는 이야기 안에서** 마스터가 말을 바꾸지 않는다는 것이다. 되감기는 플레이어가 그 이야기를 버리는 일이다.
- 사전에서 골라 확정된 실물을 남길지 지울지는 판단이 필요하다(§11의 1). 남기면 되감기로 서랍을 다시 뽑는 일이 없고, 지우면 되감기가 깨끗하다.
- 되감긴 가지의 기록을 어떻게 두는가(지우는가, 가지로 남기는가)는 사건 기록의 방식과 함께 **보류**다.

## 3. 캐시

[19](19-캐시.md)의 결론을 새 흐름([31](31-접점과-턴.md))에 맞춘다. **없어도 도는 구조 위에 얹는다.**

| 층 | 방법 | 드는 것 |
| --- | --- | --- |
| 저절로 되는 캐시 | 호출마다 **바뀌지 않는 것을 앞에, 바뀌는 것을 뒤에** 둔다. 앞이 같으면 깎인다 | 없음. 순서만 지키면 된다 |
| 만들어 두는 캐시 | 큰 시나리오에서 **판단**에 세계 전체를 준다 | 보관료(시간으로 나간다), 낡음(변한 것을 뒤에 붙이고 쌓이면 다시 만든다) |

호출별 앞부분(바뀌지 않는 것):

| 호출 | 앞에 두는 것 | 세계 전체를 받는가 |
| --- | --- | --- |
| 해석 | 행동 유형의 목록, 읽는 규칙 | 받지 않는다 (PC의 앎만) |
| 판단 | 물음의 종류와 답하는 법, 사람 일반의 가이드, 세계관의 가이드 | **받을 수 있다** (만들어 두는 캐시) |
| 서술 | 문체, 서술의 원칙, 누구나 아는 세계의 상식 | 받지 않는다 (PC의 감각만) |

- 세계 전체를 아는 곳은 판단뿐이다. 해석과 서술은 문맥으로 막힌 채로 둔다.
- 만들어 두는 캐시를 쓸지는 시나리오의 크기와 측정으로 정한다. 구 세션의 실측은 캐시 약 43,000토큰이었다.
- 느리게 하는 플레이어일수록 보관료 때문에 턴당 값이 오른다. 일정 시간 입력이 없으면 캐시를 놓고, 돌아오면 다시 만든다.

## 4. 비용과 대기

| 것 | 내용 |
| --- | --- |
| 과녁 | 턴당 50원 이하. 대기 15초 미만 [확정] |
| 재는 것 | 호출마다: 모델, 들어간 토큰(캐시된 것 따로), 나온 토큰(사고 따로), 걸린 시간, 첫 글자까지의 시간, 실패와 다시 한 횟수 |
| 턴마다 | 구간별 대기(선언→되읽기, 선언→버튼, 버튼→첫 문장), 턴의 값 |
| 역할별 모델 | 설정에서 정한다. 해석은 작고 빠른 것, 판단과 서술은 측정으로 |
| 넘칠 때 | 대기가 허용선에 닿으면: 사고를 줄인다 → 작은 모델로 → 짧은 서술. 값이 넘치는 턴이 이어지면 저작자에게 알린다 |
| 판단 없는 턴 | 뻔한 행동은 판단을 부르지 않는다([31](31-접점과-턴.md) ②). 그 비율을 잰다 |

- 구 세션의 실측(턴 57초, 50~66원)이 견줄 바닥이다.
- 아직 실제 호출로 잰 적이 없다. **구현의 첫 일이 측정이다**([35](35-구현-순서와-미결.md)).

## 5. 실패

원칙 넷([21](21-주목-대기-실패.md) §6)과 호출별 물러서기([31](31-접점과-턴.md) §5)는 그대로다. 운영에서 더하는 것:

| 실패 | 대응 |
| --- | --- |
| 과부하, 한도 | 간격을 늘리며 다시 → 다른 모델. 플레이어에게 "잠시 걸린다"고 알린다 |
| 빈 응답, 끊긴 응답 | 끝난 이유를 본다. 사고에 다 썼으면 사고를 줄여 다시 |
| 꼴이 깨진 답 | 닫힌 물음은 **정해진 꼴로만 답하게** 받는다(후보 밖의 답이 나올 수 없게). 그래도 깨지면 물음마다의 기본값 |
| 안전 필터의 차단 | 다시 해도 같다. 판단이면 다른 모델로, 서술이면 수위를 낮춰 다시 → 짧은 서술 |
| 시간 초과 | 호출마다 상한. 대기 허용선에서 거꾸로 셈한다 |
| 디스코드: 버튼의 응답 기한 | 누르면 곧바로 받았다고 답하고, 결과는 그 뒤에 |
| 디스코드: 글을 고치는 한도 | 흘러나오는 서술은 간격을 두고 모아 고친다 |
| 디스코드: 보내기 실패 | 다시 보낸다. 턴은 이미 확정되었으므로 **글만** 다시 보낸다 |
| 봇이 꺼짐 | 턴의 일지로 잇는다(§1) |
| 장부의 검사에 걸린 변화 | 실패가 아니다. 걸린 것만 버리고 남긴다. 저작자가 보는 목록에 적는다 |

- 플레이어는 언제나 지금 무슨 일인지 안다. 조용히 멈춰 있지 않는다.

## 6. 시험

| 층 | 무엇을 | LLM | 언제 |
| --- | --- | --- | --- |
| 규칙의 시험 | 상태의 규칙, 조건, 위치, 수량. 규칙마다 | 없음 | 고칠 때마다 |
| 늘 참이어야 하는 것 | 수량은 보존된다, 무엇이든 한 곳에만 있다, 고유한 것은 하나다, 닫힌 범위에 새것이 없다, 시간은 거꾸로 가지 않는다 | 없음 | **플레이 중에도 턴마다** |
| 격리의 시험 | 해석과 서술이 받는 것에 PC가 모르는 것이 없다 | 없음 | 턴마다, 시험에서 |
| 되풀이 시험 | 녹화해 둔 LLM의 답으로 턴을 다시 돌린다. 코드를 고쳐도 결과가 같은가 | 녹화 | 고칠 때마다 |
| 호출의 시험 | 호출 하나에 정해 둔 입력을 주고 답을 본다: 꼴을 지키는가, 주권을 넘는가, 모르는 것을 말하는가, 순응하는가 | 실제 | 프롬프트와 모델을 바꿀 때 |
| 가상 플레이어 | LLM이 플레이어 노릇을 한다. 성향을 나눠(조심스러운, 무모한, 속이려는, 사칭하는) 수십 턴 | 실제 | 시나리오를 쓸 때, 큰 변경 뒤 |
| 사람의 플레이 | 사용자 | 실제 | |

- 가상 플레이어의 플레이에서 뽑는 것: 대기와 값의 분포, 판단 없는 턴의 비율, 걸린 변화, **저작되지 않은 것의 목록**, 사건이 얼마나 자주 되풀이되는가.
- 서술의 채점은 둘로 나눈다. 셀 수 있는 것(분량, 금지된 낱말, PC의 내면을 썼는가)은 코드가, 읽어야 아는 것(선택을 대신했는가)은 다른 LLM이.
- 지금 있는 것: 규칙의 시험과 격리의 시험 일부(16개).

## 7. 저작 도구

저작자는 사용자 한 사람이다. [확정] 도구는 그 한 사람의 부담을 줄이는 데 맞춘다.

| 도구 | 하는 일 |
| --- | --- |
| 검사기 | 가리키는 것이 있는가, 빠진 항목(계승으로도 채워지지 않는 것), 닿을 수 없는 장소와 시작될 수 없는 사건, **너무 쉬운 조건**(되풀이의 위험), 모순 |
| 되읽기 | 조건과 규칙을 사람의 말로 되읽어 보인다. 쓴 뜻과 같은지 저작자가 본다 |
| 글을 양식으로 | 저작자가 글로 쓴 인물·장소·사건을 양식으로 옮긴다. 옮긴 것을 되읽어 확인받는다 |
| 채운 것의 검토 | 플레이 중에 LLM이 채운 항목과 채운 경우의 목록. 저작자가 받아들이면 시나리오나 공용 사전에 들어간다 |
| 돌려 보기 | 가상 플레이어로 여러 번 돌려 무슨 일이 벌어지는지 본다. 한 번도 시작되지 않는 사건, 늘 같은 길로 가는 계획 |
| 모아 보기 | 인물 정보, 관계도, 조직도([32](32-항목표.md) §15) |

- 시나리오는 글 파일로 쓴다(지금은 YAML). 형식은 저작이 실제로 시작되면 다시 본다.
- 공용 사전의 내용은 엔진이 갖춘다. 채운 것이 검토를 거쳐 들어오며 자란다.

## 8. 과금

- 지금은 설계하지 않는다. **재는 것만 갖춘다**: 세션마다, 플레이어마다 든 값(§4).
- 구조가 막지 않게 할 것 하나: 턴을 받기 전에 "이 플레이어가 턴을 받을 수 있는가"를 묻는 자리.

## 10. 설정과 보안

| 것 | 내용 |
| --- | --- |
| 열쇠(API, 디스코드) | 환경에만 둔다. 저장소와 대화에 두지 않는다 |
| 역할별 모델, 사고량, 상한 | 설정 파일 하나 |
| 세션 기록 | 저장소 밖 |
| 플레이어의 글 | LLM에는 선언으로만 간다. 플레이어의 계정 정보는 보내지 않는다 |
| 선언 속의 지시 ("이전 지시를 잊고…") | 해석은 선언을 **행동으로만** 옮긴다. 사칭과 같은 선에서 다룬다. 닫힌 판단에는 선언의 글이 그대로 들어가지 않는다 |

## 11. 필요한 판단

| # | 쟁점 | 기본안 | 반대쪽의 이유 |
| --- | --- | --- | --- |
| 1 | 되감긴 턴에서 사전으로 확정된 실물 | 사라진다. 다시 정해진다 | 되감기로 좋은 것이 나올 때까지 다시 뽑을 수 있다. 남기면 그 길이 막힌다 |
| 2 | 되감기의 한도 | 두지 않는다 | 긴장이 준다. 시나리오가 줄일 수 있게 |
| 3 | 과금 | 지금은 재는 것만 | |
| 4 | 세션의 자리 | 스레드 하나에 세션 하나 | 구 프로젝트의 방식을 모른 채 낸 안이다 |
| 5 | 만들어 두는 캐시 | 처음에는 쓰지 않고 구현한다. 큰 시나리오에서 측정한 뒤 얹는다 | |
