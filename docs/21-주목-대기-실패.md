# 주목, 대기, 실패

2026-11-13. [20](20-구-세션-기록-관찰.md)의 질문에 대한 사용자 답변과 추가 생각, 그리고 그에 따른 재검토.

## 1. 사용자 답변 (확정)

| 쟁점 | 답 |
| --- | --- |
| 20 문서에서 "목표로 읽은 것" | **맞다.** 감각 중심의 서술, 세계의 신호, 흐르는 압박, 문체와 분량(턴당 700~1,100자)을 지향한다 |
| 서술자가 채워도 되는 것 | **맞다.** 선언한 행동을 수행하는 데 따르는 몸의 움직임은 채워도 된다. 멈춤·망설임·시선·감정처럼 선택이 담긴 것은 금지 |
| 암묵적 행동 | 사용자의 설계에 이미 있는 개념이다. "물을 마시려면 뚜껑을 열어야 한다." |
| 판정 버튼 | 플레이어가 직접 누르는 것은 **지키고 싶은 경험**이다. 대기로 치지 않는다 |

### 대기의 정의 (확정)

> 대기란, **플레이어의 마지막 행동부터 다음에 나오는 버튼 제시나 묘사 시작까지**의 시간이다.

- 15초라는 허용선은 이 구간에 적용된다. 턴 전체가 아니다.
- 한 턴에는 대기가 최대 둘이다: (선언 → 버튼 또는 묘사 시작), (버튼 누름 → 묘사 시작).
- 묘사가 **끝나는** 시점이 아니라 **시작하는** 시점이다. 서술을 생성되는 대로 흘려보내는 것이 직접 효과가 있다.
- 구 세션 기록을 이 정의로 다시 재지는 않았다. 20 문서의 "57초"는 턴 전체의 길이이고 버튼 대기가 섞여 있다.

## 2. 작업 원칙의 추가 (사용자 지시)

- **이미 개발되거나 기획된 것은 매몰비용이다.** 목표에 맞지 않거나 더 나은 방법이 보이면 가차 없이 대체하거나 뒤엎는다.
- **사용자의 결정과 바람도 같다.** 다만 사용자의 생각을 뒤집을 때는 **근거를 들어 설득을 시도한다.**
- API 호출의 **다양한 실패에 대응해야 한다.** 사용량 증가로 인한 출력 실패를 포함한다.

## 3. 사용자의 생각: 인물 추적

> 장면에 등장하는 인물을 개별적으로 추적하는 것은 좋을 수 있으나, 장면의 모든 인물이 묘사에 등장하는 것도 버거울 수 있다.
> 판단 주체가 추적할 인물을 선정하고 추적하지 않아 생긴 공백을 메우는 방법을 마련하거나, 해상도를 달리하거나, 여러 방법이 있을 수 있다.
> **모든 인물에 대한 개별 판단 및 호출이라는 구조가 바뀔 수도 있음을 알아야 한다.**

## 4. 재검토: "인물은 각자의 머리로"

[08](08-Claude-독자-구상.md)의 구상 3(장면의 주요 인물마다 별도 호출)을 매몰비용으로 놓고 다시 본다.

### 이 구상이 노린 것과 치른 것

| 노린 것 | 실제로 필요한 것은 |
| --- | --- |
| 모르는 것을 말하지 못하게 한다 | 인물의 **말과 행동이 그 인물의 앎 안에 있을 것** |
| 유저에게 순응하지 않게 한다 | 인물이 **자기 이해관계로 결정할 것** |
| 한 LLM이 여러 인물을 조종하는 티를 없앤다 | 인물마다 **목소리가 다를 것** |

| 치른 것 | 근거 |
| --- | --- |
| 호출 수가 장면의 인물 수를 따라간다 | [18](18-규모.md): 30명이면 30호출, 문맥 합계 49배 |
| 대기가 는다 | 묘사 시작 전에 인물 호출이 한 겹 더 들어간다 |
| 모든 인물이 매 턴 반응한다 | 사용자 지적대로 **묘사가 버겁다.** 서른 명이 한마디씩 하는 장면은 소설이 아니다 |

- 세 번째가 결정적이다. 비용 이전에 **경험의 문제**다. 소설은 장면의 모든 사람을 따라가지 않는다. 초점이 있다.
- 구 세션 기록의 인물 대사는 호출 하나로 썼는데도 목소리가 섰다(사투리, 짧은 긴장). **목소리**는 별도 호출의 이유로 약하다.
  기록에서 실제로 보인 문제는 순응과 누설이었다.

### 고친 안: 주목과 정산 [제안]

> 엔진은 **주목 안**에 있는 것만 세밀하게 다룬다. 주목 밖의 것은 **주목이 돌아올 때 정산**한다.

1. **심판이 이번 턴의 주목을 정한다.** PC가 상대하는 인물, 그리고 이번 턴에 무언가를 **걸고 있는** 인물. 보통 하나에서 셋.
2. **주목 안의 인물은 심판이 직접 움직인다.** 심판은 그 인물의 앎, 목표, 감정을 따로 받아 그 안에서 반응을 정한다. 별도 호출이 없다.
3. **결정의 순간에만 그 인물의 머리를 따로 부른다.** 배신할 것인가, 털어놓을 것인가, 달려들 것인가처럼
   인물의 이해관계가 유저의 바람과 **정면으로 부딪히는 선택**일 때. 순응이 가장 일어나기 쉬운 곳이고, 격리된 호출이 값을 하는 곳이다.
   어느 턴이 그런 순간인지는 심판이 표시한다. 대부분의 턴에는 없다.
4. **주목 밖의 인물은 무리로 남는다.** 서술자는 무리를 배경으로만 쓴다("객잔 안의 시선이 일제히 쏠린다").
5. **주목이 돌아오면 정산한다.** 그동안 그 인물이 무엇을 보았고 무엇을 했을지를, 그 인물의 목표와 그 사이에 실제로 서술된 것에 맞춰 한 번에 정한다.
   이미 전달된 것과 어긋나면 안 된다.

- 5번은 [17](17-통찰과-새-설계.md) §7의 "관측할 때 정산한다"(화면 밖 세계의 후보)와 **같은 장치**다.
  화면 밖의 세력, 붐비는 장면의 구석에 있는 사람, 오래 안 만난 인물이 모두 "주목 밖에 있다가 주목이 돌아오는 것"이다.
- 사용자가 든 두 방법(추적할 인물의 선정과 공백 메우기, 해상도 차등)이 이 하나에 들어 있다.

### 잃는 것

- **문맥에 의한 격리가 약해진다.** 심판은 진실을 본다. 주목 안의 인물을 심판이 움직이면, 인물이 모르는 것을 행동에 반영하는 실수가 다시 가능해진다.
  "구조로 보장한다"에서 "심판에게 인물의 앎을 따로 떼어 주고 검사한다"로 한 단계 물러난다.
- 이것은 근거 없이 정할 수 없다. **측정으로 가른다**: 같은 장면(구 기록의 "형사가 무릎을 보자고 한다")을 세 방식으로 돌려 순응과 누설을 센다.
  (가) 심판이 전부, (나) 결정의 순간에만 따로 호출, (다) 주목 안의 인물마다 호출. 대기와 비용도 함께 잰다.
- 측정 전까지의 잠정안은 (나)다.

## 5. 암묵적 행동

- 사용자 설계에 있는 개념과 [17](17-통찰과-새-설계.md) §5.3의 "말하지 않은 중간 동작은 심판이 넣는 단계"가 같은 것을 가리킨다.
- 20 문서의 주권 문제와 합치면 선이 하나로 그어진다.

| | 예 | 누가 |
| --- | --- | --- |
| 선언에 **따르는** 행동 | 뚜껑을 연다, 배낭에서 헬멧을 꺼낸다 | 엔진이 채운다. 서술해도 된다 |
| 선언에 **없는 선택** | 멈춘다, 망설인다, 무기를 고쳐 쥔다, 주위를 살핀다 | 채우지 않는다 |
| 되돌릴 수 없는 따르는 행동 | 자물쇠를 부순다, 하나뿐인 약을 쓴다 | 확인을 묻는다 |

- 가르는 기준: **그 행동 없이는 선언한 행동이 성립하지 않는가.** 그렇다면 따르는 행동이다.
- 사용자의 설계 내용은 아직 전달받지 않았다. 받으면 이 선과 대조한다.

## 6. 실패에 대한 대응 [제안]

구 세션 기록에도 한 턴이 522초 걸리고 판단 호출이 세 번 되풀이된 사례가 있다.

### 원칙

1. **어떤 실패도 세계를 반쯤 바꾼 채 남기지 않는다.** 턴의 변화는 끝에 한 번에 확정된다. (최소 구현에서 시험으로 확인된 성질)
2. **이미 한 일은 다시 하지 않는다.** 서술자가 실패했다고 심판부터 다시 돌리지 않는다. 단계의 결과를 턴 안에서 보존한다.
   플레이어가 버튼을 눌러 굴린 주사위도 같은 턴 안에서는 유지한다. (되감기는 다른 일이며, 되감으면 다시 굴린다는 결정은 그대로다)
3. **역할마다 없어도 되는 정도가 다르다.** 덜 중요한 역할의 실패가 턴을 막지 않는다.
4. **플레이어는 언제나 지금 무슨 일이 벌어지는지 안다.** 조용히 멈춰 있지 않는다.

### 역할별 물러서기

| 역할 | 실패하면 |
| --- | --- |
| 심판 | 없으면 턴이 없다. 다시 시도 → 다른 모델 → 그래도 안 되면 플레이어에게 알리고 선언을 보존한다 |
| 인물의 별도 호출 | 없어도 된다. 심판이 그 인물을 직접 움직인다 |
| 서술자 | 줄여도 된다. 다시 시도 → 다른 모델 → 짧은 서술 → 최후에는 "해석의 되읽기 한 줄 + 확정된 사실"만 전한다. 세계는 이미 정해져 있으므로 턴은 성립한다 |
| 전달 기록 등 턴 뒤의 일 | 턴을 막지 않는다. 밀린 채로 다음 턴이 진행될 수 있어야 한다 |

### 실패의 종류

| 종류 | 대응 |
| --- | --- |
| 과부하, 사용량 한도 (출력이 오지 않음) | 간격을 늘리며 다시 시도. 정해진 횟수 뒤에는 다른 모델 |
| 빈 응답, 중간에 끊긴 응답 | 끝난 이유를 확인한다. 사고에 토큰을 다 쓴 경우면 사고량을 줄여 다시 |
| 형식이 깨진 응답 | 다시 시도. 되풀이되면 고쳐 읽기 |
| 형식은 맞으나 검사에 걸린 제안 | 실패가 아니다. 걸린 제안만 버리고 나머지로 진행한다 |
| 시간 초과 | 호출마다 상한을 둔다. 대기 허용선에서 거꾸로 계산한다 |
| 안전 필터에 의한 차단 | 다시 시도해도 같다. 서술 수위를 낮춰 다시 요청하거나 물러선다 |

- 최소 구현은 이 가운데 1번 원칙만 갖고 있다. 나머지는 없다.
- 구 프로젝트의 "굴린 눈 유지"를 버린 것과 2번은 충돌하지 않는다. 버린 것은 **되감기 뒤에도** 같은 눈이 나오게 하는 것이다.
  같은 턴의 기술적 재시도에서 플레이어가 누른 결과를 바꾸는 것은 다른 문제이고, 바꾸지 않는다. **사용자 동의 (2026-11-13).**
