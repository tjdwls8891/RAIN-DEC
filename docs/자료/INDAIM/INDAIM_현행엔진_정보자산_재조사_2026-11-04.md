- 조사일: 2026-11-04
- 분석 대상: 사용자가 제공한 `TRPG-Sub-Game-Master-main.zip`
- 파일 SHA-256: `638eab9e60b42eb0cf47258b98e7a3f4071e5a461aea9125e0c325e1bdab585f`
- 저장소 자체 표기: INDAIM v9.2.1, 세션 스키마 v5 (`CLAUDE.md`)
- 방식: 압축 해제본의 시나리오 JSON 4개 전수 필드 집계, 공용 어휘 2개 확인, 세계·행동·판정·정보·NPC·아이템·상태·사건·시작·기억 관련 실제 코드 직접 열람, 개발 문서 및 결함 테스트 일부 대조. **정적 조사이며 테스트 실행·런타임 검증은 수행하지 않음.**
- 목적: 차기 엔진에서 **인지할 정보, 표현할 개념, 지속할 관계, 갱신할 원리, 처리 가능한 예외**를 최대한 수집한다. **현재 코드 구조, 컴포넌트·효과 방식, 호출 계약, DB 구조는 계승 조건이 아니다.**

## 0. 해석 규칙

1. **[확인·데이터]** 시나리오 JSON과 공용 정의에 실제로 저작되어 있는 속성.
2. **[확인·처리]** 관련 소스 코드에서 판독·계산·제한·갱신하는 것을 직접 확인한 개념. 실제 세션에서 모든 경로가 정상 사용됨을 증명하는 뜻은 아니다.
3. **[파생·기획]** 1·2의 존재 이유에서 도출한 차기 엔진의 정보·판단 요구사항. 기존 기능이 완성되어 있다는 뜻도, 차기 채택 확정이라는 뜻도 아니다.
4. **[공백·미확인]** 조사한 자료 범위에서 범용 정보 표현/규칙을 확인하지 못했거나 저작 텍스트·특정 장르로 범위가 좁은 부분. 저장소 전체에 절대 없다고 단정하지 않는다.
5. `specs/*.md`는 v5.29.1에서 역추출한 **HISTORICAL** 명세이므로 최신 실행 동작의 직접 증거로 사용하지 않는다. `CLAUDE.md`, 데이터, 현행 소스 및 테스트를 우선했다.

## 3. 관리 방식 중 **아이디어로만 추출할 것**

### 3.1. 사실·기록·인식·표현은 서로 다르다

- 세계에 실제로 존재하는 사건, 특정 인물이 아는 사건, 그 인물이 믿는 사건, 플레이어가 전달받은 문장은 서로 다른 성질이다.
- `cognition.py`에서는 **인지 획득이 믿음 자동 상승을 의미하지 않고**, `information.py`에서는 **정보가 반박되어도 과거에 그 사실을 믿은 행위자가 자동 교정되지 않는다**.
- 명제의 이력(`CURRENT/SUPERSEDED/REFUTED`)은 모든 명제의 객관적 참·거짓을 직접 표현하는 완전한 진리값 모델과 동일하지 않다.
- 차기 모델에서는 '세계 진실 / 행위자 인식 / 행위자 믿음 / 공개된 정보 / AI의 단순한 표현'을 각각 정보로 구별할 가치가 있다. **현재 구현과 동일한 필드 구조가 필요하다는 뜻은 아니다.**

### 3.2. 서술적 정보는 풍부하지만 기계적으로 작동하는 정보는 제한적이다

- 현재 NPC의 가치관·약점·목표·걱정·비밀은 풍부한 자유 서술이며, 장소도 시각·기능·분위기 설명이 길다.
- 그러한 설명만으로 NPC의 목표 수행, 위험 판단, 물체의 인과적 특성이 구조적으로 모델링되었다고 주장할 수 없다.
- `NPC persona.now.goal`은 **목표의 존재를 저작**한 사례이지, 모든 NPC에 대해 목표 달성 작업을 자동으로 계획·실행하는 일반 시스템의 존재를 증명하지 않는다.
- 이는 오히려 '원래 세계관 텍스트 안에만 존재하던 판단 근거가 무엇인가'를 전수 추출할 필요가 있음을 보여 준다.

### 3.3. 실제 세계 상태와 행위자의 인지 상태를 구별한다

- 이동에서는 실제 길의 통행 조건과 PC가 그렇게 **알고 있는지**의 조건이 따로 존재한다.
- NPC의 실제 위치는 사건 개입으로 인한 명시 배치, 일과에서 계산되는 위치, 정보가 없는 위치를 구별한다.
- 물품에서도 실물의 장소·보유 여부와 발견·인지·지칭은 분리된다.
- **정보 없음은 부재의 증거가 아니다**라는 원칙은 이동·지식·신체 상태 등 여러 범위로 확장해 볼 수 있다.

### 3.4. 판단한 세계 변화와 다른 정보로의 영향은 연관되어 있다

- 영도 사건 저작에는 출입문 상태, NPC 위치, 시간, 정보 취득, 경고 신호 등 상이한 변화가 연결되어 있다.
- 청람호의 추적자는 소리를 듣고 **다음 턴**에 반응하도록 하여 지각→판단→이동 사이 시간을 보존한다.
- 생리 상태는 날씨·장소·착용 물품·행동 시간·소모품 처치를 서로 참조한다.
- 사건의 변화를 여러 정보 범주에 전파한다는 개념은 가치가 있으나, **현재의 사건 템플릿 기법이 곧 범용 물리·사회적 인과 추론을 제공하는 것은 아니다.**

### 3.5. 독창적인 행동도 사실·성질·권한·후속 변화로 환원될 수 있다

- 물품 사용과 제작에서는 실제 재료·수량·소유·특수 물품 제한을 확인하는 규칙이 존재한다.
- 임의의 주변 발견에는 미등록 소품 보완을 허용하되 주요 단서·숨은 길·유일한 사건 유물 등으로 확장하지 않으려는 구분이 존재한다.
- 플레이어가 문을 열었다고 해서 **상대가 그것을 허용했는지, 문을 지나갔는지, 그 결과를 전부 알고 있는지**까지 자동으로 확정할 수 없다.
- 새 엔진에서 추출할 핵심은 별도 모듈 구조가 아니라 **새로운 행동에도 적용할 수 있는 전제 조건·물리적/사회적 작동 성질·결과 범위·부정적 부작용·추가 인식·권한 경계**다.

### 3.6. 예외를 안전하게 처리하려면 '시도'와 '확정된 사실'이 달라야 한다

- 플레이어가 '경비병을 속여 무전기를 가져갔다'고 선언했을 때, 허용되는 것은 통상 **그 행동을 시도한 사실**이며, 성공·대상 반응·무전기 위치는 실제 세계 상태에 의해 결정할 사안이다.
- 이전에 얻은 굴림 결과는 API 단계 실패 후에도 같은 사건에 재사용하며, 비동기 결과는 해당 턴 상태가 여전히 유효한 경우에만 받아들인다는 사례가 있다.
- 이러한 운영상 원리는 게임 내부 세계의 정보 관리 범주와는 별도로, **무엇을 확정할 수 있는가**라는 공통 문제를 보여 준다.

## 6. 새 엔진 구조를 독립적으로 구상하기 위한 명확한 분리 기준

현재 조사로 확인되는 것은 몇 개의 모듈이나 인터페이스가 필요한지가 아니다. 서로 혼동하면 안 되는 **정보의 차원**이다.

1. **존재의 정의 ↔ 그 존재의 상태 ↔ 상태 변경 사건**: 정체성, 현재 조건, 그 원인의 구별.
2. **객관적 세계의 사실 ↔ 행위자별 지식 ↔ 행위자의 믿음 ↔ 플레이어에게 표현된 내용**.
3. **사물의 물리적 가능성 ↔ 사회적 허용·권한 ↔ 시도 방법 ↔ 판정 필요성**.
4. **플레이어 의도·시도 ↔ 플레이어가 통제하지 못하는 결과 ↔ 세계의 후속 반응**.
5. **현재 진행 상태 ↔ 미래의 예약 조건 ↔ 발생한 사건의 이력 ↔ 아직 정해지지 않은 가능성**.
6. **일상에서 추론 가능한 일반 사실 ↔ 세계관/시나리오가 특별하게 고정한 사실**.
7. **지속적으로 개별 추적할 행위자·물체 ↔ 필요할 때만 추상적으로 평가할 집단·영역**.

이 구별들은 기존 INDAIM 코드 조직과 무관하게 차기 기획의 논리적 검증 기준으로 사용할 수 있다. 하지만 현재 조사에서 이미 최적의 분류나 데이터 모델을 결정했다고 주장하지 않는다.

## 7. 후속 조사에서 특히 가치 있는 원자료와 사용법

### 7.1. 실제 시나리오 원자료

- `scenarios/*.json` — **대상 사실**의 직접적인 원천. `worldview`, `default_npcs`, `places`, `movement_edges`, `information_definitions`, `event_templates`, `start_frames`.
- 영도: 인물의 속성과 세계관·세력의 다면적 관계를 수집하기 좋다.
- 설화재: 사실·증언·증거·오인·판정된 진상·법적 결단을 분리하기 좋다.
- 청람호: 위치·감각·시간·추적·임무 준비가 충돌하는 상황을 수집하기 좋다.
- 균열: 다수 행위자, 전투·상태·기술·성장과 반복되는 세계 구간을 수집하기 좋다.

## 8. 이번 재조사의 판단

**[확인]** 현 INDAIM은 예상보다 다양한 세계 지식을 소유한다. 특히 인물의 사적 동기·감정·비밀 같은 **서술형 저작**, 세계의 특정 상태를 변경하는 **구조화 사건**, 객관 사실과 인식을 구분하는 **정보 표현**이 함께 있다. 그러나 각 정보가 일반적인 상호작용과 자율 변화에 모두 동등하게 참여하는 것은 아니다.

**[분석]** 차기 버전에서 계승할 핵심 자산은 코드 구조가 아니라 아래 세 가지다.

- **세계의 정보 어휘:** 세계에 무엇이 있고 어떤 성질과 관계·이력을 가지며, 누가 그것을 알고 믿는가.
- **세계의 작동과 판단 규칙:** 무엇을 언제 시도·허용·판정·실행할 수 있고, 그 결과에 무엇이 연쇄적으로 영향을 받는가.
- **예외 처리 경계의 역사:** 잘못된 전지적 NPC, 정보 부재의 부정화, 플레이어의 선택 선취, 존재하지 않는 소유품의 지급, 소급 순간이동, 사후 묘사 추출의 모순 등을 막으려던 실무적 경험.

**[한계]** 이것은 신엔진의 모듈 설계·기술 스택·저장 방식·AI 호출 구조를 제안하거나 확정하는 문서가 아니다. 새 아키텍처는 현재 구현으로부터 자유롭게 다시 기획한다.
