## 1. 요약: 이번 재조사에서 새롭게 확보한 가치

정보를 얼마나 세세하게 보유할지뿐 아니라 **언제 판정하는지, 어떤 데이터를 판정 근거로 삼는지, 어떤 결과를 확정할지, 실패와 불명확성을 어떻게 다루는지**에 관한 실질적인 게임 규칙이 확인되었다.

| 차원 | 확인된 핵심 자산 | 새 버전에서 보존을 *검토*할 원리 |
|---|---|---|
| 확률 판정 | 2d50, 엄격한 성공 조건, 단일 목표치 내역 | **기록·설명 가능한 확률 판정**과 **확률·효과 분리** |
| 판정 수단 | 능력·숙련·장비·방법·상태·난도·협력 | **서로 다른 근거의 가산과 중복 방지**, 실재하는 자원 기반 보정 |
| 대결·전투 | 독립 대결, 성공 여유 비교, 부상·내구·보호 | 대결 결과와 부상 등 **게임 결과의 별도 단계화** |
| 메타 진행 | 실패 기반 성장, 성장 포인트, 행운 | 실패·성과·자원 소비를 **별개 진행 규칙**으로 활용 |
| 선언 해석 | 시도와 성공 선언 구별, ASK/ROLL/NO_ROLL/차단 | 플레이어의 **행동 선택권**과 세계의 **결과 결정권** 분리 |
| 공간 이동 | 실제 접근 / 알려진 접근 / 확인이 필요한 행동 | **세계의 진실과 관측자의 지식에 따른 행동 선택지 분리** |
| 신체·환경 | 단계적 상태, 발현 지연, 치료·완화, 조건 평가 | 상태를 단일 수치가 아닌 **시간·조건·상호작용하는 과정**으로 관리 |
| 아이템·자원 | 수량/단위/고유성, 손상, 제약, 상호 변환 | 자원 보존·소유·발견·활용을 나눠 **복합 행위의 실제 효과** 표현 |
| NPC·관계·지식 | 목표/루틴, 신뢰 변화 감쇠, 믿음 출처 | **행동 주체별 비대칭성**, 이력·인지에 기반한 반응 |
| 사건·자율 변화 | 3값 조건, 단계, 의존성, 시간 예약 | 플레이어 선언을 넘어서 진행되는 **조건부·자율적 세계 변화** |
| 운영 안정성 | 계약 검증, 중복 방지, 일관된 재시도, 원자적 확정 | 인간 GM의 즉흥 보정을 대체할 **실제 규칙 검증과 실패 복구** |

이 자료를 종합하면, 단순히 '판정 시스템' 하나를 더 정교하게 만드는 것보다 **① 선언의 의미 판단 → ② 결과 성립 판단 → ③ 효과의 범위 결정 → ④ 실제 세계 변화 → ⑤ 영향 전파 → ⑥ 확정된 정보의 서술**을 구별하는 것이 유력한 설계 질문이다. 이는 *차기 엔진을 위한 분석*이지 현행 처리 경로를 계승하자는 주장이 아니다.

## 2. 판정 규칙의 정밀 복원

### 2.1 기본 굴림과 확률 분포 [확인]

원천: `indaim/rules/checks/logic.py`, `indaim/turn/roll_sides.py`, `indaim/rules/checks/judgment.py`

- 독립적인 1~50 정수 주사위 두 개를 더한다: `R = d50 + d50`. 범위는 **2~100**, 경우의 수는 2,500이다.
- 기준 목표치: `T = 52 + A + S + E + M + H + D`; 실제 대결 시 협력 보정 `P`가 추가되어 `T = 52 + A + S + E + M + P + H + D`가 된다.
- **`R < T`만 성공**. `R = T`는 실패. 여유치 `m = T - R`; 성공이면 양수, 동점 실패는 0.
- 대성공·대실패의 별도 임계 구간은 기본 판정 코드에 없다.
- 합계는 균등 분포가 아니라 **삼각형 분포**이다. 목표치 +10이 성공률에 주는 효과는 현재 목표치에 따라 다르다.

| 목표치 T | 가능한 성공 확률 | 해석 |
|---:|---:|---|
| 32 | 18.60% | 낮은 성공 가능성 |
| 42 | 32.80% | 불리한 판정 |
| 52 | 51.00% | 기본 목표치 |
| 62 | 68.80% | 유리한 판정 |
| 72 | 82.60% | 높은 성공 가능성 |
| 82 | 92.40% | 매우 높은 성공 가능성 |
| 101 이상 | 100% | 모든 눈의 합 성공 |

**[추출]** 판정 메커니즘의 중요한 가치는 특정 주사위 숫자보다도 다음에 있다: 판정 근거의 세부 내역을 보존한다; 목표치와 실제 굴림을 구분한다; 성공의 여유를 다른 효과 계산에 재사용할 수 있다; 인간에게 보여 주는 확률과 실제 구현을 일치시킨다. **[한계]** 이 확률 모델은 자연 법칙이 아니며 차기 엔진에 반드시 유지해야 할 조건도 아니다.

### 2.2 구성 요소별 기준치 조정 [확인]

| 변수 | 현행 산식·범위 | 근거·의미 | 조사상 유의점 |
|---|---|---|---|
| `A` 능력 | 원스탯 1~20일 때 `2 × (스탯 − 10)` | 실제 캐릭터 능력 | 값 부재·범위 위반 시 환산 불가, 가짜 수치 생성 금지 |
| `S` 숙련 | 옛 형식의 소유한 지정 기술 `+6`; 새 형식은 정의된 보너스 | 직업·숙련의 기여 | 보유하지 않은 기술을 선언해도 자동 적용하지 않음 |
| `E` 장비 | 정의된 효과 태그에 따른 보정 | 장착·사용한 실제 자원 | 몸에 입은 장비의 자동 효과와 직접 지목한 장비 효과의 **중복 방지** |
| `M` 행동 방법 | `−12 ~ +12` 정수 | 수행 방식, 준비, 도구 운용 등 | 판단층위의 제안값을 **코드가 검증** |
| `H` 상태 | `−15 ~ +15` 범위 | 상처·피로·기타 상태의 판정 영향 | 분야가 설정된 현행 경로에서는 코드가 적용 상태로부터 계산 |
| `D` 난이도 | 단계별 상수 | 행위 자체의 어려움 | 다른 보정 항목과 같은 사실을 중복 반영해서는 안 됨 |
| `P` 협력 | 파티 역할에 정의된 가산, 기본 `+4` | 다른 행위자의 실질적인 도움 | 적절한 행동 상황과 실제 행동 가능한 구성원 필요 |

난이도 단계의 현행 기본값:

| 난도 | `D` |
|---|---:|
| 쉬움 | +20 |
| 약간 쉬움 | +10 |
| 보통 | 0 |
| 어려움 | −15 |
| 매우 어려움 | −30 |
| 극도로 어려움 | −40 |

**[추출]** 행위 난이도(대상이 얼마나 어려운가), 행위 방식(어떻게 수행하는가), 사용자 상태(실제 능력이 저하됐는가), 이용 자원(진짜 보유·사용 가능한가)을 **서로 다른 판단 근거**로 관리하면 임의 행동에도 원인을 설명할 수 있다. 반대로 판정 요소가 많은 만큼 같은 사실을 D/M/E/H에 중복 배분하는 위험이 발생한다. 차기 기획에서는 '각 보정 요인이 무엇을 대표하고 어떤 요인은 배타적이어야 하는가' 자체가 관리 대상이다.

### 2.3 상시 능력, 발동 능력, 비용과 분야 [확인]

원천: `indaim/rules/checks/logic.py`의 `skill_terms`, `skill_entry`, `check_skills`.

- 기술 정의를 설명 문자열(옛 형식) 또는 `desc`, `kind`, `bonus`, `domains`, `cost`의 구조화 정보로 받는다.
- **상시 기술**: 판정 분야에 해당하는 여러 상시 기술 가운데 가장 높은 보너스 하나를 자동 반영. 지정할 필요가 없다.
- **발동 기술**: 소유자가 현재 판정에서 해당 기술을 지정하고, 필요한 분야에 속할 때 적용된다. 종류에 따라 상태 단계 증가 등의 사용 비용이 발생한다.
- **자원 고갈**: 비용에 쓰는 상태가 마지막 단계에 도달하면 발동 효과도 비용도 적용하지 않는다.
- 상시 기술에는 비용을 두지 않도록 정의 검증. 보너스의 저작 범위는 0~20.

**[추출]** 기술을 이름 목록이 아니라 **기동 조건·분야·비용·효과·중첩 규칙**이 붙은 상태 변환 능력으로 다룰 수 있다. 이는 일반적인 기술뿐 아니라 특수 장비, 조직 지원, 계약상의 권리 등에도 응용 가능한 추상 개념이다.

### 2.4 장비 보정의 정합성 [확인]

원천: `indaim/turn/roll_sides.py`, `indaim/rules/items/items.py`, `indaim/rules/items/logic.py`.

- 지목한 PC의 장비는 실제 보유·착용/손에 든 상태, 등록된 효과 태그, 관련 판정 능력·분야가 맞아야 적용된다.
- 착용 중인 장비에서 발생하는 자동 효과는 따로 산출하며, 직접 지목 보정과 **동일 장비 이중 가산을 방지**한다.
- 장비의 부정적인 착용 영향은 특정 분야에서 자동으로 발생할 수 있다.
- NPC 대결 시 NPC가 실제로 갖춘 장비의 유리한 하나를 참고할 수 있다.

**[추출]** '장비가 있다'와 '그 판정에서 장비가 실제로 기여한다'를 분리해야 한다. 장비 사용 가능성은 **소유·위치·접근·손에 들기/착용·상태·용도·행동 방법**의 결합으로 결정되어야 한다.

### 2.5 판정 요구 자체도 판정해야 한다 [확인·추출]

원천: `indaim/content/prompts/judgment.py`.

현행 판단 지침은 굴림을 기본값으로 삼지 않는다. 사실상 성공이 자명한 행위는 판정 없이 진행하고, 확정 설정상 불가능한 행위 역시 '일단 굴려 본다'가 아니라 성립하지 않는 이유를 설명하도록 규정한다. 불확실하고 판정이 필요한 경우에만 `ROLL`을 요청한다. 불명확한 시도는 `ASK`로 명료화하며, 사실 질문·가벼운 상황 확인은 `NARRATE` 경로를 둘 수 있다.

**[추출]** 게임 시스템이 결정할 것은 **성공률**만이 아니라 **① 확실히 성립, ② 확실히 불성립, ③ 성립하나 결과 불확실, ④ 의미 자체가 불명확, ⑤ 정보 확인 요청**이라는 구분이다. 현실적 위험이 없고 결과가 자명한 행위에 불필요한 주사위를 남발하지 않는 GM적 판단이 중요하다.

### 2.6 대결의 계산 방식 [확인]

원천: `indaim/rules/checks/logic.py`의 `contest_outcome`; `indaim/turn/service.py`의 대결 결과 처리.

양측은 각각 별도의 목표치 및 2d50 결과를 갖는다.

1. 한쪽만 성공(`m > 0`)하면 그쪽이 우세하다.
2. 양쪽 모두 성공하면 **여유치가 큰 쪽**이 우세하다.
3. 양쪽 모두 성공하고 여유치가 같으면 `TIE`.
4. 양쪽 모두 실패하면 `NONE`(우열 없음). 무조건 한 쪽이 이기는 구조가 아니다.

**[추출]** '대립 행위에 항상 승자를 하나 생산하지 않는다'는 원칙이 유용하다. **교착·양측 실패·서로 다른 유형의 부분 성과**는 인간 GM이 자주 처리하는 반응이다. 현재 방식은 고정 비교 규칙이지 모든 심리전·협상의 복잡한 결과까지 해결하는 만능 대결 규칙은 아니다.

### 2.7 제작 판정 [확인]

원천: `indaim/rules/checks/logic.py`의 `CRAFT`, `indaim/turn/service.py`의 제작 결과 처리, `indaim/rules/items/logic.py`의 `CRAFT` 연산.

제작은 일반 능력 판정과 구분되는 `CRAFT` 종류를 가진다. 굴림의 성공 여유는 제작 품질에 관한 서사적 기준으로 쓰일 수 있지만, **모든 제작물에 공통으로 적용되는 정량 품질 단계가 기본 판정에서 산출되는 것은 아니다**. 제작 실패 역시 자동으로 모든 재료를 소실시키는 것으로 처리되지 않는다. 재료의 실제 소비와 결과물 획득은 아이템의 별도 규칙에 연결된다.

**[추출]** '제작할 수 있었는가'와 '완성품의 품질·결함·소모량은 어떤가'를 분리할 필요가 있다. 향후 제작뿐 아니라 치료·협상·연구·정보 분석 등에 같은 원리를 확대 검토할 수 있다.

### 2.8 대결 → 공격 → 부상의 단계적 처리 [확인]

원천: `indaim/turn/turn_world.py`의 `combat_hits`.

- 부상 자동 처리 자체가 **해당 시나리오의 `combat_wounds` 기능 선언**에 종속된다.
- 대결의 우세가 확정된 후, **이긴 쪽의 판정 분야가 공격 분야**(기본 `근접`, `원거리`)일 때만 패자에게 부상을 부여한다.
- 양측 성공 여유차 `diff = 승자 m − 패자 m`를 기준으로 부상 단계 기본치: `diff ≥ 30 → 3단계`; `15 ≤ diff < 30 → 2단계`; `1 ≤ diff < 15 → 1단계`.
- 대상의 `toughness`(최소 1)로 기본 단계를 나눈 뒤 올림 처리하여 최종 단계 증가량으로 삼는다.
- 보호 역할의 동행 인원이 있으면 **그 턴의 PC 피해 한 번**을 대신 받는 처리가 가능하다.
- 해당 장르의 전투 결과는 상태·죽음·처치 보상 등 다른 규칙의 입력이 된다.

**[추출]** 판정값 → 대결 결과 → 피해 산식 → 신체 상태 → 사망/전투 외 후속 효과의 **단계적 변환**. 다만 심각한 폭력의 결과를 반드시 성공 여유의 차이만으로 결정해야 한다는 결론은 아니다. 무기 성질·위험 환경·공격 목적·방어 상황이 더 폭넓게 개입할 여지도 있다.

### 2.9 시나리오 선택형 판정 규칙 [확인]

`combat_wounds`, `party`, `growth`, `pursuit` 등의 기능은 시나리오에서 선언해야 활성화되는 영역이 있다. 따라서 동일한 기본 2d50이라도 판정 이후의 결과 처리나 게임 진행은 장르별로 달라진다.

**[추출]** **세계의 물리법칙이나 공통 행동 의미와, 장르별 게임성에 관한 선택 규칙을 구별**할 가치가 있다. 이것은 '현행 capability 구현을 계승한다'는 뜻이 아니라, 세계관과 플레이 스타일에 맞는 규칙 조합 가능성을 의미한다.

## 3. 성장·행운·파티 — 판정 외 게임성의 추출

### 3.1 실패를 학습 기회로 전환하는 성장 규칙 [확인]

원천: `indaim/rules/growth/growth.py`.

- 기본 성장 설정: 해당 능력의 판정 실패 누적 `3회`에 도달하면 성장 검사를 시행한다. 시나리오별 별도 확률 트리거도 가능하다.
- 성장 검사에는 일반 2d50이 아닌 **별도의 d20**을 사용한다.
- `d20 > 현재 원스탯`일 때 '성장 판정에서도 실패한 경우'로 간주하고 해당 능력을 `+1` 성장시킨다(상한 적용).
- 성장 검사를 한 뒤 실패 횟수 누적은 초기화된다.
- 성장 검사 시점에 행운 검사를 중복 실시하지 않는다.

**의미:** 주사위 판정 실패를 단순한 실패 비용이 아니라 캐릭터 발전의 계기로 쓰는 디자인이다. 능력이 높은 캐릭터일수록 추가 성장하기 어려운 구조이며, 장기적인 성장 속도까지 영향을 준다.

### 3.2 확률적 행운과 성공 판정의 분리 [확인]

같은 파일에서 기본 행운의 *백그라운드 발생 검사* 확률은 **원판정 실패 시 10%, 성공 시 3%**이다. 발동 후보가 되면 행운 능력(없으면 가상 기본 10)에 대한 d20 굴림으로 발생 여부를 결정한다.

**주의**: 행운 발생이 원판정의 `success`를 소급해 `True`로 바꾼다고 해석하면 안 된다. 원래의 성공·실패는 유지되며, 행운은 그 결과에 부수하는 서사적 완충·기회를 뜻한다.

**[추출]** 결과를 무효화하는 재굴림 없이도 우연·기회·부분 보상·실패 완충의 게임성을 표현할 수 있다. 이와 같은 메타 기제는 **인과관계를 바꾸는 실제 효과**와 **서사를 풍부하게 하는 기회**의 경계를 명료히 해야 한다.

### 3.3 포인트·훈련·직업 기반의 별도 성장 방식 [확인]

원천: `indaim/rules/growth/logic.py`, `indaim/rules/growth/growth.py`.

`growth` 기능을 쓰는 시나리오는 위 실패 누적 성장 대신 **성장 포인트** 방식으로 운영할 수 있다. 기본 비용은 능력치 2포인트, 기술 3포인트이며, 교육 가능한 기술 목록·직업·훈련 장소·능력치 상한 등에 따라 구매 가능성을 제한한다. 플레이어가 실제 선택한 성장만 반영하며, 획득 포인트와 사용 포인트를 구별한다. 적대 인물 처치 보상은 시나리오의 명시 조건과 실제 PC 행동의 연결에 따라 지급된다.

**[추출]** 성장 자산은 **경험 원인, 점수 획득, 사용 가능 조건, 캐릭터의 명시적 선택, 상태 변경**을 구분해 관리할 수 있다. 같은 캐릭터 발전이라는 목적 아래 여러 정책이 가능하다.

### 3.4 동행자의 역할과 행동 주권 [확인]

원천: `indaim/rules/party/party.py`, `indaim/turn/roll_sides.py`.

- 전투 역할: **막기·공격·치유·보조**.
- 보조는 조건에 맞는 PC 판정에 추가 보정(기본 +4)을 제공한다.
- 막기는 그 턴 특정 피해를 한 번 대신 받는다.
- 공격은 동행 NPC 자신과 적의 정본 능력으로 판정한다.
- 치유는 치료 대상과 소모를 고려한 효과에 연결된다.
- **플레이어가 해당 동행자에게 직접 명령한 행동**과 자동 역할 행동을 한 턴에 중복 실행하지 않는다.
- 행동 불능·비용 고갈·소속 자격·파티 인원 상한 등 조건이 있다.

**[추출]** NPC의 자율 행동은 **역할, 현재 자원, 실제 행동 가능성, 명시적 지시, 이미 수행한 행동**의 결합으로 결정되어야 한다. '보조 NPC가 행동을 두 번 한다'는 오류를 막는 **행동 점유·중복 방지 정보**가 가치 있다.

## 5. 구체적인 사례로 연결한 시스템 작동 원리

### 사례 1. “경비병의 시선을 돌리려고 창문을 깨고 옆문으로 나갑니다.”

추론·판정이 요구하는 정보를 분해하면 다음과 같다.

1. **선언 해석**: 유리를 깨는 행위, 경비병 주의 유도라는 목적, 옆문 이동을 연속 수행하려는 의도.
2. **실재 조건**: 창문이 실제로 존재하는가? 유리·도구·거리·접근·현재 위치는 무엇인가?
3. **성립·굴림**: 유리를 깨는 데 필요한 힘·도구 및 성공의 확실성. 판정이 불필요한 자명한 상태인지.
4. **실제 효과**: 유리 파손, 소음, 유리 조각, 도구 상태, 행동 시간. 이 중 일부만 명시적으로 관리할 수도 있다.
5. **관측 전파**: 소리의 도달과 경비병의 실제 청각·주의, 경비병의 지식/믿음.
6. **자율 반응**: 경비병은 직접 확인, 경보, 매복, 무시, 지원 요청 중 자신의 상황에 맞는 행동을 선택할 수 있다.
7. **후행 이동**: 경비병이 움직였는지와 별개로 옆문의 실재·개방 상태·접근 조건을 확인해야 한다.
8. **결과 서술**: 확정된 사건, 보이는 변화, 아직 알 수 없는 사실을 분리하여 묘사한다.

**발견:** 기존 기능 단위로는 '소음', '파손', '이동', '추적'이 존재하더라도, 실제 난점은 **선언된 복합 행위의 각 단계와 후속 인과의 결속**이다. 이 연결은 다음 버전에서 우선 검토할 가치가 있다.

### 사례 2. “상대의 짐에서 붕대를 찾아 사용하고, 남은 것을 가방에 넣습니다.”

문제는 붕대 사용이란 목록형 기능 하나가 아니다.

- 타인의 짐이 실제로 어디에 있는가(공간/점유).
- 대상의 허가가 있는가(규범과 관계; 허가 없어도 절도 자체는 물리적으로 가능할 수 있음).
- 가방이 닫히거나 봉인되었는가(상호작용 조건).
- 붕대의 존재·수량·단위가 확정되어 있는가(미정 사실과 물품 등록).
- 치료에 필요한 붕대 수량 및 그 효과·시간·상태가 무엇인가(사용과 치료의 분리).
- 남은 붕대가 누구의 소유인지, 실제로 어디에 있는가(소유와 위치의 구별).
- NPC가 이 행동을 보거나 알아차렸는가(관측과 지식의 분리).

**발견:** 복합 행동을 구현하기 위한 중요한 정보는 '붕대 아이템 기능'이 아니라 **포함·접근·사용·소모·이전·치료·관측의 조건과 상태 변경**이다.

### 사례 3. “신분을 속여 검문소로 들어갑니다. 들키면 바로 도망치겠습니다.”

이 경우 하나의 성공 판정으로 전체를 처리하면 경비 규정·NPC의 지식·검문 장치·도주 가능성이 삭제된다.

- 진입 권한(사회적 허용)과 물리적 통행 가능성은 별개다.
- 경비병의 시야, 교대 일정에 관한 지식, 플레이어의 외형과 제시한 증거를 구별한다.
- '들키면'이라는 **조건부 후속 행동**은 현재 단계의 확정 사실이 아니다.
- 경비병이 속는지와 검문소 출입문이 열리는지 역시 다르다.
- 도주가 시작된 뒤에야 실제 출구·장애물·시각·추적자의 상태가 의미를 갖는다.

**발견:** 조건부 선언의 **트리거, 실행 권한, 실패 분기**와 상태의 선후관계를 관리해야 인간 GM의 판단에 가깝다.

### 사례 4. “예전에 그 사람에게 도와준 적이 있으니 이번에는 믿어 줄 겁니다.”

- 과거 도움은 사건이나 관계 기억으로 정본에 있을 수 있다.
- NPC가 실제로 그 도움을 기억하고 있는가?
- NPC가 도움의 의도를 긍정적으로 해석했는가?
- 도움이 신뢰를 높였어도 이번 요청이 위험하면 거절할 수 있다.
- 신뢰는 행동 선택의 한 요인이지 '반드시 협력'이라는 확정 결과가 아니다.

**발견:** 관계를 일률적인 호감도만으로 계산하지 않고 **기억의 내용, 관점, 동기, 현재 위험과 이해관계**를 함께 판단하는 것이 중요하다.

## 6. 특히 보존할 가치가 있는 '실패를 막는 원칙'

이는 구현 상세보다 **누적 개발 과정에서 학습한 문제 방지 요구사항**에 가깝다.

| 원칙 | 방지하려는 실제 문제 | 차기 기획에서 확인할 질문 |
|---|---|---|
| **판정의 근거를 명시** | 합리적 설명 없이 목표치가 바뀜 | 어떤 정보에 근거해 난도·방법·상태가 평가됐는가? |
| **성공 여부와 효과 크기를 구별** | 판정 성공을 무제한 효과로 오인 | 성공이 보장한 범위는 어디까지인가? |
| **정보 부재와 부정 구별** | 명시하지 않은 NPC·물체가 존재하지 않는 것으로 처리 | 무엇을 모르는가, 무엇이 존재하지 않는다고 확정했는가? |
| **시도와 세계 결과 분리** | 플레이어가 자신의 발언으로 NPC 동의/승리를 강제 | 누가 행동을 선택하고 누가 결과를 결정하는가? |
| **숨은 정보 누설 금지** | 플레이어가 아직 모르는 비밀 경로를 경로 안내가 사용 | 관측자에게 어떤 세계 정보가 공개 가능한가? |
| **행동의 선후·의존성 관리** | 복합 행동 중 앞선 실패가 무시됨 | 각 단계에서 어떤 조건이 새로 성립했는가? |
| **물품·수량 보존** | 같은 물건이 재생성되고 인벤토리가 복제됨 | 무엇이 실제 어디서 어디로 이동·소모·생성되었는가? |
| **판정 실패를 세계의 절대적 부정으로 오인 금지** | 반복 탐색·발견 세계가 일관성을 잃음 | 실패는 무엇을 확인하지 못했다는 뜻인가? |
| **NPC의 지식·위치·행동 능력 검증** | 적대자가 전지적·순간이동하는 행동 | 그 NPC는 어떤 정보를 어떤 경로로 알고 있고 현재 무엇이 가능한가? |
| **판정·상태 확정의 멱등성** | AI 재호출 때 다시 굴리거나 아이템/보상 중복 지급 | 같은 플레이가 여러 번 호출되면 결과가 보존되는가? |
| **일시적 완화와 영구적 해결 구별** | 치료 후 원인까지 근거 없이 소멸 | 상태 변화는 증상 완화인가 원인 제거인가? |
| **시나리오 장르별 규칙의 경계** | 한 장르의 물리·판정 메커니즘이 다른 장르에 과도하게 적용 | 공통 세계 원리와 장르 게임 규칙은 어떻게 구별할 것인가? |
| **서사 기억과 확정 사실의 권위 분리** | 요약 과정에서 세계의 과거가 바뀜 | 기억용 요약과 실제 정본의 충돌은 무엇을 우선하는가? |
| **확정 이전 묘사에 새 사실 생성 금지** | AI가 말한 뒤 나중에 엔진 상태와 충돌 | 표현 가능한 사실의 범위가 사전 확정되었는가? |

## 7. 현행 데이터에서 주의해야 할 한계와 남은 공백

이번 조사에서 *유용한 아이디어를 찾는 것*과 *이미 범용 시스템을 달성했다고 평가하는 것*을 구별해야 한다.

1. **복합 행동의 일반적인 결과 생성**: 기존에는 서로 다른 규칙이 존재하지만 임의의 목적·수단·대상 조합을 완전하게 분석·실행하는 범용 메커니즘이라고 볼 수 없다.
2. **물리적 상식의 폭**: 물품의 수량·상태·효과를 알더라도 밧줄·상자·문·화재·무게·지지력·소음처럼 새롭고 복합적인 상호작용의 판정을 모두 다룰 수 있는 것은 아니다.
3. **상태 수치의 포괄성**: 현재 2d50과 상태 보정은 특정 규칙에서 엄밀하지만, 사람의 몸과 환경에서 모든 인과관계가 정밀하게 계산된다는 의미가 아니다.
4. **심리·의사결정의 실제 수행**: NPC 프로필의 목표·가치관과 일과, 관계 변화가 존재한다고 해서 이 목표를 달성하기 위한 자율적인 일반 계획·재계획 능력이 완성되었다는 뜻은 아니다.
5. **사회적 규칙의 일반성**: 소속·신뢰·권한과 일부 접근 제약은 있지만 사회적 역할·규범·계약·조직 정책·의무의 완전한 범용 관리와는 차이가 있다.
6. **미정 사실 생성 권한**: 주변 소품의 제한적 발견 메커니즘은 유용하지만 모든 미저작 공간·도구·NPC를 정본에 안전하게 추가하는 일반 규칙과 동일하지 않다.
7. **조건부 행동과 일과의 충돌**: 장기 활동, 여러 NPC의 동시 행동, 플레이어의 'A하면 B' 선언에는 별도 시간·행동 점유·연쇄 실패 규칙이 더 요구될 수 있다.
8. **묘사 이전 세계 확정의 미완성**: 현행은 부분적으로 묘사 이후 추출·상태 반영의 경로를 가진다. 차기 목표인 **판단 → 코드의 세계 확정 → 확정된 정보만 묘사**와 다르다.
9. **검증의 범위**: 일부 제약은 코드에서 강제되지만 일부는 프롬프트 지시로만 표현된다. 프롬프트에 적혀 있다는 이유로 언제나 지켜지는 것으로 평가하지 않는다.
10. **게임성을 위한 규칙과 시뮬레이션 진실**: 성장 포인트, 편의적 판정 보너스 등은 재미를 위한 규칙이다. 이를 세계에 관한 객관적인 물리 사실로 오인하지 않아야 한다.

## 8. 추출 결과의 새 기획에서의 위치

이번 조사는 차기 엔진의 아키텍처나 시스템 경계를 정하지 않았다. 대신 다음과 같은 **검토 대상 묶음**을 제공한다.

| 묶음 | 추출한 관리 질문 |
|---|---|
| **행동의 의미** | 행위자·대상·목적·수단·순서·조건부 후속 행동·플레이어의 허용 재량 |
| **행위 가능성** | 물체·공간·신체·사회·지식에서 무엇이 행동을 허용·제약하는가 |
| **판정과 효력** | 확실한 경우/불명확한 경우/판정이 필요한 경우/성공의 효과 범위/대가 |
| **상태 변화** | 물체의 소모·변환, 신체 상태, 장기 변화, 사회 관계, 지식과 인식 |
| **자율 반응** | NPC가 알게 된 사실, 반응 조건, 목표와 행동, 조직·환경의 연쇄 변화 |
| **정보의 권위** | 확정/미정/반박/정보 생성 권한/플레이어에게 공개 가능한 사실 |
| **판정·변경의 안전성** | 검증, 중복 방지, 결정 이후 재시도, 관측되지 않은 곳의 시뮬레이션 상세도 |
| **게임 규칙의 다양성** | 장르에 따라 다른 전투·성장·협력·상태·행운 규칙 |

### 최종 관찰

현행 INDAIM의 가치 있는 성과는 `2d50` 하나나 특정 사건·상태 모델 하나에 있지 않다. **게임이 '판단하기 위해 무엇을 알아야 하는지'와 '판단 이후 무엇을 세계에 남겨야 하는지'를 여러 실패를 거쳐 세분화했다는 점**이 더 중요하다.

특히 차기 버전에서 인간 GM의 부재를 극복하려면 **판정은 결과의 일부일 뿐**이라는 인식이 필요하다. 판정 전에 행동 의미·성립 조건·지식 한계가 정해져야 하고, 판정 뒤에는 효과의 범위·후속 인과·지속 상태가 확정되어야 한다. 비로소 그 뒤에 묘사가 확정 사실을 표현한다.

이 문서의 항목은 **제안·검토를 위한 수집물**이며 사용자의 승인 전에는 어느 것도 새로운 차기 시스템으로 채택하지 않는다.
