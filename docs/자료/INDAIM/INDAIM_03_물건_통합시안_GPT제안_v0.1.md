# INDAIM 전면 재설계 — 03. 물건 설계실
# 사용자 초기 구상 + 1·2차 조사에 근거한 물건 시스템 통합 시안 v0.1

> **문서 지위: GPT 작성 설계 시안. 사용자 검토·승인 전.**
>
> 이 파일에는 구체적인 **설계 제안**이 포함되어 있다. 본문에서 `제안한다`, `두자`, `사용한다`라는 표현은 모두 **GPT의 시안**으로만 읽어야 하며 승인된 정책·기존 결정이 아니다. 사용자의 구상을 기술적으로 구체화하면서 만들어진 부가 사항은 `[제안]`으로 표시한다. 미정 부분은 `[미정]`으로 남긴다. 사용자의 문장 원문은 제1파일, 조사 원본의 상세 기록은 제2파일을 참조한다.

## 0. 목적, 출처, 판정의 지위

### 0.1 문서의 성격

- **[사용자 초기 구상 U02]** 물건의 원본 데이터와 세션 세계 상태 구분, 이름 중심의 물건 종류 구분, 단위의 유연성, 의복·손 점유·착용, 효과·상태, 배치·우발적 존재·묘사 사물, 열쇠/잠금 호환성, 분할·소비·오염·부패 및 LLM의 일관성 통제.
- **[조사 자료 G1/G2]** Evennia/Unity/Godot, Inform/TADS/Scenery, Cataclysm, RimWorld/Dwarf Fortress, Minecraft, Project Zomboid, Unreal GAS, SHACL, PDDL, 정성적 물리, 어포던스, STORY2GAME 등 서로 다른 목적의 실제 사례와 연구.
- **[선행 승인 원칙]** 시간 영역의 기초 정책 P01~P08(공통 시간축, 고정 최소 해상도 없음, 시간 정보의 사실별 분산 소유, 역사는 시간 영역의 소유 아님). 장소·공간 통합 v0.2는 공식 검토 자료일 뿐 미승인.
- **[이 문서의 새 내용]** 아래 ‘관리 단위’, ‘상태/기능 연결’, ‘물건 사실 확정’, ‘변화 처리’ 등 **모두 GPT가 합성한 미승인 시안**이다.

### 0.2 설계의 목표와 비목표

**[제안] 목표:** 고유 저작 물건은 충분히 풍부하게, 흔한 물건과 의복·가구는 필요 수준만큼 가볍게 표현하면서, 플레이어의 자유로운 행동 이후에도 물건의 존재·수량·상태·위치·연결·효과가 모순되지 않게 유지한다. 세계에서 이미 결정된 사실은 보존하고 미정인 부분만 제약 아래 구체화한다.

**[제안] 비목표:** 모든 물질의 분자 수준 조성, 모든 손상 충돌의 실제 응력 계산, 의복의 3D 충돌 계산, 모든 물건의 모든 가능한 행동 열거, 무조건 성공하는 키/퀘스트 배치, 모든 상태를 수치 필드로 환원. **물리 모델의 상세함보다 중요한 사실의 정확한 지속을 우선**한다.

### 0.3 최소 원칙 8개 — 이 시안의 골격(전부 [GPT 제안])

1. **물건 종류를 부르는 이름**과 **세션 세계에서 실재하는 물건/묶음**을 구별한다.
2. 원본 정보와 세션 사실은 분리하지만, 이를 단순한 불변 템플릿과 그 복제품 관계로 고정하지 않는다.
3. 물건의 **지속 성질**, **현재 상태**, **다른 대상과의 관계**, **작동 가능한 기능**을 개념적으로 구별하고 필요할 때만 상세화한다.
4. 모든 물건을 최고 해상도로 만들지 않는다. 중요한 물건의 부분·재료·효과는 자세히, 평범한 물건은 상황에 충분한 만큼만 기록한다.
5. 수량의 단위·내용물·묶음·물건의 일부/수납/장착을 혼동하지 않고, 나누거나 합칠 때 중요한 차이를 지운 채 수량만 합산하지 않는다.
6. 착용·손에 듦·소유·보관·작동은 서로 다른 관계와 사실이다. 기능은 현재 조건과 상태에서 발현된다.
7. 배치·확률·LLM·묘사로 추가되는 사물은 기존의 확정 사실과 제약을 위반하지 않아야 한다. 기록되지 않은 것과 없는 것은 다르다.
8. 구조적 일관성이 요구되는 사실은 검증·지속하고, 정의가 부족한 물리 작용/임의 사용은 불충분한 계산을 강제하기보다 제약 있는 맥락 판단으로 다룬다.

# 1. 관리할 대상의 범위

## 1.1 물건은 ‘휴대 인벤토리 품목’만이 아니다

**[사용자 초기 구상]** 특별히 저작하는 물건 → 흔한 물건·의복 → 가구까지 포괄하는 조사·설계 범위. 손에 든 것·착용한 것·장소에 배치된 것·다른 물건 안에 든 것·구조물과 결합한 물건을 모두 고려.

**[제안]** 물건 영역의 관리 대상으로 다음을 수용한다: 휴대 도구, 무기, 식품·의약품·액체, 포장·용기, 의복·착용 장비, 가구·설비, 문·창문·고정 장치 등 공간 구조와 결부되는 물리 대상. 그러나 **모든 고정 구조를 물건 영역이 소유한다는 결론은 아니다.** 벽의 구멍, 출입 경계, 위치 관계 등은 공간 영역과 공동 검토.

**[미정]** 불연속 물질(먼지·흩어진 액체·연기), 건축물 전체, 토양·물웅덩이·환경의 물질은 언제 물건이고 언제 환경/공간 사실인가? 이 시안은 경계를 강제하지 않는다.

## 1.2 ‘관리 대상’과 ‘상세한 독립 객체’는 다른 말이다

**[제안]** 물건의 존재/상호작용을 의미 있는 정보로 표현하면서도, 반드시 모든 실물에 동일한 크기의 구조화 객체를 만들지는 않는다. 다음 표현 수단을 **필요에 따라 조합**한다.

- **종류 설명:** 흔한 물건에 공통되는 이름·성질·사용 가능성. 실물 하나의 현존을 뜻하지는 않는다.
- **세션 내 실물:** 독립된 현재 위치/소유/상태/수량/결합을 기록할 필요가 있는 대상.
- **배경에 존재하는 사물 기술:** 장면·장소의 배경으로 서술된 대상의 존재와 최소 특징. 플레이어가 조작하면 독립 관리 정보가 추가될 수 있음.
- **복합 물건의 부분:** 고유 부품을 따로 추적할 필요가 없는 부분은 상위 물건의 구조 설명에 포함하고, 분리·수리·이동·손상 등 독립 변화가 필요한 부분은 별도 관리로 전환 가능하도록 설계할 여지를 둔다.

**[미정]** 어떤 사건에 의해 최소 정보만 가진 배경 물건을 개별 실체로 구체화할지, 해당 구체화가 언제/누구에 의해 승인되는지. 자동 승격은 아직 승인되지 않았다.

# 2. 세계 데이터와 세션 세계의 역할

## 2.1 두 층위에 대한 제안적 해석

**[사용자 초기 구상]** `물건 자체에 대한 원본 데이터`와 `세션 세계에서 보관 상태나 묶음, 소유, 손상인 조합 여부 등이 관리되어야 하는 데이터`를 구분한다.

**[제안]** 다음 정보의 *역할*을 구별하되, 반드시 두 개의 단일 데이터베이스/두 개의 완전 대응 테이블로 고정하지 않는다.

| 역할(제안) | 무엇을 보존하는가 | 사례 | 주의 |
|---|---|---|---|
| 일반 물건 정의 | 물건 이름을 기준으로 구별하는 종류와 일반적인 성질·가능성 | ‘물’, ‘타이레놀’, ‘목재 의자’, ‘작업복’ | 종류 정의만으로 실존 개수 확정 안 됨 |
| 저작된 특정 물건 사실 | 스토리상 독특한 실물/유물의 개별 성질·역사·중요 호환/초기 배치 등 | ‘경비실의 전용 출입카드’ | 원본이 항상 종류 템플릿이라는 가정 금지 |
| 세션 세계의 현재 사실 | 실재 대상의 상태·수량·실제 위치·소유/보유/착용·결합·내용물 등 | 현재 주머니에 든 카드키, 젖은 작업복 | 원본을 임의로 덮어쓰지 않음 |
| 필요 시 구체화된 추가 사실 | 사전에 빈칸이었던 상세 구조/소품을 제약 내에서 정해 기록 | 묘사된 유리컵의 구체적 위치 | 기존 정본 위반·중요 사실 임의 창작 금지 |

**[제안]** 원본은 완전히 불변이라고 가정하지 않고, 원본 수정·세션 파생·세계관 패치/규칙 변경을 구별하여 **전파 시점을 결정할 별도 정책**을 검토한다. 이 시안에서 구체 전파 정책은 결정하지 않는다.

## 2.2 이름으로 종류를 구별하되, 동일 이름의 실물은 지속적으로 구별

**[사용자 초기 구상]** 물건의 ‘구분(고유x, 타이레놀과 물 구분 정도)’은 이름으로 통일.

**[제안]** 사용자에게 의미 있는 물건 종류는 **정규화된 종류 이름**으로 참조한다. 같은 이름은 같은 종류를 가리키되, 별칭/언어별 표기/세부 규격의 처리 정책은 미결정으로 둔다.

**[제안; 구현 논의 아님]** 같은 종류의 물건이 서로 다른 장소·상태를 갖거나 쪼개졌다 합쳐져도 서로 잘못 덮어쓰지 않도록 **세션 안의 개별 실체를 구별할 수 있는 수단**을 둔다. 이를 어떤 내부 식별자로 구현할지는 이후 결정한다. 이는 '물건 종류를 고유 아이템 ID로 구분하지 말라'는 사용자 의도와 충돌하지 않게 별개의 **실체 추적 문제**로 취급한다.

**[예시]** 물 500mL와 물 200mL는 같은 이름의 종류를 가리키지만 다른 용기, 다른 오염 상태, 다른 실제 위치를 가질 수 있다.

**[미정]** 타이레놀이라는 명칭에 함량·제형/서로 다른 제품 규격을 어디까지 포함할지, 이미 저장된 정의의 이름 변경과 별칭 충돌 등.

# 3. 물건을 표현하는 정보의 층위

## 3.1 최소 공통 사실과 선택적 상세 정보

**[제안]** 물건마다 모든 속성 필드를 채우기보다, 필요하면 아래 사실군을 병렬로 표현할 수 있도록 한다. '항목이 존재한다'는 것과 '모든 물건에 그 값이 반드시 존재한다'는 뜻은 다르다.

| 사실군 | 정보 예시 | 필수성 제안 | 관련 조사 |
|---|---|---|---|
| 이름·종류 | 물·타이레놀·셔츠·컵, 종류/별칭 | 종류 구분의 공통 출발점 | Evennia, Minecraft |
| 물리적 성질 | 재료·형태·용량·무게·부피·색·형상·제작 품질 | 관련 있을 때만 | Cataclysm, RimWorld, glTF |
| 서술·외형 | 고유 외관, 눈에 띄는 흠집, 설명 | 저작의 목적에 따라 | World Anvil, OpenUSD |
| 구성·내용물 | 부품, 구성 비율, 수납 공간, 내용물 | 합성/분할/장착을 판단할 때 | TADS, DTDL, Pocket |
| 현재 상태 | 손상·젖음·방전·오염·부패·작동/꺼짐 | 해당 물건에 의미가 있을 때 | Pathfinder, Cataclysm |
| 현재 관계 | 위치, 수납, 손 점유, 착용, 연결, 물건 간 묶음 | 세션 내 변화가 생길 때 | Inform, IFC, TADS |
| 기능 | 사용 가능성, 전용 기능, 판정·상태 영향 | 물건 사용에 필요할 때 | GAS, ALFWorld, Fate |
| 저작 특수성 | 개별 역사, 권한, 예외, 비공개 설정 | 특별한 물건에 선택적 | World Anvil, Dwarf Fortress |
| 시간 연관 | 사용기한, 변질/상태 변화 시점, 시간 의존성 | 관련 있을 때만 | Cataclysm, EPCIS |
| 사실의 출처/결정 상태 | 언제/무슨 근거로 존재를 확정했는가 | 특히 동적 생성 시 | Loot Table, PROV, OWA |

**[중요한 제안]** 자연어로만 표현된 물건도 유효한 출발점으로 허용하되, 위치·수량·호환성·지속 상태 등 **변화 후 모순이 위험한 사실**은 명시적으로 보존할 수 있도록 한다. 모든 자연어 표현을 완전하게 계산하려 하지 않는다.

## 3.2 성질과 상태, 결과와 평가를 분리

**[제안]** 다음 정보를 서로 구별한다.

1. **기저 성질:** 금속 재질, 유연함, 정격 용량, 원래 형태 등. 상황에 따라 변할 수 있는 값이라도 기본·정의적 성질의 역할을 할 수 있음.
2. **현재 상태:** 젖어 있음, 반쯤 방전됨, 찢어짐, 손상 등. 정도/범위/관찰된 단서를 필요에 따라 포함.
3. **가능한 기능:** 물을 담을 수 있음, 열을 낼 수 있음, 열쇠로 인증 가능함 등.
4. **기능의 발현 조건:** 착용, 손에 듦, 잠금장치와의 실제 호환, 전력·배터리, 대상·환경 조건 등.
5. **효과:** 판정에 영향, 신체/환경 변화, 다른 물건 상태 변동, 행동의 허용/불허, 자연어로 서술되는 기능적 변동.

**[제안]** 사실을 단순히 태그로 붙였다는 이유만으로 그 효과를 자동으로 확정하는 것을 피한다. `젖음`처럼 동일한 말이 재질·정도·문맥에 따라 서로 다른 결과를 갖는다면 물건의 적용 조건과 기능 해석을 함께 참조한다.

## 3.3 적용 가능한 상태만 부착

**[사용자 초기 구상]** 젖음·방전·손상 등은 붙을 수 있는 물건에만 붙어야 함. 상태가 기능을 바꿀 수 있음.

**[제안] 상태 표현 후보:** 상태마다 `적용 전제`, `값의 형태(참/거짓·정도·부위 등)`, `필요하다면 변화 추적 정보`, `기능에 미치는 영향의 근거`를 기술할 수 있게 한다. 적용 전제가 충족되지 않으면 해당 상태 부여를 **거절하거나 재해석 필요로 표시**하고, 임의로 사실을 고치지 않는다.

**[가상 예시]** 손전등의 내장 전지가 방전된 경우 발광 불능; 반대로 배터리가 장착되지 않은 손전등은 ‘배터리가 방전됐다’와 다른 상태. 옷이 젖었다는 사실은 허용될 수 있어도 어떤 보온/마찰 변화가 생기는지는 재료·착용·환경을 확인할 필요.

**[미정]** 상태 종류를 데이터로 등록하는 방식, 물건 종류별 허용 목록 vs 성질 기반 조건 vs LLM 검증의 비중, 부정/미확정 상태와 정도 척도의 구조.

# 4. 수량, 분할, 혼합, 묶음

## 4.1 물건 이름과 단위를 함께 관리

**[사용자 초기 구상]** `ml`, `g`처럼 개수 이외의 단위 사용.

**[제안]** 각 물건 종류에는 **기본적인 취급 수량의 차원**을 지정할 수 있다(낱개 수, 부피, 질량 등). 필요 시 단위 변환과 다른 물리량을 별도로 표현한다.

| 예시 | 기본 취급 수량(시안) | 분리해야 하는 추가 정보 |
|---|---|---|
| 물 | mL | 용기의 용량·현재 물량·오염/혼합 조성 |
| 고기 | g | 식품 부패·오염·육질/포장·조각 수 |
| 알약 | 정 | 1정의 유효성분 mg, 한 조각의 비율, 습기 노출 여부 |
| 티셔츠 | 벌/개 | 피복 범위·사이즈·재질·젖음/손상 |
| 열쇠 | 개 | 실제 대응 잠금장치, 손실 여부 |
| 천 조각 | 개 또는 길이/넓이/질량(미정) | 실제 사용에 적합한 규격·형태 |

**[제안]** 같은 물리 차원의 단위만 안전하게 환산한다. 질량↔부피 변환은 밀도 등 필요한 정보가 있어야 하며, 임의 추측으로 바꾸지 않는다. '정'처럼 낱개 단위라도 분쇄·분할 가능 여부는 별도 문제.

## 4.2 묶음의 서로 다른 의미를 구별

**[제안]** ‘묶음’은 적어도 세 현상을 혼동하기 쉽다.

1. **동종 물건의 수량 집합:** 같은 종류·실질적으로 같은 상태의 알약 8정 등. 개별 실물을 일일이 식별하지 않아도 정보 손실이 없는 경우.
2. **물리적 묶음·포장:** 끈으로 묶인 장작, 밀봉 포장된 알약, 한 상자에 담긴 도구. 물리적 포장 자체가 상호작용에 영향을 줌.
3. **서로 다른 실물의 수납/동거:** 약통 속 정상 약과 젖은 약의 공존. 총량이 합쳐진다고 상태가 같아지는 것은 아님.

**[제안]** 단순 화면상의 묶음 표시와 세계의 실제 구성·포장 상태를 혼동하지 않는다. 실제로 따로 상태·위치·결합 관계가 달라지는 순간 표현을 더 세분화할 수 있어야 한다.

## 4.3 분할·합병의 정보 불변 조건

**[제안]** 분할·병합은 '수량의 산술'이면서 동시에 '대상과 상태의 변화'이다.

- **분할:** 나눈 총량이 원래 총량과 일치해야 하지만, 나누어진 부분의 상태/조성도 합리적으로 이어져야 한다. 불균질한 대상은 동일 성질을 단순 복제하지 않는다.
- **병합:** 비슷한 이름이라는 이유만으로 서로 다른 오염·부패·손상·혼합 성분을 없애지 않는다. 섞인 것을 한 덩어리로 표현할지, 내용물들이 같은 용기 안에 공존하는지 구별한다.
- **형태 변경:** 10정의 약을 빻아 가루로 바꾸면 같은 낱개 수로 계속 다루기 어려울 수 있다. 필요한 경우 대상의 형태·수량 기준을 바꾸되 기여 물질이나 중요한 상태를 설명 가능하게 한다.
- **결과가 불확실한 변화:** 실제로 어떤 부분에 얼마나 오염이 옮았는지 정보가 없으면 근거 없이 정밀 수치를 지어내지 않는다. 적절한 정성 표현이나 판단 보류가 가능해야 한다.

**[미정]** 개별 실체/배치/수량 묶음 간의 내부 전환 방식, 혼합 시 조성 보존의 상세 정책, 분할되기 전 물건의 동일성 이력의 소유권.

# 5. 용기·내용물·가구·부품·결합

## 5.1 용기와 내용물은 원칙적으로 다른 존재

**[사용자 초기 구상]** 물을 일부 마시거나 전부 마시면 빈 통이 남고, 물/식품/알약을 나누어 보관할 수 있어야 함.

**[제안]** 지속 상태가 중요한 용기와 내용물은 구별할 수 있게 한다. 물병·약통·가방·책상 서랍·탄창을 모두 '다른 것을 담거나 장착하는 역할'로 참고하되 상세 구조는 필요에 따라 달리 둔다.

**[제안]** 용기의 수납 자리/내부 영역을 설명할 수 있다면 `최대 수용량`, `허용 물질/형상`, `개구부`, `밀봉`, `내용물에 미치는 특성` 등을 필요한 경우만 기록한다. 하지만 평범한 컵의 정확한 지름/개구부 단면적 등을 필수 정보로 만들지 않는다.

**[실제 대비 사례]** Minecraft의 `사용→잔여물` 변환형과 Project Zomboid의 `용기+부분 내용물` 실체형 모두 가능. **[제안]** 지속적 조작의 깊이에 맞는 표현을 선택할 수 있는 여지를 두고 초기부터 모든 일회용 포장을 고해상도 구성 객체로 관리하지 않는다.

## 5.2 수납, 구성, 장착, 연결은 서로 다름

**[제안]** 아래 관계를 분리된 의미로 취급한다.

| 관계 | 예시 | 다른 관계와 구별해야 할 이유 |
|---|---|---|
| 수납/포함 | 약통 안의 알약, 서랍 안의 열쇠 | 공간적 위치/수용 |
| 위에 놓임 | 책상 위의 컵 | 수납과 달리 표면 배치 |
| 부분/구성 | 문의 손잡이, 전등의 전구 | 전체 물건의 일부·기능적 연결 |
| 장착/부착 | 렌즈를 장착한 손전등, 총에 장착한 부품 | 제거·호환·부착 위치의 영향 |
| 물리적 연결 | 충전 케이블과 장치 | 연결 상태가 기능 조건 |
| 묶음/포장 | 끈으로 묶은 장작, 테이프로 봉함 | 그룹 자체가 조작 대상 |
| 잠금·제어 연결 | 자물쇠가 문의 이동을 막음 | 물건 작동과 공간 구조에 공동 영향 |

**[제안]** 관계마다 모든 물건에서 통일된 계산을 요구하지 않고 의미 있는 불변 조건만 유지한다. 예를 들어 같은 일상적 컵을 모순되게 두 개의 서랍 안에 동시에 존재한다고 기록하지 않아야 하지만, 긴 케이블처럼 여러 공간에 걸치는 대상은 단순 '한 좌표만'으로 설명하기 어렵다. 장소·공간 영역의 구조를 이 설계실에서 선점하지 않는다.

## 5.3 부분의 독립성이 달라지는 경우

**[제안]** 평소에는 '문에 손잡이가 있음'이라는 설명으로 충분할 수 있다. 그러나 손잡이를 떼어 가방에 넣는 행동이 성립한다면 기존 부분이 독립적으로 이동·소유·손상되는 상태를 표현할 수 있어야 한다. 이때 원본 전체의 관련 사실(손잡이 없음·문을 여는 데 어려움 등)과 모순 없이 연결한다.

**[미정]** 물건의 동일성을 유지할 기준, 떼어낸 부분이 원래와 같은 물건인지 새 물건인지, 다시 조립 시 관계와 기능을 복원하는 원칙.

# 6. 의복과 손 점유: 물건의 장착 관계

## 6.1 장착을 물건 범주의 특수 형태로 취급

**[사용자 초기 구상]** 의복도 물건. 손에 든 물건과 몸에 착용한 의복을 단순 점유/소지와 구분. 겹쳐 입기와 의복별 착용 범위 차이. 효과가 판정과 신체·환경 계산에 영향을 줌.

**[제안]** 의복에만 존재할 수 있는 정보 후보를 다음처럼 둔다.

- **피복 부위:** 머리·손·몸통·팔·다리 등 어느 신체 범위에 닿고 덮는가. 상세 부위 체계는 신체 영역에 요청.
- **피복 정도:** 완전히 가리는가, 일부만 가리는가. 단일 확정 비율을 모든 옷에 강제하지 않음.
- **중첩 순서/착용 층위:** 내의-상의-외투 등 상대적 순서와 겹침. 경우에 따라 특정 부위만 겹치는 옷도 가능해야 함.
- **물리적 특징:** 방수·투습·두께·소재·보온 등 근거가 존재하는 특징. 수치를 반드시 요구하지 않음.
- **착용 조건/제약:** 착용 가능한 몸의 상태·부위·치수, 충돌하는 장비, 착용 방식.
- **현재 착용 사실:** 누구의 어느 부위에 어떤 방식으로 장착되어 있는가. 소유자와 동일할 필요 없음.

**[제안]** ‘옷이 소지됨’과 ‘착용됨’, ‘착용됨’과 ‘정상적으로 밀착/기능함’을 분리한다. 여러 옷의 효과를 무조건 더하지 않고 중첩·조건·상태의 의미에 맞춰 판단한다.

## 6.2 손에 들기

**[제안]** 손에 들기/손으로 쥐기/손에 걸치기와 같은 물건의 실제 사용 방식은 단순 소지와 구분하여 표현할 수 있도록 한다. 손의 능력·사용 가능 상태는 신체 영역에 의존하므로 이 시안에서 손 슬롯 수/잡는 힘/양손 무기 규칙을 고정하지 않는다.

**[예시]** 손전등을 주머니에 소지, 손에 쥠, 켜서 조사함은 다른 사실. 우산을 손에 들었어도 접힌 상태라면 빗물 차단 효과가 발휘되지 않을 수 있다.

## 6.3 다른 영역과의 계약 후보

**[제안]** 물건 영역은 `현재 착용/손 점유 상태`, `피복/기능 근거`, `물건 상태`를 제공하고, 신체·건강·환경·판정 등은 자신의 원리로 영향을 평가한다. 판정의 수정치가 이미 저작되어 있다면 이를 정확히 전달할 수 있도록 한다. **효과가 어떤 규칙으로 계산되는지의 최종 소유권은 미정.**

# 7. 기능·효과·활용 가능성

## 7.1 ‘기능’을 허용 행동의 닫힌 목록으로 만들지 않기

**[사용자 초기 구상]** 기능에는 판정에 주는 영향이 모두 포함됨. 물건의 상태·착용·손 점유 등이 효과에 영향.

**[제안]** 최소한 두 형태의 기능 설명을 공존시킨다.

1. **명시적 기능:** 특정 열쇠의 대응 잠금장치 해제, 정해진 약품 복용 효과, 손전등의 발광, 저작된 주사위 판정 수정처럼 확정적·중요한 조건과 결과가 있는 기능.
2. **성질에 기반한 사용 가능성:** 쇠막대로 문을 괴기, 책상을 엄폐물로 쓰기, 천으로 액체를 닦는 등 사전에 열거되지 않은 활용. 물건 성질·상황·대상·행위자를 함께 보고 판단하며, 가능 여부나 결과를 확정하려면 필요한 정보를 확인한다.

**[제안]** 물건의 **용도**('무엇을 위해 제작됐나')는 기능의 참고 정보지만, 그 물건의 **모든 가능한 행동 목록**과 동일시하지 않는다. 어포던스에 관해 중요한 부분이다.

## 7.2 기능을 서술할 때 구별할 네 질문

**[제안]** 중요한 기능은 적어도 다음 질문에 답할 수 있는 정보를 갖도록 한다. 모두가 정형 필드일 필요는 없다.

| 질문 | 예시 |
|---|---|
| 이 물건은 원칙적으로 무엇을 할 수 있나? | 빛을 내기, 잠금 해제, 물 담기, 체온 유지에 도움 |
| 지금 그 기능을 사용하려면 무엇이 필요한가? | 켜져 있음, 전력 공급, 올바른 열쇠-잠금 대응, 몸에 착용 |
| 현재 상태로 인해 기능이 제한되거나 변했나? | 방전, 젖음, 찢어짐, 오염, 파손, 부품 부재 |
| 기능이 발현되면 무엇에 영향을 미치나? | 판정, 신체, 환경, 정보 획득, 다른 물건, 공간 이동 |

**[제안]** 효과의 표현은 수치/조건/정성적 설명/대상 영역에 전달할 요구 중 적절한 것으로 둔다. 단, 원본에서 명시된 정확한 수치·호환성·영구 제한은 LLM이 임의 재해석하지 못하게 한다.

## 7.3 중복·경합·우선순위는 미결

**[미정]** 두 방한복의 보온 효과가 합산·최대치 선택·상황적 상호작용 중 무엇인지; 보호복이 젖은 상태와 오염 상태가 동시에 존재할 때 어떤 조건부터 적용되는지. 상태/효과의 일반 프레임만으로 자연현상 법칙까지 확정하지 않는다.

---

# 8. 열쇠, 카드키, 전용 장치의 호환성

## 8.1 작동 가능한 대상은 실제 관계로 표현

**[사용자 초기 구상]** 열쇠/카드키는 대응되는 자물쇠/잠금장치에만 작동하며 개연성 있는 곳에 의도 배치 가능.

**[제안]** 단순한 이름 일치나 '열쇠'라는 종류의 일반 능력만으로 잠금 해제를 허용하지 않는다. 실제 해제 가능 여부의 근거가 되는 **호환 관계·식별 구조·권한/유효 상태**를 필요 수준에서 표현한다.

**[예시]** 실물 열쇠가 자물쇠 A에는 맞고 B에는 맞지 않는다; 마스터키가 여러 잠금장치에 해당될 수 있다; 카드키는 읽는 장치와 권한 설정·취소 여부에 따라 작동할 수 있다. 카드키는 특히 한 물건의 기계적 형상만이 아니라 다른 시설·권한 정보와 연결될 수 있다.

**[제안]** 실제 맞는다는 사실과 NPC/PC가 알고 있거나 '맞을 것 같다'고 생각하는 사실은 분리한다. 물건 영역에서 **실제 호환성**의 근거를 제공하되 지식·오해 자체는 정보 영역 검토에 맡긴다.

## 8.2 배치 개연성과 사용 가능성은 분리

**[제안]** 열쇠가 어느 장소에 있을지와 어느 장치를 열 수 있는지는 서로 다른 사실이다. 의도 배치는 장소의 성격, 역사, 점유자, 관련 시설, 제약된 동선 등과 연결될 수 있지만, **항상 플레이어가 찾을 수 있는 열쇠를 보장한다**는 규칙은 도입하지 않는다.

**[미정]** '열쇠를 하나의 자물쇠에 대응'시키는 연결 방식 vs 프로파일/규격/권한 규칙으로 여러 잠금장치를 처리하는 방식의 병용 범위.

# 9. 배치, 존재의 미결정, 묘사와 세계 사실의 연동

## 9.1 물건의 존재를 정하는 세 경로를 구별

**[사용자 초기 구상]** 사전 배치, 무작위 또는 LLM 선정으로 존재 확정, 묘사에 등장한 물건 활용.

**[제안]** 물건의 세션 내 현존은 아래 경우 모두 지원할 수 있게 한다.

1. **저작된 확정 사실:** 특정 장소에 특정 물건이 존재한다. 관련된 부재 사실과 접근 조건이 이미 결정될 수 있다.
2. **허용된 빈칸의 지연 구체화:** 일반적인 사무실에 볼펜이 있는지처럼, 사전 저작하지 않았고 기존 사실에도 제약되지 않는 작은 사물의 존재를 필요 시 정한다. 확률·LLM 선택은 후보 생성 수단일 뿐, 그 자체로 사실을 정당화하지 않는다.
3. **이미 묘사된 구체 사물의 추적:** 서술에 '책상 위 유리컵'이 실제 장면의 존재로 등장했다면 이후 플레이어가 그 유리컵을 활용할 수 있어야 한다. 이전 묘사와 모순되지 않는 최소 사실을 기록하고, 필요한 때 상세화한다.

**[제안]** '기록에 없음', '명시적으로 없음', '존재함', '존재하지만 이 주체는 모름', '존재 여부가 아직 미결정'은 동일하지 않다. 단 이것을 곧바로 고정된 다섯 상태의 스키마로 확정하지는 않는다.

## 9.2 사실을 만들지 않고 설명할 수 있는 범위

**[제안]** 시스템이 새로운 물건을 생성하려 할 때 확인할 범주:

- **기존 확정 사실:** 이미 존재한다고/없다고 정해진 물건, 원본 고유 사실, 기존 관계에 모순되는가?
- **중요성:** 새 물건이 잠금·사건·과업·세력 비밀·서사적 핵심 단서를 갑자기 해결하거나 뒤집는가?
- **맥락의 개연성:** 장소의 종류, 사용 이력, 거주·방치 상태, 신체/환경·사회규범과 모순되는가?
- **생성 범위:** 평범한 배경의 미정 세부를 보완하는 것인가, 핵심 세계관 사실을 창작하는 것인가?
- **이후 지속성:** 한번 존재를 확정하면 위치·수량·상태 등이 이후 장면과 충돌 없이 유지되는가?

**[제안]** 이 조건이 불확실할수록 보수적으로 처리하여 추가 근거/GM 판단/사용자 의도 확인이 필요할 수 있다. **결과를 만드는 방식(확률/LLM/규칙)은 이 시안에서 확정하지 않는다.**

## 9.3 묘사된 사물의 약속과 사실 등록

**[제안]** 서사적 장면에 분명하게 등장한 구체적인 물건을 나중에 플레이어가 사용하려고 할 때 '데이터에 없으니 존재하지 않는다'고 처리하지 않도록 **묘사-세계 사실 연결**을 설계 후보로 둔다.

**실현 후보(비확정):**
- **방식 A:** 묘사 직전에 실제 조작 가능성이 있는 새 물건의 최소 세계 사실을 확정·기록한 뒤 서술.
- **방식 B:** 묘사된 사물의 지시 대상·필수 속성을 별도 약속/사실로 기록하고, 구체적으로 조작하는 시점에 필요한 상세 상태를 채움.

두 방식은 **등록 시점/결정 범위의 차이**가 있으며 하나가 열화판인 관계가 아니다. 방식 B가 중요 물건의 존재를 마음대로 바꾸는 권한을 주지는 않는다.

**[미정]** 실제 저작/설명/인지의 경계, 거짓 서술이나 등장인물의 오해를 표현하는 방법(정보·감각 영역과 협의).

## 9.4 확률·LLM에 의한 선정은 제약 안에서

**[제안]** Collection식 독립 선택/Distribution식 가중치 선택/구성 요소 동시 출현/LLM의 맥락적 후보 선정 등을 도구로 검토한다. 그러나 **출현 후보가 적법한가**와 **후보 중 무엇이 선택되는가**는 다른 판단이다.

**[예시]** '휴게실에 볼펜이 있을 수 있음'과 '진행의 유일한 출입카드가 갑자기 발견됨'은 같은 생성 권한으로 처리해서는 안 될 수 있다. 특정 키가 의도적으로 배치되었다면 그 사실을 대체 생성하지 않는다.

# 10. 손상·젖음·방전·오염·부패와 시간

## 10.1 상태의 표현 해상도를 상황에 맞게 선택

**[사용자 초기 구상]** 손상만이 아니라 젖음·방전 등 다양한 상태. 오염·부패 정도를 표현. 상태는 해당 물건에만 적용되고 기능에 영향.

**[제안]** 상태는 변화가 실제 판단에 의미가 있을 때 다음 해상도 중 적합한 방식을 사용할 수 있게 한다.

- **범주적:** `정상`, `젖음`, `심하게 손상`, `작동 불능`처럼 분류로 충분한 경우.
- **정도 있는 정성 표현:** `약간 젖음`, `거의 방전`, `부패가 진행됨`처럼 정확한 측정이 어렵지만 크기 차이는 중요한 경우.
- **수치/양이 명확한 경우:** 잔여 배터리량, 물의 총량, 오염 물질 농도 등 근거 있는 측정·계산이 필요하고 가능한 경우.
- **부분별 표현:** 화면만 금이 간 기기, 셔츠 소매 부분만 젖음 등.

**[제안]** '정밀 수치가 기록되지 않았다'는 것을 '기본 수치가 0'과 혼동하지 않는다. 확인되지 않은 값과 명시적으로 확정한 정도의 차이를 보존한다.

## 10.2 기능에 미치는 효과

**[제안]** '젖은 옷 → 보온 저하', '침수된 전자기기 → 일부 기능 불능', '오염된 식수 → 건강 위해 가능성', '파손 열쇠 → 호환되지만 사용 불능'처럼 상태가 기능 조건을 변경할 수 있다. 단 결과의 정확한 폭/확률/계산은 기저 성질 및 다른 영역에 따라 달라지므로 포괄적 공식 도입은 유보한다.

## 10.3 시간에 따른 변화

**[선행 승인]** 공통 시간축, 고정 최소 시간 해상도 없음. 시간 영역은 공통 시간 표현을 관리하며 사실에 귀속된 시간은 각 영역에 분산 소유; 역사는 시간 영역 외부.

**[제안]** 물건이 식품 변질, 배터리 자연 방전, 습기 건조, 금속 부식 등을 겪을 수 있더라도 **시간이 지났다는 이유만으로 모든 대상에 기본적으로 변화를 발생시키지 않는다.** 실제 변화가 필요한 상태와 그 원인·필요 자료를 선택적으로 제공한다.

**[중요한 한계]** 마지막 처리 시각부터 현재까지 3일이 지났다는 정보만으로 그 3일 동안 냉장고가 작동했는지·실내 온도가 어떻게 바뀌었는지 알 수 없다. 부분 이력 없이 정교한 변질값을 추론하면 허위 정밀도가 생긴다. 외부 영역의 환경 기록이 필요한 경우 요구사항으로 남긴다.

**[미정]** 시간 의존 상태의 평가 시점/캐싱/지연 갱신, 환경 이력의 제공 범위, 예외적 상태 복구 등은 엔진 전체와 통합 시 결정.

# 11. 변화 및 상호작용의 표현

## 11.1 결과를 세계 사실로 남기는 최소 요구

**[제안]** 하나의 행동이 물건을 바꾸면, 다음 종류의 사실이 필요한 범위에서 함께 갱신될 수 있어야 한다.

| 변화 | 바뀌는 세계 사실의 예 | 보존해야 하는 것 |
|---|---|---|
| 획득/이동 | 장소/보관 위치/보유자 | 같은 물건의 중복 존재 방지 |
| 손에 듦/내려놓음 | 손 점유/물건 위치 | 단순 소유와 구별 |
| 착용/탈의 | 신체 피복·의복 중첩·착용 상태 | 의복의 실체와 상태 지속 |
| 분할/분배 | 수량·묶음·새 보관 위치 | 총량·중요 상태·조성 |
| 혼합/병합 | 구성·함께 보관되는 대상/내용물 | 오염·조성·부패 차이 소실 금지 |
| 소비/섭취 | 남은 내용물, 빈 용기, 주체에 대한 영향 | 대상 소멸/잔존의 구분 |
| 손상/고장 | 물리 상태와 가능한 기능 변화 | 물건 존재 자체는 유지할 수 있음 |
| 부착/분리 | 구성·장착·연결, 호환성 | 부품 이동 및 전체 기능 변화 |
| 잠금/해제 | 장치·공간 경계 상태 | 열쇠-장치 호환·권한 |
| 파괴/가공 | 기존 물건의 잔존 여부·파편·산출물·공간 변화 | 원인/결과, 기타 영역에 미치는 영향 |

## 11.2 정합성 검증: 시안이 지키려는 최소 불변 조건

**[제안]** 다음은 구체 구현 이전에 유익할 수 있는 **검증 목적**이다. 아래 규칙의 예외와 표현 방법은 미결.

1. 동일한 실물의 현재 위치·수납·착용 정보가 서로 모순되지 않아야 한다(분산 배치되는 대상 등의 예외는 개별 검토).
2. 물건이 분할/소비/혼합되더라도 기록된 총량과 중요한 조성이 조용히 증감하거나 사라지지 않아야 한다(실제로 누출·손실·증발 등이 일어난 경우는 명시).
3. 허용되지 않는 상태를 실물에 붙이거나 작동 조건이 충족되지 않았는데 효과를 확정하지 않는다.
4. 서로 대응되지 않는 열쇠/권한으로 잠금이 해제되었다고 기록하지 않는다.
5. 물건이 움직이거나 변형된 뒤 이전 장소·묘사·지식이 곧바로 현재 세계의 진실로 오인되지 않도록 한다.
6. 공간 경계에 영향을 준 물건 변화(문 파괴 등)가 공간 사실과 모순된 채 남지 않게 연동 요구를 만들되, 공간 구조의 소유권은 장소 영역과 협의한다.
7. 이미 정해진 고유 물건의 존재·정체성·핵심 기능·배치를 '보완'이라는 명분으로 다시 창작하지 않는다.

**[제안]** 서로 관련된 현재 사실들을 갱신할 때는 일부만 반영되어 모순이 남지 않도록 **일관된 결과 묶음으로 반영될 필요**가 있다. 원자적 데이터베이스 트랜잭션이라는 특정 구현을 지금 확정하는 것은 아님.

## 11.3 변화 기록과 현재 사실은 구별

**[제안]** 현재 상태로부터 알 수 없는 중요한 과거(어떤 고유 물건이 어떻게 수리되었는가, 어디서 얻었는가, 누가 임의로 바꿨는가 등)를 필요 시 재구성할 수 있는 관련 이력·출처를 남길 여지가 있어야 한다. 다만 **이력을 물건 영역에 모두 저장하는 구조를 결정하지 않는다.** 시간 영역은 역사를 소유하지 않는다는 선행 원칙을 존중하며 정보/사건 영역과 역할 협의.

# 12. LLM과 구조적 정보의 역할 — 판단을 고정하지 않는 제안

## 12.1 정밀도는 ‘정보의 근거’와 함께 결정

**[사용자 초기 구상]** 완전한 고해상도 시뮬레이션은 불가능하지만 LLM에게 충분한 사실을 전달하여 개연성을 확보하고, 지시되지 않은 사실이나 중요한 새 사실의 자의적 창작을 줄여야 함.

**[제안]** 하나의 물건 판단에서 다음을 분리해 생각할 수 있도록 한다.

- **명시된 사실:** 실제 종류, 현재 물량, 정본 호환성, 착용 상태, 설정상 효과 등. 변경은 해당 사실을 갱신하는 적법한 행동의 결과여야 함.
- **안전한 계산/검증:** 동차원 단위 변환, 명시된 수량 차감, 허용 관계/상태 검증 등. 필요한 정보가 충분할 때만 정확성을 요구.
- **맥락적 해석:** 파손의 개연성, 예상 밖 도구 사용, 정성적 상태 변화, 일반 사물의 존재 추정 등. 기존 세계 사실과 중요도를 제약으로 제공.
- **미결정의 인정:** 근거가 없는 경우 결과를 과도하게 구체화하는 대신 정성적 표현, 보류, GM 판단 또는 제한된 보완을 선택할 수 있음.

**[중요]** 이 네 범주는 **개별 처리를 코드와 LLM 중 누가 담당할지를 확정한 분류가 아니다.** 원본/세션 사실과 해석의 정확도 및 출처를 구별하기 위한 관점이다.

## 12.2 사실 보완은 범위가 있는 권한

**[제안]** 원본에 없는 상세 정보가 필요하다는 사실을 발견한 뒤에는 (a) 현재 정보로 판단 가능한가, (b) 기존 사실의 비중요 빈칸인가, (c) 중요한 정본/사건 진실을 새로 결정하게 되는가를 구별한다. (c)는 일반적인 자유 창작과 다른 승인·보호가 필요할 수 있다.

**[제안]** 새 사실을 확정한 경우 무엇을 어떤 근거로 정했는지 남겨 반복 질문 때 같은 사실을 사용할 수 있어야 한다. 다만 모든 자연어 추론을 영구히 개별 데이터화하는 것은 비용·불필요한 구속을 만들 수 있으므로 보존 기준은 미정.

# 13. 설계가 실제로 성립하는지 살펴보는 사례 실험

아래 예시는 **확정된 게임 규칙·세계관 사실이 아닌 테스트 장면**이다. 아이디어의 표현 가능성과 정보 손실 위험만 검증한다.

## E01. 물 1L, 빈 병, 나눠 담기, 오염

**초기 가정:** 병 A에 물 1000mL. 빈 병 B. A는 한 종류의 물로 표현되지만 일부 오염에 관한 정성 사실이 있을 수 있다.

1. A에서 B로 물 300mL를 옮긴다 → 원칙적으로 A 700mL, B 300mL. 용기 A/B 각각 계속 존재.
2. A의 물 700mL를 마신다 → A에 물 0mL, 병 A는 지속. 섭취에 따른 신체 영향은 다른 영역과 연계.
3. 서로 다른 오염 상태의 물을 합친다 → 합계 물량만 보존하고 혼합 위험을 지워버리면 안 된다. 오염의 의미가 충분하지 않으면 임의로 정확한 농도를 계산하지 않는다.
4. 구멍 난 병에 액체를 채우려고 한다 → 정격 용량만으로는 유효한 저장이 보장되지 않으며 실제 파손 상태/조건을 고려해야 한다.

**검증하는 원리:** 종류≠실물, 수량/내용물/용기 분리, 상태 및 혼합 정보의 지속, 계산 가능한 부분과 개연성 판단의 구별.

## E02. 같은 이름의 알약 12정과 보관 상태

**초기 가정:** 정상 8정, 습기 노출 4정. 같은 이름이지만 상태가 다르다.

1. 한 약통에 모두 넣는다 → 총 12정이지만 단일한 정상 상태로 통합하지 않는다.
2. 2정을 먹는다 → 어느 상태의 2정인지 근거가 없다면 임의로 정상/오염을 확정하지 않으며, 필요한 선정/판단 문제로 남김.
3. 약통을 버린다 → 약통과 내용물의 이동/소멸 관계를 구별.
4. 복용 효과·위해 가능성은 신체/건강 영역과 연계.

**검증하는 원리:** 수량 묶음과 실제 내용물의 상태 차이, 내용물 선정 근거, 효과의 외부 영역 의존.

## E03. 속옷·셔츠·외투·방독면

**초기 가정:** 인물이 가방에 외투를 보관하고 셔츠를 착용, 양손으로 다른 도구를 들 수 있는 상황.

1. 외투를 가방에서 꺼내 입음 → 보관 위치·착용 관계 갱신, 셔츠와 겹침.
2. 외투가 젖음 → 외투의 상태 변화, 보온 효과가 어떻게 달라지는지는 물건 성질/환경/신체 정보와 함께 판단.
3. 방독면이 가방 안에만 있음 → 착용 효과 없음.
4. 방독면을 착용해도 필터 부재/손상이 확인됨 → 정상 기능 발현을 단순 착용으로 확정할 수 없음.

**검증하는 원리:** 소유/보유/손 점유/착용/작동의 구별, 신체 부위 피복 및 겹침, 상태에 따른 기능.

## E04. 특정 출입카드·잠긴 문·사전 배치

**초기 가정:** 문 X는 출입카드 K에만 반응하도록 중요한 저작 사실이 존재한다고 가정.

1. 카드 L은 종류가 '카드키'이지만 K와 다른 실물이다 → 단순히 종류/이름으로 X 해제 불가.
2. K는 특정 관리실에 배치된 것으로 이미 확정 → LLM이 즉흥적으로 같은 권한의 카드를 근처 책상에서 만드는 것은 금지되어야 할 수 있다.
3. K 소유자가 K의 기능을 모를 수 있음 → 실제 호환 관계와 인물 지식은 별개.
4. 문을 부숨 → 잠금장치의 작동과 공간 경계 구조의 변화는 다른 영역과 함께 정합성 유지 필요.

**검증하는 원리:** 저작 고유 사실의 보호, 호환성 vs 지식, 의도 배치 vs 즉흥 생성, 물건/공간 경계.

## E05. 묘사에 등장한 유리컵

**초기 가정:** LLM이 '책상 위에 유리컵 하나가 놓여 있다'고 실제 장면 서술을 했다.

1. 플레이어가 컵을 집어 든다 → 이전 묘사의 컵이 실제 조작 대상으로 연결되어야 함.
2. 컵을 주머니에 넣으려고 함 → 물리적 크기·형태가 중요한 경우만 추가 정보 확인/제약 판단.
3. 컵을 깨트림 → 컵의 손상·파편/잔해와 장소의 현재 상태 변화. 정확한 파편 수를 무단 생성하지 않음.
4. 이후 다른 플레이어가 같은 컵을 찾음 → 과거 책상 묘사만으로 현재 책상 위에 컵이 있다고 다시 만들어서는 안 됨.

**검증하는 원리:** 묘사-세계 사실 연결, 필요 시 세부화, 지속 정보·상황 일관성.

## E06. 문손잡이 제거와 가구의 내부 구조

**초기 가정:** 문은 원래 손잡이가 있는 정상적인 문이었고, 별도의 개체로서 손잡이는 생성되지 않았다.

1. 손잡이의 존재를 문 설명/부분으로 간략히 표현하고 있을 수 있다.
2. 플레이어가 손잡이를 떼어냄 → 손잡이는 별도 추적 가능한 물건으로 바뀔 수 있다.
3. 문은 손잡이가 없는 상태가 되고, 관련 기능이 달라질 수 있다.
4. 문을 통한 이동 경로의 접근성이 바뀔 경우 공간 영역의 사실과 정합성이 필요.

**검증하는 원리:** 가변 상세도, 부분-실체 전환, 부분 파손이 전체 기능/공간 구조에 주는 영향.

# 15. 실제 설계에서 갈리는 미결정 선택지

단순히 더 좋은 안/열화판을 배치하는 것이 아니라 **출발 철학이 다른 실질 대안**을 보존한다. 어느 것도 채택되지 않았다.

## Q01. 흔한 물건을 언제 독립 객체로 만들 것인가?

- **방식 A — 초기 실체화 중심:** 장소/보관함의 일반 사물도 시나리오 시작이나 장소 생성 시 대부분 세계 실물로 확정. 검색과 반복 일관성이 좋지만 사전 작성·저장 비용이 높다.
- **방식 B — 서술·상호작용 시 실체화 중심:** 처음에는 장소의 일반 사물 후보/개요를 가볍게 관리, 묘사/상호작용을 통해 상세 실물로 확정. 풍부한 세계를 적은 데이터로 표현하지만 이전 묘사와 사실 승격의 경계를 정해야 한다.
- **방식 C — 고유/중요 실물 선확정, 일반 실물 지연:** 구속력이 높은 물건은 먼저 정하고 흔한 배경은 필요 시 확정. 절충 방식이며 '중요'의 기준과 사실 보호 정책이 필요하다.

## Q02. 특별한 효과를 어느 정도 정형화할 것인가?

- **방식 A — 효과 계약/조건 중심:** 직접 판정에 영향을 주는 핵심 효과를 정형화해 판정 정확성 확보. 효과 추가·유지 비용 증가.
- **방식 B — 성질·기능 서술 중심:** 물건의 작동 원리/상태/서사를 충분히 기술하고 구체 결과는 맥락 판단. 비정형 활용에 유리하지만 정합성 검증이 어렵다.
- **방식 C — 정확성 우선의 선택적 정형화:** 수량·확정 호환성·저작 판정 효과는 명시, 맥락 물리/활용은 정성 기술. 두 방식 간 일관된 경계 규칙 필요.

## Q03. 물질·혼합을 얼마나 상세하게 다룰 것인가?

- **방식 A — 분리된 성분과 조성:** 용기 내용물의 종류·양·성분·중요 오염 정보 보존. 분할·혼합 추적에 유리하지만 표현 비용과 적용 가능한 계산이 제한된다.
- **방식 B — 단일 내용물과 상태:** 물 500mL + 현재 오염 상태 등으로 간결. 일반 소비에 유리하지만 이질 혼합물의 상태를 손실하기 쉽다.
- **방식 C — 필요 시 조성 상세화:** 단순 상태로 시작, 이질 혼합/정밀 보존이 필요한 물건만 분해해 표현. 세부화 시 과거 정보가 부족하면 어떤 값을 확정할지 결정하는 정책 필요.

## Q04. 부품과 결합을 어떻게 표현할 것인가?

- **방식 A — 부분 객체 중심:** 주요 부품은 초기부터 독립 관계로 연결. 분해·수리 추적이 쉽지만 데이터가 크다.
- **방식 B — 전체 객체 중심:** 부분은 상위 물건의 특성/상태로만 관리하다 필요 시 독립화. 일반 물건은 간결하나 나중에 동일성/관계 재구성이 필요하다.
- **방식 C — 혼성:** 특별한 부품만 처음부터 실체화하고 나머지는 서술/내재적 구성 정보. 초기 저작 시 중요도·세부화 판단이 필요하다.

## Q05. 상태를 어떻게 허용하고 효과에 연결할 것인가?

- **방식 A — 선언적 상태 목록 + 물건 유형의 허용 규칙:** 검증이 명확하며 모델 안정성에 유리. 새로운 상태와 비정형 상황을 포괄하기 어렵다.
- **방식 B — 기저 성질에 따른 동적 허용성 판단:** 상태의 의미를 재료/형태/작동 원리에서 유도. 다양한 상황에 강하지만 일관된 판단 근거가 중요하다.
- **방식 C — 핵심 상태는 명시, 주변 상태는 맥락 판단:** 높은 영향의 상태를 규칙화하면서 나머지는 유연하게 해석. 경계와 충돌 조정 정책이 필요하다.

**[미정 공통]** 확정 상태의 기록/제약이 없는 경우의 생성 권한, 외부 영역에 대한 효과 전달 방식, 일반 물건의 기본값에 대한 기대, 이름 변경/동의어, 사용자 정의 스키마 확장, 원본 변경 정책 등.

# 16. 시안의 위험·반례·검증 항목

## 16.1 이 시안의 주요 위험 (GPT의 자기 비판)

1. **추상화 비용:** 공통 관계/상태/기능 계층을 제안했지만 실제로 너무 많은 메타 구조를 구축하면 고유 물건 하나를 저작하는 비용이 커질 수 있다. 기능 보존 비용으로 정당화해야 함.
2. **미정 사실의 오용:** 존재를 늦게 결정하는 구조는 LLM이 중요한 사실을 만들기 쉽게 할 위험. '중요한 세계관 요소'와 '평범한 빈칸'을 정의할 책임이 남음.
3. **묘사의 확정력:** 모든 묘사 단어를 세계 실체로 만들면 중복·환각이 늘고, 아무것도 등록하지 않으면 플레이어가 묘사된 사물에 접근하지 못한다. 발화 전/후 사실 등록의 균형이 필요.
4. **단위와 복합성:** 물 g/mL와 알약 정을 모두 지원하더라도 조성·부패·오염에 실제 근거가 없다면 결과가 거짓 정밀도로 바뀐다.
5. **상태 적용성의 과적합:** '젖음 허용' 목록만으로 모든 재질의 침수 영향이 같다고 보지 말 것. 특히 멀티-상태 효과의 상호작용을 간단한 합산 규칙으로 단정하기 어렵다.
6. **다른 영역 선점:** 착용/몸/손, 장소/문/벽, 환경 변질, 정보의 인지와 실제 호환성, 사건의 핵심 진실은 물건 단독 구조로 확정할 수 없다.
7. **원본·세션 대응의 오해:** 저작 원본에는 '종류'뿐 아니라 특정 개별 유물/열쇠의 초기 사실이 존재할 수 있고, 세션에서 추가된 사실이 다시 전체 세계의 기본 정의로 승격되어서는 안 될 수도 있다.
8. **부분의 동일성:** 깨트린 컵, 재조립한 기계, 반으로 나눈 알약 등의 '동일한 실물' 개념은 경계 사례가 많다. 무리하게 보편적 유일 규칙을 만들지 말 것.

## 16.2 향후 시안을 검증할 질문

- 타이레놀 10정이 여러 보관 장소로 나뉘고 일부만 변질되었을 때 개수·장소·상태가 보존되는가?
- 물 1000mL를 마신 뒤 용기가 남고, 다른 종류의 물과 섞을 때 실제로 모르는 오염 정보가 수치로 지어지지 않는가?
- 젖은 옷·찢어진 외투·여러 겹 의복의 착용이 보유/착용/정상 작동 조건에 따라 달라지는가?
- 원본이 정한 출입카드-문 대응은 LLM 생성이나 장소 개연성에 의해 바뀌지 않는가?
- 묘사에 등장한 사물을 플레이어가 조작할 때 새로운 배경 설명이 앞서 확정한 사실을 뒤엎지 않는가?
- 문손잡이를 떼거나 문을 파괴할 때 물건과 공간의 상태가 서로 모순되지 않는가?
- 물건의 속성이 부족할 때 과도한 물리 계산 대신 정성적 판단이나 미정 유지가 가능한가?
- 추가된 일반 사물은 일관되게 지속되고, 세션 바깥 원본 자료까지 무단 변경하지 않는가?
