# 제1부. 결정의 권한·출처·상태

## 1.1 상태 표기의 정의

| 표기 | 의미 | 문서에서 허용되는 사용 |
|---|---|---|
| **[U-명시]** | 사용자가 분명히 직접 말한 요구·방침·지시 | 그 발언 자체를 정확히 기록한다. 맥락과 함께 읽는다. |
| **[U-구상]** | 사용자가 제시한 아직 검토·수정·폐기 가능한 아이디어 | 현재 탐색의 기준이되 ‘최종 승인 설계’로 격상하지 않는다. |
| **[U-제한]** | 사용자가 현재 배제 또는 경계하라고 명시한 방향 | 사용자가 말한 **정확한 범위**에만 적용한다. |
| **[GPT-제안]** | 이전 또는 현재 GPT가 제시한 후보·권고 | 채택되지 않은 설계 의견으로만 기록한다. |
| **[GPT-재평가]** | GPT가 자신이 제안한 내용을 유지·수정·철회·보류한 이력 | 사용자 승인을 대체하지 않는다. |
| **[조사]** | 외부 문헌·엔진·TRPG 사례에서 확인하거나 해석한 내용 | INDAIM에 자동으로 적용하지 않는다. |
| **[미결]** | 아직 권한 있는 결론이 없는 쟁점 | 선택·기본값·업무 절차를 임의로 확정하지 않는다. |
| **[기록 오류]** | 이전 통합본의 압축·권한 혼입·부정확한 해석 | 정정 이유와 원문을 함께 제시한다. |

‘사용자가 반대하지 않았다’는 사유만으로 `[GPT-제안]`을 `[U-명시]`로 바꾸지 않는다. `[U-구상]`은 사용자의 직접 발언인 동시에 변경 가능한 가설일 수 있다. 사용자의 추가 설명이 이전의 모호성을 해소한 부분은 더 나중의 직접 발언을 우선하여 읽되, 이전 발언은 이력상 삭제하지 않는다.

## 1.2 작업의 상위 목표 및 영역 경계

- [U-명시] INDAIM은 **인간 GM의 감독 아래 AI가 세계를 운영하고 서사를 진행하는 Discord 기반 TRPG 보조 GM 시스템**이다. 플레이어의 자유로운 행동에 세계가 일관되고 개연성 있게 반응하여 높은 서사 품질과 몰입감을 제공하는 것이 목적이다.
- [U-명시] 현행 INDAIM의 코드 구조를 계승하는 리팩터링이 아니라 **전면 재설계**다. 기존 구현·실패 사례는 참고 자료일 뿐 강제된 설계가 아니다.
- [U-명시] 14개 정보 영역은 설계 탐색을 위한 분류이며 반드시 14개 모듈로 구현하라는 뜻이 아니다. 본 설계실은 **02. 장소 및 공간**, 현재는 ‘세계를 그리는 방식’을 우선 다룬다.
- [U-명시] 장소 및 공간은 시간 다음 두 번째 기초 설계 영역이다. 이는 다른 영역을 거의 참조하지 않는다는 뜻이 아니라 **자기 구조가 다른 영역의 결정에 비교적 덜 종속된다**는 분류다.
- [U-명시] `시간`의 P01~P08 승인 사실을 존중하지만, 원문 없이 구체적인 시점 표현·해상도·이력 정책 등을 작성하지 않는다.
- [U-명시] **전반에서 부분으로**, 개별 예외 기능의 누적보다는 근본적인 표현 원리를 탐구하며, 다른 영역의 책임을 임의로 가져오지 않는다.
- [U-명시] 사용자의 지시와 승인 없이 공식 설계를 확정하거나 기존 결정을 변경하지 않는다.

### 1.4 명시적으로 **결정된 것처럼 쓰면 안 되는 것**

다음은 사용자 의도에 부합할 가능성은 있지만 **본 설계실의 최종 승인 결론이 아니다**.

- 특정 DB·클래스·객체 모델, 단일 부모를 강제하는 구체적 참조 스키마, 좌표계나 그래프 데이터베이스 채택.
- 계승 가능한 속성의 **목록**, 속성의 ‘미설정/부재/불명’ 표현과 계승 시 우선순위 전반.
- 공간 경계·문·벽을 반드시 별도 **독립 객체**로 만들어야 한다는 규칙.
- `인접·접촉·교차·중첩·상대 위치` 관계 전체를 의무 저작하는 규칙.
- `연속 도로 전체`를 별도의 논리적 장소/개체로 반드시 관리하는 규칙.
- 장소 내부 위치를 항상 기준점/좌표로 표현해야 한다는 규칙.
- 환경의 광학·음향·열역학·유체 데이터를 일괄 수치화한다는 규칙 및 그 반대의 **모든 수치 계산 금지**.
- 구조 변화 시 모든 물리 효과를 선제적·자동적·영속적으로 갱신한다는 규칙.
- 미저작 부분은 언제나 GM에게 보고하거나 **GM의 별도 승인을 받아야만** 진행할 수 있다는 구체적인 제어 절차.
- 장소 조각은 단순 묘사문도 포함한다는 확대 해석, 정형 결합 포트·자동 접점 생성, 결합 결과의 원형 갱신/전파 정책.
- 세계 데이터와 세션 세계의 관계가 `템플릿→사본`, `사전 저작→세션 실재화`, `불변 원형→가변 인스턴스`라는 특정 모델이라는 단정.
- 이벤트 소싱/스냅샷/시뮬레이션 활성화 거리/계산 캐시 등의 도입.
- **영속화할 사실의 판별·승격 절차**와 LLM 출력이 어느 때 세계의 사실을 추가할 수 있는지에 대한 정책.
- 시간 영역 정책 P01~P08의 구체 내용, 다른 영역의 소유권·판정 방식.

# 제2부. 사용자의 구상을 보존한 통합 공간 개념

이 부는 **사용자 구상의 세부 사항을 덜어내지 않고**, 해당 구상이 어느 문제를 다루는지 배열한 것이다. GPT 보완은 명시적으로 분리한다.

## 2.1 장소 조직: 분류 헤드 / 상위 장소 / 하위 장소

**[U-구상 및 C03 용어 해명]**

```text
[분류 헤드 α]                  ← 장소가 아님. 물리적 지리적 범위 아님.
  ├─ [상위 장소 A]              ← 물리적 장소 계층 A의 뿌리, 장소임.
  │    ├─ [하위 장소 A-1]       ← 직속 부모인 A 내부에 물리적으로 위치.
  │    │    └─ [더 하위 장소]   ← 직속 부모인 A-1 내부에 위치.
  │    └─ [하위 장소 A-2]
  └─ [상위 장소 B]              ← 독립된 다른 물리적 포함 계층의 뿌리.

[분류 헤드 β]                  ← 다른 분류 헤드 역시 장소가 아님.
  ├─ [상위 장소 C]
  └─ [상위 장소 D]
```

- 이 그림은 **포함/분류 관계를 읽기 위한 개념 예시**이며 확정 데이터 형식이 아니다.
- 최상위 항목이라는 용어는 물리적 크기·넓이·대륙/국가 수준을 뜻하지 않는다. 원문이 '구역 혹은 카테고리'라고 했을 때 최상위 항목이 실제 물리적 구역일 수도 있다는 해석은 **뒤이은 명시 해명(C03)으로 배제**됐다.
- `상위 항목`이 '단 하나'라는 뜻은 **각 포함 계층의 최상단에 놓이는 하나의 장소**이지, 하나의 분류 헤드에 뿌리 장소를 하나만 둘 수 있다는 뜻이 아니다.
- 부모와 자식의 계층은 물리적 포함을 의미한다. **단지 같은 분류 헤드에 들어 있다는 이유로 두 상위 장소가 서로 인접·연결·물리적으로 포함되는 것은 아니다.**
- [U-구상] 건물 내부의 복도·객실, 객실 내부 방·화장실은 포함 계층의 예시다. 교도소에서 컨테이너 원룸까지 장소의 수·규모·분할 세밀도가 다를 수 있다.
- [U-구상] 건물 사이의 구름다리는 어느 한 건물에 포함된 하위 장소로 끼워 넣지 않고 **건물 상위 항목 바깥의 공간**으로 다룬다. 이 발언만으로 **구름다리를 반드시 독립 뿌리 장소로 만든다거나 특정 분류 헤드에 배치한다**는 설계가 승인된 것은 아니다.
- [미결] 같은 물리적 위치의 복수 공간 개념(예: 수직 계단실, 다른 공간을 가로지르는 시설)의 교차/중첩, 포함 계층의 세부 허용 관계, 일부가 외부까지 뻗는 구조물을 어떻게 처리할지는 미결이다.

## 2.2 계층상의 속성 계승: **선정된 속성만**

**[U-명시]** 사용자는 질문에 재차 답하면서 **기존에 선정해 둔 항목에 한해서만** 속성을 계승한다고 명확히 밝혔다. 이를 다시 일반적인 '모든 속성 계승'을 전제로 재질문해서는 안 된다.

```text
계승 대상이라고 미리 지정된 속성 P의 값 조회:
  1) 해당 장소에 P의 값이 있으면 그 값을 사용.
  2) 없다면 부모 → 조부모 → ... → 분류 헤드 방향으로 탐색.
  3) 가장 먼저 P의 값을 가지고 있는 조상 항목의 값을 사용.
  4) 해당 속성이 계승 대상으로 지정되지 않았다면 위 탐색 규칙을 적용하지 않음.
```

이 의사코드는 발언을 설명하기 위한 것으로, 실제 저장 방식·NULL 의미·우선순위 상세 스키마를 확정하지 않는다.

- 최상위 분류 헤드는 하위 장소에 공통 속성을 제공하기 위한 편의 장치다. 이는 **인접한 구역들이 비슷한 성격을 가지는 경향**이 창작물에서는 더 두드러진다는 사용자의 근거에 따른다.
- 직접 명시된 하위 속성은 상위 값보다 우선한다. *어떤 속성을 계승할지*는 아직 목록이 전달되지 않았다.
- [미결] 직접 값의 ‘없음’과 값 자체의 부재, 불명, 부정(예: 없음)을 어떻게 표현할지는 후속 정보 표현 문제다. **이 쟁점을 근거로 이미 정해진 ‘선정 속성만 계승’ 원칙 자체를 다시 선택지로 만들지 않는다.**
- [GPT-제안] 일부 속성은 장기 저작 편의를 위한 기본값인지 실제 물리 상태인지 구분하는 것이 유익할 수 있으나, 아직 이를 **별도의 데이터 계층**으로 도입하자는 결정은 없다.

## 2.3 누락 없는 공간 표현의 **목표와 그 미완의 방법**

**[U-구상, 표현 그대로]** “복도나 통로, 야외의 길이나 산, 들 등 일반적으로 장소로 표현하지 않는 항목도 표현해 **빈 장소가 없도록 하는 것이 목표**”다.

- 길·도로·복도·통로·공터·산·들 등은 장면 전환의 빈틈을 채우는 단순 묘사 장치가 아니라 **공간 표현의 실제 대상**이 될 수 있다.
- 건물/구역에서 바깥으로 나간 뒤 **어느 길 위나 어떤 외부 구역에 서 있게 되는지**가 표현되어야 한다.
- 길은 멀리 뻗어 있고 많은 공간과 연결된다. **지역·구역·연결된 장소 등에 따라 길을 여러 구간으로 끊어 관리하는 방안**을 사용자가 제시했다. 이는 정확한 분할 기준·길이·최소 단위를 정한 것은 아니다.
- [U-제한, 이후 추가] 미저작 공간의 **임의 ‘창작’은 배제**됐다. [U-구상] 대신 **미리 만든 장소 조각을 가져다 붙이는 기능**은 검토 가능하다.
- **핵심 미해결 긴장:** ‘공간에 빈틈이 없도록’ 하고, 동시에 ‘저작되지 않은 공간을 창작하지 않는다’는 요구를 **어떤 원리로 양립시킬지 아직 답이 없다.** 장소 조각을 쓰자는 아이디어가 이를 자동 해결했다고 기록해서는 안 된다. 외부 구역의 포괄적 저작 범위, 장소 조각의 허용 변형, 미저작 공백을 만났을 때 처리 등은 미결이다.
- **[기록 오류 정정]** v0.1은 이를 ‘불연속적인 장면 목록에만 의존하지 않고 설명하는 목표’로 재해석했다. 그 문장은 GPT의 가능한 해석일 뿐 **원래의 ‘빈 장소가 없도록’이라는 공간 표현 목표를 대체할 수 없다.**

## 2.4 독립적인 이동·연결과 다양한 통과 방식

**[U-명시]** 이동 가능성은 **포함·계층 구조와 관계없이** 표현 가능해야 한다. 분류/포함/연결은 같은 뜻이 아니다.

- [U-구상] 문, 창문, 개구멍, 복도·길 같은 기존 통행로뿐 아니라 **벽을 부수어 이동**하는 행동도 있다. 어떤 장소 간에는 여러 이동 방법이 있을 수 있다.
- [U-구상] 통로는 **막혀 있거나, 숨겨져 있거나, 잠겨 있을 수 있다.** 이 상태는 ‘공간 간 연결이 사라졌다’는 뜻과 반드시 동일하지 않다.
- [U-명시] 열쇠의 정보·사용은 물건 영역과 접할 수 있고, 숨긴 통로의 발견은 감각·정보 영역과 접할 수 있다.
- [U-구상] 구조물이 파괴되어 **새로 생긴 구멍을 저작할 수 있어야 한다.** 여기서 세계에 실제 생겨난 물리적 변화는 **사전에 없는 새 건물·방을 AI가 창작하는 것과 구별**해야 한다.
- [GPT-제안] `장소들의 관계 / 경로 후보의 존재 / 특정 주체의 통과 가능성 / 실제 이동 결과`는 실질적으로 서로 다른 질문이다. 그러나 이 분리를 곧바로 **네 개 테이블이나 네 단계 실행 파이프라인**으로 확정하지 않는다.
- [GPT-제안] 같은 출입구라도 사람·쥐·드론·운반 물품의 통과 가능성은 달라질 수 있고, LLM이 정성적 사실과 맥락을 보고 판단할 수도 있으며 실제로 수치 비교가 중요한 장면만 수치 계산을 사용할 수도 있다.
- [미결] 미등록 경로를 어떻게 해석할지, 새 구멍의 상태를 어느 영역에 어떻게 기록할지, 경로의 시작·종점·중간 구간·방향성 등의 표현 형식은 아직 결정되지 않았다.

# 제3부. GPT 통합 설계 **후보** — 사용자 구상을 대체하지 않는 보완책

**이 부 전체의 지위: [GPT-제안], 사용자 미승인.** 유용성이나 개연성을 근거로 확정 사양으로 읽으면 안 된다. 초기 구상의 **각 기능을 어떻게 일반적인 구조로 구현할 수 있을지** 비교하기 위한 후보군이다.

## 3.1 공간 관계의 표현 확장 — 선택적이고 정성적일 수 있음

- **문제:** 물리적 포함 계층 및 통행 연결만으로는 `A방과 B방은 벽을 사이에 두고 있다`, `복도 끝에서 북쪽으로 샛길이 꺾인다`, `서로 다른 길 구간이 같은 도로의 연속이다`라는 사실을 설명하기 어려울 수 있다.
- **후보:** 포함과 별개로 **인접·접촉·상대 위치·연속성·경계 반대편·필요시 교차/중첩** 등을 정성적 문장이나 별도 관계로 나타내는 능력. 관계를 좌표 계산으로만 강제하지 않는다.
- **상당한 실례:** IFC(기본 포함 + 비계층 공간 구역), IndoorGML(공간 분할 + 연결), GeoSPARQL(정성적 위상 관계), 로봇 장면 그래프.
- **반대 이유/비용:** 모든 관계를 사전 등록하면 저작량이 많고 중복·갱신 불일치가 생긴다. 자유로운 자연어 서술만 있으면 명시적 질의와 정합성 검사가 어렵다.
- **미결:** 최소로 구조화해야 할 관계는 무엇인가, 어떤 관계를 자연어로 남길 것인가, 같은 공간을 교차해 지나는 구조를 어떻게 표현할 것인가.

## 3.2 공간의 경계·개구부 — 물리 계산 엔진이 아니라 판단 근거

- **문제:** 통행 경로가 **없어도** 두 방 사이에 벽이 실재할 수 있다. 파괴할 벽이 무엇이며 반대편이 어디인지는 이동 그래프에 없는 별도 사실일 수 있다.
- **후보:** `A와 B 사이에 벽`, `창문은 길가를 향함`, `문은 잠김`, `벽에 구멍이 남음` 등의 **주요 물리적 상태와 공간 관계**를 표현. 필요한 경우 재질·형태·크기·파손 정도를 **문장 또는 수치로 선택적** 보강.
- **직접 저작의 예시:** “두 객실 사이에는 얇은 합판 벽이 있다.” 이 사실은 소리·파괴·시야·통과를 해석하는 맥락이 될 수 있지만 **합판의 음향 투과율 필드를 추가하라는 뜻이 아니다.**
- **보류:** 벽·문을 물건 영역이 독립된 개체로 관리하는지, 장소 사실의 일부로 관리하는지, 필요할 때 승격할 수 있는지. 같은 벽을 두 영역에 서로 다른 정본으로 쓰지 않도록 하는 방법.
- **폐기된 강경안:** 모든 경계의 재료·두께·광학·열·음향 수치를 명시하고 각 현상을 범용 물리 계산으로 처리하자는 주장.

## 3.3 장소 내부의 위치·배치·길 — 위치와 장소가 완전히 같은 뜻은 아님

- **문제:** 대형 공장·창고·광장·숲에서 ‘같은 장소 안에 있다’는 사실만으로 거리·장애물·접근/시야 차이를 처리하기 어렵다.
- **표현 후보(위계가 아닌 선택지):** (a) 장소명 수준, (b) “정문 왼쪽/북쪽 창가/서쪽 선반 뒤”처럼 정성적 상대 위치, (c) 반복 쓰는 관찰·이동 기준점, (d) 정말 중요한 곳의 거리·좌표·형상.
- **장점:** 좌표계 없는 텍스트 저작을 살리면서도 플레이어가 방 안의 특정 위치에 접근·숨기·우회하는 행동을 설명할 수 있다.
- **주의:** 서로 다른 표현 세밀도를 병용할 때 같은 장소·위치의 동일성을 어떻게 지킬지 해결이 필요하다. 모든 공간에 기준점·좌표를 의무화하지 않는다.
- **독립적으로 추적해야 할 사용자 요구:** 진입 순간 보이는 것과 특정 위치에서 보이는 것, 장소 안 이동 경로의 존재.

## 3.4 도로·복도·산 등 연속 공간의 구획과 물리적 연속성

- **문제:** 하나의 길을 여러 구간으로 나누는 것은 사용자 구상의 핵심이다. 반면 구간 나눔이 막힌 벽처럼 처리되면 공간의 개연성이 깨진다.
- **후보:** 어떤 구간이 원래 하나의 연속 도로·산길·하천·긴 복도에 속하며 서로 어디서 이어지는지 표현하는 수단. **분할 경계와 실제 장애물**을 구별한다.
- **미결:** ‘한 도로 전체’를 독립 장소/대상으로 저작할지, 구간들 사이의 관계로만 나타낼지. 언제 더 잘게 나눌지. 연속 관계가 가시성·소리·바람 등 모든 현상에 자동 적용되는지는 별도 문제다.
- **주의:** ‘연속 공간 동일성’ 자체는 **기존 GPT가 추가한 보완 기능**이지 사용자가 특정 동일성 자료구조를 승인한 것은 아니다.

## 3.5 이동의 구조적 근거와 행동 가능성·실행 결과

- **사용자 기반:** 이동은 포함 계층과 독립적이고, 문/창문/개구멍/벽 파괴 등 수단이 다양하며 통로 상태는 막힘/은폐/잠금일 수 있다.
- **GPT 후보 구분:** (a) 두 공간의 물리적 관계, (b) 통과할 경로/개구부의 존재, (c) 특정 주체가 현재 조건에서 해당 방법으로 통과 가능함, (d) 실제로 그 행동을 했고 어디로 이동했음.
- **참고 사례:** Evennia의 출구 객체(일방향 이동도 가능), Godot의 NavigationLink(경로 선택과 실제 이동 분리), TADS의 감각/이동 분리.
- **중요:** ‘닫힌 문’·‘잠긴 문’은 별개의 상태일 수 있다. 하나의 `connected=true`가 물리적 인접·전파·행위자별 통과·실제 이동을 모두 대변하도록 강제하지 않는다.
- **계산 책임:** 사람의 크기·장비·열쇠·기술 등을 반영할 수 있지만, 이를 모두 고정된 수식/물리 엔진으로 판정해야 한다는 결론은 없다. LLM의 맥락 판단이 유용할 수 있다.
- **미결:** 통과 방식/방향/조건의 최소 표현, 새로 만들어진 경로가 기존 관계와 어떻게 결부되는지.

## 3.6 구조 변화 — **지속적인 사실**과 **필요시 판단** 분리 후보

- **사용자 기반:** 벽을 부수면 **새 구멍을 저작**할 수 있어야 한다.
- **기존 GPT 주장:** 파괴 순간 이동/시야/빛/소리/공기/열 네트워크 모두를 자동 변경하자는 방향.
- **GPT 재평가:** **이 주장을 철회**했다. 물리 매질의 불완전한 모델이 오히려 현실감·개연성을 해칠 수 있다는 사용자 경고를 반영한다.
- **현재 GPT 후보:** 우선 ‘어느 벽의 어디에 어느 정도의 구멍이 생겼다’는 **핵심 물리적 사실**을 기록하고, 나중에 실제로 문제가 되는 이동·시야·소리·연기 등의 판단은 이 변화와 상황을 근거로 **필요시** 수행한다. 정교한 계산이 적절한 상황에서는 계산을 사용할 수 있다.
- **절대 혼동 금지:** (a) 벽에 생긴 구멍이라는 **세계 구조의 지속 변경**, (b) 그 구멍을 통해 무엇이 보일지에 대한 **맥락적 판단**, (c) 플레이어가 실제로 무엇을 보았는지에 대한 **감각/정보 사실**, (d) 플레이어에게 전달된 **묘사**는 동일하지 않다.
- **승인 미결:** 언제 어떤 LLM 판단을 세계의 지속 상태로 반영할지, 누가 승인할지, 변경 기록·시간·원자성 문제는 여기서 정하지 않는다.

## 3.7 빛·소리·온도·공기 — 구조정보를 과도한 수치 모델로 만들지 않는 후보

- **사용자의 경고 원문 요지:** “소리나 빛의 투과 같은 세부 물리정보를 시스템으로 정하고 프롬프트로 전달하면 과적합 내지는 시스템의 한계에 의한 개연성 붕괴”가 생길 수 있고 “LLM이 묘사 수준에서 일부 직관을 발휘”할 수 있다.
- **GPT의 수정 의견:** 실내외의 상대 배치, 창문의 존재, 밀폐/개방/재질 같은 **서술적 물리 정보**만으로도 LLM이 ‘빛이 비칠 수 있음’, ‘문 너머의 소리가 웅웅거릴 수 있음’ 등을 개연성 있게 다룰 수 있다.
- **조사상 반례:** Radiance는 형상/광원/재료를 사용하고, EnergyPlus의 Space·Zone·Enclosure와 NIST CONTAM의 구역/흐름, Steam Audio/Wwise의 음향 구역은 **현상별 계산 구획이 장소 계층과 다를 수 있다**는 점을 보여준다.
- **중요한 유보:** 조사상 존재하는 계산 구조가 곧 INDAIM에 필요한 것은 아니다. 사용자도 **모든 시스템 계산을 일률 금지하지 않았음**. 필요성이 크고 정확도·비용을 감당할 만한 경우에 한해 명시적 계산을 검토할 수 있다.
- **GPT가 철회한 것:** 모든 벽·문에 소리/빛/열/공기 투과율을 사전에 설정하고 모두 갱신하는 **보편적 의무**. 철회는 **현상을 무시한다**거나 **환경 영역을 설계하지 않는다**는 뜻이 아니다.
- **[미결]** 환경 영역이 물리적 구조로부터 어떤 신호와 결과를 어떻게 계산·판단할지는 그 영역과 함께 정한다. 별도의 열 구역/음향 구역을 일단 필수 구성 요소로 삼지 않는다.

## 3.8 감각·가시성·환경과 실제 세션 묘사의 관계

- [U-구상] 장소의 **외관·내관**, 위치별 **보이는 것**, **진입하면 보이는 것**, 내부·외부의 **존재물**, **분위기·공기·환경** 등 정보 제공 요구는 유지한다.
- [GPT-제안] 장소에서 알려진 물리적 배치·차폐·광원 관련 사실을 제공하고, 감각 영역이 주체의 감지/식별과 연계하며, 정보 영역이 해당 주체의 지식/오해 등을 다루도록 하는 **책임 분리 후보**가 있다.
- TADS의 시각·청각·후각·접촉 구분은 경로별 차이를 보여주지만 **그 규칙의 정확한 복제는 권고하지 않는다**.
- ‘주관적 분위기’, ‘실제 물리 환경’, ‘감각 신호’, ‘최종 자연어 묘사’를 모두 장소의 하나의 확정 상태로 합치지 않는다. 그러나 **그 값이 어디에 저장되고 언제 확정되는지는 미결**이다.
- [GPT-제안] 시야목록을 모든 위치·시점마다 정적으로 저작하기보다는 장소 구조·진입 위치·장애물·맥락을 전달받아 필요할 때 판단하는 방식을 연구할 가치가 있다.

## 3.9 사물·가구·구조물: **비관리 대상도 장소에는 있어야 한다**

- [U-구상] 장소 내외부의 무엇이 있는지에는 **물건 영역에서 독립 관리되지 않는 물체, 배경 사물, 가구**까지 포함된다. 이를 ‘상호작용하는 건 물건 영역이 맡는다’고 줄여 쓰지 않는다.
- [GPT-제안] 문·벽·창문·가구가 독립 물건 개체일 수도 있고, 장소 사실/서술의 일부일 수도 있으며, 필요한 순간 세부 관리 대상으로 전환하는 방안을 검토할 수 있다. **하지만 이러한 전환/승격 절차는 아직 승인되지 않았다.**
- 물건 영역의 독립 개체 여부와 별개로, 그 사물이 특정 위치에 **존재하고 무엇을 가리는지, 어떤 동선에 놓이는지, 무엇과 맞닿는지** 등의 정보가 필요할 수 있다.
- [미결] 장소/물건/정보 영역 사이의 진실 소유권과 변경 권한. 이 미결정 문제는 사용자 요구 자체를 보류한다는 의미가 아니다.

## 3.10 기성 장소 조각: **창작과 재조합을 구별**

- [U-제한] 미저작 공간의 ‘창작’은 배제했다.
- [U-구상] 대신 **필요한 경우 여러 기성 장소 조각들을 만들어 두고 가져다 붙이는 기능**을 사용할 수 있다. 사용자가 예시로 든 것은 **시가지, 마을, 주택 내부, 기타 장소**다.
- [조사] Unity Prefab, Unreal Level Instancing의 원형/배치 사례, Dungeon Architect의 결합점/남는 접속부 처리 연구가 참고가 된다.
- [GPT-제안] 동일한 조각을 여러 곳에 배치해도 각 장소의 현재 상태가 혼동되지 않도록 `저작 원형`과 `실제 세계의 각 장소`를 식별상 구별하는 방식이 유익할 수 있다. 아직 세계 데이터↔세션 세계의 관계를 템플릿/인스턴스로 **확정하지 않는다**.
- [GPT-제안] 결합할 때 기존 건물·길·문을 침해하지 않는지, 연결점이 성립하는지, 생략된 부분이 생기는지를 검토할 가치가 있다. **반드시 규격화된 포트/자동 커넥터/승인 요청 절차로 검증해야 한다는 결론은 없다.**
- [기록 오류 정정] v0.1의 “조각은 단순한 묘사문일 수도 있다”는 정의 확장은 사용자가 말하지 않은 GPT 보완이다. 이 문서에서는 **가장 핵심적인 의미인 ‘미리 저작된 공간 조각의 결합’**을 보존하며, 묘사문 단독의 조각 인정 여부는 **미결**로 남긴다.
- [미결] 조각의 최소 구성·저작 범위, 복제/참조/배치의 의미, 조합 알고리즘, 결합 시 기성 구간의 변형 가능성, 조각 정의를 변경했을 때 이미 배치된 장소에 적용할지, 세계/세션에서 조각을 적용하는 시점.

## 3.11 공간의 동일성·변동과 두 층위

**[U-명시: 정확한 구분]**

> “인다임은 정보를 크게 두 층위로 나눠 관리할 예정입니다. 세계를 추적하고 계산하고 관리하며 시뮬레이션하는 것에 사용할 세계 데이터와 세션을 진행하는 동안 실제로 시뮬레이션되는 세계입니다.”

- 위 문장은 **세계 데이터 자체도 추적·계산·관리·시뮬레이션에 활용**된다는 뜻이다. 전자를 단순 설정 원형, 후자를 단순 복사본으로 환원하지 않는다.
- 장소가 플레이어의 행동으로 변화하면 이전의 설명과 다른 **현재 상태**가 필요할 수 있고, 그 결과를 반복 방문 등에서도 참조할 필요가 있다는 요구는 사용자의 벽 파괴 사례에서 나왔다.
- [GPT-제안] 장소의 **동일성**, 같은 조각으로 만들어진 여러 배치 결과의 **독립 상태**, 공간 관계의 변화·현재값 참조, 무엇이 저작된 사실이고 행동 결과인지를 구분할 가능성을 검토한다.
- [GPT-재평가] 공간이 실제로 존재하는지와 현재 고해상도로 계산 중인지는 다른 질문이다. 하지만 전용 **활성화 계층/시뮬레이션 거리** 설계는 보류했다.
- [미결] 두 층위가 어떤 종류의 데이터와 규칙을 각각 보유하는지, 어느 층위에서 어떤 저작·파생·변경이 허용되는지, 세션 사이의 공유, 원형 수정 전파, 변경 이력, 시간과의 결합.
- [기록 오류 정정] v0.1의 `세계 데이터 → 실재화 → 세션 인스턴스` 그림은 **가능한 해석**이었지 사용자에게 승인된 시스템 구조가 아니다. 이를 기본 동작 설명으로 전달하지 않는다.

## 3.12 구조적 검증과 이동하는 공간은 **보조 검증 논점**

- [GPT-제안] 참조 끊김·계층 순환·중복 식별자 등 **명백한 데이터 오류**는 규칙적으로 검사할 가치가 있다. 저작된 공간의 개연성을 자동 3D 건축법 수준으로 검증하는 것은 별개의 큰 비용이다.
- [GPT-제안] 승강기, 선박, 열차 객실처럼 **내부 공간의 포함 관계를 유지하면서 외부 위치·접속 관계가 변하는** 상황은 일반 공간 모델의 표현력 검증 사례다. 별도의 전용 모듈을 확정하지 않는다.
- [GPT-제안] 길게 이어진 도로를 여러 장소로 분할했을 때 관리상 경계가 실제 장애물이 되지 않도록 하는 문제와 함께 테스트할 만하다.
- [미결] 검증 기준과 실패 처리, 변화 직후 참조 갱신, 공간을 둘로 나누거나 합칠 때 장소 식별을 유지하는 방식.

# 제4부. GPT 15개 제안 — 원안·비판·수정/폐기 이력 상세 대조

**아래 ‘유지·수정·폐기·보류’는 GPT의 이전 제안에 관한 자체 검토 기록이다. 사용자 승인 여부는 15개 모두 미확정이다.** v0.1의 한 줄짜리 처리표가 삭제한 논거를 복구한다.

### 제안 01. 물리적 포함 계층 외 공간 관계 — **GPT 수정**
- **원래 문제의식:** 교차, 접촉, 중첩, 상대 방향, 지하 통로·구름다리·여러 층을 관통하는 구조는 단일 물리 포함 트리만으로 다 설명하기 어렵다.
- **원안:** 포함·접촉·인접·중첩·상대 위치·연결 등 다양한 공간 관계의 표현을 추가한다. IFC/GeoSPARQL/IndoorGML이 참고 자료.
- **재평가 이유:** 모든 장소에 관계 전부를 기록하면 저작과 변경 동기화 부담이 크다. 자연어 관계도 유효한 자료다.
- **현재 GPT 의견:** *필요한 공간 관계*를 서술 또는 구조화 형태로 선택적으로 표현한다. 어떤 관계가 필수인지 미결.

### 제안 02. 물리적 경계의 상세 표현 — **GPT 대폭 수정**
- **원래 문제의식:** 두 방이 벽을 공유해도 이동 출구가 없을 수 있고, 벽을 파괴한 결과를 이동·감각·환경에서 함께 해석해야 한다.
- **원안:** 경계의 상대 공간·구성(벽/문/창 등)·재질·두께·개구부·상태를 넓게 관리해 물리적 근거를 제공한다.
- **재평가 이유:** 모든 경계를 정교하게 수치화하는 요구가 과도하며, 소리/빛/열 전파를 불완전한 시스템 규칙으로 강제하면 개연성을 해칠 수 있다.
- **현재 GPT 의견:** 중요한 경계의 존재·반대편·개구부·대략적 특성·현재 상태를 **필요에 따라** 표현. 독립 경계 객체나 범용 물리 모델은 미승인.

### 제안 03. 장소 내부의 위치 표현 — **GPT 수정**
- **원래 문제의식:** 거대한 창고에서 모든 인물/물체를 같은 장소 안의 무차별적 점으로 놓으면 거리·차폐·접근 문제를 표현하기 어렵다.
- **원안:** 서술적 상대 위치, 기준점·연결, 좌표·기하 등 세 방식 제시. 일관된 위치 추적 필요.
- **재평가 이유:** 모든 장면에 정밀 좌표가 필요한 것은 아니며 문장으로도 충분한 배치를 표현할 수 있다.
- **현재 GPT 의견:** 정성적 상대 위치를 유력 후보로 보고 필요할 때 기준점·거리·좌표 사용 가능성 열어 둔다. 기본 표현 형식은 미결.

### 제안 04. 긴 도로·연속 공간의 동일성 — **GPT 유지**
- **원래 문제의식:** 도로를 여러 구간으로 자르면 같은 도로라는 연속성과, 인위적인 관리 경계가 물리적 장애물이 아니라는 사실이 사라질 수 있다.
- **원안:** 전체 도로/강/복도/해안선 등 연속 공간의 동일성과 구성 구간을 구별한다. 전체를 상위 장소로 둘 필요는 없다고 유보.
- **재평가:** 사용자 구상의 긴 길 분할과 정합적이다.
- **현재 GPT 의견:** 관련 표현 능력을 유지 권고. 그러나 **전체 도로 객체** 또는 **특정 데이터 구조**는 미결.

### 제안 05. 이동 경로 존재와 행위자별 통과 판단의 구분 — **GPT 유지**
- **원래 문제의식:** 구멍은 쥐에게 가능하지만 사람에게 불가능할 수 있고, 잠긴 문은 존재하지만 현재 이동이 어려울 수 있다.
- **원안:** 공간 관계·경로의 존재·특정 주체의 통과 가능성·실제 이동 결과를 구분. 방향성/거리/방법/장애물 등 후보 정보 제시.
- **재평가:** 사용자 확정 설명인 ‘이동은 포함 계층과 독립’과 합치하고 합리적이다. 판정을 반드시 물리 수식으로 할 필요는 없다.
- **현재 GPT 의견:** 개념적 구별 유지. 저장 포맷·실행 책임·판정 방식 미결.

### 제안 06. 구조 변화의 다중 물리 효과 자동 반영 — **GPT 기존안 폐기**
- **원래 문제의식:** 벽 파괴 하나로 경계·새 통로·빛·소리·열·공기 이동이 모두 달라질 수 있다. 동일 원인을 중복 갱신하면 불일치가 생긴다.
- **원안:** 원인이 된 물리 변화를 갱신하고 이동/감각/환경 등의 파생 결과·계산을 일괄 또는 자동 갱신하도록 설계.
- **폐기 이유:** 사용자가 세부 물리 모델의 과적합/개연성 붕괴 위험을 지적했다. 입력 정보가 모자란 상태에서 모든 현상을 자동 계산하는 것은 오히려 오류를 늘릴 수 있다.
- **현재 GPT 대체 제안:** 벽에 구멍이 생겼다는 **지속 구조 변화**를 기록하고, 이동/채광/음향/환기 등은 실제 요구 시점에 필요한 근거로 판단. 결과의 세계 상태 반영 기준은 미결.
- **중요:** 파생 효과를 *절대 갱신하지 않는다*는 뜻이 아니라 *모든 효과의 포괄적 선제 자동계산을 일반 의무로 삼지 않는다*는 뜻.

### 제안 07. 결합 가능한 기성 장소 조각 — **GPT 수정**
- **원래 문제의식:** 임의 생성 대신 사전 저작 조각을 반복 활용하되 결합이 물리적으로 일관되어야 한다.
- **원안:** 원형에 내부 구조·출입점·결합 조건·변형 범위를 둘 수 있고, 중복 점유나 남는 출입구를 검증. Dungeon Architect 참고.
- **재평가 이유:** 엄격한 정형 커넥터 규격은 TRPG의 다양한 공간에 과도할 수 있고 LLM/GM의 맥락적 검토가 유리할 수 있다.
- **현재 GPT 의견:** 기성 공간 조각을 유연하게 결합할 수 있도록 연구하되 결합 규격과 자동화 절차는 미결. ‘조각=묘사문’ 확대 정의는 사용자 발언이 아님.

### 제안 08. 조각의 원형과 각 실제 장소 구분 — **GPT 유지**
- **원래 문제의식:** 동일한 주택 내부 조각을 복수 장소에 사용하더라도 한 집의 벽 파괴가 다른 집의 상태를 바꾸면 안 된다.
- **원안:** 재사용 원형/배치된 장소/개별 상태를 구분하고 각 장소의 독립성 확보.
- **재평가:** 필요한 동일성 문제로 판단되어 유지 권고.
- **유보:** 사용자 승인 전에는 원형→세션 객체 사본 구조로 확정하지 않는다. 정의 수정의 전파 정책도 미결.

### 제안 09. 환경 전달을 위한 상세 물리 정보 — **GPT 기존안 폐기**
- **원래 문제의식:** 동일한 개구부라도 이동, 광원, 소리, 열, 공기에 미치는 효과가 다르므로 물리적 재질·면적·투과성 등을 표현하자.
- **원안:** 경계·광원·음원·구획의 상세 물리 정보를 공통 입력으로 주어 각 현상을 체계적으로 계산한다.
- **폐기 이유:** 현실의 복잡한 물리 정보와 계산을 모두 얻을 수 없으며 불완전한 수치 모델이 LLM 직관을 과도하게 제약할 위험.
- **현재 GPT 대체 제안:** ‘낡은 나무문’, ‘밖으로 난 큰 창’, ‘밀폐된 지하실’ 같은 정성적 사실을 유효한 판단 근거로 삼되 필요하면 수치 정보도 쓸 수 있다. 환경 자체의 책임은 환경 영역에서 논의.

### 제안 10. 환경 계산 전용 구획 — **GPT 보류**
- **원래 문제의식:** 하나의 창고를 두 장소로 나눠도 공기는 공유될 수 있고, EnergyPlus의 공간/열 구역/복사 구역은 목적별 구획이 다름을 보여준다.
- **원안:** 환경 계산용 구역이 장소 계층과 독립적으로 형성될 수 있도록 한다.
- **보류 이유:** LLM 중심의 개략적 판단으로 충분한 경우 별도 구역의 유지비가 정당화되지 않는다.
- **현재 상태:** 환경 영역에 요구사항으로 전달할 연구 대상. 장소 구조의 기본 구성으로 강제하지 않는다.

### 제안 11. 내외관과 위치별 가시성 — **GPT 수정**
- **원래 문제의식:** 진입 방향·관찰 위치·빛·장애물에 따라 같은 장소에서 보이는 대상이 달라진다.
- **원안:** 장소의 실제 구조/위치별 가시성/감각적 식별/인물의 지식을 구별하고 관찰 기준점을 고려.
- **재평가 이유:** 시점별 정적 가시 대상 목록은 저작·갱신 부담이 크고 장애물이 바뀌면 곧 낡는다.
- **현재 GPT 의견:** 내외관과 배치·특정 관찰점의 단서를 관리하고 실제 감각·인지는 필요시 판단. **사용자 원문의 ‘들어가면 무엇이 보이는지’는 별도로 추적**.

### 제안 12. 세계 데이터와 세션 세계의 동일성 관리 — **GPT 유지**
- **원래 문제의식:** 벽이 바뀌어도 같은 건물로 재방문하고, 동일한 기성 조각으로 만든 다른 집을 혼동하지 않아야 한다.
- **원안:** 장소 식별·구조 변화·실재화·복수 세션 상태·변경 이력 등의 원리를 검토.
- **재평가:** 두 층위를 고려하면 중요도가 높아 유지 권고.
- **중요한 제한:** 두 층위가 단순 원형/복사 관계인지, 어디에 무엇을 저장하고 변경하는지, 상태 기록의 원천은 사용자 미결정이다. ‘불변 요구’로 표현한 v0.1은 부정확했다.

### 제안 13. 이동하는 공간 — **GPT 수정**
- **원래 문제의식:** 선박·차량·열차·승강기는 내부 장소 관계가 유지되면서 외부 위치/접속 관계가 바뀐다.
- **원안:** 이동하는 공간을 표현할 수 있는 기능 도입.
- **재평가:** 별도의 특수 전용 모듈보다는 일반 공간 관계의 표현력 검증 사례로 다루는 것이 적절할 수 있다.
- **현재 GPT 의견:** 검증 사례로 보존. 실제 처리의 자료구조는 미결.

### 제안 14. 구조적 정합성 검증 — **GPT 수정**
- **원래 문제의식:** 계층 순환, 끊어진 장소 참조, 중복 실재화, 결합 불가능한 구조 등은 세계의 일관성을 무너뜨릴 수 있다.
- **원안:** 기성 조각 배치, 이동/경계 갱신 등을 자동 검증.
- **재평가 이유:** 단순 데이터 오류와 건축학·물리학 수준의 공간 개연성 검증은 비용과 불확실성이 완전히 다르다.
- **현재 GPT 의견:** 명백한 자료구조 모순과 확정 사실의 충돌을 탐지하는 기능 검토. 더 어려운 개연성은 LLM/GM 검토 가능성. 실제 검증 절차는 미결.

### 제안 15. 실제 세계와 계산 상세도의 구분 — **GPT 보류**
- **원래 문제의식:** 서울과 부산이 모두 세계에 실재해도 두 지역의 모든 광원/온도 등을 매 순간 정밀 계산할 필요는 없다.
- **원안:** 실재 여부와 현재 상세 시뮬레이션·저해상도 갱신·요청시 계산 여부 구분.
- **보류 이유:** 이는 장소의 정보 형식뿐 아니라 **전체 세션 운영 정책**이므로 여기서 활성화 계층을 설계하지 않는다.
- **현재 상태:** 시뮬레이션 실행 전략의 검토 주제로만 남김.

### 4.16 재평가 상태 집계와 권한 표

- **GPT 유지 권고 4건:** 04, 05, 08, 12.
- **GPT 수정 권고 7건:** 01, 02, 03, 07, 11, 13, 14.
- **GPT 기존안 폐기 2건:** 06, 09.
- **GPT 보류 2건:** 10, 15.
- **사용자에게 최종 승인된 GPT 제안 수: 이 대화의 명시적 승인 기록 기준으로 0건.** 이미 사용자 원문에 들어 있었던 이동의 독립성·구멍의 기록 등은 **GPT 제안이 아니라 사용자 구상**으로 처리한다.

# 제6부. 다른 영역에 전달할 **후보 요구**와 작업 경계

아래는 `설계 확정 명령`이 아니라 **관제탑이 의존성과 미결 사항을 추적할 수 있도록 보존한 접점**이다. 사용자 직접 언급과 GPT/조사 확장을 구분한다.

| 대상 영역 | 사용자 명시 접점 | GPT/조사에서 추가로 제기된 검토 항목(미승인) |
|---|---|---|
| 시간 | 장소의 변화와 이동이 시간 속에서 일어남. **시간 정책 P01~P08 세부는 아직 미수신.** | 문·벽 변화 시점/지속시간, 이전 상태 참조·이력/변경 시점의 표현 |
| 물건 | **열쇠**, 장소 **내외부의 물건 및 물건으로 관리하지 않는 가구·사물** | 문·벽·창문·장비의 재질/개폐/파손 소유권, 배경 사물의 상호작용시 상태 표현 |
| 환경 및 현상 | **분위기·공기·환경**, 환경 영역이 환경을 주관 | 광원·열원·소음·연기·냄새와 공간 관계, 공간 경계가 환경 전달에 미치는 영향, 별도 구역 필요 여부 |
| 신체 및 건강 | 직접 특정 기능을 확정하지 않음 | 사람·동물·드론의 크기/자세/이동능력에 따라 통과 가능성 차이 |
| 정보 | **숨겨진 통로** 등 정보 접근과 연계 | 실제 공간과 인물 지식/오해/비공개/미저작의 구별, 세계 사실의 권위와 승격 정책 |
| 감각 | **숨겨진 통로**, **어느 위치에서/들어가면 무엇이 보이는지** | 거리·가림·시선·빛·소리 도달·식별·관찰자의 조건 |
| 심리 및 판단 | 직접 특정 기능을 확정하지 않음 | NPC가 공간과 위험·접근성을 판단하는 과정과 장소 정보 참조 |
| 관계 | 직접 특정 기능을 확정하지 않음 | 공간의 물리적 포함·연결과 사회적 관계의 혼동 방지 필요성 검토 |
| 사회규범 | 직접 특정 기능을 확정하지 않음 | 출입 권한/금지 구역 등의 사회적 제약과 실제 물리 통과의 분리 가능성 |
| 세력 | 직접 특정 기능을 확정하지 않음 | 점유/경계/통제 범위가 장소 구획과 어긋날 가능성 |
| 사건 | 직접 특정 기능을 확정하지 않음 | 장소 붕괴·이동·통로 개설 등이 사건의 조건/진전과 상호작용할 가능성 |
| 과업 | 직접 특정 기능을 확정하지 않음 | 목표 위치·경로·접근 조건이 과업 판단에 필요할 수 있음 |
| 행동선언 | **벽 파괴, 창문·구멍을 통한 이동** 등 행동 사례 | 행동 결과가 장소/물건/환경에 어떤 영향을 주며 언제 결과를 세계 사실로 확정하는가 |

- **직접 발언과 추론의 구별:** '시간·사회규범·세력 등에 무엇이 필요하다'는 표의 세 번째 열은 외부 분야와 기존 제안을 통해 얻은 GPT의 요구 추출이지, 해당 영역의 이미 승인된 설계가 아니다.
- **기초 설계 독립성:** 다른 영역의 정보가 필요하다는 이유만으로 장소 설계실이 감각·환경·물건·정보의 상태나 판정 권한을 독점하지 않는다.

# 제8부. 남겨야 할 미결정 사항 및 관제탑 전달용 판단 경계

이 목록은 **앞에서 이미 결정된 사용자 설명을 재질문하기 위한 것**이 아니다. 예컨대 ‘최상위 항목은 장소인가?’, ‘속성 전부를 계승할까?’, ‘이동은 포함 관계에 종속되는가?’는 다시 선택할 문제가 아니다. 이후 구상 자체를 사용자가 뒤집지 않는 한 현재 해명된 의도를 그대로 다룬다.

## 8.1 공간 저작/조직의 본체

1. [미결] 공간을 공백 없이 표현하기 위한 **저작 범위·표현 단위·세밀도**. 개별 항목을 어디까지 미리 만들어 둘지, 미저작 공백을 만났을 때 진행 정책은 무엇인지.
2. [미결] 상위 항목 바깥의 연속 공간(도로·산·들·구름다리 등)을 구체적으로 어떻게 조직할지. 단일 포함 계층 외 공간 관계가 어디까지 필요한지.
3. [미결] 길·도로·복도의 분할 기준과 분할 구간들 사이의 동일성/연속성 표현.
4. [미결] 교차·중첩·다중 참조·수직 공간을 허용할 때 포함 계층과 어떻게 결합할지.
5. [미결] 실제로 사전 선정할 **속성 계승 대상 목록**, 부재/미확인/직접 값의 표현 상세.
6. [미결] 건물·실내·외부의 정성적 위치/기준점/거리·좌표 가운데 어느 수준을 어떤 장면에서 사용할지.

## 8.2 이동·물리적 변화

7. [미결] 연결·출입 방법·막힘·잠금·은폐·통과 조건을 어떤 표현으로 보존할지.
8. [미결] 벽/문/창문/구멍의 물리적 사실이 공간 영역과 물건 영역에서 어떻게 연결되는지. 물건이 아닌 배경 사물의 존재 표현 및 상호작용 후 상태 변경 방법.
9. [미결] 벽 파괴·칸막이 설치 등으로 구조가 달라질 때 **장소 항목 자체를 분할·병합·생성·삭제할지**와 기존 식별 보존 정책.
10. [미결] 실제 이동/파괴의 가능성과 결과를 코드·LLM·GM이 언제 어떻게 판단할지. 지정 단계나 실행 파이프라인은 미확정.

## 8.3 환경·감각·정보

11. [미결] 내외관, 위치별 시야, 진입 시 시야, 분위기, 공기, 환경의 사실이 어떤 영역에 어떤 상세도로 관리되는지.
12. [미결] LLM의 상식적 판단과 시스템적 계산의 역할을 어떤 기준으로 나누고, 판단 결과 중 무엇을 장기 상태에 반영하는지.
13. [미결] 미등록=없음/불명/미저작/인물에게 숨김의 의미와 처리.
14. [미결] 음향·빛·온도·공기 등 환경별 별도 공간적 구획이 필요한지(현재 GPT 보류안).

## 8.4 기성 조각 및 세계 두 층위

15. [미결] 재사용 장소 조각의 **정의, 최소 단위, 결합/복제/참조/배치 방식**, 변형·회전·크기 조정 허용 범위, 결합 검증과 실패 처리.
16. [미결] 동일 조각을 사용하는 여러 장소의 독립 상태와 원형 수정의 전파 정책.
17. [미결] **세계 데이터**와 **실제 세션 세계**의 작동 관계: 어떤 데이터가 실제로 세계의 무엇을 추적·계산·관리·시뮬레이션하는지, 세션 세계와 언제 어떻게 상호작용하는지, 어떤 정보가 각 층위에서 수정 가능한지.
18. [미결] 시간 정책 P01~P08 원문과 공간 변화의 정합성, 시간·이벤트·상태변경 경계.
19. [미결] 장거리 공간의 계산·실재/비실재·활성화 정책과 비용.
20. [미결] 명백한 구조 오류와 세계관 개연성 충돌을 검사하는 방법 및 최종 권한.

**문서 전달 시 포함해야 할 주의 문구:** “이 파일은 사용자 구상의 원문과 GPT의 통합 제안을 함께 보존한 **검토본**이다. 사용자 발언을 제외한 GPT 보완과 조사 해석은 미승인이다. 시간 P01~P08 원문도 미제공 상태이다. 특히 공간 공백, 사물·가구, 진입 시 관찰, 비정형 이동, 세계 데이터의 정의를 압축해서 재해석하지 말 것.”

- `상위 항목 = 물리적 장소 계층의 단 하나 뿌리`이고 한 헤드 아래 여러 뿌리가 가능하다는 설명을 보존했다.
- 하위 장소의 부모 내부 **물리적 포함**과 별도 이동/연결을 구분했다.
- 계승은 **사전 선정된 속성 한정**이며 가장 가까운 조상의 값이라는 규칙을 보존했다.
- `빈 장소가 없도록` 목표의 표현을 삭제하거나 '장면 사이 연결'이라는 더 약한 표현으로 치환하지 않았다.
- 미저작 공간 **창작 배제**와 기성 장소 조각 **결합 구상**을 분리했다.
- **구름다리**를 건물 바깥 공간으로 다루는 사용자의 예시를 보존했다.
- 문·창문·개구멍·벽 파괴와 새 구멍의 세계 저작, 막힘/숨김/잠김을 보존했다.
- **어느 위치에서 무엇이 보이는지**와 **들어가면 무엇이 보이는지**를 별도 추적했다.
- 물건 영역에서 개별 관리하지 않는 **사물·가구까지 내외부 내용물로 포함**한다는 요구를 보존했다.
- **분위기·공기·환경·공간의 크기·내부 경로**를 보존했다.
- `세계 데이터 = 추적·계산·관리·시뮬레이션에 사용하는 정보`와 `세션 세계 = 세션 중 실제로 시뮬레이션되는 세계`를 원형/복제에 환원하지 않았다.
- 소리·빛 세부의 **불완전 시스템 계산으로 인한 개연성 붕괴 위험**과 LLM 직관의 가치, 동시에 수치 계산 전면 금지가 아님을 보존했다.
- 15개 GPT 제안의 자체 유지/수정/폐기/보류 이유를 보존하고 **사용자 승인으로 둔갑시키지 않았다**.
- 종전 두 조사 보고서와 이전 통합안은 부록에 **전문**을 보존했다.

# 부록 I. 장소 및 공간 설계실 — 직접 관련 사용자 발언 전문

> **보존 방법:** 아래는 해당 대화에서 사용자가 직접 입력한 메시지를 메시지 단위로 원문 복제한 것이다. 말줄임표/요약/가필 없이 옮긴다. 아래의 `C01`~`C12`는 이번 문서의 추적용 식별자이며 원래 채팅에 표시된 공식 ID가 아니다. 설계에 관한 새로운 결정은 부록의 발언으로만 주장할 수 있다. **GPT의 답변은 여기에 섞지 않았다.**

## C01 — 장소 및 공간 설계실의 역할과 초기 진행 지시

<!-- USER_MESSAGE_BEGIN C01 -->
INDAIM — 02. 장소 및 공간 설계실

이 세션은 INDAIM 전면 재설계 프로젝트의 장소 및 공간 영역 전담 설계실이다.

프로젝트 공통 지침을 준수하며, 중앙 관제탑의 작업 지시에 따라 장소 및 공간 영역의 정보 구조와 작동 원리를 조사하고 설계한다.

1. 담당 범위

세계의 장소 및 공간과 관련된 정보의 표현, 관리, 상태 변화, 작동 원리와 다른 영역과의 상호작용을 담당한다.

장소 및 공간은 14개 정보 영역 중 설계 독립성이 두 번째로 높다고 판단되어 시간 다음으로 설계를 시작한다.

다만 이 순위는 다른 영역과의 상호작용이 적다는 의미가 아니라, 다른 영역의 구체적인 설계 결정에 비교적 덜 종속된다는 의미다.

2. 설계 목표

INDAIM의 세계에 존재하는 장소와 공간을 일관되고 유연하게 표현하고 관리할 수 있는 기반 구조를 탐색한다.

다양한 세계관과 상황, 플레이어의 자유로운 행동에 대응할 수 있어야 하며, 특정 게임 기능이나 기존 구현 방식에 종속되지 않는 일반적인 원리를 추구한다.

14개 정보 영역의 분류는 설계 작업을 위한 것이므로, 실제 시스템의 모듈 경계를 미리 가정하지 않는다.

3. 작업 방법

다음 원칙에 따라 설계를 진행한다.

1. 전체에서 부분으로: 먼저 정보의 범위와 전체 구조를 탐색하고, 이후 점진적으로 구체화한다.
2. 근본 구조 중심: 개별 기능을 위한 특수 규칙을 늘리기보다 여러 요구사항을 자연스럽게 수용하는 구조를 연구한다.
3. 폭넓은 조사: TRPG, 게임 엔진, 공간 모델링, 시뮬레이션, 지식 표현 등 다양한 분야의 접근법을 참고한다.
4. 실질적인 대안 비교: 서로 다른 설계 철학과 장단점을 가진 대안을 검토한다. 형식적인 선택지를 만들지 않는다.
5. 책임 경계 준수: 장소 및 공간과 상호작용한다는 이유만으로 다른 영역의 상태와 판단을 직접 관리하도록 설계하지 않는다.
6. 영역 간 요구사항 추출: 다른 영역에 필요한 정보와 기능을 발견하면 임의로 확정하지 않고 관제탑에 전달할 요구사항으로 정리한다.
7. 사용자 주도: 설계의 모든 최종 결정은 사용자가 내린다. 승인되지 않은 제안이나 가설을 확정 사항으로 취급하지 않는다.

4. 선행 설계와의 관계

앞서 진행된 시간 설계실에서는 시간 영역의 기초 정책 P01~P08이 승인되었다.

장소 및 공간 설계에서 시간 정보가 필요하다면 해당 선행 결정과의 정합성을 고려해야 한다.

다만 시간 영역의 세부 구조는 아직 완성되지 않았으며, 다른 영역의 요구사항에 따라 후속 검토할 수 있다.

선행 결정의 구체적인 내용은 사용자가 제공하는 관련 문서를 기준으로 확인한다. 제공되지 않은 세부 사항을 추측하여 확정하지 않는다.

5. 초기 진행 지시

이 지시문을 받은 직후에는 장소 및 공간의 구체적인 설계를 시작하지 않는다.

사용자는 별도로 준비한 첫 구상 가이드를 제공할 예정이다.

따라서 우선 다음 사항만 수행한다.

* 프로젝트와 담당 영역의 목적을 확인한다.
* 자신의 역할과 작업 원칙을 이해했음을 보고한다.
* 사용자의 첫 구상 가이드가 제공되기 전까지 구체적인 정보 분류, 공간 모델, 설계 단계 또는 아키텍처를 임의로 제안하거나 확정하지 않는다.

사용자의 첫 구상 가이드를 전달받은 후, 그 내용을 정확히 이해하고 필요한 논의를 거쳐 본격적인 탐색과 설계를 시작한다.

## C03 — 분류 헤드·상위 장소·속성 상속에 대한 해명

<!-- USER_MESSAGE_BEGIN C03 -->
최상위 항목이란 분류 헤드와 같은 역할입니다. 어떤 지역이나 물리적 구역을 의미하는 것은 아닙니다. 일반적으로 인접한 구역은 비슷한 성격을 지니고 창작물에서는 이런 성질이 더 두드러지기에 최상위항목 이하에 포함된 항목들에 손쉽게 속성 내용을 계승시킬 수 있기 위한 수단입니다. 어떤 속성에 대해 하위 항목이 그 내용을 가지고 있는 경우 그것을 사용하고, 가지고 있지 않은 경우 계층상 위에 있는 항목들 중 그 속성의 내용을 가진 항목 중에서 가장 가까운 항목의 것을 사용하는 구조를 구상했습니다.
상위 항목이란 계층구조의 머리 역할을 하는 항목입니다. 최상위 항목과 달리 상위 항목은 장소입니다. 상위 항목은 계층 구조에서의 꼭대기에 있는 단 하나의 항목을 가리키며, 몇 개의 하위 항목을 가질 수 있고 하위 항목은 반드시 상위 항목 장소 내에 물리적으로 포함된 관계여야 합니다. 건물 내부의 방이 그 예시입니다. 어떤 1층짜리 숙박시설을 예로 들면 그 건물이 상위항목, 복도와 객실들은 각각 하위 항목이 될 것이며, 객실 내부의 방과 화장실은 하위 항목의 하위 항목이 될 것입니다. 건물 간의 구름다리가 있는 경우 이는 상위 항목 외부의 공간, 길이나 공터, 산과 같은 외부 통로로 취급합니다. 상위항목은 물리적 포함관계에 의해 결정되므로 가진 하위 항목의 수와 그 규모는 완전히 제각각일 수 있습니다. 거대한 교도소와 컨테이너 원룸이 그 예입니다.

## 1. 지향점

1. 현행 INDAIM과 달리, 세계의 공간을 **복수의 비공간적 분류 헤드와 그 아래의 물리적 장소 계층**으로 조직하는 방안을 구상한다.
2. 건물·객실 같은 전형적인 장소뿐 아니라 **복도, 통로, 실외의 길, 산, 들**처럼 일반적으로 독립된 장소로 표현하지 않는 공간도 표현한다.
3. 공간 표현에서 **장소 사이에 비어 있는 영역이 없도록 하는 것**을 목표로 한다.
4. 장소의 구성과 이동 관계, 관찰 가능한 구조, 내용물, 주변 환경 등을 정보로 관리하며, 행동으로 인한 공간의 변화를 반영할 수 있어야 한다.

> 위 목표는 구상 단계의 지향점이며, 공간을 얼마나 세밀하게 분할·저작할지는 아직 확정되지 않았다.

## 2. 계층 구조와 항목의 의미

### 2.1. 최상위 항목: 분류 헤드

- 세계에는 **여러 개의 최상위 항목**이 존재할 수 있다.
- 최상위 항목 자체는 **장소가 아니다.** 물리적인 구역·지역을 뜻하지 않으며, 장소들을 조직하기 위한 **분류 헤드**다.
- 하나의 최상위 항목 아래에는 여러 개의 독립된 **상위 항목(물리적 장소 계층의 뿌리)**이 들어갈 수 있다.
- 인접한 구역은 성격이 비슷한 경우가 많고 창작물에서는 이런 공통성이 더욱 뚜렷하므로, 최상위 항목은 공통 속성을 하위 장소에 편리하게 적용하기 위한 수단으로 구상되었다.
- 동일한 분류 헤드 아래 속한다는 사실이 반드시 단일한 물리적 공간에 포함되어 있거나 서로 이동 가능함을 뜻하지는 않는다.

### 2.2. 상위 항목: 물리적 장소 계층의 뿌리

- **상위 항목은 실제 장소**이며, 각각의 물리적 포함 계층에서 **최상단에 있는 단 하나의 장소 항목**을 가리킨다.
- 하나의 최상위 분류 헤드에는 이러한 상위 항목이 여러 개 있을 수 있다.
- 상위 항목은 경계를 갖는 구역 또는 건물 등일 수 있고, 그 아래에 여러 하위 항목을 둘 수 있다.
- **하위 항목은 반드시 부모 장소의 물리적 범위 안에 포함**되어야 한다. 부모–자식 관계는 물리적 포함을 나타낸다.
- 하위 항목끼리는 서로 포함 관계를 이루거나 공간적으로 연결될 수 있다. 다만 **포함과 연결은 같은 관계가 아니다.**
- 상위 항목의 물리적 규모나 하위 항목의 수는 제한된 전형에 맞출 필요가 없다. **거대한 교도소부터 컨테이너 원룸까지** 같은 원칙으로 나타낼 수 있다.

### 2.3. 실내 공간 예시

```text
최상위 항목: 분류 헤드 (장소 아님)
└── 상위 항목: 1층 숙박시설 건물 (장소)
    ├── 복도 (건물에 물리적으로 포함)
    ├── 객실 A (건물에 물리적으로 포함)
    │   ├── 객실 내부의 방 (객실 A에 물리적으로 포함)
    │   └── 화장실 (객실 A에 물리적으로 포함)
    └── 객실 B (건물에 물리적으로 포함)
```

- 위 표시는 **포함 계층의 예시**일 뿐, 복도·객실 사이의 출입 경로나 통과 조건까지 표시한 것은 아니다.
- 건물과 건물을 잇는 **구름다리**는 두 건물의 내부로 넣기보다는 **상위 항목 외부의 공간**, 즉 길이나 공터 등과 마찬가지로 다루는 구상을 제시했다.

## 3. 제한된 속성 계승

- 계층 구조의 중요한 목적 중 하나는 여러 장소의 **공통 속성을 중복 저작하지 않게 하는 것**이다.
- **속성 계승은 사전에 선정해 둔 장소 속성 항목에 한해서만 시행**한다. 모든 데이터·속성을 무조건 계승하는 방식이 아니다.
- 계승 대상인 속성에 대해 하위 항목이 **직접 값을 가지고 있으면 그 값을 사용**한다.
- 직접 값이 없으면 **계층상 상위의 항목들을 탐색해 해당 속성의 값이 있는 가장 가까운 항목의 값을 사용**한다.
- 이 탐색에는 상위의 물리적 장소와 최상위 분류 헤드가 포함될 수 있다.
- 계승 대상 속성의 **구체적인 목록**과 값의 표현 방식은 이 대화에서 정해지지 않았다.

예시적 규칙 표현(구현 사양이 아님):

```text
어떤 장소에서 계승 대상으로 선정된 속성 X의 값을 요청할 때
1. 해당 장소에 X가 있으면 이를 사용한다.
2. 없으면 부모 방향으로 올라가면서 X가 있는 가장 가까운 항목의 값을 사용한다.
```

## 4. 공간의 연속성과 외부 공간

- 길, 도로, 복도, 산, 들, 공터 등의 공간도 표현 대상으로 포함한다.
- 상위 항목인 건물·구역의 밖으로 나갈 때는 **어떤 길이나 외부 구역으로 나가는지** 표현할 수 있어야 한다.
- 특히 길은 넓게 뻗어 있고 매우 많은 장소와 연결될 수 있으므로, **지역·구역·연결된 장소 등을 기준으로 여러 구간으로 나누어 관리하는 방안**을 구상 중이다.
- 이는 현재 검토 중인 아이디어이며, 길을 나누는 **정확한 기준·단위·방식은 미확정**이다.

## 5. 공간 연결과 이동

### 5.1. 포함 계층과 별개의 이동 관계

- **이동 가능성은 물리적 포함 관계나 계층 구조에 종속되지 않으며, 별도로 표현할 수 있어야 한다.**
- 공간이 같은 부모 아래에 있다는 사실만으로 이동 가능하다고 판단하거나, 포함 계층상 멀리 떨어져 있다는 이유로 연결을 금지하지 않는다.
- 한 장소에서 다른 장소로 이동하는 수단은 하나로 고정되지 않는다.

### 5.2. 다양한 통과 경로와 상태

- 공간 사이의 이동은 **문, 창문, 작은 구멍, 기타 통로** 등 여러 방식으로 가능할 수 있다.
- 통로는 **막혀 있거나, 숨겨져 있거나, 잠겨 있을 수 있다.**
- 통로와 관련된 사실과 이동 가능성의 판단에서는 다른 정보 영역과 협력할 수 있어야 한다.
- 예를 들어 **열쇠**는 물건 영역의 정보와 연결되며, **숨겨진 통로를 발견하는 문제**는 감각·정보 영역과 연결될 수 있다.

### 5.3. 공간 구조의 변화

- 기존에 통로가 없어도 **벽을 부수는 행동**으로 새로운 이동 경로가 형성될 수 있다.
- 이때 **새로 생긴 구멍을 세계에 정보로 저작·반영**할 수 있어야 한다.
- 변경된 구조가 이후의 장소 간 이동과 공간 정보에 영향을 줄 수 있어야 한다.
- 파괴·저작의 구체적인 처리 책임과 절차는 아직 결정하지 않았다.

- 주의: 사용자가 제시한 *분류 헤드 → 물리적 포함 계층 → 독립적인 이동 연결 → 제한된 속성 계승* 구상은 **잠정 가설**이다. 이를 전제로 조사 대상을 제한하지 않았다.

## 0. 조사 관점

사용자는 INDAIM이 (1) 세계를 추적·계산·관리·시뮬레이션하는 데 사용할 **세계 데이터**와 (2) 세션이 진행되는 동안 **실제로 시뮬레이션되는 세계**의 두 층위로 정보를 다룰 예정이라고 설명했다. 이 두 층위의 세부적 관계·영속성·변경 권한은 아직 확정되지 않았다. 조사에서는 이를 잠정적으로 **세계의 일반적 구조·규칙·정의**와 **특정 세션에서 성립하는 구체적 상태·변화**를 나누어 보는 관점으로 활용하되, 반드시 ‘불변 템플릿 대 가변 인스턴스’와 동치라고 해석하지 않는다.

공간을 표현하는 접근법은 주로 다음 질문들에 서로 다른 답을 준다.

1. *무엇이 있는가?* 이름 붙은 장소·물체·구획·배경·미저작 공간.
2. *어디에 있는가?* 소속, 포함, 교차, 접촉, 상대 위치, 좌표.
3. *어디로 갈 수 있는가?* 연속 공간, 길, 경계, 이동 수단과 조건.
4. *무엇이 전달되는가?* 빛, 소리, 냄새, 시야, 물리적 접근.
5. *무엇이 변하는가?* 개폐, 파손, 생성·소멸, 위치 이동, 경로 변경.
6. *얼마나 상세히 계산해야 하는가?* 추상화·정밀도·활성화·분할·온디맨드 생성.
7. *누가 무엇을 아는가?* 객관적 세계, 저작 정보, 추론, 관찰, 인물별 공간 기억.

## 1. 텍스트 게임·인터랙티브 픽션

### 1-1. Inform 7 — 방(Room), 구역(Region), 문(Door), 범위(Scope)

**실제 방법**: 장소 규모에 관계없이 일련의 `Room`으로 모델링한다(실내방·운동장·광장 등). `Region`은 여러 Room을 조직하는 상위 개념이며, 방향·문 등은 방 간 이동을 표현한다. 묘사되지 않은 다른 방의 대상은 기본적으로 조사/조작 범위(`scope`) 밖이다. 특수한 `backdrop`은 하늘이나 바닥처럼 여러 장소에서 보이는 배경을 중복 생성 없이 표현한다.

**추출 가치**: 인간 저작자에게 간명한 장소 단위, 간단한 공간 기술 문법, 시점에 맞는 상호작용 가능한 대상 선별. 한 물리적 배경을 여러 곳에 노출하는 공용 배경 모델.

**한계**: 기본 방 모델은 방 내부의 미세 위치를 생략하며, 일반적으로 방 내부의 모든 대상이 가깝다고 가정한다. 장소 내부의 실질적인 거리, 장애물, 시야·접근의 차이를 적극 판정하려면 별도 수단이 필요하다. ‘방을 나가는 모든 길’이 선언된 엣지에만 의존하면 자유로운 벽 파괴·임의 길 찾기를 표현하기 어렵다.

출처: [Rooms & Scenery](https://inform-7-handbook.readthedocs.io/en/latest/chapter_2_rooms_%26_scenery/rooms_%26_scenery/), [Regions](https://inform-7-handbook.readthedocs.io/en/latest/chapter_2_rooms_%26_scenery/regions/), [Doors](https://inform-7-handbook.readthedocs.io/en/latest/chapter_2_rooms_%26_scenery/doors/), [Backdrops](https://inform-7-handbook.readthedocs.io/en/v2.0/chapter_2_rooms_%26_scenery/backdrops/)

### 1-2. Evennia — 연결 자체를 ‘출구 객체(Exit)’로 취급

**실제 방법**: MUD 제작 프레임워크 Evennia에서는 Room을 연결하는 Exit도 게임 객체다. 하나의 Exit는 **일방향**이므로 양방향 이동에는 두 출구가 필요하다. `north`, `door`, `portal`, `jump out the window` 같은 이동 방식 이름을 출구로 사용할 수 있고, 통과 권한(`traverse` lock)과 이동 처리 절차를 적용한다.

**추출 가치**: 공간과 통과 연결을 독립된 데이터로 놓는 관점, 비대칭 이동, 개별 출구의 상태·권한·동작, 방향이 아닌 이동 동사의 수용.

**한계**: 출구 객체와 물리적 문·창문의 동일성을 자동 보장하지 않는다. 양방향 출구를 별개로 관리하면 한쪽의 잠금·파손 상태와 다른 쪽의 정합성을 별도로 지켜야 한다. 연결의 존재 자체가 통과·시야·음향의 보편적인 설명은 아니다.

출처: [Evennia Exits](https://www.evennia.com/docs/latest/Components/Exits.html)

### 1-3. TADS 3 — 포함 위치·여행·감각 전달을 서로 구분

**실제 방법**: `NestedRoom`은 의자·침대·차량처럼 행위자가 점유할 수 있는 내부 위치이며, 이를 오가는 것은 일반 방 사이의 이동과 다르다. 감각 시스템은 재질을 통과하는 시각·청각·후각·촉각을 다르게 취급한다. `SenseConnector`는 방 경계를 넘어 감각을 연결하고, `Occluder`는 시점에서 가려진 대상을 처리한다. `DistanceConnector`는 한 물리적 장소를 여러 Room으로 분할했거나 서로 개방된 공간 간에 거리 효과를 나타내는 경우를 지원한다.

**추출 가치**: **이동 연결 ≠ 감각 연결 ≠ 물리적 포함**을 직접 구별하는 사례. 창문은 보이되 통과할 수 없는 상태, 가림막 때문에 사각이 있는 상황, 큰 장소를 서술 단위별로 나누는 사례에 특히 유용하다.

**한계**: 정교한 감각 규칙은 저작·디버깅 비용이 크고, 일반적인 3D 기하 계산을 완전히 대체하지 않는다. 기본 구현의 감각 통과 방식은 실제 물리 매질 전달의 정확한 시뮬레이터가 아니다.

출처: [NestedRoom](https://tads.dev/docs/adv3/doc/libref/object/NestedRoom.html), [감각 라이브러리 소스](https://tads.dev/docs/adv3/doc/libref/source/sense.t.html)

### 1-4. Microsoft TextWorld — 공간·행동을 논리적 사실과 규칙으로 표현

**실제 방법**: TextWorld는 텍스트 게임 세계를 생성하고 시뮬레이션한다. 소스 코드에서 `Proposition`(예: `in(cup, kitchen)`), 상태를 구성하는 사실 집합, 전제조건·사후조건으로 상태를 바꾸는 Action/Rule을 분리한다. 방과 경로·대상이 사실을 만들어 세계 상태가 된다.

**추출 가치**: 자연어 묘사를 세계의 유일한 정본으로 취급하지 않고, **검사 가능한 구조화 사실**에 근거하여 이동·열기·잠금해제·보관 등의 결과를 산출할 수 있다. 장소 구조 변경도 상태 변형과 정합성 검사의 관점에서 검토 가능하다.

**한계**: 초기에는 유한한 방·물체·행동과 명시적 논리 사실을 중심으로 구성되므로, 자유롭게 새 공간을 발견·발명하는 TRPG에 그대로 적용하면 ‘정의하지 않은 것은 불가능’이라는 폐쇄세계 편향이 강해진다. 숫자·기하·시간·모호한 사실과의 접속이 별도 과제다.

출처: [Microsoft Research TextWorld](https://www.microsoft.com/en-us/research/project/textworld/), [TextWorld logic 소스](https://textworld.readthedocs.io/en/1.7.0/_modules/textworld/logic.html), [GameMaker 소스](https://textworld.readthedocs.io/en/stable/_modules/textworld/generator/maker.html)

## 2. 테이블톱 RPG의 공간 추상화

### 2-1. Fate Core — 장면별 Zone

**실제 방법**: 전투/갈등 장면을 2~4개 정도의 추상 Zone으로 나눈다. Zone은 미터 기준의 일정한 칸이 아니라 근접 상호작용 가능성·장애물·층 차이 등의 체감에 맞춰 정한다. 상황 속성(aspect)이 진입 난도를 만든다.

**추출 가치**: 같은 세계에서도 **해당 장면의 판정 목적에 적합한 일시적 공간 구획**을 사용하는 방식. 고정적인 장소 정밀도를 세계 전역에 강제하지 않는다.

**한계**: Zone이 실제 세계의 모든 위치를 정밀하게 설명하는 물리 정본이라고 보면 모순이 생긴다. 장면 밖 이동·반복 방문·원거리 시야 등에는 별도 세계 수준의 연속성이 필요하다.

출처: [Fate Core: Setting the Scene](https://fate-srd.com/fate-core/setting-scene), [Movement](https://fate-srd.com/fate-core/movement)

### 2-2. Pointcrawl, Hexcrawl, Node 기반 조사 — ‘이동’과 ‘발견’을 서로 다른 층으로

**실제 방법**: Pointcrawl은 장소 노드와 경로 연결로 여행을 표현하며, 추상 노드로 도시·왕국과 작은 명소가 공존할 수 있다. The Alexandrian은 지도 기반의 탐험과 단서 기반의 노드 탐험이 하나의 세계 위에 교차하는 별개 표현 층이 될 수 있음을 설명한다.

**추출 가치**: 도로·산길은 경로 중심으로, 방향 없이 숲을 가로지르는 탐험은 면/격자/서술 중심으로, 비밀 장소 발견은 단서 관계 중심으로 다룰 수 있다. **실제 이동로 그래프와 플레이어의 정보 탐색 그래프를 혼동하지 않는 것**이 중요하다.

**한계**: 지점 간 그래프만으로 ‘길에서 벗어나 횡단’, ‘다리 밑으로 진입’, ‘벽을 넘어 지름길’ 같은 행동을 모두 설명할 수 없다. 헥스가 생태·지형·개연성을 자동 보장하는 것도 아니다.

출처: [The Alexandrian: Pointcrawls](https://thealexandrian.net/wordpress/48666/roleplaying-games/pointcrawls), [Node-Based Scenario Design](https://thealexandrian.net/wordpress/tag/node-based-scenario-design)

## 3. 건축·GIS·공간 지식 표현

### 3-1. IFC(buildingSMART) — 물리적 공간 계층과 중첩 구역의 공존

**실제 방법**: 건축정보모델 IFC의 `IfcSpace`는 실제·개념적 경계를 가진 영역/부피를 표현하고 공간의 일부로 다시 나눌 수 있다. `IfcRelContainedInSpatialStructure`는 물리 요소의 **주 포함 위치 하나**를 지정하며, `IfcRelReferencedInSpatialStructure`는 다른 층 등에도 연결할 수 있다. `IfcSpatialZone`은 온도·조명 등의 목적에 따라 **비계층·중첩 가능**한 구역을 표현한다. `IfcZone`은 물리적 형태 없이 여러 공간을 묶는 데 쓰인다.

**추출 가치**: ‘유일한 포함 부모’가 관리에 유익해도 모든 공간적 관계를 독점할 수는 없음을 보여준다. 건물, 객실, 설비, 여러 층에 걸친 승강기 통로, 여러 구역에 걸친 조명·온도 영역을 동일한 트리로 강제하지 않는다. 분류 헤드·물리 포함·기능상의 구역은 개념적으로 구별 가능하다.

**한계**: 전문 BIM 모델은 게임/TRPG 저작에 과도할 수 있고, 정확한 3D 경계가 없으면 일부 계산은 할 수 없다. 또한 ‘하나의 기본 포함’은 표준의 조직 방식이지 세계에 존재하는 모든 관계의 본체를 단일 부모로 제한한다는 의미는 아니다.

출처: [IfcSpace](https://technical.buildingsmart.org/projects/2024tunnel/schema/ifcproductextension/lexical/ifcspace.htm), [주 포함 관계](https://technical.buildingsmart.org/projects/2024tunnel/schema/ifcproductextension/lexical/ifcrelcontainedinspatialstructure.htm), [추가 참조 관계](https://technical.buildingsmart.org/projects/2024tunnel/schema/ifcproductextension/lexical/ifcrelreferencedinspatialstructure.htm), [IfcSpatialZone](https://technical.buildingsmart.org/projects/2024tunnel/schema/ifcproductextension/lexical/ifcspatialzone.htm), [IfcZone](https://buildingsmart.or.kr/newsfile/ifc4_3/HTML/lexical/IfcZone.htm)

### 3-2. OGC IndoorGML — 실공간의 분할과 통행 네트워크를 병렬로

**실제 방법**: 실내 공간을 cell로 분할하고, 인접(adjacency)과 연결(connectivity)을 구분하며, 실제 공간과 그 쌍대적 네트워크(공간 노드와 통행 링크)를 만든다. 논리적(연결만 존재)·기하적(위치·길이 존재) 경로를 구분한다. 여러 해석 층(예: 물리적인 구획, Wi-Fi 센서 범위)에서 서로 다른 분할을 허용한다. 2.0 개념 모델은 2025-08-28 공식 공개되었다.

**추출 가치**: 사용자가 생각한 **포함 계층과 무관한 이동 연결**을 정식 개념으로 연구할 만한 가장 직접적인 참고 자료 중 하나. 같은 물리 공간에서 목적에 따라 다른 네트워크를 얻을 수 있다.

**한계**: 모든 지하실, 산, 바다를 완전히 모델링해야 한다는 요구는 아니다. 원래는 실내 정보와 내비게이션 용도의 표준이며, TRPG의 벽 부수기·서사적 생성의 책임 규칙을 제공하지 않는다.

출처: [OGC IndoorGML 2.0 발표](https://www.ogc.org/announcement/ogc-publishes-indoorgml-2-0-part-1-conceptual-model-standard/), [멀티레이어 모델 개요](https://www.indoorgml.net/)

### 3-3. GeoSPARQL / W3C 공간 데이터 — 의미적 관계, 위상 관계, 거리·방향

**실제 방법**: GeoSPARQL은 공간 개체의 RDF 기술과 공간 질의를 위한 어휘를 제공하고, 정성적 공간 추론과 정량적 계산을 수용한다. 관계로는 포함/내부/접촉/교차/중첩/분리 등이 있다. W3C의 공간 데이터 가이드는 이름 있는 장소, 상대적 표현, 실제 좌표 등 **서로 다른 정확도와 참조 방법**을 목적에 맞게 사용할 수 있다고 설명한다.

**추출 가치**: `A는 B 안`, `A는 B 북쪽`, `A에서 B까지 40m`, `A는 B와 닿음`, `A는 B에서 보임`은 같은 유형의 사실이 아니다. 좌표 없는 정성적 관계도 유효한 세계 데이터가 될 수 있다.

**한계**: 위상 관계만으로 ‘통과 가능’, ‘한 방향으로 열림’, ‘보임’, ‘사회적으로 출입 허가됨’을 도출할 수 없다. 공간 관계들을 전부 RDF/온톨로지로 구현할 필요는 없다.

출처: [OGC GeoSPARQL](https://www.ogc.org/standards/geosparql/), [W3C Spatial Data on the Web Best Practices](https://www.w3.org/TR/sdw-bp/), [PostGIS ST_Contains](https://www.postgis.net/docs/ST_Contains.html)

### 3-4. 다층 공간 장면 그래프 — 로봇의 공간 이해

**실제 방법**: MIT의 Hydra 연구는 공간을 저수준 형상부터 물체·장소·방·건물 등 상위 의미 계층까지 연결한 3D scene graph로 표현한다. 계층 내/사이의 다양한 관계를 노드와 간선으로 다룬다.

**추출 가치**: 장소·사물·기하·연결을 같은 해상도의 평면 목록으로 만들지 않고 **여러 수준의 의미와 관계**로 나타내는 방향. 계층 표현이 꼭 ‘오직 포함 관계로만 구성된 트리’를 뜻하지 않는다는 점.

**한계**: 3D 센서·로봇 자율주행용 계산의 상당 부분은 텍스트 TRPG에 불필요하다. 설명할 수 없는 자동 인식 오류가 정본을 오염시킬 수 있다.

출처: [MIT Hydra 연구 초록](https://dspace.mit.edu/entities/publication/cfaa97a6-7969-46b0-9610-efe73c885421), [Hydra 오픈소스](https://github.com/MIT-SPARK/Hydra)

## 4. 이동 가능성·가시성·감각의 서로 다른 계산

### 4-1. Godot — 내비게이션 메시와 특수 이동 링크

**실제 방법**: 주어진 표면에서 이동 가능한 영역을 NavMesh로 나타내고, 서로 떨어진 영역에 사다리·도약대·순간이동 등의 특수 연결 `NavigationLink`를 둔다. 링크는 시작·끝 위치, 양방향 여부, 이동 비용 등의 속성을 갖는다. **경로 탐색기가 해당 링크를 선택했다고 해서 사다리를 오르는 행동 자체를 자동 실행하지는 않는다**. 실제 행동은 별도의 게임 코드가 처리한다.

**추출 가치**: ‘공간상 가능한 경로 후보’와 ‘행위자가 실제 이동을 수행하는 과정’을 분리하는 사례. 벽을 뚫으면 이동망을 갱신하되 파괴 자체는 다른 체계에서 처리하는 개념에 유익하다.

**한계**: 좌표·기하 NavMesh는 저작 비용이 크고 TRPG의 자유 발화·추상적인 장거리 이동에는 과한 경우가 많다.

출처: [NavigationRegions](https://docs.godotengine.org/en/latest/tutorials/navigation/navigation_using_navigationregions.html), [NavigationLinks](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationlinks.html)

### 4-2. Isovist / Visibility Graph — 위치별로 ‘보이는 범위’를 관계화

**실제 방법**: Isovist는 특정 시점에서 시야에 들어오는 영역을 나타내고, visibility graph는 장소의 여러 시점 사이의 상호 가시성을 그래프로 연결한다. 건축공간 분석에서 사용한다.

**추출 가치**: ‘같은 방에 있다’와 ‘서로 보인다’는 별개. 정밀한 가시성이 중요한 장면에서 공간의 형태·장애물을 기반으로 시야 후보를 제공하는 별도의 계산 틀이 있다.

**한계**: 선분/영역의 기하와 차폐물 데이터가 필요하다. 계측된 가시성이 실제 인물의 인지·식별을 자동 결정하지는 않는다.

출처: [Turner et al. (2001), From Isovists to Visibility Graphs](https://journals.sagepub.com/doi/10.1068/b2684)

### 4-3. TADS의 감각 경로 — 이동·시야·소리·냄새·접촉의 비일치

유리창은 **시야는 열려 있지만 물리적 접근은 차단**할 수 있다. 닫힌 문은 **이동이 차단되어도 소리는 전달**할 수 있다. 유리·종이·철망처럼 물리적 매질을 감각별로 다르게 평가한다. TADS는 실제로 시각/청각/후각/촉각을 분리한 재질 규칙을 갖는다.

**추출 가치**: 단일 `connected=true`에서 모든 공간적 상호작용을 유추하는 오류를 경계. 공간 영역이 경계·개구부의 정보만 제공하고 감각 영역이 이를 활용하는 가능성, 또는 공통 관계 사실을 쓰는 가능성을 조사할 근거가 된다.

출처: [TADS sense.t](https://tads.dev/docs/adv3/doc/libref/source/sense.t.html)

## 5. 세계 데이터와 실제 세션 세계의 관계에 관한 사례

### 5-1. Unity Prefab Variants / Evennia Prototypes — 공통 정의, 변형, 실체

**실제 방법**: Unity Prefab은 공통 객체 정의를 만들고, Prefab Variant가 이를 상속해 속성을 개별적으로 바꾸며, 씬에 생성된 인스턴스는 구체적인 객체로 존재한다. Evennia도 prototype 사전 정의와 prototype-parent의 재사용·오버라이드를 제공하며 실제 게임 객체를 생성한다.

**추출 가치**: ‘창작 정보 재사용’과 ‘세션에 존재하는 실제 장소·객체’는 구분할 수 있다. 변경된 인스턴스가 곧 원본 정의를 바꾸어서는 안 되는 경우가 많다. 사용자의 *가장 가까운 조상에서 속성 계승*은 이와 유사한 일부 성격을 가졌으나, **분류·구조 상속과 물리적 포함에 따른 계승은 꼭 같을 필요가 없다**는 대조 사례이기도 하다.

**한계**: 프리팹이 공간의 실제 물리적 위상을 보장하지 않으며, 런타임 변경과 베이스 데이터 갱신 정책은 별도 결정이 필요하다.

출처: [Unity Prefab Variants](https://docs.unity.com/en-us/engine/6000.0/manual/working-with-gameobjects/prefabs/prefab-variants), [Evennia Prototypes](https://www.evennia.com/docs/latest/api/evennia.prototypes.spawner.html)

### 5-2. Unreal Engine World Partition — 세계 정본과 로드된 공간의 분리

**실제 방법**: 월드 데이터를 하나의 지속 레벨 관점에서 관리하되 런타임에는 격자 셀로 분할해 스트리밍 소스 주변을 로드한다. 데이터 레이어와 HLOD(멀리 있는 것을 저해상도로 표현)도 구분한다.

**추출 가치**: **존재하는 세계 ≠ 현재 메모리에 구체적으로 활성화된 공간**. 복잡한 구역 전부를 한꺼번에 실제 판정할 필요는 없다는 힌트. 다만 정본과 메모리 로딩의 구분은 곧 사용자가 말한 ‘세계 데이터/세션 세계’의 두 층위와 동치가 아니다.

**한계**: 좌표 기반 자동 격자 분할은 텍스트 기반 사건 시뮬레이터의 표현 단위와 다를 수 있다. ‘스트리밍하지 않는 곳에는 중요한 일이 생기지 않는다’로 오해해서는 안 된다.

출처: [Unreal World Partition](https://dev.epicgames.com/documentation/unreal-engine/world-partition-in-unreal-engine), [HLOD](https://dev.epicgames.com/documentation/unreal-engine/world-partition---hierarchical-level-of-detail-in-unreal-engine)

### 5-3. Minecraft — 렌더 거리와 시뮬레이션 거리의 구별

**실제 방법**: 세계는 청크로 나누고 생성한다. Minecraft의 렌더 거리는 보여주는 범위, 시뮬레이션 거리는 게임의 틱 업데이트가 작동하는 범위이며, 지정된 예외 구역은 멀리 있어도 계속 처리할 수 있다.

**추출 가치**: ‘존재’, ‘저장됨’, ‘플레이어에게 보임’, ‘매 순간 정밀 시뮬레이션’은 서로 다른 상태다. 세션의 실제 세계와 시뮬레이션 실행의 범위를 반드시 일치시켜야 한다는 가정은 필요 없다.

**한계**: Minecraft의 일정 거리 밖 정지는 블록 기반 게임에 맞춘 구현 정책이다. TRPG 세계에서 멀리 있는 세력·사건·NPC의 변화까지 중단하면 세계의 개연성이 무너질 수 있다.

출처: [Microsoft Minecraft: Simulation Distance, Render Distance, and Ticking Areas](https://learn.microsoft.com/en-us/minecraft/creator/documents/simulationrenderdistanceguide?view=minecraft-bedrock-stable)

### 5-4. Roblox Instance Streaming — 참여자에게 전달된 세계와 서버의 세계 분리

**실제 방법**: 서버가 가진 공간 중 일부만 플레이어 클라이언트로 스트리밍한다. 중요 모델은 항상 전달하거나 그룹 전체를 함께 로드하게 할 수 있으며, 로드되지 않은 클라이언트의 공간 질의는 실제 서버 세계와 다를 수 있다. 공식 기술 문서는 **전체 세계를 반영해야 하는 시야 판정은 서버에서 하라**고 안내한다.

**추출 가치**: 세계 진실에 대한 질의와 현재 플레이어에게 제공된 로컬 표현을 혼동하지 말아야 한다. NPC·플레이어의 지식/시점과는 또 다른 기술적 구분이지만 시사점은 크다.

**한계**: 클라이언트 네트워크 스트리밍 기술 자체는 Discord TRPG에 직접 필요하지 않다.

출처: [Roblox Instance Streaming](https://create.roblox.com/docs/workspace/streaming), [Streaming Techniques](https://create.roblox.com/docs/workspace/streaming/techniques)

### 5-5. Event Sourcing — 공간 구조 변화의 기록과 재구성

**실제 방법**: 데이터의 최신 값만 저장하는 대신 변화 사건의 순서를 보존하고 현재 상태를 재구성하며, 성능을 위해 스냅샷을 쓸 수 있다. Microsoft는 이 방식의 감사·복구상 이점과 높은 복잡성·스키마 변경 난점을 함께 설명한다.

**추출 가치**: 벽 파괴·문 개방·길 붕괴·신규 공간 출현처럼 과거 사실과 현재 사실이 달라지는 사례에 적용 가능한 *변화 관리 아이디어*. 시간 영역, 사건 영역과의 관계를 밝히는 조사 소재.

**한계**: 사용자 프로젝트에 이벤트 소싱을 채택해야 한다는 뜻은 아니다. 모든 변화에 전면적인 이벤트 로그를 강제하면 구현 복잡성·비용이 증가한다. 변경 이력과 현재 정본의 유지 방법은 별도 문제다.

출처: [Microsoft Event Sourcing Pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)

## 6. AI와 절차적 공간 생성

### 6-1. Generative Agents (Smallville) — 객관적인 지도와 개별 에이전트의 공간 기억

**실제 방법**: Smallville의 물리적 공간·대상은 계층(세계→지역/건물→구역→객체)로 설명되고 에이전트는 자신이 관찰한 부분집합을 개인의 공간 기억으로 유지한다. 이동하는 동안 관찰 정보가 갱신되므로 오래된 기억과 현재 환경이 달라질 수 있다. 실제 구현은 타일 기반 환경과 경로 탐색도 사용한다.

**추출 가치**: ‘공간이 존재한다’는 객관 사실과 ‘인물이 공간 구조를 알고 있다’는 인지 사실을 분리해야 함을 보여주는 직접적인 AI 시뮬레이션 사례. LLM에는 내부 데이터 전체 대신 필요한 구역·대상을 자연어로 압축해 전달할 수도 있다.

**한계**: 논문의 목적은 인간 행동의 개연성 연구이며, 정교한 공간 물리나 일관된 임의 벽 파괴·재구축에 대한 보편적 해법은 아니다. 에이전트의 공간 기억과 정본 세계를 동기화하는 문제도 남는다.

출처: [Park et al., Generative Agents (UIST 2023)](https://doi.org/10.1145/3586183.3606763), [저자 코드](https://github.com/joonspk-research/generative_agents)

### 6-2. 실제 평면도 → 텍스트 게임의 공간 구조 변환(2023 연구)

**실제 방법**: 연구자들이 실제 실내 평면도에서 이동을 위한 공간적 단위와 연결을 추출하고 이를 TextWorld에 결합했다. 복잡한 공간 분할과 관찰자 중심 이동 언어를 추가해 대피 시나리오에 적용했다.

**추출 가치**: ‘복도·홀·실내 모든 경로를 텍스트 게임 속 장소로 표현’하고자 할 때, 단순 방 목록에 없던 **중간 공간 분할·방향/상대 위치의 표현**이 실제 연구 문제였다는 근거. 평면도 없이도 어떤 개념을 추가해야 하는지 사고 실험에 쓸 수 있다.

**한계**: 물리 평면도에서 개념을 자동 추출하는 연구로서, 지도 없이 자연어로만 무한한 세계를 생성하는 문제를 해결하지는 않는다.

출처: [Arabsheibani et al. (2023), From Floorplan to Navigation Concepts](https://agile-giss.copernicus.org/articles/4/2/2023/)

### 6-3. 절차적 생성 — 시드·제약·문법을 통한 미리 정의하지 않은 공간의 구체화

**실제 방법**: Minecraft는 지형·생태계·구조물 등을 세계 생성 규칙으로 구성한다. 게임 레벨 생성 연구에서는 액션/장면 제약을 그래프 문법으로 표현해 던전 구조를 만든다. Wave Function Collapse는 주변 패턴의 합법적인 조합을 제약으로 새 배치를 만든다.

**추출 가치**: ‘세계의 모든 위치에 대해 미리 텍스트를 작성할 것인가’에 대한 대안. 상위 세계관 규칙과 배치 제약이 있다면 미저작 공간을 요청 시 구체화하는 접근을 검토할 수 있다. 단, 알고리즘 생성은 공간의 **제약 만족**을 보장하는 범위에서만 일관성이 있으며 사건·서사 논리까지 자동 보장하지 않는다.

**한계**: 생성한 구조를 영속화하지 않으면 방문 때마다 바뀔 수 있다. 미리 설정된 사건·NPC·지리 사실과 충돌할 수 있으며, 제약 부족 시 국소적으로는 맞지만 전역적으로 모순될 수 있다. WFC는 본래 국소 패턴 제약 기법으로, 서사 개연성 보증 수단이 아니다.

출처: [Minecraft World Generation Overview](https://learn.microsoft.com/en-us/minecraft/creator/documents/world-generation), [Designing Procedurally Generated Levels (AIIDE)](https://ojs.aaai.org/index.php/AIIDE/article/view/12592), [WaveFunctionCollapse 원저자 저장소](https://github.com/mxgmn/wavefunctioncollapse/)

## 7. 서로 다른 표현 철학 비교 (조사 해석)

| 접근 | 정보의 기본 단위 | 강점 | 가장 큰 구멍/비용 |
|---|---|---|---|
| A. 장소 노드 + 출구 그래프 | 방·장소·연결 | 저작 친화적, 이동·설명 간결 | 임의 위치/비정해진 이동, 시야·거리 |
| B. 순수 계층 포함 트리 | 공간·상위공간 | 중첩 장소 관리, 속성 계승 | 교차·중첩, 역동적 외부 연결, 통과 |
| C. 위상·의미 관계 그래프 | 개체·공간 관계 | 유연한 방향/포함/접촉/참조 | 거리·형상·계산 정밀도가 부족할 수 있음 |
| D. 좌표/격자/기하 중심 | 셀·좌표·형상 | 임의 위치·가시성·경로 계산 | 저작·연산 비용, 이야기 의미의 결핍 |
| E. 다층(계층+네트워크+필요시 기하) | 복수의 공간적 관점 | 여러 문제에 적합한 표현을 병용 | 정합성·중복·변경 전파의 복잡성 |
| F. 생성 규칙 중심 | 제약·생성기·시드 | 미저작 공간 확장, 저작 부담 완화 | 생성 이후 일관성·영속성·정본 통제 |
| G. 장면별 서술/Zone 중심 | 서술적 구역·장면 | 낮은 비용, TRPG 판단에 맞는 해상도 | 반복 방문과 지속적 물리 관계 일치가 어려움 |

위 접근들은 실제 제품에서도 서로 섞여 있다. ‘단일 승자’를 가리기 위한 선택지가 아니라, 무엇을 **세계 사실로 보존**하고 무엇을 **목적에 맞게 계산·투영**할지 논의하기 위한 비교 축이다.

## 8. 두 층위에서 검토할 수 있는 데이터 요소 (제안이 아닌 조사 목록)

**세계 데이터 후보**
- 장소·범주·구획의 식별과 의미, 구조·배치 제약, 상대 위치와 위상 사실.
- 일반적 장소의 기본 외관·분위기·저작 템플릿 및 제한된 속성 계승 정책.
- 정의된 통로·경계·구조물·이동 수단과 초기 조건.
- 지형·건축·통과·감각·구획 생성에 사용할 일반 규칙 또는 기본값.
- 장면에 대한 최소 기술, 보완 가능 범위, 원래부터 미정인 내용.

**세션에서 성립하는 세계의 후보**
- 특정 세션/세계 인스턴스의 실제 장소, 실재화된 하위 공간·경로·물체.
- 열린 문, 파괴된 벽, 생긴 구멍, 무너진 길, 옮겨진 물체 등 시점별 상태.
- 원래 없던 장소나 연결이 실제로 확정된 경우의 영속적인 식별과 사실.
- 각 주체의 현재 위치, 행동 경로, 물리적 점유, 허용되는 이동.
- 공간 관계를 근거로 계산된 현재 경로·시야·음향 등 *파생 결과*.

**별도로 혼동하지 않아야 할 축**
1. 정본 세계 사실 **대** 인물의 공간 지식·착각·미지(정보 영역 관련).
2. 세션에 실제로 존재하는 세계 **대** 매 순간 고정밀로 계산하는 활성 구역(실행 전략 관련).
3. 실제 공간 **대** 장면/화면에 표시되거나 LLM에 전달된 서술(사용자 경험 관련).
4. 작가가 사전에 명시한 정보 **대** 규칙·판정을 거쳐 생성·확정된 정보(저작/출처 관리 관련).
5. 세계의 위치·경계 **대** 행위자별 실질적 이동·접근 가능성(행동/물건/신체 등 관련).

## 9. 반례 및 검증용 시나리오

1. **숙박시설**: 건물→복도/객실→방/화장실. 상위 분위기를 계승하지만 객실의 예외 상태는 독자적임.
2. **두 건물의 구름다리**: 각 건물이 독립 상위 장소이고 연결하는 구름다리는 외부 이동 구역. 소속·포함·접촉·이동이 서로 다른 사실임.
3. **길게 이어진 도로**: 관리 편의상 도로를 나누더라도 한 도로라는 연속성을 잃지 않아야 함. 구간 경계가 세계 내 물리적 장벽이라는 잘못된 해석을 방지해야 함.
4. **잠긴 문**: 인접·연결은 있으나 인물에 따라 통과 불가. 잠금 해제가 공간 그래프 자체의 소멸/재생을 요구하는지는 미결정.
5. **유리창과 철창**: 시야, 청각, 냄새, 접촉, 물건 통과, 신체 통과가 서로 다를 수 있음.
6. **벽에 구멍 만들기**: 통로 개설뿐 아니라 경계면·가시성·소리 전달·파손 정도가 달라짐. 구조물 사실과 이동 경로 변경의 정합성이 관건.
7. **숨은 통로**: 현실에는 존재하지만 인물이 모르거나 발견하지 못했음. 세계의 통로 존재와 인물의 지식은 다름.
8. **숲속에서 길 이탈**: 미리 지정된 노드·도로만 있는 경우 횡단·우회·새 길 찾기를 어떻게 처리할 것인가.
9. **거대한 광장/공장**: 하나의 이름 붙은 장소라도 입구에서 반대편 물체를 만질 수 없음. 내부 거리·장애물·부분 가시성의 필요 수준은 장면마다 다름.
10. **양쪽으로 돌출된 구조물**: 벽·계단·배관·광원 등이 복수 장소에 걸쳐 있거나 모두에 영향을 줌. 한 부모 관계만으로 충분한가.
11. **원거리 사건**: 플레이어가 다른 지역에 있어도 다리가 붕괴하거나 세력이 이동함. ‘활성화되지 않음’은 ‘세계에 변화 없음’을 뜻하지 않음.
12. **생성된 미저작 장소 재방문**: 새 장소가 처음 확정된 시점, 원래 세계 데이터에 없던 것이 어디까지 영속하며 무엇이 변경 가능한가.
13. **위치별 전망 차이**: 2층의 창가와 방 중앙에서 보이는 내용이 다름. 방 단위 가시성이 한계를 드러내는지 검증.
14. **이동수단 차이**: 같은 구간에서 사람·쥐·드론·차량의 경로가 다름. 이동 가능성을 보편적 공간 속성으로만 저장할 수 없는 사례.

## 10. 조사에서 드러난 주요 분석 결과

### 관찰 1 — 단일 계층이 감당하기 어려운 관계가 많다

IFC의 단일 주 포함 관계와 중첩되는 SpatialZone, IndoorGML의 복수 레이어, 로봇의 다층 장면 그래프는 공통적으로 **‘한 공간의 대표적인 계층’과 ‘그 밖의 공간적 관계’가 공존**함을 보여준다. 원래 구상을 당장 폐기해야 한다는 결론은 아니다. 다만 *계층만을 모든 공간 관계의 정본으로 삼는 것*과 *저작 편의상 대표 계층을 사용하는 것*은 다르다.

### 관찰 2 — 모든 장소를 미리 저작하지 않아도 모든 행동을 받아들일 수 있는 방향이 있다

Inform/MUD의 고정 Room/Exit 그래프는 간단하지만 자유로운 횡단을 제한한다. 지도·기하, 상대 관계, 생성 규칙, 장면별 추상화를 상황에 따라 결합하면 미저작 공간을 설명할 여지가 있다. 그러나 미저작 공간을 생성하는 시점에는 **사용자의 선언이 아무 세계 사실이나 임의 변경하도록 할 것인지**, 기존 세계의 제약에 따라 보완할 것인지 책임 경계가 중요하다.

### 관찰 3 — 이동 그래프·시야 그래프·감각 전달 그래프는 같을 필요가 없다

TADS와 Godot 사례가 명확하다. 공간의 인접 관계, 실제 통과할 경로, 시야/소리/냄새의 전달은 서로 다른 조건을 가진다. 동일한 물리적 경계 사실에서 여러 관점의 관계를 계산하는 방식과, 각각 별도 관계를 저작하는 방식에는 정합성·비용 차이가 있다.

### 관찰 4 — ‘공간의 표현 정밀도’와 ‘시뮬레이션의 정밀도’는 직교할 수 있다

World Partition·Minecraft·Fate는 서로 목적은 달라도 세계 공간의 상세도와 실행/묘사의 상세도를 획일화할 필요가 없음을 보여준다. 고정 격자, 고정된 방 목록, 장면 Zone 각각이 하나의 사용처에 최적화된 *공간 해석 방법*일 수 있다.

### 관찰 5 — 두 층위를 실제로 분리한다면 동기화·영속화가 핵심이다

Prefab/Prototype의 정의→실체, TextWorld의 Logic→State, 생성 규칙→실제 생성된 지형, Event Sourcing의 변경 기록→현재 상태는 서로 다른 ‘기본 정보와 구체 세계’의 관계를 보여준다. 그러나 **정의가 바뀌면 세션 중 기존 장소도 바뀌는지**, **새로 발견한 공간을 어디에 기록하는지**, **초기에 미정이던 정보가 확정되면 어느 층위의 사실이 되는지**는 서로 다른 정책이다.

### 관찰 6 — 데이터가 없다는 뜻을 명확히 해야 한다

미등록 통로는 ‘실제로 통로가 없음’, ‘아직 저작하지 않음’, ‘어떤 인물도 모르고 있음’, ‘이 시점의 이동 수단으로 접근 불가’ 중 무엇일 수 있다. 저작 가능한 개방형 TRPG에서는 이 차이를 덮어두면 새 행동을 불허하거나 즉석 생성으로 이미 확정된 사실을 침해할 위험이 있다.

## 11. 후속 탐색에서 실제로 가치 있는 쟁점(확정 안 함)

- 물리적 장소의 대표적인 분할과, 감각/이동/관리상 추가 영역을 어떻게 구별할지.
- 장면에서 장소의 상세도를 바꾸어도 같은 장소와 사실을 지속적으로 식별할 수 있을지.
- 포함 트리와 이동/감각 네트워크 중 어느 쪽을 원본으로 놓고 어느 쪽을 파생할지(또는 둘 다 정본인지).
- 텍스트만으로 정해진 정성적 관계와 명시적 거리·좌표·기하를 어느 수준까지 함께 허용할지.
- 통로 존재, 통과 가능성, 주체별 통과 능력, 실제 이동 실행의 책임을 어떻게 구별할지.
- 미저작 공간의 존재 추정·생성·검증·확정을 어느 시점에 수행할지.
- 세계 데이터의 변경이 실제 세션 세계에 미치는 영향, 새 공간의 고정·수정·회귀 방법.
- 인물별 공간 기억과 객관적 공간 사실이 불일치할 때의 참조·표시 방법.

이 목록은 검토할 만한 문제의 축이며 사용자 승인 없이 설계 정책으로 승격할 수 없다.

## 1. 기성 장소 조각의 결합: 조사와 추출 가치

### 1.1. Unity Prefab / Unreal Level Instance
- Unity Prefab은 객체 구성·속성·자식 구조를 재사용하며, 인스턴스별 오버라이드·중첩·변형을 지원한다.
- Unreal Level Instancing은 저작된 작은 레벨 구성(건물·관심 지점 등)을 반복 배치하며 원본 수정 사항을 재사용할 수 있다.
- **INDAIM에 주는 착안점**: 조각의 공통 정의와 실제 세계에 배치된 개별 공간의 **동일성을 분리**할 수 있다. 같은 '일반주택 내부 조각'을 두 번 가져오더라도, 두 주택 내부의 문·사물·손상 상태까지 같은 개체로 취급하면 안 된다.
- **주의**: 엔진 프리팹은 원본 변경을 인스턴스에 전파할 수 있으나, 이를 이미 진행 중인 세션의 세계에 그대로 적용해야 하는지는 별도 정책이다.

출처: [Unity Prefab](https://docs.unity3d.com/kr/current/Manual/Prefabs.html), [Unreal Level Instancing](https://dev.epicgames.com/documentation/unreal-engine/level-instancing-in-unreal-engine)

### 1.2. Dungeon Architect — 모듈, 결합 지점과 여분 개구부
- Snap 기반 조립의 **모듈은 미리 제작된 방이나 복도**이며, 각 모듈의 출입 가능 가장자리에 **결합점(connection)**을 둔다.
- 두 모듈이 해당 지점에서 연결되면 문을 배치하고, 연결되지 않은 결합점에는 벽을 배치할 수 있다.
- 모듈의 경계와 방향, 회전, 출입 가능 지점이 맞아야 한다. 일부 방식은 일정한 크기 단위를, 일부는 임의 모양의 경계를 사용한다.
- **INDAIM에 주는 착안점**: '조각 A와 B를 함께 놓는다'는 행위와 '실제로 통과 가능한 연결이 생겼다'는 사실은 다르다. 공간 결합에 앞서 결합 가능한 접점, 남는 접점의 종결 상태, 중복 점유·내부 모순을 검토할 수 있다.
- **핵심 위험**: 서로 다른 조각이 겹치거나, 출입구가 없는 면끼리 연결되거나, 빈 공간이 남는 문제를 사후 서사 보정으로 숨기지 말아야 한다.

출처: [Dungeon Architect Modules](https://docs.dungeonarchitect.dev/unreal/snap-flow/snapflow-design-module/), [Connections](https://docs.dungeonarchitect.dev/unity/snap-flow/snapflow-connections/), [Snap Grid Flow Connections](https://docs.dungeonarchitect.dev/unity/snap-grid-flow/sgf-connections/)

### 1.3. 조각 결합에서 검토할 정보(조사 기반의 후보, 확정 아님)
| 측면 | 검토할 정보 | 그렇지 않으면 생길 수 있는 오류 |
|---|---|---|
| 저작 원형 | 조각의 종류·식별자·기본 내부 구성 | 서로 다른 곳에 배치된 조각의 상태 혼동 |
| 배치 | 조각이 놓인 공간·방향·규모·기존 공간과의 관계 | 중복 점유, 물리적으로 불가능한 배치 |
| 접속 | 결합 가능한 경계·개구부·출입 방향·상대 위치 | 벽으로 막힌 곳을 출입구로 간주 |
| 종결 | 연결되지 않은 접점의 마감·차단 상태 | 갑자기 외부로 통하는 문 생성 |
| 동일성 | 원형과 각 배치 결과의 구분 | 한 집의 파손이 다른 집에도 전파 |
| 변형 | 세션에서 바뀐 구조·상태와 공통 원형의 관계 | 조각 재호출 때 변경 내역 소실 |
| 정합성 | 주변 세계의 기존 사실·연결·물리적 차지 공간 | 기존 장소와 충돌하거나 설정 무단 변경 |

**미해결 핵심 문제**: 재사용한다는 것이 (1) 원형을 복제해 독립된 장소로 만드는지, (2) 기존 장소 구조를 가져와 편집하는지, (3) 이미 저작된 여러 공간 간 결합만 선택하는지를 뜻하는지는 아직 결정되지 않았다. 이 차이는 외부 사례로부터 자동 결정할 수 없다.

## 2. 이동·연결: 장소 그래프만으로 다루기 어려운 사실

### 2.1. 공간 인접성, 경계, 통행 가능성의 구별
- OGC **IndoorGML 2.0**은 공간과 그 분할, 연결의 유형, **논리적·측정적 내비게이션 네트워크**를 구별한다.
- buildingSMART IFC의 **IfcRelSpaceBoundary** 계열은 공간을 둘러싼 경계가 물리적인지 가상적인지, 경계의 건축 요소가 무엇인지, 반대편에 다른 공간이 있는지를 모델링한다. 열전달을 위해 공간 반대편과 재료가 바뀌는 지점에 따라 경계를 세분하는 사례가 있다.
- **INDAIM에 주는 착안점**: A와 B가 물리적으로 맞닿아 있더라도 통과 가능한 출입구가 없을 수 있다. 그 사이의 벽은 통행 연결이 없더라도 이미 존재하는 경계일 수 있다. 벽을 뚫을 때 처음부터 물리적 인접 관계를 창작해야 하는 것과, 기존 경계에 개구부를 추가하는 것은 다르다.

출처: [OGC IndoorGML 2.0 발표](https://www.ogc.org/announcement/ogc-publishes-indoorgml-2-0-part-1-conceptual-model-standard/), [IfcRelSpaceBoundary](https://technical.buildingsmart.org/projects/2024tunnel/schema/ifcproductextension/lexical/ifcrelspaceboundary.htm), [2nd-level space boundary](https://technical.buildingsmart.org/projects/2024tunnel/schema/ifcproductextension/lexical/ifcrelspaceboundary2ndlevel.htm)

### 2.2. 경로 후보, 통과 조건, 이동 행동의 구별
- Godot NavigationLink는 떨어진 통행 영역을 잇고 양방향 여부·시작/끝점 등을 표현한다. **경로를 찾았다는 사실만으로 도약·사다리 오르기 등의 실제 행위가 실행되지는 않는다.**
- Godot는 행위자 크기(높이·반경), 서기/기어가기 등의 이동 자세, 출입 가능 등급에 따라 서로 다른 경로를 찾을 수 있다.
- Godot의 출입 제어 설명에 따르면 경로 검색 조건 변경과 기존 경로 갱신은 구분된다. 따라서 시간이 지나 문 상태가 변하면 기존 탐색 결과가 낡을 수 있다.
- **INDAIM에 주는 착안점**: 연결된 장소들 사이에 가능한 **이동 후보**가 있고, 실제 가능한지는 특정 주체의 크기·기술·열쇠·상태·행동에 따라 달라진다. 고정된 `이동가능=true/false`는 일반적인 사실을 표현하지 못한다.

출처: [Godot NavigationLinks](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationlinks.html), [행위자 크기](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_different_actor_types.html), [행위자 자세](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_different_actor_locomotion.html), [구역 접근](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_different_actor_area_access.html)

### 2.3. 공간 구조 변화 후 재계산
- Unreal의 내비게이션 메시는 충돌 지형으로부터 경로 그래프를 만든다. 동적 갱신 시 변화가 영향을 미친 부분을 다시 처리할 수 있다.
- 이 사례를 INDAIM에 대입하면, '벽 파괴'는 새 장소를 저작한다는 의미가 아니라 **기존 경계의 변화**가 이동 경로와 감각·환경의 전파 조건에 영향을 미칠 수 있다는 것을 보여준다.
- 주의: Unreal의 구현을 그대로 도입할 필요는 없다. 조사 가치가 있는 것은 **원인이 된 물리적 변화**와 **그 변화로 무효화되는 파생 판단**의 관계다.

출처: [Unreal Navigation System](https://dev.epicgames.com/documentation/unreal-engine/navigation-system-in-unreal-engine), [Dynamic Navigation Mesh](https://dev.epicgames.com/documentation/unreal-engine/overview-of-how-to-modify-the-navigation-mesh-in-unreal-engine)

### 2.4. 길·산·복도 등 개방 공간을 분할할 때
- 장거리 도로나 넓은 들판을 여러 장소로 나누는 **관리상 경계**가 반드시 벽·문과 같은 **물리적 장벽**은 아니다.
- 외관상 이어진 도로가 두 장소 항목으로 나뉘어도, 연결 경계에서 통행·시야·소리가 갑자기 차단되어서는 안 된다.
- 반대로 하나의 큰 공간 항목 안에도 담장, 장애물, 낙차, 출입구가 있을 수 있으므로 내부 이동이 항상 자유로운 것은 아니다.
- **검토 사항**: 장소를 나누는 단위(저작·탐색·관리 목적)와 실제 물리적 장애/접속 구조가 다를 수 있다. 이와 관련된 표현의 세밀도는 아직 미결정.

## 3. 광원·시야: 공간과 감각을 이어 주는 인과 정보

### 3.1. Radiance — 장면의 형상, 재료, 광원, 시간·하늘 조건
- 건축 조명 시뮬레이터 Radiance의 주요 입력은 **장면 형상(geometry), 표면 재질, 조명기구, 시간·날짜·하늘 조건**이다. 산출은 지점의 조도, 표면 휘도, 눈부심 등이다.
- 시야가 열려 있는 것과 충분한 광량이 도달하는 것은 다르다. 투명한 창문은 구조물 너머를 볼 가능성을 열지만, 역광/암부/눈부심/연기 같은 요인으로 실제 판별력은 달라진다.
- 조명은 다른 공간까지 전파되며, 광원이 동일해도 위치·시점에 따라 밝기와 그늘이 다르다.
- **INDAIM에 주는 착안점**: 공간의 '밝음'이라는 정적 문자열과 실제 광원·가림·유입 경로의 정보를 구별하면, 문 개폐·전원 차단·시간 변화 시 일관성 향상 가능성이 있다.

출처: [Radiance 소개](https://www.radiance-online.org/about), [Godot 조명·차폐](https://docs.godotengine.org/ko/4.x/tutorials/2d/2d_lights_and_shadows.html)

### 3.2. TADS 3 — 빛이 도달하고 인물이 감지하는 경로는 별개
- TADS 3는 소재의 `seeThru`, `hearThru`, `smellThru`, `touchThru`를 구별하고, 빛의 존재 및 감각 경로의 투명도와 대상 크기에 따라 감각 가능성을 판정한다.
- 단순 `상호가시=true`보다 **광원, 장애물, 거리, 시야 방향, 관측 대상의 크기·대비** 등이 중요한 논점이라는 사례다. 다만 TADS의 규칙은 개략적이고 광학·음향 물리의 정밀 모델이 아니다.

출처: [TADS 3 sense.t](https://tads.dev/docs/adv3/doc/libref/source/sense.t.html)

### 3.3. 후보 입력 정보(확정 아님)
- 광원 측: 위치 또는 작용 범위, 밝기·색, 방향성, 지속성·작동 상태, 외부 자연광 여부.
- 경계 측: 불투명·반투명·투명, 틈과 개구부, 차폐물, 반사/흡수 특성.
- 관찰 측: 대상/관찰자의 위치, 가려짐, 대비, 광량, 시야 방향; 인식·해석의 세부는 감각/정보 영역과 협력.
- 최소화 가능성: 장소별 서술형 '밝음/어두움'만 보관 → 빠르지만 동적 영향과 위치 차이 처리에 약함. 광학 엔진 수준 계산 → 정확하지만 텍스트 TRPG에는 비용 과다.

## 4. 온도·공기·연기: 장소와 시뮬레이션 구역의 불일치

### 4.1. EnergyPlus — Surface / Space / Zone / Enclosure
- EnergyPlus는 **표면(Surface), 공간(Space), 열 구역(Zone), 복사·일광 교환 영역(Enclosure)**을 구별한다.
- 하나의 열 구역은 여러 공간을 포함할 수 있고, 열 구역에서 공기 온도와 습도의 열·수지 평형을 계산한다. 복사 교환을 위한 Enclosure는 반드시 같은 분할이 아니다.
- 열 구역의 공기 온도는 실내 발열, 벽의 대류, 외기 침투, 이웃 구역의 공기 혼합, HVAC 등의 영향을 받는다.
- **핵심 발견**: 장소 트리를 열 구역 트리로 그대로 복제할 필요는 없다. 실제 '한 장소 항목'보다 넓거나 좁은 환경 계산 단위가 사용될 수 있다. 각 장소마다 개별 온도를 저장하는 것이 반드시 정확하지도 않다.

출처: [EnergyPlus Building Surfaces, Spaces, Zones, Enclosures](https://energyplus.readthedocs.io/en/stable/guides/engineering-reference/1.3-building-spaces-zones-enclosures.html), [Zone Air Heat Balance](https://energyplus.readthedocs.io/en/stable/guides/engineering-reference/2.1-basis-for-the-zone-and-air-system-integration.html), [Inside Heat Balance](https://energyplus.readthedocs.io/en/latest/guides/engineering-reference/3.6-inside-heat-balance.html)

### 4.2. EnergyPlus AirflowNetwork / NIST CONTAM — 공기 연결과 물질 이동
- EnergyPlus의 AirflowNetwork는 공간 구역을 노드로, 문·창문·균열·환기 설비를 공기 흐름의 연결로 다룬다. **문이 닫혀도 틈으로 공기가 흐를 수 있다.** 공기 흐름은 압력 차, 바람, 부력과 개구부 상태 등에 의해 달라진다.
- NIST CONTAM은 이와 관련하여 실내외 공기 흐름, 오염물질·연기의 공간 간 이동, 오염물질의 제거·침착 등을 계산한다.
- **핵심 발견**: 사람의 이동 경로, 공기의 이동 경로, 열의 이동 경로는 같지 않다. 단열벽은 통행 불가능해도 열을 전달하고, 닫힌 문도 누기가 있으며, 열린 환기구는 공기가 지나가지만 사람이 통과할 수 없을 수 있다.
- **한계**: 다구역 모형은 보통 각 구역을 균일하게 혼합된 공기로 간주한다. 층위별로 연기가 쌓이는 현상 등은 이 가정에서 놓칠 수 있다.

출처: [EnergyPlus AirflowNetwork](https://energyplus.readthedocs.io/en/stable/guides/engineering-reference/13.1-airflownetwork-model.html), [NIST CONTAM](https://www.nist.gov/services-resources/software/contam), [NIST Smoke Management limitations](https://www.nist.gov/el/beed/nist-multizone-modeling/applications/smoke-management)

### 4.3. 후보 입력 정보(확정 아님)
- 구역 측: 부피, 대략적인 밀폐 정도, 내부 발열/냉각원, 외부 환경의 영향, 시간에 따른 상태.
- 경계 측: 벽·문·창문의 열전달 성질, 개구부 면적, 틈새, 외기 연결, 개폐 상태.
- 물질/현상 측: 온도·습도·공기 흐름·오염원/냄새/연기 등의 발생과 감쇠.
- **책임 유의**: 현재 사용자는 환경 상태를 *환경 및 현상* 영역이 주관한다는 방향을 제시했다. 공간 영역에서는 이를 가능하게 하는 형상·인접·경계·개구부 등의 정보 요구사항을 추출하되 온도/공기 계산 책임은 임의로 가져오지 않는다.

## 5. 소리: 단순한 ‘방 간 들림’보다 중요한 전달 방식

### 5.1. Steam Audio — 직접 경로, 차폐, 투과, 반사, 우회 경로
- Steam Audio는 소리를 만드는 대상과 듣는 대상의 위치 사이에서 **직접음의 차폐(occlusion)**, 구조물 재질을 통한 **투과(transmission)**, **반사·잔향**, 문·창문·복도를 따라 돌아가는 **다중 경로**를 구분한다.
- 문을 열면 직접음이 갑자기 들리기 시작하고, 닫혀 있어도 벽을 통한 감쇠된 소리는 남을 수 있다.
- **INDAIM에 주는 착안점**: 단일 `들을 수 있음 / 없음`보다 음원 위치, 거리, 경계의 재질·개폐, 통로의 경로, 주변 소음 등을 근거로 '어렴풋이', '웅웅거림', '말을 분간 가능' 등의 판단을 할 수 있다.

출처: [Valve Steam Audio](https://partner.steamgames.com/doc/features/steam_audio), [Steam Audio Core Guide](https://github.com/ValveSoftware/steam-audio/blob/master/core/doc/guide.rst)

### 5.2. Wwise — Rooms & Portals
- Wwise의 Rooms & Portals는 음향학적 방과 문·개구부를 모델링해 방 사이로 전달되는 소리와 잔향을 제어한다. 한 시스템의 공간 분할 목적이 꼭 장소의 포함 계층과 같지는 않다는 추가 근거다.
- 열린 통로가 없어도 구조물 매질을 통해 감쇠된 음이 전달될 수 있으므로, 통행 그래프를 곧 음향 그래프로 삼을 수 없다.

출처: [Wwise Rooms and Portals Tutorial](https://documentation.help/Wwise-Unity/pg__rooms__portals__tut.html)

### 5.3. 후보 입력 정보(확정 아님)
- 음원: 위치 또는 영역, 세기, 소리 종류·대략적 주파수 성격, 지속시간.
- 공간·경계: 거리, 구조적 차폐, 벽·문·유리의 흡음/투과, 개구부, 반사적 공간 성격(넓이·마감·잔향).
- 청취 측: 청취 위치, 배경 소음, 신체·감각 상태. 인지·의미 해석은 후속 감각·정보 영역과 연결.
- 모든 공간에서 정밀한 음향 시뮬레이션이 필요하다는 뜻은 아니다. **연결 구조가 감쇠·굴절·차폐 같은 간략 판단의 근거를 제공할 수 있느냐**가 관건이다.

| 투명한 유리창 설치 | 일반적인 보행 차단 | 빛/시선 일부 투과 | 감쇠된 소리 | 공기 흐름 억제, 열전달 존재 |
| 창문 개방 | 일부 주체 통과 가능 | 차폐 일부 제거 | 직접 전달 경로 증가 | 외기 유입·열교환 변화 |
| 벽에 구멍 생성 | 개구부 크기·주체에 따라 새 통행 가능 | 새로운 시선/빛 경로 | 새로운 직접·우회 소리 경로 | 공기·연기·냄새 흐름 경로 변화 |
| 얇은 벽 유지 | 통과 불가 | 시선 차폐 | 진동에 의한 투과음 가능 | 열전도 가능 |
| 장거리 도로의 장소 항목 분할 | 원래 이어진 도로라면 이동 유지 | 행정적 분할로 차폐 발생하지 않음 | 행정적 분할로 차폐 발생하지 않음 | 행정적 분할로 인공적인 환경 경계가 생기면 오류 |

표는 물리적 경향에 대한 예시이다. 모든 사례에 대해 정량적인 계산이나 실시간 시뮬레이션을 요구하는 것이 아니다.

## 7. 접근법 비교 — 설계안 선택이 아닌 연구상 대안

| 표현 철학 | 주요 원본 정보 | 강점 | 한계/비용 | 특히 유용한 맥락 |
|---|---|---|---|---|
| **A. 장소 그래프·조건부 연결 중심** | 장소, 저작된 연결, 연결 조건, 간단 환경 태그 | 텍스트 저작 용이·계산 간단·검사 가능 | 이동 통로가 없는 벽의 인접성, 빛/열/소리 전파 설명 어려움 | 서사 중심·거친 해상도의 이동과 감각 묘사 |
| **B. 공간 구획·물리적 경계 중심** | 구획, 공유 경계, 재료, 개구부, 관계 | 물리적 변화 하나에서 여러 효과의 공통 근거 확보 | 경계 정보 저작 부담·지속적 갱신 비용 | 벽 파괴·개폐·연기·소리·환경 상호작용 비중 높을 때 |
| **C. 위치/형상 기반 공간 중심** | 좌표·상대 위치·형상·장애물·재료 | 거리, 경로, 그림자, 세부 시점 계산 | 막대한 저작·계산 부담, 임의 정밀도 요구 | 촘촘한 위치·시야·물리적 공간 판단이 중요한 구역 |
| **D. 목적별 축약 공간 모델** | 장소와는 별도로 이동/열/음향/조명에 필요한 요약 영역·연결 | 필요한 정확도만 계산·비용 통제 | 같은 세계 사실의 중복·불일치가 발생하기 쉬움 | 넓은 세계와 일부 고충실도 지역을 공존시킬 때 |

실제 시스템은 일부 요소를 결합할 수 있다. **그러나 임의로 A+B+C+D의 모든 요소를 쌓는 것이 정답이라는 근거는 없다.** 설계의 정당성은 필요한 행동·환경 파급을 실제로 얼마나 적은 정보와 일관된 규칙으로 처리하는지에 달려 있다.

## 10. 주요 결론(조사자의 해석, 채택 여부 미정)

1. **기성 장소 조각을 재사용하는 방법에는 탄탄한 실례가 있다.** 그러나 조각 자체의 재사용과 결합된 세계의 물리적 정합성은 별개 문제다.
2. **장소 사이의 이동 연결만 기록하면 설명되지 않는 상태가 많다.** 두 장소를 가르는 경계와 그 경계를 이루는 재질·개구부는 이동 외의 환경과도 연결된다.
3. **환경 계산의 구획은 장소의 계층·분할과 일치하지 않을 수 있다.** 특히 EnergyPlus의 Space/Zone/Enclosure 구분은 온도와 광학적 교환에서 이 차이를 보여준다.
4. **빛·열·공기·소리는 같은 통로를 동일하게 따라가지 않는다.** 하나의 `연결` 값을 모두에게 적용하는 것은 오류를 낳을 수 있다.
5. **미리 저작된 조각의 결합과 임의의 새 공간 창작은 구별된다.** 전자는 기존 콘텐츠의 선택·배치·접속을 포함하며, 결합 결과의 신규 구조가 허용되는 범위는 후속 검토가 필요하다.
6. **정밀한 물리 시뮬레이션이 곧 목표는 아니다.** 표현된 정보가 의미 있는 상태 변화를 일관되게 설명할 수 있는지가 우선이다.

# INDAIM 전면 재설계 — 02. 장소 및 공간 통합 설계안

- **문서 버전:** v0.1
- **작성일:** 2026-11-08
- **문서 지위:** **논의용 통합 설계 초안. 사용자 승인 전이며, 확정 설계가 아니다.**
- **작성 목적:** 사용자의 장소·공간 초기 구상, 이후 명시한 방침, 두 차례의 조사, GPT 제안의 재평가를 하나의 일관된 설계 후보로 통합한다.
- **적용 범위:** 장소 및 공간의 세계 정보 표현과 상태 변화, 이동 및 타 영역에 제공할 공간적 근거. 구체적인 DB 스키마·API·모듈 경계·계산 알고리즘은 확정하지 않는다.

## 0. 핵심 요약

INDAIM의 공간은 **장소를 조직하는 계층**, **계층과 독립적인 공간 관계 및 이동 연결**, **필요할 때 참고할 수 있는 위치·구조·서술 정보**, **세션에서 변화하는 실제 상태**를 함께 사용해 표현하는 방향으로 설계한다.

- 비공간적인 **복수의 최상위 분류 헤드** 아래에 물리적 장소 계층의 **상위 항목(뿌리 장소)**을 둔다. 하위 장소와 부모의 관계는 물리적 포함이다.
- **사전에 선정한 속성에만** 최근접 조상 값 계승을 적용한다. 분류 헤드에 속한다는 사실만으로 물리적 인접성이나 이동 연결을 뜻하지 않는다.
- 복도·도로·산·들판·공터 등도 공간 표현에 포함한다. 길고 큰 공간은 관리상 분할할 수 있지만, 분할 자체가 물리적 장벽을 만들지는 않는다.
- **포함·인접·연결·실제 통과 가능성·실행된 이동**은 다른 개념이다. 경로의 존재와 실제 통과 판단은 구별한다.
- 문·창문·벽·구멍 같은 **경계·구조의 중요한 사실**을 필요에 따라 표현한다. 모든 경계의 재질이나 음향·광학·열역학 수치를 의무적으로 모델링하지 않는다.
- 공간 내부의 위치는 자연어 상대 위치·기준점·수치 정보 중 **상황에 유용한 정밀도**로 표현한다. 좌표계는 일반 요구사항이 아니다.
- 구조 변화가 생기면 **원인이 되는 세계의 사실과 지속되는 결과**를 갱신한다. 광량·소리·온도·공기 흐름 등 모든 파급 효과를 자동 계산·상태화하지 않는다. 필요한 시점에 구조화된 계산과 LLM의 맥락 판단을 적절히 사용한다.
- **미저작 공간의 임의 창작은 배제**한다. 대신 미리 저작된 장소 조각의 선택·복제·결합을 검토한다. 이미 존재하는 벽을 부수어 생긴 구멍처럼 **행동으로 발생한 구조 변화**는 미저작 공간 창작과 구별한다.
- **세계 데이터**와 **세션에서 실재하며 변화하는 세계**는 구별하되, 둘을 단순한 불변 템플릿과 복사본으로 단정하지 않는다.

> **설계 판단의 핵심:** 상세한 물리 모델을 최대한 구축하는 것이 아니라, **지속적으로 보존할 공간적 사실을 명료하게 유지하고, LLM이 이를 근거로 자연스럽게 판단·묘사할 여지를 확보**한다.

## 1. 근거의 지위: 사용자 방침과 통합 제안 구분

### 1.1. 사용자로부터 명시적으로 확인된 내용

1. 최상위 항목은 **물리적 지역이 아닌 분류 헤드**이며, 여러 개 둘 수 있다.
2. 상위 항목은 각 물리적 포함 계층의 **뿌리 장소**다. 그 아래 하위 항목은 **부모 장소 내부에 물리적으로 포함**된다.
3. 속성 계승은 **미리 선정한 장소 속성에만** 적용하며, 직접 값이 없으면 조상 중 가장 가까운 정의를 사용한다.
4. 장소 간 **이동 가능성은 포함 계층과 독립적으로** 표현할 수 있다.
5. 복도·길·산·들 등까지 표현하여 공간적 공백을 최소화하고, 다양한 출입 경로와 동적인 구조 변화에 대응하고자 한다.
6. 환경은 별도 **환경 및 현상** 영역과 연동하는 것을 전제로 한다.
7. **미저작 공간의 임의 창작은 배제**하고, **기성 장소 조각을 가져다 붙이는 방식은 활용할 수 있다.**
8. INDAIM은 **세계 데이터**와 **세션에서 실제로 시뮬레이션되는 세계**라는 두 층위를 구분한다.
9. 물리적 세부를 과도하게 시스템화하면 LLM의 직관을 제약하고 개연성을 해칠 수 있다. **묘사·맥락 판단에서 LLM의 능력을 활용할 여지를 열어 둔다.**

### 1.2. 아직 사용자 승인을 받지 않은 이 문서의 통합 제안

- 계층 외 **선택적 공간 관계**, **선택적 경계 정보**, **장소 내부 위치 표현**을 하나의 공간 정보 체계에서 활용한다.
- 장소·연결·구조물·조각 원형과 세션 내 실체의 **동일성 및 참조 관계**를 유지한다.
- 구조 변경 이후 **유효한 지속 상태만 영속화**하고, 소리·시야·열 등은 필요할 때 판단한다.
- **장소 정보의 완전성 점검**과 **결합 시 정합성 검토**를 제공하되, 기하학적 검증을 전면 의무화하지 않는다.
- 공간 정보의 **정성적 서술**을 유효한 판단 근거로 인정하고, 수치·형상은 필요한 경우에만 보강한다.

이하의 문장 중 ‘한다’, ‘둔다’, ‘구별한다’는 **이 통합 설계안이 제안하는 작동 방식**을 기술한다. 사용자 승인 사실을 뜻하지 않는다.

## 2. 설계 목표와 비목표

### 2.1. 목표

1. **공간의 지속적 일관성:** 플레이어가 재방문하거나 구조물을 변경해도 기존 사실이 보존된다.
2. **자유로운 행동 대응:** 통상적인 출입 외에 창문 통과, 장애물 우회, 벽 파괴, 길 이탈, 이동체 이용 등을 기존 사실에 근거해 다룬다.
3. **텍스트 저작 친화성:** 수치·좌표 없이도 유용한 공간 정보를 저작·관리할 수 있다.
4. **계산과 LLM 판단의 조화:** 명확한 구조적 제약은 프로그램이 활용하고, 세부 물리·분위기·장면의 직관은 LLM이 맡을 수 있다.
5. **저작 재사용:** 분류 헤드의 제한된 속성 계승 및 기성 장소 조각 재사용으로 중복 저작을 줄인다.
6. **영역 간 책임 준수:** 물건·환경·감각·정보 등의 고유 상태와 판단을 공간 영역이 임의로 독점하지 않는다.
7. **세계관 독립성:** 도시·야외·건물·차량·던전·초현실 공간 등 다양한 배경에 적용 가능한 일반 원리를 지향한다.

### 2.2. 의도적으로 목표에 넣지 않는 것

- 모든 지형·건물의 완전한 2D/3D 지도와 물리 수치 구축.
- 모든 위치를 미리 독립된 장소 항목으로 분할.
- 창작되지 않은 방·도로·시설의 LLM 즉석 발명.
- 소리·빛·온도·공기 등 물리 현상의 범용 정밀 엔진 구축.
- 이동·시야·음향·열 전달을 **하나의 연결 불리언**으로 단순화하거나, 반대로 현상마다 전체 독립 공간 지도를 필수로 요구.
- 세션의 정보 제공·프롬프트 구성·서사 생성 절차 전체를 이 영역에서 설계.

## 3. 전체 개념 구조

```text
세계 데이터 (장소 정의·조각 원형·공통 특성·허용된 구조적 사실 등)
  ├─ 비공간적 분류 헤드와 제한된 속성 계승
  ├─ 장소의 물리적 포함 계층
  ├─ 공간 관계·이동 연결·주요 구조와 배치 정보
  └─ 재사용 가능한 장소 조각
                     │
                     │ 세션 세계와 연계·실재화 (상세 정책 미정)
                     ▼
세션에서 실제로 존재하는 장소·구조·연결·현재 상태
                     │
          ┌──────────┼─────────────┐
          ▼          ▼             ▼
      구조적 조회   조건적 판단   LLM 맥락 판단
   (포함·연결 등) (필요한 계산) (물리 직관·서술)
          └──────────┼─────────────┘
                     ▼
        행동 결과·지속 사실은 세션 세계에 반영
                     │
                     ▼
          감각·정보·서사 영역과 상호작용
```

이 그림은 **논리적 책임 구분**이다. 세계 데이터와 세션 세계의 저장 위치, 객체 생성 방식, 프롬프트 호출 순서 또는 모듈 개수를 정하지 않는다.

### 3.1. 주요 개념의 의미(데이터 스키마가 아닌 개념 목록)

| 개념 | 무엇을 나타내는가 | 주의 사항 |
|---|---|---|
| **분류 헤드** | 비공간적 항목 묶음 및 제한된 속성 계승의 출발점 | 지도상의 장소·구역·이동 목적지로 취급하지 않음 |
| **장소** | 세계에 실제로 존재하는 구획·영역·실내·실외 공간 | 방뿐 아니라 복도·길·산·공터 등 포함 |
| **포함 관계** | 한 장소가 다른 장소의 물리적 범위 안에 있음 | 대표 부모는 하나라는 사용자 초기 구상 유지 |
| **기타 공간 관계** | 인접·접촉·상대 위치·연속성·특정 경계의 양측 등 | 필요한 사실만 기록; 관계 종류 전체를 필수화하지 않음 |
| **이동 연결** | 장소·위치 사이에서 고려할 수 있는 통행 경로와 방식 | 연결의 존재 ≠ 모든 행위자에게 통과 가능 |
| **경계·개구부·구조** | 공간을 가르거나 연결하는 벽·문·창문·구멍 등 | 물건 영역의 실체와 중복 소유하지 않도록 연계 필요 |
| **내부 위치·기준점** | 장소 안에서의 상대적인 위치, 배치와 경로의 근거 | 좌표 및 고정 단위 의무화하지 않음 |
| **장소 조각** | 사전에 저작되어 반복 활용할 수 있는 공간 구성 | 배치 결과는 각각 독립된 세션 장소가 될 수 있음 |
| **세션 상태** | 실제 세션에서 유지되는 개폐·파괴·막힘·배치 등 | 묘사에서 일회성으로 언급한 인상과 구별 |

단일 개념이 반드시 독립된 객체·테이블·문서로 대응하는 것은 아니다. 특히 구조물이 **물건 영역의 개체**라면 공간은 해당 구조물과 장소 사이의 관계만 제공할 수 있다.

## 4. 장소 조직: 분류 헤드와 물리적 포함 계층

### 4.1. 분류 헤드

- 복수의 최상위 분류 헤드를 허용한다.
- 분류 헤드 자체에는 물리적 면적·경계·출입구·내부 위치를 요구하지 않는다.
- 각 헤드 아래에 **여러 뿌리 장소(상위 항목)**가 들어갈 수 있다.
- 분류 헤드의 주된 기능은 **저작의 조직과 선정된 속성의 계승**이다. 같은 헤드의 항목들이 반드시 인접하거나 하나의 연결된 구역이어야 하는 것은 아니다.

### 4.2. 뿌리 장소와 하위 장소

```text
분류 헤드: 도시 시설 (장소 아님)
├─ 뿌리 장소: 여관 (장소)
│  ├─ 복도
│  ├─ 101호
│  │  ├─ 침실
│  │  └─ 화장실
│  └─ 102호
└─ 뿌리 장소: 경비초소 (장소)

분류 헤드: 외부 통로 (장소 아님)
├─ 뿌리 장소: 여관 앞 골목 구간 (장소)
└─ 뿌리 장소: 구름다리 (장소)
```

- 여관→101호→화장실은 **물리적 포함**을 뜻한다.
- 여관 출입구→골목, 여관 창문→구름다리처럼 계층 밖으로 이어지는 이동은 **별도 연결 관계**로 표현한다.
- 구름다리가 두 건물 사이에 있다는 이유로 어느 한 건물의 하위 장소로 강제하지 않는다.
- 같은 물리적 장소를 여러 부모 아래 중복 배치하는 방식은 기본안으로 채택하지 않는다. 여러 장소와 관련되는 관계는 별도 참조로 다룬다.

### 4.3. 속성 계승

적용 대상은 **사전에 계승하도록 지정된 속성만**이다.

```text
값 확인 순서:
해당 장소의 직접 값 → 직속 물리적 부모 → 그 조상들 → 분류 헤드
(처음 발견한 명시 값 사용)
```

- 직접 값이 있으면 상속 값보다 우선한다.
- **값이 비어 있음**, **명시적으로 해당 성질이 없음**, **알 수 없음**을 필요에 따라 구분한다. 다만 구체적인 표기·해석 규칙은 정보 영역과 함께 결정한다.
- 계승 가능한 속성의 **실제 목록은 아직 확정되지 않았다.** 분위기·양식 등의 사례가 있다고 해서 모든 환경 상태·시설 존재·구조물을 계승하도록 미리 정하지 않는다.
- 세션의 실제 상태 변화가 계승된 저작 기본값과 어떤 우선순위 관계를 가지는지는 두 층위의 정책과 함께 검토한다.

## 5. 공간 관계: 계층 외의 정보

### 5.1. 포함 계층과 별도로 표현할 사실

물리적 포함만으로 표현되지 않는 관계가 필요할 수 있다.

- **공간적 인접·접촉:** 서로 벽을 사이에 두고 있음, 마당과 도로가 맞닿음.
- **상대적 배치:** 여관의 서쪽, 복도 끝, 창고 뒤편, 지하.
- **연속성:** 여러 구간으로 표현해도 실제로는 하나의 도로·복도·하천임.
- **특정 경계의 양측:** A방 벽의 반대편은 B방이라는 사실.
- **교차·중첩:** 계층으로 설명하기 어려운 공간적 공존이 필요한 경우.

이 중 일부는 수치나 기하학 없이 **명시적 관계 또는 자연어 설명**만으로 충분하다. 모든 장소에 전체 인접 목록·접촉 면적·위상 관계를 입력할 의무는 없다.

### 5.2. 연속된 공간을 여러 항목으로 나눌 때

도로·복도·숲·산처럼 큰 공간은 관리 편의·서사적 구분·분기점 등에 따라 분할할 수 있다.

- 분할된 각 부분에는 필요한 경우 독립된 위치·상태·연결을 부여할 수 있다.
- 각 부분이 **어떤 연속 공간에 속하는지**, 서로 **어떤 방식으로 이어지는지** 보존할 수 있어야 한다.
- **장소 항목의 경계 ≠ 실제 물리적 차단**이라는 점을 명시한다.
- 분할의 정확한 기준과 규모는 세계관·장소·필요 판단에 따라 달라질 수 있으며, 고정된 최소 단위를 강제하지 않는다.

### 5.3. 공간적 공백과 미저작 정보의 경계

사용자의 **‘빈 공간이 없도록 한다’**는 목표는, 플레이어의 움직임과 주변 공간을 불연속적인 장면 목록에만 의존하지 않고 설명할 수 있게 하자는 요구로 해석한다.

그러나 **‘모든 물리적 위치를 미리 개별 항목으로 작성’**한다는 뜻은 아니다. 동시에 **미저작 공간의 즉석 창작을 허용한다는 뜻도 아니다.**

따라서 후보 원칙은 다음과 같다.

1. 이동·주변 구조를 판단하려면 기존에 저작된 장소·외부 구간·기성 조각·확정 관계에서 근거를 찾는다.
2. 구체적인 방·시설·길을 저작한 적이 없다는 사실만으로 **존재하지 않는다고 단정하지 않는다.** 그렇지만 그 장소가 **존재한다고 창작해서도 안 된다.**
3. 저작 데이터와 기존 조각으로 필요한 공간을 특정할 수 없다면 **미확정·저작 공백**으로 다룬다. GM에게 보고하거나 적법한 저작·배치 절차로 해결하는 방향을 검토한다.
4. 이때 무엇이 단순한 자연어 묘사이고 무엇이 새로운 공간적 사실의 확정인지는 정보·서사 영역과 책임을 구분한다.

> **남은 긴장:** 임의 창작을 금지하면서 ‘공백 없는 세계’를 달성하려면 저작 범위, 일반화된 기존 장소 설명, 조각 결합, 미정 시의 진행 정책을 함께 정해야 한다. **현 초안에서 해결되었다고 가정하지 않는다.**

## 6. 장소 내부의 위치와 배치

장소가 하나라는 이유로 그 내부가 균일하게 접근·관찰 가능한 것은 아니다. 특히 창고·광장·산·긴 복도에서 중요하다.

### 6.1. 허용할 표현 수준(선택 가능)

| 표현 수준 | 예시 | 쓰임 |
|---|---|---|
| 장소 단위 | ‘101호 안’ | 세밀한 위치가 필요하지 않을 때 |
| 상대 위치·서술 | ‘남쪽 창가’, ‘입구 왼편 선반 뒤’ | 대다수의 서사·행동 판단 |
| 식별 가능한 기준점 | ‘북문’, ‘복도 동쪽 끝’, ‘우물 옆’ | 반복 방문·이동·발견의 위치 일관성 |
| 정량적 정보 | ‘문에서 약 8m’, 좌표·대략적 크기 | 수치 판단이 실제로 중요한 경우 |

이 표는 데이터 필드를 모두 추가하겠다는 결정이 아니다. **정보 표현 능력의 단계**이며, 모든 장소에 같은 정밀도를 요구하지 않는다.

### 6.2. 장소 내부 경로

- 내부에도 여러 출입구·기준점·장애물·이동 경로가 존재할 수 있다.
- 단일 장소 내 이동 역시 필요하다면 경로·방향·거리·우회·차단 정보를 가질 수 있다.
- 장면마다 모든 미시 위치를 별도 장소로 분할하지 않고도 ‘입구에서 창고 뒤편으로 접근’ 같은 행동을 판단할 수 있어야 한다.
- 좌표를 사용하지 않는 경우, 시스템이 **저작되지 않은 정확한 거리·방향을 계산한 것처럼 단정하는 것**은 피한다.

## 7. 이동 연결과 통과 판단

### 7.1. 구별할 네 단계

1. **공간 관계:** 두 위치가 인접·접촉·연속해 있거나 특정 경계로 구분되는가?
2. **경로의 존재:** 문·창문·복도·계단·구멍·외부 길 등의 통행 후보가 존재하는가?
3. **현재의 통과 가능성:** 특정 행위자가 현재 조건과 방법으로 지나갈 수 있는가?
4. **실제 이동 결과:** 행동을 실행했고 언제·어디까지 이동했는가?

장소의 계층상 가까움은 ②~④를 보장하지 않는다. 반대로 포함 계층상 다른 뿌리에 속한 장소 사이에도 경로를 둘 수 있다.

### 7.2. 연결에서 유용할 수 있는 정보

- 시작·도착 장소 또는 구체 위치와 **이동 방향**(일방향도 가능).
- 통행 방식: 출입문, 창문, 좁은 통로, 계단, 사다리, 지상 길, 우회, 이동체 등.
- 경로가 가리키는 **실제 구조물·개구부**와 현재 상태.
- 잠금·막힘·붕괴 등의 객관적 사실, 거리나 위험 등 저작된 조건.
- 중간에 지나가야 하는 공간이나 구간이 중요한 경우 그 사실.

이 항목들의 저장 방식은 미정이다. 경로에 값을 중복 저장하는 대신 문·벽·열쇠 등의 실제 세계 개체를 참조하는 편이 적절할 수 있다.

### 7.3. 통과 판단의 역할 분담

- **공간 영역:** 경로·위치·개구부·현재 구조에 관한 근거 제공.
- **물건 영역:** 열쇠·장비, 문·구조물의 해당 영역 소유 상태 제공.
- **신체 및 건강:** 행위자의 크기·자세·능력·제약에 관한 근거 제공.
- **정보·감각:** 행위자가 경로를 아는지, 숨겨진 통로를 발견했는지와 관련된 판단.
- **행동 판단·판정:** 주체와 상황에 따른 이동의 성립과 결과 결정.

가령 ‘쥐는 지나가지만 성인은 통과하기 어려운 환기구’라는 **정성적 사실**만으로도 충분할 수 있다. 필요할 때는 폭·높이 같은 수치 정보를 추가할 수 있다. 어떤 판단을 항상 코드로 계산해야 한다고 미리 고정하지 않는다.

### 7.4. 미등록 경로의 의미

경로가 등록되지 않았다는 사실은 그 자체로 **물리적으로 절대 통과할 수 없음**을 증명하지 않는다. 특히 벽 파괴·등반·우회는 기존의 ‘통행용 출구’가 없어도 고려될 수 있다.

반면 플레이어가 막연히 ‘옆방으로 벽을 뚫는다’고 했다는 이유만으로 **옆방의 존재나 벽 반대편의 구조를 새로 만들어서는 안 된다.** 이미 확정된 인접·경계·배치·기성 조각 등 근거가 있는지를 판단해야 한다.

## 8. 경계·개구부 및 구조물

### 8.1. 적극적으로 표현할 가치가 있는 정보

- ‘A와 B 사이에 벽이 있음’, ‘이 창문은 바깥 골목에 면함’, ‘복도 끝은 철문으로 막힘’ 같은 **물리적 관계와 구조**.
- ‘문이 잠겼다’, ‘벽에 사람이 지나갈 만한 구멍이 생겼다’, ‘계단이 무너졌다’ 같은 **현재의 지속 상태**.
- 특정 판단에 필요한 **재질·형태·크기·강도·파손 정도** 등의 정보. 자연어로 표현해도 된다.

### 8.2. 의무화하지 않을 정보

- 모든 벽·모서리·창문의 완전한 목록과 기하 형상.
- 재질별 광학·음향·열·유체 특성의 통일된 수치 규격.
- 모든 문 개폐 시 전 세계의 감각·환경 네트워크를 자동 재계산하는 절차.

### 8.3. 구조물의 책임 경계

‘벽’이 물건 영역에서 관리하는 물리 실체라면 그 재질·파손을 공간 영역에 또 하나의 정본으로 저장하지 않는다. 장소 쪽에는 **어떤 공간을 가르는 구조물인지**, 어떤 개구부·이동과 관련되는지를 연결할 수 있다.

반대로 일반적인 배경 요소처럼 별도의 물건으로 관리하지 않는 구조물도 **서술된 세계 사실**로 존재할 수 있다. 플레이어가 그 구조물을 실제로 손상시키는 순간, 이를 어떤 영속 상태로 관리할지는 물건 영역·행동 처리와의 합의가 필요하다.

## 9. 빛·소리·온도·공기와 LLM의 역할

### 9.1. 핵심 분리

| 구분 | 예시 | 이 설계안의 처리 관점 |
|---|---|---|
| **공간의 객관적 사실** | ‘창문이 열려 있고 복도와 외부가 이어진다’ | 지속되는 사실이면 보존 |
| **환경·현상의 실제 상태** | ‘복도에 연기가 차 있다’, ‘휴대용 램프가 켜져 있다’ | 환경·물건 등 해당 영역과 연계하여 보존 |
| **현상에 관한 판단** | ‘이 거리에서 소리를 분간할 수 있는가’ | 필요할 때 명시적 계산 또는 LLM 판단 |
| **감각 결과** | ‘인물이 희미한 말소리를 들었다’ | 감각·정보 영역과 연계. 지속할 기록 여부는 해당 영역 결정 |
| **서사 묘사** | ‘문틈으로 미약한 빛이 새어 나온다’ | 세계 사실과 모순되지 않는 한 LLM의 직관·표현 활용 |

### 9.2. 환경과의 연계에 관한 권고

- 공간 정보는 ‘좁은 폐쇄 복도’, ‘두 방 사이에 두꺼운 콘크리트 벽’, ‘밖으로 통하는 큰 개구부’ 등 **의미 있는 근거**를 제공한다.
- 환경 영역은 열원·광원·기온·연기·소음 등의 현상 자체를 관리한다.
- 감각 영역은 신호와 인물의 감지·식별, 정보 영역은 인지·기억·오해 등을 다룬다.
- **소리의 투과율이나 조도를 필수 공식으로 산출하지 않는다.** 다만 향후 특정 장면의 판정에 정량 계산이 필요할 경우, 그 계산에 필요한 정보를 선택적으로 사용할 수 있다.
- 공간의 물리적 구획과 환경 계산 구획이 반드시 일치하지는 않는다. 그러나 별도의 ‘열 구역·음향 구역’을 기본 구조로 **지금 확정하지 않는다.**

### 9.3. LLM 직관이 허용되는 범위와 한계

- LLM은 서술적 공간 정보와 일반 상식을 바탕으로 **일시적인 감각·환경의 개연성 판단**을 할 수 있다.
- 판단에 충분한 사실이 없으면 **불확실성을 유지**한다. 미저작 구조물·출입구·비밀방을 만들어 판단을 성립시키지 않는다.
- **지속되는 결과**가 발생했다면, 그것을 단지 묘사 문장에만 남겨서는 안 된다. 담당 영역의 세계 상태에 반영되어 이후 판단에서 참조할 수 있어야 한다.
- 반대로 순간적인 인상이나 표현을 모두 정본 상태로 승격시킬 필요도 없다. **무엇이 지속적 세계 사실인지는 별도로 판별**해야 한다.
- LLM이 과거에 확정된 문 상태·경로·위치·비밀에 반하는 묘사를 만들었다면, 묘사를 세계 상태보다 우선시키지 않는다.

### 9.4. 예시: 벽에 구멍을 낸 경우

```text
기존 사실: A방과 B방은 벽으로 구분되어 있다.
행동: 벽을 부수는 시도.
판단: 실제 파괴 성공 여부와 결과 크기·형태 결정.
지속되는 변화: 해당 벽에 구멍이 생겼고 현재 그 구멍이 유지됨.
가능한 이용: 새 이동 후보, 시야·빛·소리·공기에 대한 판단 근거.
비의무: 빛/열/음향 수치를 전부 계산하고 자동 갱신할 것.
```

‘이 구멍을 통해 연기가 B방으로 실제로 번졌다’는 결과가 **확정되면**, 연기의 실제 상태를 담당 영역에서 유지해야 한다. 그것이 확정되지 않은 상태에서 단순히 ‘그럴 수도 있다’는 가능성을 세계 사실로 저장하지 않는다.

## 10. 기성 장소 조각의 재사용과 결합

### 10.1. 조각의 성격

사전에 저작된 **주택 내부, 골목 구간, 시가지 블록, 마을 일부, 지하 통로, 계단실, 산길 구간** 등을 재사용할 수 있다.

조각은 단순한 묘사문일 수도 있고, **장소 계층 + 연결 + 내부 배치 + 기본 특성**을 가진 비교적 복합적인 구성일 수도 있다. 그 범위를 하나의 정형 포맷으로 제한하지 않는다.

### 10.2. 원형과 배치된 실체

- **조각 원형:** 재사용되는 저작 정의.
- **배치 결과:** 특정 세계·세션에서 실제로 존재하는 장소와 구성 요소.
- **세션 상태:** 배치 결과에 발생한 개별적 변경.

같은 ‘소형 주택’ 조각을 두 주택에 사용해도, 한쪽의 문 파괴와 다른 쪽의 상태는 **독립적**이어야 한다.

### 10.3. 결합·배치의 정합성

결합 방식의 후보 원칙:

1. 가져온 조각이 **어느 장소의 내부에 놓이거나 어떤 공간과 맞닿는지**를 특정한다.
2. 기존 장소와 연결되는 지점·방법에 대한 **저작된 근거**를 확인한다.
3. 이미 확정된 벽·통로·주변 구조를 이유 없이 지우거나 변경하지 않는다.
4. 연결되지 않은 출입구의 존재·마감 상태를 **추측으로 발명하지 않는다.** 저작 원형에 관련 정보가 없으면 미결정으로 남기거나 GM의 저작 판단을 받는다.
5. 결과가 실재화되었다면 기존 원형과 별개로 **식별·상태 변경**할 수 있어야 한다.

모든 조각에 규격화된 커넥터·격자·좌표를 강제하지 않는다. 대신 필요한 결합 조건은 **구조화된 정보, 자연어 조건, LLM/GM 검토**로 충족할 수 있는 가능성을 열어 둔다.

### 10.4. 창작 금지와 조각 결합의 차이

| 상황 | 이 설계안의 취급 |
|---|---|
| 기존에 없는 마을·집·비밀방을 LLM이 즉석 발명 | **사용자 방침에 따라 배제** |
| 미리 저작된 ‘소형 주택 내부’ 조각을 허용된 위치에 사용 | **검토 가능한 기능** |
| 기존에 정의된 방의 벽을 부숴 새 구멍을 만듦 | **행동 결과에 따른 구조 변화**로 취급 |
| 조각 결합 과정에서 미저작 방·복도·문을 임의로 덧붙임 | **별도 저작 승인 없이 허용하지 않는 방향 제안** |
| 이미 저작된 구조가 부족하여 위치를 특정할 수 없음 | **미확정으로 처리하고 저작/GM 경로를 요구** |

**미결정:** 조각 배치의 자동화 범위, 사용 가능한 변형·회전·크기 조정, 원형 변경의 기존 실체 전파, 세션 도중 허용 시점.

## 11. 세계 데이터와 세션 세계

### 11.1. 두 층위에 대해 현재 말할 수 있는 것

- **세계 데이터:** 세계를 추적·계산·관리·시뮬레이션하는 데 쓰는 정의, 자료, 구조, 규칙, 저작된 정보 등을 포함하는 층위.
- **세션 세계:** 세션 동안 실제로 성립하며 시뮬레이션되는 장소·구조·상태 및 변화가 존재하는 층위.

둘의 관계는 **단순한 ‘정적 설계도→사본’으로 확정되지 않았다.** 어떤 세계 데이터가 세션에서 언제 실재화되는지, 세션 사이에 공유하는지, 원본 수정이 이미 진행 중인 세션에 미치는 영향은 미결정이다.

### 11.2. 어떤 구조를 택해도 지켜야 할 불변 요구

1. **장소 동일성:** 벽이 부서졌어도 같은 객실인지 판별할 수 있어야 한다.
2. **상태 독립성:** 서로 다른 세션·배치 실체의 문·벽·물체 상태를 잘못 공유하지 않는다.
3. **구조 변경 보존:** 새 구멍·막힌 길·이동한 구조물 등의 지속 결과를 이후에 참조한다.
4. **정보의 근거:** 원래 저작된 사실인지, 조각 사용으로 생긴 사실인지, 세션 행동에 따라 변화한 사실인지 구별할 수 있어야 한다(기록 상세 수준은 미정).
5. **미확정과 부재 구분:** 명시되지 않은 장소·연결의 존재를 무단 단정하지 않는다.
6. **다른 영역과 동기성:** 장소가 이동해도 그 안의 인물·물건이 일관되게 위치할 수 있도록, 필요한 참조가 유지되어야 한다.

### 11.3. 실재와 계산 상세도의 구분

세션에 실제로 존재하는 공간이라고 해서 매 순간 조도·온도·소리·이동 경로를 정밀 계산할 필요는 없다. **세계의 존재 여부와 현재 수행하는 계산의 범위는 다른 문제**다.

단, 이는 **별도의 활성화 계층이나 시뮬레이션 거리 시스템을 도입한다는 결정이 아니다.** 실행 전략은 다른 영역과 함께 검토한다.

## 12. 공간 변화의 처리 원리

**개념적 흐름(확정된 실행 파이프라인 아님):**

1. **선언과 맥락 확인:** 무엇을 어느 위치에서 어떤 방식으로 하려는가.
2. **기존 사실 조회:** 대상 장소·구조·이동 경로·필요한 타 영역의 상태가 무엇인가.
3. **결과 판단:** 확정 규칙/수치 계산이 적합한 경우와 LLM의 맥락 판단이 적합한 경우를 구별하여 행동 결과를 결정한다.
4. **지속되는 변경 반영:** 성공·실패의 결과로 달라진 장소·개구부·이동 관계·물건 상태 등을 해당 권위 있는 정보에 반영한다.
5. **후속 판단:** 이후 이동·감각·환경·서사는 변경된 사실을 참조한다. 모든 가능한 물리 파생 결과를 선제 계산하지는 않는다.

**예외 유의:** 어떤 구조물의 상태 변경이 구조화된 이동 연결을 직접 무효화한다면, 해당 **명시적 연결의 유효성**은 최신 상태와 일치해야 한다. 이것은 모든 물리 효과를 미리 계산하자는 뜻이 아니라 **서로 모순되는 지속 사실을 두지 않으려는 요구**다.

### 변화의 유형별 간단한 사례

| 상황 | 보존할 공간적 사실 | 별도 판단 또는 담당 영역 |
|---|---|---|
| 문 잠금 | 문·연결에 관한 현재 잠금 상태 또는 그 참조 | 열쇠·출입 권한·실제 이동 |
| 벽에 구멍 | 벽의 변경, 구멍의 위치/크기에 관한 충분한 사실, A–B 관계 | 통과·시야·소음·환기 영향 |
| 도로 붕괴 | 해당 구간의 현재 단절/위험 상태 | 우회 이동, 위험, 사건 진전 |
| 승강기 이동 | 동일한 승강기 공간의 현재 외부 위치/접속 관계 | 탑승자 위치·시간·운행 조건 |
| 이동식 선박 | 선실 포함 관계 유지, 선박의 외부 상대 위치 변경 | 선박 운항, 외부 환경 |
| 큰 방에 칸막이 설치 | 새 분리 구조·통행 조건 | 장소 항목을 실제로 둘로 나눌 필요가 있는지 |

장소를 물리적으로 분할·결합했다고 **장소 항목의 생성·삭제가 자동으로 필수**라고 보지는 않는다. 항목 개편의 필요 여부는 독립적인 논점이다.

## 13. 타 영역과의 계약 후보

| 대상 영역 | 장소 및 공간에서 제공·요구할 것 | 임의로 확정하지 않을 것 |
|---|---|---|
| **시간** | 장소·통로 상태 변화의 시점, 이동에 필요한 시간의 공간적 근거 | 시간 정책 P01~P08의 세부 내용(문서 미수신) |
| **물건** | 벽·문·창문·가구·열쇠 등과 공간 관계·상호작용 | 구조물/가구의 최종 소유권·승격 절차 |
| **환경 및 현상** | 위치·연결·경계·개구부·밀폐에 대한 정성적·정량적 근거 | 빛·온도·연기·소리의 자체 계산 규칙 |
| **신체 및 건강** | 공간·통로 크기·장애물 등의 근거 | 행위자별 이동능력의 계산 규칙 |
| **정보** | 객관적인 장소·통로 존재 및 비공개 근거 | 인물별 지도·기억·오해·발견의 데이터 모델 |
| **감각** | 위치·가림·관찰 방향·환경 연계에 필요한 사실 | 감지·식별·인지의 최종 판단 소유권 |
| **심리 및 판단** | 상황 속 상대 위치·접근·위험에 관한 객관 정보 | NPC의 의사결정 과정 |
| **사건** | 장소·경로·구조 변화가 사건 조건에 참고될 수 있음 | 사건 상태와 발생 규칙 |
| **행동선언** | 공간적 행동의 대상·근거·결과를 기록할 수 있는 접점 | 판정 계약과 실행 파이프라인 |

14개 영역의 분류는 **설계 탐색용**이며, 위 행이 곧바로 구현 모듈 경계를 뜻하지 않는다.

## 14. 검증 시나리오(합격 기준의 초안)

| 사례 | 이 설계안이 통과해야 할 조건 |
|---|---|
| **1. 숙박시설** | 건물→복도·객실→침실·화장실의 물리 포함, 계승 속성 오버라이드, 객실별 상태 독립성 |
| **2. 구름다리** | 서로 다른 뿌리 건물 사이의 외부 공간을 통해 통행; 분류 헤드가 이동 장소가 되지 않음 |
| **3. 긴 도로** | 구간 분할 후에도 도로 전체의 연속성이 유지되며, 분할점이 물리적 장애물로 취급되지 않음 |
| **4. 밀폐된 두 방** | 출입 경로가 없어도 벽을 사이에 둔 인접 사실을 표현할 수 있음 |
| **5. 벽 파괴** | 이미 확인된 벽의 파손·구멍이 유지되고, 이후의 이동/시야 판단에서 활용됨 |
| **6. 숨겨진 통로** | 실제 존재와 특정 인물의 발견 여부를 혼동하지 않음 |
| **7. 환기구** | 쥐·사람·물건의 통과 가능성을 같은 고정 불리언으로 취급하지 않음 |
| **8. 창가 vs 방 중앙** | 같은 방에서도 관찰 위치에 따라 다른 결과를 합리적으로 판단할 근거가 있음 |
| **9. 두 주택에 같은 조각 사용** | 한 주택의 문 파괴가 다른 주택으로 전파되지 않음 |
| **10. 누락된 구조** | 데이터에 없는 비밀방·새 도로를 LLM이 임의로 생성하지 않음; 미정/저작 필요 상태 처리 가능 |
| **11. 승강기** | 승강기 내부의 포함 관계를 보존하며 층에 따라 바깥 연결을 갱신할 수 있음 |
| **12. 빛·소리·연기** | 공간 사실이 판단에 쓰이지만, 상세 물리 수치 없다는 이유만으로 불합리한 계산값을 강제하지 않음 |
| **13. 원거리 변화** | 플레이어가 있지 않은 곳의 구조 변화도 세션 세계에 성립하고 보존될 수 있음 |
| **14. 공간 설명의 충돌** | 확정된 ‘막힌 벽’과 ‘열린 통로’처럼 모순되는 지속 사실을 탐지·검토할 수 있음 |

검증은 **실제로 필요한 기능이 성립하는지**를 확인하기 위한 것이며, 모든 시나리오에 개별 전용 규칙을 만들라는 의미가 아니다.

## 16. 확정 전 핵심 미결정 사항

다음은 이 문서의 **실질적인 의사결정이 필요한 부분**이다. 자동으로 채택된 기본값이 아니다.

### A. 공간 표현의 본체

1. **장소 내부 위치의 기본 표현:** 단순 서술, 명시적 기준점, 혼합 방식 중 어떤 수준이 장기적인 일관성에 충분한가?
2. **경계의 지위:** 경계를 독립적으로 식별할 필요가 있는 사례는 어디까지인가? 문·벽 등 물건과 어떻게 연결하는가?
3. **외부 연속 공간의 분할:** 언제 독립 장소를 만들고 언제 한 장소 내부의 부분 위치로 처리할 것인가?
4. **비계층 공간 관계의 최소 집합:** 어떤 관계가 반복 조회·상태변화를 위해 정말 필요한가?

### B. 정보 표현과 판단의 권위

5. **구조화와 자연어의 혼용 규칙:** 설명이 구조화된 연결과 충돌할 때 무엇을 검증·정정하며 어떤 정보가 우선하는가?
6. **LLM 판단의 기록 범위:** 순간적 묘사·일회 판단·지속되는 세계 사실의 경계를 어떻게 정할 것인가?
7. **미정/없음/숨김/미저작의 구별:** 표현과 판단 절차를 정보 영역과 어떻게 맞출 것인가?

### C. 재사용과 두 정보 층위

8. **조각 결합 권한·범위:** 누가 언제 결합하는가? 기존 조각의 재배치·변형은 어디까지 허용되는가?
9. **조각 원형 변경의 전파:** 이미 세션에서 실재화된 장소에 원형 수정이 영향을 주는가?
10. **세계 데이터→세션 세계 관계:** 실재화의 시점·중복 세션·상태 공유·변경 이력의 최소 정책은 무엇인가?
11. **‘공백 없는 공간’과 창작 금지의 양립:** 기성 저작이 부족한 상황에서 진행을 어떻게 처리할 것인가?

### D. 타 영역과의 계약

12. **구조물·가구의 소유권:** 어떤 것은 장소 설명이고 어떤 것은 물건 영역의 개체인가? 상호작용 시 전환 방법은?
13. **환경·감각과의 입력 계약:** 공간이 제공할 최소 서술·관계 근거가 무엇인가?
14. **시간 정책 정합성:** 시간 영역 P01~P08 원문을 확인한 후 공간 변화·이동 기간과의 관계 검토.
