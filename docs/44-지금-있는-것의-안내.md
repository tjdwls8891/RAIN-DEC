# 지금 있는 것의 안내 — 구조, 방식, 결정의 출처

2026-11-14. 사용자의 말: 모든 결정이 사용자의 머릿속에 있지 않고, 구조와 방식의 파악이 완전하지 못한데, 눈앞의 만들어진 구조는 부족하거나 근시안적으로 보인다. 운영과 화면은 뒤로 미룬다.

이 문서는 **새로 정하는 것이 없다.** 지금 코드에 실제로 있는 것을 있는 그대로 설명하고, 그 하나하나가 누구의 결정인지를 적는다.
사용자가 전부를 머릿속에 넣고, 남길 것과 버릴 것을 정할 수 있게 하는 것이 목적이다.

## 1. 한 줄로

> 플레이어의 선언을 LLM이 읽고(해석), 다른 LLM 호출이 "세계에서 무엇이 바뀌는가"를 적고(판단), 코드가 그것을 검사해 장부에 반영하고, 또 다른 LLM 호출이 PC가 지각한 것을 글로 쓴다(서술).

**지금 있는 것은 "PC가 무언가를 하면 세계가 받는다"가 전부다.** 세계가 스스로 움직이는 부분은 없다.

## 2. 저장되는 것

| 것 | 꼴 | 예 |
| --- | --- | --- |
| 개체 | 이름과 표지 | `뒷문` [통로], `주모` [인물], `찻주전자` [물건] |
| 사실 | 항목(주체 → 대상) = 값 | `잠김(뒷문) = 참`, `위치(철검 → 강호민) = "허리에"`, `지킨다(주모 → 뒷문을 아무에게나 열어 주지 않는 것) = 큼` |
| 앎 | 누가 어떤 사실을 아는가 (진실과 따로) | 강호민은 `잠김(뒷문)`을 모른다. 열어 보다 걸리면 알게 된다 |
| 사건의 기록 | 턴마다 확정된 변화의 묶음. 덧붙이기만 한다 | 처음부터 다시 쌓으면 지금의 세계가 된다. 되감기는 여기서 나온다 |
| 사전 | 항목마다의 정의 (아래 §4) | |

- 세계의 "지금"은 사실의 모음이다. 사실이 아닌 것(서술의 문장)은 저장되지 않는다.

## 3. 한 턴 — 실제 예

선언: **"의자로 뒷문 자물쇠를 내리쳐 부순다."**

| 단계 | 누가 | 하는 일 | 이 예에서 |
| --- | --- | --- | --- |
| ① 해석 | LLM (PC가 아는 것만 받는다) | 선언을 "하려는 일"의 글로 옮기고, 유형과 대상을 고른다 | 하려는 일: "나무 의자로 뒷문의 자물쇠를 내리쳐 부순다". 유형: 공격/제압/피해. 대상: 뒷문, 나무 의자 |
| ② 판단 | LLM (진실을 본다) | 뜻대로 되면 바뀌는 것을 변화로 적는다. 굴리는가, 능력, 난이도, 방법, 걸리는 시간. 장면에 있는 인물의 말과 하는 일 | 변화: `손상(뒷문) = 파손`. 주모: 말 "무슨 짓이야!" |
| ③ 판정 | 코드 + 플레이어의 버튼 | 기준값을 만든다. 버튼. 2d50. 여유로 정도를 낸다 | 손상에는 "버팀: 견고함"이 걸려 있다. 뒷문의 견고함이 단단함이라 −15. 기준 41. 굴려서 37 → 아슬한 성공 |
| ④ 검사와 반영 | 코드 | 변화마다: 바뀔 수 있는 항목인가, 붙는 곳인가, 값이 맞는가, 손이 닿는가, 조건이 참인가. 통과하면 장부에 쓴다 | 아슬한 성공이라 한 칸만: `손상(뒷문) = 흠` |
| ⑤ 규칙 | 코드 | 조건이 참이 된 규칙의 귀결을 낸다 | "부서진 것은 잠그지 못한다"는 파손일 때만이라 걸리지 않는다. 문은 잠긴 채다 |
| ⑥ 서술 | LLM (PC가 지각한 것만 받는다) | 글로 쓴다 | "…문에 얕은 흠이 파인다." |
| ⑦ 확정 | 코드 | 턴의 변화를 사건 하나로 기록. 상태판 | |

## 4. 사전의 항목에 적는 것 — 아홉 칸

지금 `common.yaml`의 정의 하나가 가질 수 있는 칸이다.

| 칸 | 뜻 | 어떻게 생겼는가 |
| --- | --- | --- |
| 값 | 등급이나 열거 | 처음부터 |
| 겉보기 | 누구나 / 관찰 / 숨김 | 처음부터 |
| 고침 | 행동으로 바뀌는가 (누구나 / 본인) | 엔진을 다시 쓸 때 |
| 조건, 걸리면, 알게됨 | 그 값이 되지 못하게 막는 조건과 그때의 글 | 잠긴 문 때문에 |
| 드러남 | 값이 겉으로 보이는 꼴 | "기분: 경계"가 그대로 서술에 나가서 |
| 버팀 | 힘으로 바꿀 때의 난이도 | 문을 부수는 난이도가 흔들려서 |
| 붙는곳 | 그 항목을 가질 수 있는 것 | 사람에게 "손상: 흠"이 붙어서 |
| 기준 | 그 값이 붙는 기준의 글 | 사용자의 말을 반영하려고 (비어 있다) |
| 내면, 능력 | PC의 것인가, 능력치인가 | 엔진에 박힌 낱말을 빼려고 |

**이 표의 오른쪽 열이 문제다.** 아홉 칸 가운데 일곱이 설계된 것이 아니라, 돌려 보다 증상이 나올 때마다 **하나씩 덧붙인 것**이다.

## 5. 근시안적인 곳 (Claude의 판단)

| # | 곳 | 왜 |
| --- | --- | --- |
| 1 | **덧붙여서 자랐다** | 사전의 칸, 판단에 묻는 물음, 검사의 갈래가 전부 "돌려 보니 이상해서 하나 더"로 생겼다. 사용자가 처음에 말한 구 프로젝트의 실패("아쉬운 점과 추가하고 싶은 기능을 덧붙이는 식으로 개발해와 … 수정 비용이 커")를 이틀 만에 되풀이했다 |
| 2 | **턴이 "PC의 행동 하나"를 축으로 서 있다** | 인물은 그 행동에 대한 반응으로만 움직인다. 시간, 계획, 사건이 들어올 자리가 턴에 없다. 나중에 넣으려면 턴의 뼈대를 다시 짜야 한다 |
| 3 | **판단 한 번이 너무 많은 것을 한다** | 변화, 굴림, 난이도, 방법, 시간, 가리킨 것, 발견, 닿는 것, 기색, 인물마다의 말과 하는 일(많게는 세 벌)을 한 호출에 묻는다. 무엇을 한 번에 물어야 하고 무엇을 나눠야 하는지 설계한 적이 없다 |
| 4 | **코드가 아는 것이 위치와 여닫이뿐이다** | 손이 닿는가, 길이 있는가, 닫힌 용기인가, 남이 지닌 것인가. 나머지 영역(정보, 관계, 물건의 수량·착용, 환경)은 코드가 아무것도 모른다. "코드 권위의 세계"의 극히 작은 조각이다 |
| 5 | **객잔 한 장면으로만 만들었다** | 인물 둘, 방 셋. 여기서 돈다는 것이 다른 데서 돈다는 뜻이 아니다 |
| 6 | **설계 문서와 코드가 따로 간다** | 항목표(32)의 항목 약 170개 가운데 코드에 있는 것은 열 남짓이고, 그 열 남짓은 항목표에서 가져온 것이 아니라 Claude가 그때그때 지은 것이다 |

## 6. 결정의 출처

### 사용자가 정한 것 (원문에 있다)

| 결정 |
| --- |
| 대목표와 세 가치(자유도 100%, 확장성, 개연성) |
| 주권의 분리. 플레이어는 PC의 생각·말·행동·의도, 마스터는 세계와 결과 |
| 판정: 2d50, 요소를 조합한 기준값, 명백하면 굴리지 않는다, 버튼은 플레이어가 누른다, 둘이면 연달아, 기만·설득에 강제권, 여유에 따른 성패의 정도 |
| 묘사는 PC가 지각하는 범위. 전달된 것은 철회하지 않는다("착각이었다" 금지) |
| 코드가 상태의 권위를 갖는다. 부여·해제에는 저작된 기준이 있다. LLM은 명확한 기준과 정해진 판단만 |
| 비어 있으면 LLM이 채우고, 채운 것은 편입할 수 있다 |
| 물건: 16갈래, 명시적 기능과 성질에 의한 행동, 재질, 구성요소 |
| 서사의 진행은 시간만으로 정하지 않는다. 조직과 계획. 사건은 저작된 틀과 경우 |
| 인물: 경우별 태도와 판단 방식의 가이드 |
| 판단 물음은 되도록 없앤다 |
| 발견 선언의 허용선 |
| 위치의 방식은 자연어 |
| 암묵적 행동. 소급은 지금의 시도로 |
| 상태판은 턴마다, 서술이 끝난 때 |
| 턴당 50원 이하, 대기 15초 미만(마지막 행동부터 버튼이나 묘사 시작까지) |
| 행동의 유형: 판정이 필요한가와, 판단에 필요한 정보를 꾸리는 법을 정하는 데 |
| 저작은 사전을 포함해 나중. 지금은 시스템. 운영과 화면은 뒤로 |

### Claude가 정해 코드에 넣은 것 (허가받지 않았다)

| # | 결정 | 있는 곳 |
| --- | --- | --- |
| 1 | LLM 호출을 해석 / 판단 / 서술 셋으로 나눈다. 해석과 서술은 PC가 아는 것만, 판단은 진실을 | 턴 전체 |
| 2 | 판단이 일어날 일을 (개체, 항목, 대상, 값)의 변화로 적고 코드가 검사한다 | 턴 전체. 40에서 제안했고 사용자가 "좋습니다"라고 했으나, 세부를 이해하고 허가한 것은 아니다 |
| 3 | 사전의 항목에 적는 아홉 칸 | §4 |
| 4 | 판단 한 번이 장면의 인물 셋까지의 말과 하는 일을 정한다 | 판단 |
| 5 | 사람을 상대로 한 일의 세 갈래(그냥 말함 / 속임 / 밀어붙임)와, 인물마다 반응을 세 벌(성공했을 때 / 지킬 때 / 닿지 않을 때) 받는 것 | 판단 |
| 6 | 인물이 "지키려는 것"과 그 무게를 저작하고, 거기서 난이도를 낸다. 무게의 값 | 판정 |
| 7 | 기준값의 값들: 기본 52, 능력 ×2, 방법 다섯 단계 ±12, 난이도 여섯, 정도의 경계 (큰 실패 −40만 사용자가 건드렸다) | 판정 |
| 8 | 아슬한 성공이면 등급을 한 칸만 움직인다 | 검사 |
| 9 | 한 선언을 행동 여럿으로 쪼개 차례로 처리하고, 걸리면 멈춘다 | 턴 |
| 10 | 위치: "어디"는 개체, "어떻게"는 자연어. 방식의 글에서 "속"과 "감춤"을 낱말로 읽는다. 사람이 사람에게 가면 그 사람의 자리로 | 검사 |
| 11 | 발견을 막을지 가리는 물음(흔한 소품 / 중요·고유 / PC가 지녔다고 하는 것) | 판단 |
| 12 | 채운 항목은 자유로운 글로 기록만 한다 | 검사 |
| 13 | PC의 변화는 PC가 지각하는 것에만 닿는다 | 검사 |
| 14 | 유형마다 "굴리는 기준 한 줄"과 "기본 능력"을 적는다 | 사전 |
| 15 | 살피는 유형이면 대상의 "관찰" 항목을 굴림 없이 알게 된다 | 준비 |
| 16 | 모델은 셋 다 gemini-3-flash, 사고는 최소 | 설정 |
