# 진행 — 조직, 계획, 사건, 과업 (3단계)

2026-11-13. 서사를 나아가게 하는 부분이다. [27](27-전체-설계도.md) §3의 방향을 한 단계 내린다.
깊이는 다른 영역과 같다: 무엇을 적고, 코드가 무엇을 하고, 마스터가 무엇을 판단하는가. 전부 **[제안]**이다.

## 1. 바탕

| | |
| --- | --- |
| 사용자의 구분 | 상태의 계산은 시간에 따라 한다. **서사의 진행은 시간만으로 정하지 않는다** |
| 사용자의 경험 | LLM은 작가로서 부족하다. 매 턴 서사를 다시 짜게 하는 것은 비싸고 잘하지도 못한다 |
| 사용자의 경험 | 사전저작 사건은 저작 부담 때문에 무거웠다 |
| 지켜야 할 것 | 플레이어는 완전히 자유롭다. 세계는 자율적으로 움직이며 과하게 수동적이지 않다 |
| 과제 | 표현력을 줄이지 않고 저작 부담을 줄인다 |

이 넷을 함께 만족하는 길:

> **서사를 나아가게 하는 것은 목표를 가진 주체다.** 저작자는 줄거리가 아니라 주체와 목표를 쓴다.
> 마스터는 서사를 짓지 않고, 주체의 자리에서 **정해진 틀 가운데 고른다.** 벌어지는 일은 조건에 걸려 있어서 플레이어가 바꿀 수 있다.

```
조직·인물 ──목표──▶ 계획 ──단계가 벌어질 때──▶ 사건 ──PC가 알게 되면──▶ 과업
    ▲                 │                          │
    └──── 막히면 다시 세운다 ◀── 플레이어의 행동이 조건을 바꾼다
```

## 2. 조직

### 적는 것

| 항목 | 적는 꼴 | 비고 |
| --- | --- | --- |
| 구성과 직책, 체계 | 관계 | 조직도는 모아 보는 창 |
| 사상, 규칙, 역할 | 문장·가이드 / 규범 | 구성원의 태도와 권한에 물려진다 |
| 영향력, 위상 | 등급, 미치는 권역 | |
| 자산 | 실물의 소유 + 뭉뚱그린 양(인원, 물자) | 세세한 것은 필요할 때 실물로 확정한다 |
| 영역 | 관계 (쥐고 있는 장소) | |
| 다른 조직과의 관계 | 방향이 있는 등급 | 구성원의 기본 태도가 된다 |
| **목표** | 이루려는 사실(조건)과 문장 | 계획의 출발점 |
| 역량 | 분야별 등급 (무력, 정보, 재력 …) | 화면 밖에서 맞설 때의 근거 |

### 조직이 아는 것

- 조직이 안다는 것은 **지휘하는 자리의 인물이 안다**는 것이다. 구성원이 본 것은 전달이 있어야 그 자리에 닿는다.
- 조직의 판단(계획을 세우고 고치는 일)은 그 자리의 앎으로 한다. 플레이어가 척후를 막으면 지휘부는 모르는 채로 움직인다.

### 코드 / 마스터

- 코드: 소속, 자산의 양, 영역, 역량의 등급.
- 마스터: 조직이 무엇을 하려 하는가 (계획).

## 3. 계획

> 목표를 향한 단계의 목록. 주인은 PC, 인물, 조직 가운데 하나다.

### 계획 하나에 적는 것

| 항목 | 뜻 |
| --- | --- |
| 주인과 목적 | 누가, 무엇을 이루려는가 (참이 되기를 바라는 사실) |
| 단계 | 순서가 있는 목록 |
| 누가 아는가 | 앎. PC가 알게 되면 과업의 후보가 된다 |
| 상태 | 진행 중 / 막힘 / 이룸 / 버림 |

### 단계 하나에 적는 것

| 항목 | 뜻 | 예 (흑풍채의 상단 습격, "호위 수 확인" 단계) |
| --- | --- | --- |
| 하는 일 | 무엇을 하는가 | 척후가 객잔에서 주모에게 듣는다 |
| 필요한 것 | 이 단계를 하려면 참이어야 하는 사실 (사람, 자원, 정보, 기회) | 척후가 객잔에 있다. 주모가 호위 수를 안다 |
| 걸리는 시간 | 등급. **보조**다 | 하룻밤 |
| 이뤄졌는가 | 참이 되면 다음 단계로 넘어가는 사실 | 지휘부가 호위 수를 안다 |
| 막는 것 | 참이 되면 단계가 막히는 사실 | 척후가 잡혔다. 주모가 입을 닫았다 |
| 조짐 | 이 단계가 진행 중일 때 남이 지각할 수 있는 것 | 객잔에 술을 마시지 않는 낯선 사내 |
| 벌어질 때의 사건 | PC가 그 자리에 있으면 어떤 틀로 나타나는가 | (그냥 장면이다. 틀이 없어도 된다) |

- 단계는 **조건이 맞아야** 나아간다. 시간은 "하는 데 걸리는 시간"으로만 들어간다. 시간이 찼다고 일이 이뤄지지 않는다.
- 플레이어가 "필요한 것"을 없애거나 "막는 것"을 만들면 계획이 멈춘다. 플레이어는 이 길로 서사에 끼어든다.

### 계획은 어디서 오는가

| 길 | 내용 |
| --- | --- |
| 저작 | 시나리오의 큰 줄기. 세션이 열릴 때 이미 진행 중이다 |
| **계획의 틀에서 세움** | 공용 사전에 계획의 틀이 있다(습격, 잠입, 매수, 수색, 도주, 보복, 거래 …). 마스터는 주체의 목표·앎·자원을 보고 **틀을 고르고 빈칸을 채운다** |

- 마스터에게 "이 조직은 이제 무엇을 할까"를 자유롭게 지으라고 하지 않는다. **고르게 한다.** LLM이 작가로서 부족하다는 것에 대한 답이다.
- 고칠 때(재수립)도 같다. 막힌 계획의 주인에게 틀의 후보를 주고 고르게 한다.

### 코드 / 마스터

| | |
| --- | --- |
| 코드 | 살아 있는 계획마다 지금 단계의 "필요한 것", "막는 것", "이뤄졌는가"를 평가한다. 진행을 기록한다. 조짐을 권역에 건다 |
| 마스터 | 계획을 세우고, 고치고, 버린다 (틀에서 고르는 판단) |

### 언제 따져 보는가

| 때 | 누가 | 대기에 걸리는가 |
| --- | --- | --- |
| 플레이어의 행동이 어떤 계획이 가리키는 사실을 바꿨을 때 | 코드. 조건이 어느 사실을 가리키는지 알고 있다 | 아니오 |
| 턴이 끝날 때, 살아 있는 계획의 지금 단계 | 코드 | 아니오 |
| 계획이 막혔을 때의 재수립 | 마스터. **턴과 턴 사이에** 뒤에서 한다 | 아니오 |

- 살아 있는 계획은 많아야 수십이다. 턴마다 코드로 평가해도 부담이 없다.
- 마스터를 부르는 일(재수립)은 플레이어가 기다리는 구간 밖에서 한다.

### 화면 밖에서 단계가 이뤄지는 방식

- 필요한 것이 다 참이고 막는 것이 없으면, 걸리는 시간이 지난 뒤 "이뤄졌는가"의 사실이 참이 된다. 코드가 한다.
- 다른 주체와 맞서는 단계(습격을 받는 쪽이 있다)는 양쪽의 역량으로 **맞서는 판정**을 한다. 코드가 한다. 결과는 여유의 정도로 갈린다.
- PC가 그 자리에 있으면 화면 밖 처리를 하지 않는다. 사건으로 벌어진다.

## 4. 사건

> 세계에서 벌어지는 한 덩어리의 일. PC가 겪을 수 있는 꼴로 짜인 틀이다.

### 어디서 오는가

| 길 | 예 |
| --- | --- |
| 계획의 단계가 벌어진다 | 흑풍채의 "매복" 단계 → 매복 사건 |
| 세계의 조건이 맞는다 | 밤의 숲을 지난다 → 들짐승과의 조우. 폭우가 사흘째 → 다리가 끊긴다 |

### 사건의 틀에 적는 것

| 항목 | 뜻 |
| --- | --- |
| 빈칸 | 누가, 누구를, 무엇을, 어디서. 채우는 후보의 조건 |
| 시작 조건 | 참이면 벌어질 수 있다 |
| 국면 | 순서나 갈림이 있는 단계들 |
| 유지 / 해결 / 취소 조건 | 사건이 이어지고, 끝나고, 없던 일이 되는 조건 |
| 방치했을 때 | 플레이어가 끼어들지 않으면 어떻게 가는가 |
| 되풀이와 동시 | 몇 번까지, 다른 사건과 함께 벌어져도 되는가 |

### 국면 하나에 적는 것

| 항목 | 뜻 |
| --- | --- |
| 들어가는 조건 | 참이면 이 국면이다 |
| 조짐 | 플레이어가 지각할 수 있는 것. 긴장의 재료 |
| 주체들이 하려는 것 | 이 국면에서 각 역할이 무엇을 바라는가 (마스터의 가이드) |
| 세계에 가하는 변화 | 국면에 들어설 때 확정되는 사실 |

### 저작 부담을 줄이는 세 가지

구 사건 방식에서 무거웠던 것은 **경우의 수를 미리 쓰는 일**이었다고 본다(국면마다 플레이어의 행동에 따른 전개를 문장으로).

1. **경우를 쓰지 않는다.** 국면은 조건으로 넘어간다. 국면 안에서 무슨 일이 벌어지는지는 "주체들이 하려는 것"과 판정으로 그때 정해진다.
   플레이어의 돌발 행동은 따로 대응하지 않아도 된다. 조건이 그 결과를 읽는다.
2. **틀은 엔진이 갖춘다.** 시나리오는 빈칸의 후보와 그 세계만의 문장을 쓴다.
3. **이탈은 조건이다.** 플레이어가 떠나면 유지 조건이 거짓이 되고 "방치했을 때"로 간다. 이탈 처리를 따로 쓰지 않는다.

- 표현력은 줄지 않는다. 시작·유지·해결·취소의 조건, 국면, 빈칸, 되풀이가 모두 있다. 줄인 것은 **문장으로 쓴 경우의 수**다.
- 걱정: "주체들이 하려는 것"만으로 국면 안의 전개가 흥미롭게 나오는가. 이것은 마스터의 판단의 질에 달려 있고, 돌려 봐야 안다.
  부족하면 그 틀에만 경우를 더 쓴다.

### 서사의 자유도

- 사건의 조건은 전부 **세계의 사실**을 가리킨다. 시간도 조건의 하나일 수 있으나 그것만으로 벌어지지 않는다.
- 결과를 문장으로 못 박지 않는다. 사건이 정하는 것은 "세계에 가하는 변화"뿐이고, 그 뒤는 열려 있다.

### 코드 / 마스터

| | |
| --- | --- |
| 코드 | 조건의 평가(참·거짓·모름), 국면의 전이, 빈칸 후보의 추림, 되풀이의 셈 |
| 마스터 | 시작할 수 있는 사건이 여럿일 때 **후보에서 고른다.** 빈칸의 후보에서 고른다. 국면 안에서 주체를 움직인다 |

## 5. 과업

> 플레이어에게 권하는 방향. 강제도 보상도 없다.

### 적는 것

| 항목 | 뜻 |
| --- | --- |
| 시작 조건 | 대개 **PC가 무엇을 알게 되었는가** |
| 내용 | 문장 |
| 빈칸 | 따르기로 할 때 채워지는 것 |
| 달성 조건 | 참이 되면 이뤄진 것 |
| 후속 과업 | |

### 어디서 오는가

| 길 | 예 |
| --- | --- |
| 저작 | 시나리오가 준비한 방향 |
| PC가 아는 계획과 약속에서 | "흑풍채가 내일 상단을 친다"를 알게 됐다 → 알릴 수도, 막을 수도, 끼어들 수도 있다 |
| 플레이어가 스스로 세운 목표 | PC의 계획이 곧 과업이다 |

### 따르기로 하면 세계가 채워진다 [확정 — 사용자 답변]

- 플레이어가 과업을 따라가기로 하면, 미리 저작된 선 안에서 빈칸이 채워져 세계 사실이 된다.
- 예: "실종된 약초꾼을 찾는다"를 따르기로 한다 → 약초꾼이 어디에 어떤 꼴로 있는지가 그때 확정된다 (저작된 후보 가운데).
- 채우는 길은 확정의 사다리와 같다. 이미 확정된 사실과 어긋날 수 없고, 닫힌 범위를 건드릴 수 없다.

### 코드 / 마스터

| | |
| --- | --- |
| 코드 | 시작·달성 조건의 평가. PC의 앎에서 과업의 후보를 뽑는다. 빈칸을 채울 후보를 추린다 |
| 마스터 | 지금 권할 만한 것을 고른다. 빈칸의 후보에서 고른다 |

## 6. 한 번 따라가 보기

```
세션이 열린다
  흑풍채(조직)  목표: 강남 상단의 물건을 빼앗는다
  계획: 상단 습격   단계: 정탐 ✓ → [호위 수 확인] → 길목 선정 → 매복 → 습격
    지금 단계 "호위 수 확인"
      필요한 것: 척후가 객잔에 있다 ✓, 주모가 호위 수를 안다 ✓
      이뤄졌는가: 지휘부가 호위 수를 안다
      조짐: 객잔에 술을 마시지 않는 낯선 사내

1턴  강호민이 객잔에 들어선다 → 조짐이 감각에 잡힌다 ("구석의 삿갓 쓴 사내는 술잔에 손을 대지 않는다")

4턴  강호민이 뒷문을 따고 주모와 실랑이한다 → 소란 → 척후가 자리를 뜬다 (그의 태도: "들키면 싸우지 않고 빠져나간다")
     코드: "척후가 객잔에 있다"가 거짓이 됐다 → 단계의 필요한 것이 깨졌다 → 계획이 막힘

4턴과 5턴 사이 (뒤에서)
     마스터가 흑풍채 지휘부의 자리에서 고른다. 지휘부가 아는 것: 척후가 돌아왔다, 호위 수는 모른다
     후보: 다시 보낸다 / 호위 수를 모르는 채 인원을 늘려 친다 / 미룬다
     → "인원을 늘려 친다"  → 계획이 고쳐진다: 길목 선정 → 매복(인원 증원) → 습격

며칠 뒤  강호민이 주모에게서 척후의 정체를 캐낸다 (설득의 판정이 주모를 구속한다)
     PC가 "흑풍채가 상단을 노린다"를 안다 → 과업의 후보: 상단에 알린다 / 길목에서 기다린다 / 모른 체한다
```

- 이 줄거리는 누구도 쓰지 않았다. 저작된 것은 흑풍채의 목표, 계획의 단계, 인물의 태도다.

## 7. 미결

| 쟁점 | 내용 |
| --- | --- |
| 계획의 틀과 사건의 틀의 목록 | 4단계. 엔진이 처음에 몇 개를 갖추는가 |
| 재수립이 턴 사이에 끝나지 않았을 때 | 다음 턴이 그 계획에 닿으면 어떻게 하는가 |
