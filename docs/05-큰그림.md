# 큰 그림 (살아 있는 문서)

현재 시점의 전체 설계를 한 장으로 요약한다. 질답이 진행될 때마다 갱신한다.
표기: **[확정]** 사용자가 확정 · **[제안]** Claude 제안, 사용자 확인 대기 · **[미탐색]** 아직 다루지 않음.

최종 갱신: 2026-11-12

## 1. 무엇을 만드는가

Gemini API 기반 디스코드 봇. **장르 중립적인 엔진 하나**와 **시나리오 데이터 여럿**으로 구성되며,
유저는 시나리오를 골라 PC에 이입해 TRPG처럼 플레이한다. **[확정]**

> 대목표: 유저는 매력적인 소설의 등장인물이 된 듯한 경험을 한다. **[확정]**

세 가치: **자유도 100% · 확장성 · 개연성**. **[확정]**

## 2. 질답의 목표

질답은 아래를 완성하기 위해 진행한다.

1. **원칙** — 설계 결정의 판단 기준이 되는 불변 규칙 (§3)
2. **구조** — 엔진이 한 턴을 어떻게 처리하는가, 세계를 어떻게 표현하는가 (§4)
3. **경계** — 엔진과 시나리오가 각각 무엇을 책임지는가 (§5)
4. **제약** — 비용, 시간, 플랫폼 (§6)

네 가지가 채워지면 설계 명세와 구현 계획으로 넘어간다.

## 3. 원칙

### P1. 주권 분리 [확정]

- 유저: PC의 생각·발화·행동·의도.
- 마스터: 세계의 상태와 변화, NPC, 성공 여부.
- 서로 침범하지 않는다. 마스터는 유저가 명시하지 않은 PC의 내면·행동을 쓰지 않는다.

### P2. 선언은 자유, 결과는 판정 [확정]

- 유저는 무엇이든 선언할 수 있다. 어떤 상태도 선언을 금지하지 않으며 불이익만 준다.
- 성공 여부는 여러 요소를 조합한 기준값과 주사위로 판정하고, 명백한 경우는 판정 없이 결론짓는다.

### P3. 묘사는 PC의 인지 범위 안에서 [확정]

- 세계의 **진실**과 PC가 **인지한 것**은 별개로 관리된다.

### P4. 전달된 것은 철회되지 않는다 [가치는 확정 — 실현 방식은 보류]

- 플레이어에게 전달된 사실은 **철회되지 않는다.** "착각이었다" 식의 처리는 하지 않는다. **[확정]**
- 실현 방식은 사용자 요청으로 **보류**한다. 구상이 진전된 뒤 다시 다룬다.
  이전 제안들(확정/잠정 정본, 턴을 막지 않는 추출)은 [07](07-전달불변-엔진두께-표현요건.md)에,
  후보(선언 후 사용)는 [08](08-Claude-독자-구상.md)에 남겨 둔다.

### P5. 세부는 필요할 때 생성되어 정본이 된다 [수용 — 생성 방식은 영역별]

- 시나리오는 세계의 모든 세부를 저작하지 않는다. 유저가 미저작 영역에 닿으면 기존 정본과 모순되지 않게 세부가 생기고, 그때부터 정본이다.
- **생성은 자유 창작이 아니라 틀의 선택과 조립이다.** 무엇이 있을 법한지는 사전(원형, 조각)과 분류 헤드가 정하고,
  LLM은 고르고 빈칸을 채우며 서술문을 쓴다. 구조는 코드가 검사한다. **[제안]**
- 공간의 창작은 사용자가 **조건부 허용**: 개연성을 부여할 수 있음이 밝혀지면 허용한다. 구현 초기에 실험으로 확인한다.

### P6. 서사는 저작하지 않고, 움직이는 세계에서 나온다 [제안 — 조건부 수용]

- 줄거리·사건 순서를 쓰지 않는다. **자기 목표를 가진 세력과 인물**을 저작한다.
- 유저가 개입하지 않아도 그들의 계획은 진행되며, 그것이 사건과 압박이 된다.
- LLM에게 "작가" 역할을 맡기지 않는다. 방향성은 저작된 목표에서 오고,
  LLM은 "이 인물이 이 상황에서 무엇을 하는가"라는 국소적 판단만 한다.
  (사용자의 회의 — LLM은 작가로서 부족하다 — 를 전제로 받아들인 설계)
- 수용 조건: 자율적인 세계가 실제로 잘 기능할 것. 서사의 완급 장치는 미해결.

### P7. 인물은 서술자의 도구가 아니다 [수용]

- NPC는 각자의 지식·목표·감정 상태를 가지며, 그 결정은 서술과 분리되어 내려진다.
- NPC는 자신이 알 수 있는 것만 안다 (P3의 NPC판).
- 구현 방식(인물별 별도 호출 여부 등)은 예산 안에서 정한다. **[미탐색]**

### P8. 엔진은 모든 장르를 알고, 시나리오는 고르고 고치고 더한다 [확정]

- 엔진은 장르들을 포괄하는 풍부한 **공용 항목**을 갖춘다.
- 시나리오는 공용 항목을 골라 쓰고, 수정하고, 고유 항목을 더한다.
- 시나리오별 하드코딩은 없다. 공용 항목과 고유 항목은 같은 형식이다. **[제안]**
- 세션 개설: `공용 정의 → 시나리오의 수정·추가 → 미정 사실 결정 → 유일한 세계 상태`. **[확정]**

### P9. 세계 표현은 유일하게 해석되고, 선별 가능하며, 형식이 균일하다 [제안]

- 판정과 추적에 쓰이는 사실은 호출마다 해석이 달라지지 않는 형태로 둔다.
- 세계 상태는 작은 단위로 나뉘어, 호출마다 필요한 단위만 골라 넣을 수 있다 (비용·대기 제약의 전제).
- 새 개념이 추가되어도 형식은 바뀌지 않는다.
- 근거: 구 프로젝트가 자연어에서 필드로 옮겨 간 계기 두 가지 (해석의 흔들림, 선별 전달의 어려움).

## 3-1. Claude 독자 구상 [방향 수용]

구 프로젝트를 전제하지 않고 쓴 구상. 사용자가 별도로 준비하던 재설계 구상과 거의 일치한다는 평가를 받았다. 상세는 [08-Claude-독자-구상.md](08-Claude-독자-구상.md).

> 세계를 "누가 아는지가 딸린 사실들의 장부" 하나로 두고, LLM은 그 장부를 읽고 쓰는 좁은 역할들로 쪼갠다.
> 지켜야 할 것은 프롬프트로 부탁하지 않고 구조로 보장한다.

1. 하나의 장부 — 모든 것이 한 형식의 사실, 각 사실에 "누가 아는가"
2. 구조로 보장 — 장부 정리는 코드, 정보 격리는 문맥으로
3. 인물은 각자의 머리로 — 주요 NPC는 자기 지식만 받은 별도 병렬 호출로 의도를 결정
4. 세계는 시계로, 연출가는 조절만 — 세력의 계획이 시계로 진행, 완급은 코드 연출가가 조절
5. 미정 사실은 세계의 변수 — 세션 개설 시 결정, 반복 플레이의 다채로움
6. 측정할 수 있는 엔진 — 가상 플레이어, 자동 검사, 시나리오 검사기

## 4. 구조 [제안 — 사용자 구상과 대조 대기]

Claude가 사용자의 재설계 구상을 보기 전에 독립적으로 설계했다.

### 장부 → [09-장부-설계.md](09-장부-설계.md) (통합본 v0.2) · 조건 언어 → [14-조건-언어.md](14-조건-언어.md)

- 여섯 요소: **개체, 사실, 정의, 사건, 시야, 틀**. (틀은 형식 시험에서 추가)
- 사실은 `속성(주체[, 대상]) = 값` 한 형태. 서술문 값은 묘사 재료로만 쓰이고 코드는 읽지 않는다.
- 정의는 어휘다. 행동은 세 층으로 기술한다: 코드 기제 → 선언 규칙 → 자연어 지침.
  확장은 구조가 아니라 어휘를 늘려서 한다.
- 세계 장부 하나와, 마음마다 같은 형식의 **시야**. 앎은 낡고 틀리고 출처가 있다. PC의 시야 = 전달된 것.
- 위치는 하나의 관계다 (방 안의 사람, 손에 든 검, 병 속의 물, 건물 안의 방).
- 틀은 빈칸 있는 사실 묶음이다. 물건의 원형, 장소 조각, 사건 틀, 단역 인물, 시나리오의 변수가 한 장치다.
- 지각은 명백한 경우만 코드가, 경계 사례는 심판이 정하고, 결과는 사실로 기록한다.
- 기억은 요약이 아니라 선별이다. LLM은 제안만 하고 코드가 검사해 기록한다.
- 형식 시험 → [12](12-형식-시험-물건과-장소.md), [13](13-형식-시험-나머지-열두-영역.md). **14개 영역 전부 적혔다.** 개정 사항 열셋, 기본 기제 일곱(게이지, 시계, 전이, 예약, 위치 제약, 변환, 계승).
- 시야는 "명제를 담는 모든 것"으로 일반화한다: 마음, 집단, 문서, 소문.
- 조건을 쓰는 모든 곳이 하나의 조건 언어를 쓴다. 조건은 사실과 같은 모양이고, 가리킴은 정해진 지시어로만 한다.
  못 하는 일을 일부러 정해 두고 그 너머는 심판에게 넘긴다 (조건은 단단하게, 효과만 자연어로).
- 저작자는 자연어로 쓰고, 코드가 조건을 다시 한국어로 풀어 보여 주면 확인만 한다 (되읽기).
- 종이 위의 시험이다. LLM의 제안 안정성, 문맥 선별, 비용·지연은 최소 구현으로만 확인할 수 있다.

### 턴 → [10-턴-처리-흐름.md](10-턴-처리-흐름.md)

```
선언 → ① 심판 → ② 판정(코드) → ③ 진행(코드) → ④ 인물(병렬) → ⑤ 정리(코드) → ⑥ 서술자 → ⑦ 마감(코드)
```

- LLM 역할은 셋: **심판**(진실을 봄), **인물**(자기 시야만), **서술자**(PC가 지각한 것만).
- 인물의 대사는 그 인물의 호출이 쓴다.
- 판정은 지각을 정하고, 마음은 반응을 정한다. 설득은 주사위가 아니라 인물이 정한다.
- PC와 다투는 인물의 행동은 시작만 반영하고, 유저의 대응과 함께 다음 턴에 해소한다.
- 거친 검산: 전부 Flash급이면 턴당 약 19원, 서술자만 Pro면 약 44원. 공식 가격 미확인, 실측 전.

## 4-1. 사용자 재설계 자료와의 대조 → [11](11-사용자-재설계-자료-대조.md)

- 뼈대는 일치한다 (네 범주, 두 층위, 코드와 LLM의 분담, 진실과 앎의 분리, 시간 운영, 자율 세계).
- 어긋났던 것과 결론: 인간 GM은 **없다**(확정). 미저작 공간의 창작은 **조건부 허용**. 사건 틀은 **엔진 공용 항목**으로(방향 수용). 14개 영역은 **형식의 시험 문제**로(시도 승인).
- 사용자 자료에만 있는 것: 원형–실물과 단위, 불명확한 시간, 속성 계승, 과업, 사회규범, 정보의 추론 관계, 행동선언 유형.
- 권고: 14개 영역을 구조의 단위가 아니라 **어휘의 점검표이자 형식의 시험 문제**로 쓴다. **[제안]**

## 4-2. 자료 정독 대조 → [16](16-자료-정독-대조.md)

GPT 조사 자료와 영역별 설계 문서까지 읽고 현재 설계에 빠진 것을 찾았다.

- 뼈대는 유지된다. 그러나 빠진 것이 서른 개가 넘는다.
  - 형식을 고쳐야 하는 것 9건: 부정 사실, 위치가 아닌 물리 관계, 값의 해상도, 앎의 깊이, 출처 등급, 공간(열린 연속·닿음·이동 중·추적하지 않는 위치), 예약과 시계, 허위 정밀도, 묶음과 분할.
  - 턴 처리를 고쳐야 하는 것 8건: 되묻기, 효과의 크기, 다단계·조건부 선언, 보정 요인의 분류, 재시도, 중간 동작, 실패 이유의 노출, 지각과 반응의 시차.
  - 사용자 정책 결정이 필요한 것 6건, 아직 설계하지 않은 영역 9건.
- 설계가 틀린 곳: **집단 시야의 계승**(구 프로젝트는 일부러 자동 전파를 막았다), "위치는 하나의 관계"의 과대 주장, 화면 밖 시간 계산.
- 사건 기록과 예약은 Claude의 제안이며 사용자 승인이 없었다. 자료에는 채택하지 않았다고 적혀 있다.

## 4-3. 통찰과 새 설계 → [17](17-통찰과-새-설계.md) **[제안 — 사용자 검증 대기]**

16 문서의 빈틈을 하나씩 메우는 것은 덧붙이기다. 통찰과 구 해법을 가르고, 통찰 여럿을 한 번에 해소하는 설계 다섯을 제안했다.

1. **무른 사실과 단단한 사실** — 정의가 있는 속성은 코드가 검사하고, 없는 속성은 짧은 문장으로 LLM만 읽는다. 무르게 시작해 위험이 확인된 곳만 굳힌다.
2. **닫힌 범위** — 세계는 기본적으로 열려 있고, 닫힌 범위에서는 적힌 것이 전부다. 부재, 생성 권한, 서술의 제약을 한 장치로.
3. **행동은 단계의 계획** — 심판이 선언을 단계로 옮기고, 엔진이 차례로 실행하다 멈춰야 할 곳에서 멈춘다.
4. **판정** — 심판은 어려움과 방법만 판단하고 나머지는 코드가 장부에서 센다. 효과의 크기는 굴리기 전에 정한다.
5. **인물의 세 해상도** — 배경 → 단역 → 주요로 승격한다. 앎은 계승이 아니라 전달로만 퍼진다.

사용자 결정(2026-11-12): 소급 선언은 현재 시점의 시도로만. 생성 권한의 등급은 유지. 되감으면 다시 굴린다. 두 층위의 뜻과 사건 기록·예약은 **보류**.
구 프로젝트의 해법(2d50 산식, 요인 일곱, 성장·행운 규칙, 동행 역할, 판정 경로 다섯 등)은 가져오지 않는다.

## 5. 엔진과 시나리오의 경계 [미탐색 — 방향만]

- 시나리오는 사용자 혼자 쓴다. 저작 난이도가 과하면 안 된다. **[확정]**
- 시나리오가 데이터만인지, 규칙 정의까지 포함하는지는 Claude가 설계한다. **[확정된 위임]**
- 방향: 시나리오 = 세계관 + 인물·세력(목표 포함) + 장르 규칙의 **선언적** 정의. 코드는 가급적 배제. **[제안]**
