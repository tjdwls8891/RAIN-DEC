# 뼈대와 이어 돌린 실측 (1·2단계의 첫 판)

2026-11-14. 턴의 일곱 단계를 코드로 만들고([31](31-접점과-턴.md)), 객잔 장면에서 실제 모델로 열두 선언을 한 세션으로 이어 돌렸다.
[36](36-첫-실측.md)에서 찾은 문제의 수정을 넣었다.

- 코드: `raindec/engine.py`(새로 씀), `raindec/llm.py`(다시 씀), `play.py`. 옛 `turn.py`는 지웠다.
- 시험: 21개 통과(장부 11, 턴 10). 원자료: `experiments/results/play-bench-*.json`.
- 지금까지의 추정 지출: **약 185원** (상한 1,500원).

## 1. 만든 것

| 단계 | 구현 | 아직 없는 것 |
| --- | --- | --- |
| ① 해석 | 닫힌 목록(유형 18, 동작 15, 대상)에서 고르게 한다. PC의 앎만 준다 | |
| ② 준비 | 동작마다 코드가 뻔한 것을 정한다: 가기, 살피기, 둘러보기, 통로 열고 닫기, 용기 열기, 집기 | 나머지 동작 |
| ③ 판단 | 코드가 물음과 후보를 만들고, 답이 후보 밖이면 물음마다의 기본값을 쓴다 | 빈 항목 채우기 |
| ④ 판정 | 2d50. 기준값은 코드가 셈한다(난이도·방법만 판단이 고른다). 정도 여섯. 버튼 | 숙련·장비·상태·협력의 반영 |
| ⑤ 귀결 | 위치·잠김·열림·호감의 변화. 새로 지각한 것만 모은다 | 시간에 따른 상태 계산, 계획과 사건 |
| ⑥ 서술 | PC가 한 일과 지각한 것만 준다. 흘려 받는다 | |
| ⑦ 확정 | 턴의 변화를 사건 하나로 한 번에 | |

**36에서 찾은 문제의 수정**

| 문제 | 고친 방식 |
| --- | --- |
| 판단이 쓴 "걸린 것"에 PC가 모르는 것이 샌다 | 걸린 것은 **코드가 틀에서** 쓴다. 판단이 쓰는 글은 인물의 말뿐이다 |
| 강제로 얻는 것이 넘친다 | 성공했을 때 인물이 **하는 일**을 코드가 후보로 추린다(예: 열쇠에 손이 닿는 인물에게만 "뒷문을 열어 준다"). 말의 내용은 아직 지시로만 막는다 |
| "이미 쓴 것"을 다시 쓴다 | 재료에서 뺐다. 생김새도 처음 다룰 때만 준다 |
| 말 칸에 몸짓이 섞인다 | 괄호를 코드가 걷어 낸다 |

## 2. 이어 돌린 결과 (3 flash, 사고 최소)

| | |
| --- | --- |
| 선언에서 되읽기까지 | 1.1~1.7초 |
| 선언에서 판정 버튼까지 | 2.7~3.1초 |
| 선언에서 서술의 첫 글자까지 | **중앙값 2.3초, 최대 3.8초** |
| 턴당 값 | **2.6원** (판단이 든 턴 3.6~4.5원, 없는 턴 2.0~2.6원) |
| 판단 없이 끝난 턴 | 10턴 가운데 7 |
| 세계 밖의 물음, 모호한 선언 | 해석 하나로 끝났다 (1.1~1.5초, 약 1원) |

- 과녁(15초, 50원)에서 멀리 떨어져 있다. 다만 **장면이 작다.** 인물 둘, 장소 셋, 가이드 없음. 판단의 입력이 1,000토큰 남짓이다.
- 판단 없이 끝난 턴이 많은 것은 반은 설계의 뜻대로이고(잠긴 문, 이동), 반은 **코드가 다루지 못해 그냥 넘긴 것**이다. 좋은 수로만 읽으면 안 된다.

**잘 된 것**

- 잠긴 뒷문: 판단을 부르지 않고 "잠겨 있다"로 끝났다. PC는 해 보고서 잠김을 알게 되었다.
- "서랍에서 뒷문 열쇠를 찾아냈다!": 단정은 시도로 바뀌었고, 열쇠는 생기지 않았다. 서술은 "뒷문 열쇠는 보이지 않는다"로 끝났다.
- 서랍 속: 후보에서 엽전 꿰미·치부책·주판이 골라져 실물이 되었고, 다시 열었을 때 같은 것이 있었다(다시 묻지 않았다).
- 사칭: 난이도 "매우 어려움", 방법 "나쁨", 기준 23. 굴려서 31, 아슬한 실패. 주모는 증표를 요구했고 호감이 한 단계 내려갔다.
- 판정 판의 "걸린 것"에 숨은 것이 없다.

## 3. 시험이 잡은 누설

- 해석에 주는 대상 목록에 **개체의 내부 이름**이 들어 있었다. 저작자가 붙인 이름("척후")에는 진실이 묻어 있다.
- 격리 시험이 이것을 잡았다. 해석에는 부름말("삿갓 쓴 사내")만 주고 코드가 되돌려 잇도록 고쳤다.
- 얻은 것: **내부 이름은 어떤 LLM 호출에도 PC 쪽으로 내보내지 않는다.** 저작 양식에서도 같은 주의가 필요하다.

## 4. 드러난 문제

| # | 문제 | 본 것 | 뜻 |
| --- | --- | --- | --- |
| 1 | **동작의 목록이 설계의 가장 큰 빈자리다** | "맞은편에 앉는다", "검을 뽑는다"를 코드가 몰랐다. 처음에는 뒤의 행동(묻기, 위협)까지 끊겼다 | 행동 18유형마다의 "열어 볼 정보, 고칠 정보, 뻔한 귀결"(4단계)이 없으면 턴이 서지 않는다. 지금은 "제 몸과 제 것으로 하는 몸짓은 세계를 바꾸지 않고 지나간다"로 막아 두었다 |
| 2 | 서술의 작은 지어냄이 남아 있다 | "삼실로 엮은 엽전 꿰미", "행주로 탁자를 문지른다", "나무 바닥이 울린다", "객잔의 소란" | 재료를 줄여도, 생김새를 넣어 줘도 일어난다. 보류한 "지어낸 세부의 기록"에 닿는다 |
| 3 | 서술이 인물을 움직인다 | 곁에서 "끼어들어 말한다"를 고른 주모가 "다가온다", "앞을 막아선다"로 쓰였다. 장부에서 주모는 계산대 뒤 그대로다 | 태도가 위치를 바꾸는 것이면 코드가 위치를 바꿔야 하고, 아니면 재료가 "제자리에서"라고 말해야 한다 |
| 4 | 살펴서 얻은 등급이 풀이로 쓰였다 | 사내를 살피자 "기분: 경계"가 재료로 갔고, 서술이 "그는 당신을 경계하고 있다"고 썼다 | 감정은 등급이 아니라 **겉으로 보이는 것**으로 감각에 넘겨야 한다 |
| 5 | 판정의 값이 가혹하다 | 사칭의 기준 23은 성공 확률 약 10% | 값은 4단계다. 사용자와 정하기로 한 것 |
| 6 | 판단이 고른 난이도가 흔들린다 | 같은 위협에 "어려움"(36)과 "매우 어려움"(이번) | 하한을 코드가 두는 것([29](29-꿰는-것과-판정.md))을 아직 넣지 않았다 |
