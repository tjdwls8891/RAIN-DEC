# 장부 설계 (Claude 독자안)

2026-11-12. 사용자의 재설계 구상을 보기 전에 독립적으로 작성했다. 대조용이며 전부 **[제안]**이다.
표기 예시는 개념을 보이기 위한 것이고 최종 문법이 아니다.

> **개정 예고 (2026-11-12):** 물건과 장소로 형식을 시험한 결과 아홉 가지를 고쳐야 한다.
> 이 문서의 본문은 시험 이전의 상태이며, 개정 사항은 [12](12-형식-시험-물건과-장소.md) §4와 [13](13-형식-시험-나머지-열두-영역.md) §3·§4에 있다(합계 열셋).
> 어긋나는 곳은 12·13 문서가 우선한다. 특히 §3 "지각은 코드가 계산한다"는 철회되었다.
> 시험이 더 진행된 뒤 본문을 한 번에 고쳐 쓴다.

## 1. 설계 목표

P9의 세 요건과 구상 1·2를 만족해야 한다.

- 형식은 하나이고, 새 장르·새 개념이 와도 **형식이 아니라 어휘가 늘어난다.**
- 코드가 다루는 사실은 해석이 하나뿐이다.
- 호출마다 필요한 조각만 골라낼 수 있다.
- LLM은 장부를 직접 고치지 못한다.

## 2. 다섯 가지 구성 요소

장부는 다섯 가지로만 이루어진다.

| 요소 | 무엇인가 | 누가 만드는가 |
| --- | --- | --- |
| **개체** | 정체성을 가진 모든 것 (인물, 장소, 물건, 세력, 계획, 비밀) | 시나리오 저작, 플레이 중 생성 |
| **사실** | 개체에 대한 한 줄의 참 | 시나리오 저작, 사건의 결과 |
| **정의** | 어휘. 어떤 속성이 있고 어떻게 행동하는가 | 엔진 공용 + 시나리오의 수정·추가 |
| **사건** | 일어난 일의 기록. 덧붙이기만 한다 | 턴 처리 |
| **시야** | 한 마음이 아는 것. 형식은 장부와 같다 | 지각 계산(코드) |

### 2.1 개체

- 식별자와 **종류 표지** 여럿을 가진다. 종류는 계층이 아니라 표지다 (`인물`, `무림인`, `적대적` …).
- 장소, 물건뿐 아니라 **계획, 비밀, 소문**도 개체다. 덕분에 "누가 그 비밀을 아는가"를 같은 방식으로 다룬다.

### 2.2 사실

한 가지 형태다.

```
속성(주체[, 대상]) = 값      + 언제부터 · 어느 사건에서 비롯
```

```
위치(강호민) = 객잔_1층
소지(강호민, 철검) = 참
피로(강호민) = 높음
호감(주모 → 강호민) = 경계
외양(주모) = "쉰 줄의 여인. 손등에 오래된 화상 자국."
```

- 값은 네 종류뿐이다: **등급·수치**, **열거**, **개체 참조**, **서술문**.
- 서술문 값은 **묘사 재료로만** 쓰인다. 코드의 판단에는 절대 쓰이지 않는다.
  해석이 갈릴 수 있는 것은 서술문 안에만 있고, 코드가 읽는 값은 해석이 하나다.
- 긴 세계관 설명도 개체에 딸린 서술 사실로 **쪼개어** 둔다. 쪼갤 수 없는 긴 덩어리를 두지 않는다.

### 2.3 정의 — 어휘와 행동

속성 하나하나는 정의를 가진다. **공용 항목이 사는 곳**이다.

```
정의: 피로
  값: 등급 [없음, 낮음, 보통, 높음, 극심]
  겉보기: 관찰하면 보임          # 지각 규칙이 읽는다
  변화: 활동 시 상승, 휴식 시 하강
  영향: 높음 이상이면 신체 판정에 불리
  상호작용: 허기가 높음 이상이면 상승 속도 증가
  묘사 단서: 높음 = "눈꺼풀이 무겁고 동작이 굼뜨다"
```

정의는 세 층으로 행동을 기술한다. 위에서부터 단단하다.

1. **기제** — 코드로 구현된 공용 부품. 정의는 부품을 골라 매개변수를 채운다.
   예: 등급 게이지, 소모 자원, 성장 궤도, 시계(단계적 진행), 관계 척도, 비밀과 단서, 추격 거리.
2. **선언 규칙** — "조건 → 효과"의 짧은 문장. 조건과 효과는 사실의 형태로만 쓴다.
3. **자연어 지침** — 심판 역할의 LLM이 읽는 판정 지침. 코드로 미리 만들 수 없는 것의 탈출구.
   예: "내공이 상대보다 두 단계 이상 낮으면 정면 대결은 명백한 실패로 본다."

- 시나리오는 새 정의를 **기존 기제의 조합**으로 추가한다. 코드를 쓰지 않는다.
  게이트 헌터물의 "등급"은 성장 궤도, 좀비물의 "감염"은 시계 + 등급 게이지, 추리물의 "단서"는 비밀과 단서 기제다.
- 어떤 기제로도 표현되지 않는 것은 자연어 지침으로 시작하고, 여러 시나리오에서 반복되면 엔진에 기제로 승격한다.
  **확장성이 부족할 때 구조를 고치지 않고 어휘를 늘리는 경로**가 처음부터 있다.

### 2.4 사건

```
사건 #412  시각: 3일차 21:40  장소: 객잔_1층
  행위자: 강호민   유형: 조작   대상: 뒷문_자물쇠
  판정: 기준 62, 주사위 71 → 실패
  변화: 소음(객잔_1층) = 큼
  지각: 강호민(전부), 주모(소리만)
```

- 세계의 현재 상태는 사건을 처음부터 쌓은 결과다. 사건은 고치거나 지우지 않는다.
- 주사위 값과 호출 입력·출력도 사건에 남긴다. 어떤 턴이든 그대로 재현할 수 있다.
- 되감기는 "N번 사건까지만 쌓기"다. 턴 처리 도중 실패하면 아무것도 쌓이지 않으므로 재시도가 안전하다.
- 사건은 기억의 단위이기도 하다 (§3).

### 2.5 시야 — 마음마다의 장부

"사실에 누가 아는지를 딸려 둔다"(구상 1)를 구체화하면서 형태를 바꿨다.

> 세계 장부가 하나 있고, **마음마다 같은 형식의 작은 장부(시야)**가 있다.

- 이유: 앎은 진실의 사본이 아니다. **낡을 수 있고**(어제 본 문은 지금 잠겼을 수 있다),
  **틀릴 수 있고**(거짓말을 믿는다), **출처가 있다**(직접 봤다 / 주모에게 들었다).
- 시야의 사실에는 `언제 알았나 · 어떻게 알았나 · 얼마나 확신하나`가 붙는다.
- **PC의 시야 = 플레이어에게 전달된 것.** 서술자는 PC의 시야만 받는다.
- 모든 인물이 시야를 갖지는 않는다. 시야는 층으로 상속된다.

  ```
  세계의 상식 → 집단의 공유 지식(마을 사람, 문파, 수사팀) → 개인
  ```

  저작자는 사실마다 "어디까지 알려져 있나"(상식 / 어느 집단 / 누구만)를 표시하면 된다.
  단역은 집단 시야만으로 움직이고, 주요 인물이 되는 순간 개인 시야가 생긴다.

## 3. 지각과 기억

### 지각은 코드가 계산한다

- 사건이 일어나면 코드가 **누가 그것을 지각했는가**를 정한다.
  같은 장소에 있는가, 감각이 닿는가, 속성의 겉보기 등급이 무엇인가(누구나 보임 / 관찰해야 보임 / 숨겨짐).
- 지각한 마음의 시야에 그 사건과 드러난 사실이 덧붙는다.
- "NPC가 알 수 없는 것을 안다"가 구조적으로 불가능해진다. NPC 호출은 자기 시야만 받기 때문이다.

### 말은 사실의 전달이다

- 인물이 말할 때는 **무엇을 알려 주는가**가 먼저 정해진다: 자기 시야의 어떤 사실을 밝히는가, 숨기는가, 거짓을 말하는가.
- 들은 쪽의 시야에는 "주모가 이렇게 말했다"가 출처와 함께 들어간다. 참인지는 별개다.
- 소문의 전파, 거짓말, 정보 거래가 같은 장치에서 나온다.

### 기억은 요약이 아니라 선별이다

- 한 마음의 기억 = 그 마음이 지각한 **사건들** + 시야의 **사실들**.
- 호출에 넣을 기억은 관련 개체, 최근성, 중요도로 **골라낸다.** 대화 기록을 LLM으로 압축하는 단계가 없다.
- 오래 알고 지낸 인물에 대한 "관계 요약" 같은 것은 필요할 때 만들어 서술 사실로 저장한다.

## 4. LLM이 장부에 쓰는 방법

- LLM은 장부를 직접 고치지 않는다. **제안**만 낸다.

  ```
  제안: 개체 생성 / 사실 설정 / 사건 발생 / 판정 요청
  ```

- 코드가 제안을 검사한다: 정의에 맞는 값인가, 기존 사실과 모순되지 않는가, 주권을 넘지 않는가(PC의 내면을 정하려 하는가).
  통과한 것만 사건으로 기록된다.
- 미저작 세부의 생성(P5)도 같은 길을 탄다. "객잔에 뒷문이 있는가"는 심판이 제안하고 코드가 검사해 정본이 된다.

## 5. 문맥 조립

각 호출의 문맥은 장부에 대한 **질의의 결과**다.

1. 고정부: 공용 지침, 시나리오의 어조와 전제 (모든 턴에 같음 — 캐시 대상)
2. 장면: 현재 장소에 있는 개체들의 사실 (호출 주체의 시야 기준)
3. 언급: 선언에 등장한 개체, 그리고 한 걸음 떨어진 관계
4. 기억: 관련 사건 몇 개
5. 어휘: 위에 등장한 속성의 정의와 지침만

- 토큰 예산 안에서 우선순위로 자른다. 세계가 커져도 호출 크기는 장면 크기에 비례한다.

## 6. 시나리오와 세션

```
공용 정의
  + 시나리오: 정의의 선택·수정·추가, 개체와 사실, 세력의 계획, 변수
  + 세션 개설: 변수 값 결정
  = 첫 사건 묶음  →  세계 장부
```

- 변수는 사실의 값 자리에 놓인다: 후보 목록, 범위, 다른 변수에 대한 조건.
  ```
  위치(살인마) = 변수{ 보트창고 | 관리동 | 숲길 }
  정체(범인) = 변수{ 용의자 중 하나 }, 조건: 알리바이(범인) = 거짓
  ```
- 시나리오 검사기가 개설 전에 확인한다: 정의 없는 속성, 가리키는 곳 없는 참조, 값이 정해질 수 없는 변수.

## 7. 스스로 보는 약점

- **정의의 설계가 품질을 좌우한다.** 공용 기제 목록을 잘못 잡으면 시나리오마다 자연어 지침에 기대게 되고,
  그러면 해석의 유일성이 무너진다. 기제 목록은 다섯 장르를 실제로 표현해 보며 정해야 한다.
- **지각 계산의 정밀도.** 소리, 시야, 거리의 규칙을 어디까지 코드로 할지 선을 그어야 한다. 과하면 물리 엔진이 된다.
- **시야의 저장량.** 주요 인물 수 × 지각한 사건 수로 늘어난다. 집단 시야 상속으로 줄이지만 실측이 필요하다.
- **말의 구조화.** "무엇을 알려 주는가"를 먼저 정하는 방식이 대화의 자연스러움을 해치지 않는지 확인해야 한다.
