# 전체 설계도 (1단계와 2단계)

2026-11-13. 사용자 지시: 큰 그림부터 세부까지의 순서로 설계한다. 한 부분에 집중하다 다른 부분을 놓치지 않는다. **설계에 남은 시간은 3일이다.**

이 문서는 전체를 **같은 깊이로** 한 번 훑는다. 어느 부분도 깊이 파지 않는다.
앞선 문서들과 어긋나는 곳은 이 문서가 우선한다.

- 1단계: 전체가 몇 덩어리이고 서로 어떻게 맞물리는가
- 2단계: 덩어리마다 무엇을 담고, 코드와 마스터가 각각 무엇을 하는가
- 3단계(다음): 덩어리마다 항목의 목록
- 4단계(그다음): 값과 규칙의 실제 내용

## 0. 정해진 바탕

| | |
| --- | --- |
| 대목표 | 유저는 매력적인 소설의 등장인물이 된 듯한 경험을 한다 |
| 세 가치 | 자유도 100%, 확장성, 개연성 |
| 주권 | 유저는 PC의 생각·말·행동·의도를, 마스터는 세계와 결과를 정한다 |
| 분담 | **판단은 마스터가 명확한 기준으로 한 번 하고, 그 귀결의 계산과 유지는 코드가 한다.** 코드가 상태의 권위를 갖는다 |
| 순서 | 대상을 선정하고, 세계 사실을 확정하고, 그 뒤에 묘사한다 |
| 사전 | 엔진은 모든 장르를 알고, 시나리오는 고르고 고치고 더한다. 비어 있는 것은 LLM이 채우고 검토 뒤 공용에 편입한다 |
| 구분 | **상태의 계산**은 시간에 따라 코드가 한다. **서사의 진행**은 시간만으로 정하지 않는다 |
| 제약 | 턴당 50원 이하. 대기 15초 미만(플레이어의 마지막 행동부터 다음 버튼이나 묘사 시작까지) |

## 1. 1단계 — 다섯 덩어리

사용자의 네 범주에 운영을 더했다.

```

│ 가. 세계 사전        무엇이 있을 수 있고 어떻게 작동하는가          │
│     공용 사전 + 시나리오                                          │
└───────────────┬──────────────────────────────────────────────────┘
                │ 세션을 열 때 변수를 정해 세계를 만든다
┌───────────────▼──────────────────────────────────────────────────┐
│ 나. 세계 시뮬레이션  지금 세계가 어떠한가                          │
│     장부(상태) · 계산(상태의 귀결과 시간) · 진행(조직·계획·사건)    │
└───────────────┬──────────────────────────────▲───────────────────┘
        필요한 것만 골라 준다              검사를 거쳐 반영한다
┌───────────────▼──────────────────────────────┴───────────────────┐
│ 다. 마스터의 층위    무슨 일이 일어났는가를 판단한다                │
│     해석 · 판단 · 판정 · 인물                                     │
└───────────────┬──────────────────────────────────────────────────┘
                │ PC가 지각한 것만
┌───────────────▼──────────────────────────────────────────────────┐
│ 라. 묘사와 경험      플레이어가 보고 누르는 것                      │

└──────────────────────────────────────────────────────────────────┘
  마. 운영   세션 · 되감기 · 캐시 · 비용 · 실패 · 시험 · 저작 도구
```

## 2. 2단계 — 가. 세계 사전

사전은 영역별로 **유형, 항목, 상태, 규칙, 가이드**를 담는다. 형식은 하나다.

| 사전에 담는 것 | 뜻 | 누가 읽는가 |
| --- | --- | --- |
| 유형 | 어떤 종류가 있는가 (물건의 16유형, 장소의 종류, 상태의 종류) | 코드 |
| 항목 | 그 유형이 갖는 값. 코드가 추적한다 | 코드 |
| 상태 | 붙고 떨어지는 것. 부여와 해제의 기준이 딸린다 | 코드 |
| 규칙 | 상태와 항목에서 나오는 귀결 | 코드 |
| 가이드 | 마스터가 판단할 때 따르는 기준과, 인물의 태도·판단 방식 | 마스터 |
| 문장 | 묘사에 그치는 것 | 마스터 |

### 영역

사용자의 청사진과 14개 영역을 합쳤다. 영역은 설계를 나눠 보는 단위이고 모듈이 아니다.

### 영역을 꿰는 것

| 꿰는 것 | 뜻 | 걸치는 영역 |
| --- | --- | --- |
| **상태** | 붙고 떨어지며 귀결을 낳는 것. 부여·해제의 기준, 등급, 상호작용 | 물건, 신체, 환경, 심리 |
| **위치** | 무엇이 어디에, 어떤 방식으로 있는가 | 장소, 물건, 신체 |
| **앎** | 누가 무엇을 어디까지 아는가 | 정보, 감각, 관계, 조직, 사회 규범 |
| **조건** | 상태의 기준, 사건의 발생, 계획의 진행을 적는 하나의 언어 | 전부 |
| **계승** | 없는 값은 위에서 가져온다 (원형, 분류 헤드, 역할) | 물건, 장소, 심리, 사회 규범 |

- 영역마다 따로 만들지 않고 이 다섯을 **한 번만** 만든다. 구 프로젝트와 달라야 하는 곳이다.

### 인물의 가이드에 대하여 (사용자 설명, 2026-11-13)

- LLM은 사람을 그리는 데 소질이 없을 때가 있다. 현실의 대화와 비언어적 소통이 학습 자료에 풍부하기 어렵기 때문이다.
- 그래서 저작 부담을 안고서라도 **경우별 인물의 태도와 판단 방식을 가이드**한다.
- 다양성과, 인물별·세계관별로 맞추는 일이 필요하다.

이에 따른 구조:

| 층 | 무엇 | 어디에 |
| --- | --- | --- |
| 사람 일반 | 상황별로 사람이 흔히 어떻게 굴고 어떻게 말하는가 (낯선 이의 접근, 추궁당할 때, 거래, 조문) | 공용 사전 |
| 세계관 | 이 세계의 사람이 다른 점 (무림의 예법, 재난 석 달째의 경계심) | 시나리오 |
| 역할 | 그 자리에 있는 사람의 기대되는 언행 | 사회 규범 |
| 인물 | 이 사람만의 태도와 판단 방식. 관계의 단계별, 경우별 | 인물 |

- 위에서 아래로 물려받고, 아래가 위를 덮는다. 인물 하나를 쓸 때 다른 점만 쓴다.

## 3. 2단계 — 나. 세계 시뮬레이션

| 부분 | 하는 일 | 상태 |
| --- | --- | --- |
| **장부** | 세계의 현재 상태를 갖는다. 개체, 사실, 누구의 앎인가 | 코드 있음 |
| **계산** | 상태의 귀결을 굴린다. 턴이 끝날 때 흐른 시간만큼 PC와 주변의 상태를 계산한다 | 방향 확정, 설계 전 |
| **진행** | 서사가 나아가게 한다. 조직 · 계획 · 사건 | 설계 전 |
| **확정** | 대상 선정 → 저작된 것 → 사전에서 골라 실물로 → 사전에 없으면 채움 | 방향 확정 |

### 계산 [확정된 방향]

- 추위에 몇 시간 있으면 저체온증이 온다. 이런 것은 이견이 있기 어려운 사실이고 코드가 시간에 따라 계산한다.
- 신체 조건, 정도, 환경에 따라 걸리는 시간이 달라진다. 그 기준은 저작한다.

### 진행 [설계 전 — 방향만]

사용자의 구분: 세력이 언제 움직이는지를 **시간만으로** 정하는 것은 좋지 않다. 좋게 쓸 길은 있으나 주된 수단이 되면 안 된다.
청사진에 **조직**과 **계획**이 인물과 따로 있는 이유가 여기에 있다.

```
조직·인물은 목표를 갖는다
   └→ 목표를 위해 계획을 세운다 (마스터가 그 조직의 앎과 자원으로 판단)
         └→ 계획의 단계는 조건이 맞을 때 나아간다 (세계의 사실, 자원, 기회. 시간은 "걸리는 시간"으로만)
               └→ 단계가 세계에서 벌어질 때 사건으로 나타난다 (사건의 틀에 지금의 인물과 물건이 채워진다)
                     └→ 플레이어의 행동이 조건을 바꾸면 계획은 막히거나 비틀리고, 조직은 계획을 고친다
```

- 서사를 나아가게 하는 것은 시계가 아니라 **목표를 가진 주체**다.
- 플레이어는 조건을 바꿔서 서사에 끼어든다. 자유도가 좁아지지 않는다.
- 정할 것: 화면 밖의 계획을 **언제** 다시 따져 보는가. 후보는 셋이다 — 플레이어가 그 계획에 닿는 일을 했을 때, 플레이어가 그 조직의 권역에 들어설 때, 세계 시각이 크게 흘렀을 때. 3단계에서 정한다.

## 4. 2단계 — 다. 마스터의 층위

| 부분 | 하는 일 | 상태 |
| --- | --- | --- |
| 해석 | 선언을 행동으로 옮긴다. 유형을 가린다. 따르는 행동을 채운다. 사칭을 시도로 바꾼다 | 원칙 확정 |
| 판단 | 무슨 일이 일어났는가를 가린다. 코드가 낸 기준에 답한다 | **접점 재설계 필요** |
| 판정 | 난이도와 방법을 정한다. 버튼. 여유에 따른 정도. 기만과 설득에 강제권 | 구도 확정, 값은 미정 |
| 인물 | 인물이 무엇을 하고 말하는가. 가이드를 따른다 | 누가 맡는가는 측정으로 |
| 전달 | 각 호출에 필요한 것만 골라 준다. 모르는 것은 주지 않는다 | 원칙 확정 |

### 접점 [제안]

- 구 기록에서 LLM이 자유롭게 낸 연산이 양식에 맞지 않아 버려졌다 (28턴에 3번).
- "LLM은 명확한 기준과 정해진 판단만"을 접점에 그대로 옮긴다.

```
열린 부분:  선언의 해석 — 무엇을 하려는가, 어느 유형인가, 무엇을 대상으로 하는가
              ↓ 유형과 대상이 정해지면 코드가 그 유형의 기준을 꺼낸다
닫힌 부분:  코드가 묻고 마스터가 고른다
              "이 행동으로 젖는 것은?    후보: 외투, 바지, 배낭, 없음"
              "이 충격은 도자기를 깰 만한가?    예 / 아니오"
              "난이도는?    쉬움 / 보통 / 어려움 / 매우 어려움"
```

- 닫힌 부분에서는 후보 밖의 답이 나올 자리가 없다.
- 정할 것: 이것을 호출 하나로 할 수 있는가, 둘이 필요한가. 대기에 직접 걸린다. 3단계에서 정한다.

## 7. 3일의 계획 [제안]

| 날 | 할 일 | 끝났을 때 있는 것 |
| --- | --- | --- |
| 1일 (오늘) | 2단계의 합의. 3단계 착수: 꿰는 것 다섯(상태, 위치, 앎, 조건, 계승)과 판정 | 이 문서의 확정판. 꿰는 것의 명세 |
| 2일 | 3단계: 영역 16개의 항목 목록. 진행(조직·계획·사건). 접점과 턴 | 영역별 항목표. 턴과 접점의 명세 |
| 3일 | 묘사와 경험, 운영. 구현 순서와 시험 계획. 남은 결정의 정리 | 구현을 시작할 수 있는 설계 명세 한 벌과 미결 목록 |

- 영역마다 같은 틀로 쓴다: 담는 것 / 코드가 하는 것 / 마스터가 판단하는 것 / 다른 영역과 만나는 곳 / 미결.
- 한 영역에 정해 둔 분량을 넘기지 않는다. 깊이는 4단계(값과 규칙의 실제 내용)로 넘긴다. 4단계는 구현과 함께 간다.
- 사용자의 판단이 필요한 것은 그날 끝에 **한 번에 모아서** 묻는다. 기본안을 함께 적어, 답이 없으면 기본안으로 간다.
