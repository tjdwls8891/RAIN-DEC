# 구상 안내서 — 어떻게 저장되고 어떻게 작동하는가

2026-11-13. 지금까지의 구상을 한 문서로 설명한다. 다른 문서를 읽지 않아도 이해할 수 있게 썼다.
구조 검토의 출발점으로 쓴다.

## 읽는 법

- 예시는 전부 시험용 시나리오 「만리객잔의 밤」 하나로 든다. 무협 객잔에 PC 강호민, 주모, 삿갓 쓴 사내가 있다.
- 각 내용에는 상태가 붙어 있다.

| 표시 | 뜻 |
| --- | --- |
| **[확정]** | 사용자가 정했다 |
| **[수용]** | Claude가 제안했고 사용자가 받아들였다 |
| **[제안]** | Claude가 제안했고 사용자의 판단을 아직 받지 않았다 |
| **[잠정]** | 측정으로 가를 것. 그때까지 임시로 쓴다 |
| **[보류]** | 사용자가 보류했다 |

- 예시의 표기는 설명용이다. 실제 파일 문법은 정하지 않았다.
- 이 문서에 적힌 것은 전부 뒤엎을 수 있다.

## 1. 세 문장 요약

1. 세계는 **장부** 하나에 적힌다. 장부는 "누가 어디에 있고, 무엇이 어떤 상태이고, 누가 무엇을 아는가"를 한 줄짜리 사실들로 적은 것이다.
2. LLM은 장부를 직접 고치지 못한다. LLM은 **제안**하고, 코드가 **검사**해서 통과한 것만 적는다.
3. 한 턴에 LLM은 세 역할로 나뉘어 일한다. **심판**은 진실을 보고 무슨 일이 일어나는지 정하고, **서술자**는 PC가 지각한 것만 받아 글로 쓰고, **인물**은 결정적인 순간에만 따로 불려 자기 이해관계로 결정한다.

```
┌─────────────┐   세션 개설   ┌──────────┐      한 턴       ┌──────────────┐
│ 공용 사전    │ ───────────▶ │          │ ◀─── 제안 ────── │ 심판 (LLM)    │
│ + 시나리오   │  변수를 정함  │   장부    │ ──── 진실 ─────▶ │              │
└─────────────┘              │          │                  ├──────────────┤
                             │ 세계의    │ ─ 그 인물의 앎 ─▶ │ 인물 (LLM)    │
     플레이어 ── 선언 ──────▶ │ 현재 상태 │                  ├──────────────┤
              ◀── 서술 ───── │          │ ─ PC가 지각한 것▶ │ 서술자 (LLM)  │
                             └──────────┘                  └──────────────┘
                              검사·계산·주사위·기록은 전부 코드
```

# 1부. 무엇이 저장되는가

## 2. 장부의 여섯 요소 [수용 — 종이 위에서 14개 영역을 적어 봄]

| 요소 | 한마디로 |
| --- | --- |
| 개체 | 세계에 있는 모든 "것" |
| 사실 | 개체에 대한 한 줄의 참 |
| 정의 | 어떤 속성이 있고 어떤 값을 가질 수 있는가 (어휘) |
| 시야 | 누가 무엇을 아는가 |
| 사건 | 일어난 일의 기록 |
| 틀 | 빈칸을 채워 찍어내는 묶음 |

### 2.1 개체

정체성을 가진 모든 것이 개체다. 사람과 물건뿐 아니라 장소, 문, 계획, 소문도 개체다.

```
강호민        (인물, PC)
주모          (인물)
척후          (인물)          ← 플레이어에게는 "삿갓 쓴 사내"로 보인다
객잔_1층      (장소)
창가          (지점)          ← 장소 안의 자리
뒷문          (통로)
철검          (물건, 장비)
뒷문_열쇠     (물건)
저잣거리류    (분류헤드)       ← 장소가 아니다. 속성을 물려주는 머리
```

- 괄호 안은 **표지**다. 한 개체가 여러 표지를 가질 수 있다. 종류를 계층으로 나누지 않는다.

### 2.2 사실

장부의 본체다. 모든 사실이 한 모양이다.

```
속성(주체) = 값
속성(주체 → 대상) = 값
```

객잔 장면의 사실 일부:

```
위치(강호민 → 창가) = 곁에
위치(주모 → 계산대) = 뒤에
위치(철검 → 강호민) = 허리에
위치(단도 → 척후) = 품에
잠김(뒷문) = 참
조도(객잔_1층) = 어스름
피로(강호민) = 보통
기분(주모) = 경계
호감(주모 → 강호민) = 무관심
정체(척후) = 흑풍채 척후
비밀(주모) = "흑풍채 두목이 친동생이다. 누구에게도 알리고 싶지 않다."
외양(주모) = "쉰 줄의 여인. 소매를 걷어붙였고 손등에 오래된 화상 자국이 있다."
```

- 값에는 종류가 있다. `보통`, `경계` 같은 **등급**, `350ml` 같은 **양**, 다른 개체, 그리고 따옴표로 묶인 **서술문**.
- **코드는 서술문을 읽지 않는다.** 서술문은 LLM이 글을 쓸 때의 재료일 뿐이다. 코드가 판단에 쓰는 값(위치, 잠김, 등급)은 뜻이 하나로 정해져 있다.

### 2.3 위치는 하나의 관계

```
위치(강호민 → 창가) = 곁에          사람이 자리에
위치(창가 → 객잔_1층) = 안에        자리가 방에
위치(객잔_1층 → 만리객잔) = 안에    방이 건물에
위치(철검 → 강호민) = 허리에        물건이 사람에게
위치(뒷문_열쇠 → 계산대_서랍) = 안에  물건이 물건 속에
```

- 이 사슬을 따라가면 "철검은 어느 방에 있는가(객잔 1층)", "누가 지녔는가(강호민)"가 나온다.
- 손에 든 것, 입은 것, 품에 넣은 것의 차이는 **방식**(`손에`, `착용`, `품에`)이다. 품에 넣은 것은 남에게 보이지 않는다.
- 방과 방을 잇는 것은 위치가 아니라 **통로** 개체다. 통로는 잠기거나 막히거나 숨겨질 수 있다.
- 한계: 부품(문의 손잡이), 연결(발전기와 조명), 제어(자물쇠가 문을 막음)는 위치로 적히지 않는다. 따로 다뤄야 한다. [열린 문제]

### 2.4 정의 — 어휘

속성마다 정의가 있다. 엔진이 모든 시나리오에 주는 **공용 사전**에 들어 있고, 시나리오가 고치거나 더할 수 있다.

```
정의: 피로
  값: [없음, 낮음, 보통, 높음, 극심]     ← 이 다섯 중 하나만 적을 수 있다
  겉보기: 관찰하면 보임
정의: 잠김
  값: [참, 거짓]      기본: 거짓
  겉보기: 관찰하면 보임
정의: 분위기
  서술문      계승: 예                   ← 값이 없으면 위에서 물려받는다
정의: 정체
  겉보기: 숨김
```

- **겉보기**가 지각을 가른다. `외양`은 누구나 보고, `잠김`은 살펴봐야 알고, `정체`는 보이지 않는다.
- **계승**: 객잔 1층에 `분위기`가 적혀 있지 않으면 만리객잔 → 저잣거리류에서 가져온다. 비슷한 곳들의 공통 성격을 한 번만 쓰기 위한 장치다. (사용자의 분류 헤드 구상)
- 엔진은 여러 장르에 걸친 어휘를 미리 갖춘다. "엔진은 모든 장르를 알고, 시나리오는 고르고 고치고 더한다." **[확정]**

정의에는 **행동**도 적힌다. 세 층이 있다.

| 층 | 무엇 | 예 |
| --- | --- | --- |
| 기제 | 코드로 만들어 둔 부품 | 피로는 "오르내리는 값"이라는 부품을 쓴다 |
| 규칙 | 조건과 효과 | 피로가 높음 이상인 동안, 몸을 쓰는 판정에 불리 |
| 지침 | 심판에게 건네는 문장 | "기량 차이가 압도적이면 정면 대결은 통하지 않는다" |

- 기본 기제는 일곱이다: 오르내리는 값, 단계의 진행, 상태의 옮겨 감, 정해진 시점의 발동, 자리와 용량의 제약, 재료의 변환, 계승. **[수용]**
  (이 가운데 "정해진 시점의 발동"은 **[보류]**)
- 조건은 사실과 같은 모양으로 쓴다: `피로(이것) 이상 높음`, `같은 곳(살인마, 플레이어)`. 저작자는 자연어로 쓰고, 코드가 조건을 다시 한국어로 풀어 보여 주면 확인만 한다. **[제안]**

### 2.5 시야 — 누가 무엇을 아는가

세계의 진실은 하나지만, 아는 것은 사람마다 다르다. 같은 장면을 세 사람이 다르게 안다.

| 사실 | 세계의 진실 | 강호민(PC)의 시야 | 주모의 시야 |
| --- | --- | --- | --- |
| 척후의 겉모습 | 삿갓을 눌러쓴 마른 사내 | 안다 (봤다) | 안다 |
| 척후의 정체 | 흑풍채 척후 | **모른다** | 안다 (원래 알던 것) |
| 척후의 품속 단도 | 있다 | **모른다** | **모른다** |
| 주모의 비밀 | 흑풍채 두목의 누이 | **모른다** | 안다 (자기 일) |
| 뒷문이 잠겼는가 | 잠겼다 | **모른다** (아직 살펴보지 않았다) | 안다 |
| 뒷문 열쇠의 위치 | 계산대 서랍 속 | **모른다** | — |

- 시야에 든 앎에는 **언제, 어떻게 알았는가**가 붙는다 (직접 봤다 / 누가 말해 줬다). 앎은 낡을 수도 틀릴 수도 있다.
- **PC의 시야 = 플레이어에게 전달된 것**이다.
- 앎은 **전달이 있어야** 퍼진다. 같은 자리에서 보고 들었거나, 누가 말해 줬거나, 문서를 읽었거나. 세력이 안다고 구성원 전원이 아는 것이 아니다. **[제안]**
- 물려받는 것은 상식과 규범처럼 원래 모두가 아는 것뿐이다.
- 사람만 시야를 갖는 것이 아니다. 편지, 소문, 단서도 "무언가를 담고 있다". 편지를 읽으면 편지에 담긴 것이 읽은 사람의 시야로 옮겨 간다. **[수용]**

### 2.6 사건

일어난 일의 기록이다.

```
사건  시각: 21:03  행위자: 강호민  요약: 철사로 뒷문 자물쇠를 딴다
  판정: 성공
  변화: 잠김(뒷문) = 거짓
  지각: 강호민(직접), 주모(보고 들음), 척후(소리만)
```

- 최소 구현에서는 사건을 처음부터 쌓은 결과가 곧 세계의 현재 상태다. 그래서 되감기가 "앞까지만 다시 쌓기"로 된다.
- 다만 **기록을 이런 방식으로 할지는 [보류]**다. 확정된 것은 "되감을 수 있다"와 "한 턴의 변화는 한 번에 확정된다"는 성질이다.

### 2.7 틀

빈칸이 있는 묶음이다. 빈칸을 채워 장부에 찍어낸다.

| 무엇 | 빈칸 | 찍으면 |
| --- | --- | --- |
| 물건의 원형 ("타이레놀") | 수량 | 실물 하나 |
| 단역 인물 ("객잔 손님") | 이름, 있는 곳 | 인물 하나 |
| 장소 조각 ("여관 객실") | 붙는 자리 | 방, 문, 가구 |
| 사건 틀 ("매복") | 누가, 누구를, 어디서 | 진행 중인 일 |
| 시나리오 전체 | 변수 | 세션의 첫 장부 |

- 원형과 실물이 나뉜다. "타이레놀"이라는 종류와 "강호민 주머니 속 12정"은 다른 것이다. 실물에 없는 사실은 원형에서 물려받는다. (사용자의 물건 구상)
- 사건 틀은 시나리오마다 쓰지 않고 엔진이 갖춘다. **[수용]**

## 3. 아직 정해지지 않은 저장 방식

| 장치 | 내용 | 상태 |
| --- | --- | --- |
| **닫힌 범위** | 세계는 기본적으로 열려 있어 적히지 않은 것은 "모름"이다. 범위를 닫으면 그 안에서는 적힌 것이 전부다. "이 방의 출입구는 이것뿐"이라고 닫으면 뒷문을 지어낼 수 없다. 사용자가 정한 "소품은 허용, 핵심은 금지"를 구조로 만드는 장치 | 제안 |
| **무른 사실** | 정의가 없는 속성은 짧은 문장으로만 두고 LLM만 읽는다("왼쪽 소매만 젖었다"). 위험이 확인된 것만 정의를 붙여 굳힌다 | **보류** |
| **호칭** | 개체의 식별자와 "PC가 아는 이름"을 따로 둔다. 이름을 모르는 사내는 서술자에게도 "삿갓 쓴 사내"로만 간다 | 제안 |
| **출처 등급** | 저작된 사실과 즉석에서 채운 사실의 무게를 구별한다 | 열린 문제 |
| **"없다"의 표현** | 닫힌 범위로 대신할 수 있다고 본다 | 제안 |

# 2부. 어떻게 작동하는가

## 4. 세션이 열릴 때 [수용 — 최소 구현으로 확인]

```
공용 사전 (정의, 원형, 틀)
  + 시나리오 (개체와 사실, 정의의 수정·추가, 변수)
  + 변수의 값을 정함
  = 세계 장부
```

객잔 시나리오의 변수:

```
열쇠가_있는_곳:
  후보: [계산대_서랍, 주모, 술독]
```

- 세션을 열 때 셋 중 하나가 뽑힌다. 같은 시나리오라도 판마다 열쇠의 위치가 다르다. 반복 플레이의 다채로움이 여기서 나온다.
- 열린 직후 각 인물의 첫 시야가 만들어진다. 같은 방에서 **그냥 보이는 것**이 들어간다. 서랍 속 열쇠와 남의 품속 단도는 들어가지 않는다.

## 5. 한 턴 [제안 · 일부 확정]

```
선언
 │                                              ┐
 ├─ ① 심판          단계 계획, 주목, 판정 설계   │ 대기 ①
 ├─ ② 실행 (코드)   단계를 차례로. 멈출 곳에서 멈춘다
 │      ├─ 판정이 필요하면 → 버튼 제시 ─────────┘
 │      │      (플레이어가 누른다)
 │      │                                       ┐
 │      └─ 굴림, 결과 적용                       │
 ├─ ③ 인물          결정의 순간일 때만           │ 대기 ②
 ├─ ④ 정리 (코드)   PC가 지각한 것을 모은다      │
 ├─ ⑤ 서술자        산문을 흘려보낸다 ───────────┘
 └─ ⑥ 마감 (코드)   한 번에 확정
```

- **대기**는 플레이어의 마지막 행동부터 다음 버튼 제시나 묘사 시작까지다. 15초 미만이 목표다. 버튼을 누르는 시간은 대기가 아니다. **[확정]**

### 예시 A — 판정이 없는 턴

> 플레이어: **"계산대 뒤로 돌아가 뒷문을 열어 본다."**

**① 심판이 받는 것** — 장면의 진실

```
[객잔_1층] 조도 = 어스름 …
[강호민] 위치 = 창가 곁에, 피로 = 보통 …
[주모] 위치 = 계산대 뒤에, 기분 = 경계, 목표 = "… 사내가 볼일을 마치고 뒷문으로 나가게 한다", 비밀 = "…"
[척후] 위치 = 구석_탁자 곁에, 정체 = 흑풍채 척후 …
[뒷문] 잠김 = 참, 잇는다 = [객잔_1층, 뒷골목]
[뒷문_열쇠] 위치 = 계산대_서랍 안에
```

**① 심판이 내는 것** — 단계의 계획

```
되읽기: 강호민은 계산대 뒤로 돌아가 뒷문을 열어 보았다.

단계 1  계산대 뒤로 간다        전제: 갈 수 있다        판정: 없음     걸리는 시간: 잠깐
        남는 것: 위치(강호민 → 계산대) = 뒤에
단계 2  뒷문을 민다             전제: 뒷문이 잠기지 않았다   판정: 없음
        남는 것: (열리면) 뒷골목이 보인다

주목: 주모 — 손님이 자기 자리 뒤로 들어오고, 지켜야 할 문에 손을 댄다
```

**② 엔진이 실행한다**

- 단계 1: 전제가 참이다. 위치를 옮긴다.
- 단계 2: 전제를 장부에서 확인한다. `잠김(뒷문) = 참`. **전제가 거짓이다. 여기서 멈춘다.**
- 문은 열리지 않았고, 강호민은 문이 잠겨 있다는 것을 **알게 됐다.** 이것이 그의 시야에 들어간다.
- 판정이 없으므로 버튼도 없다.

**③ 인물** — 이번 턴은 결정의 순간이 아니다. 주모의 반응은 심판이 정했다 (경계하며 다가온다).

**④ 엔진이 모은다** — PC가 이번 턴에 지각한 것

```
새로 안 것:   뒷문은 잠겨 있다
본 것:        주모가 행주를 내려놓고 이쪽으로 온다
들은 것:      주모: "거긴 손님 들어오는 데가 아니오."
```

**⑤ 서술자가 받는 것**

```
[되읽기] 강호민은 계산대 뒤로 돌아가 뒷문을 열어 보았다.
[실행된 일] 계산대 뒤로 감 → 뒷문을 밀었으나 열리지 않음
[새로 지각한 것] 뒷문은 잠겨 있다
[인물의 말과 겉모습] 주모: 행주를 내려놓고 다가온다. "거긴 손님 들어오는 데가 아니오."
[장면] 탁자 여섯에 계산대 하나, 기름 등잔, 어스름. 뒷문: 두꺼운 나무문, 쇠 자물쇠.
[호칭] 주모 = "주모", 척후 = "삿갓 쓴 사내"
```

**서술자가 받지 않는 것**: 척후의 정체, 주모의 비밀과 목표, 열쇠의 위치, 주모의 속마음.
받지 않았으므로 쓸 수 없다. "말하지 마라"고 시키는 것이 아니라 **주지 않는다.**

**⑥ 마감** — 장부가 바뀐다

| 사실 | 전 | 후 |
| --- | --- | --- |
| 위치(강호민) | 창가 곁에 | 계산대 뒤에 |
| 기분(주모) | 경계 | 경계 (그대로) |
| 강호민의 시야: 잠김(뒷문) | 모름 | 참 |
| 세계 시각 | 21:00 | 21:01 |

### 예시 B — 판정이 있는 턴

> 플레이어: **"허리춤에서 철사를 꺼내 자물쇠를 딴다."**

**① 심판**

```
단계 1  철사를 꺼낸다          ← 선언에 따르는 행동. 심판이 넣었다
단계 2  자물쇠를 딴다          판정: 필요

판정의 설계 (심판이 정하는 것은 둘뿐)
  어려움: 어려움       근거: 쇠 자물쇠, 낡았지만 튼튼하다
  방법:   적절함       근거: 철사는 맞는 도구다
  성공하면: 자물쇠가 풀린다
  실패하면: 시간이 가고 쇠 긁는 소리가 난다

주목: 주모 — 눈앞에서 자기 문을 따고 있다. **결정의 순간**: 막을 것인가
```

**② 엔진** — 나머지는 코드가 장부에서 센다

```
역량:  민첩 14, 손기술 숙련 없음
상태:  피로 보통 → 손기술에는 영향 없음
조건:  조도 어스름 → 정밀한 손일에 불리
→ 성공 가능성을 계산하고 **버튼을 제시한다.**      ← 대기 ① 끝
```

**플레이어가 버튼을 누른다.** 주사위가 굴러간다. 성공이라고 하자.

**③ 인물** — 결정의 순간이므로 주모를 따로 부른다. 주모가 받는 것은 **자기가 아는 것뿐**이다.

```
[나] 객잔 주인. 셈이 빠르고 의심이 많다. 목표: 오늘 밤을 조용히 넘기고 사내를 뒷문으로 내보낸다.
     비밀: 흑풍채 두목이 친동생이다.
[내가 아는 것] 구석의 사내는 흑풍채 척후다. 뒷문은 잠겨 있었다. 젊은 검객이 검을 찼다.
[방금 본 것] 젊은 검객이 계산대 뒤에서 철사로 뒷문 자물쇠를 땄다.
```

```
주모가 내는 것
  속마음: 저 문이 열리면 오늘 밤 일이 틀어진다. 소란은 더 곤란하다.
  결정:   몸으로 문 앞을 막고, 낮은 목소리로 내보낸다. 관아를 부르겠다고 으른다.
  대사:   "그 손 치우시오. 한 번만 말하오."
```

- 주모의 호출에는 "플레이어를 만족시켜야 한다"는 것이 없다. 자기 목표만 있다. 순응을 막으려는 장치다.
- 주모가 "막아선다"는 것은 PC와 다투는 행동이다. **시작만** 이번 턴에 반영하고, 강호민이 어떻게 대응하는지는 플레이어가 다음에 선언한다.

**⑤ 서술자** → 첫 문장이 나오는 순간 대기 ② 끝.

**⑥ 마감**

| 사실 | 전 | 후 |
| --- | --- | --- |
| 잠김(뒷문) | 참 | 거짓 |
| 위치(철사) | 강호민 품에 | 강호민 손에 |
| 위치(주모) | 계산대 뒤에 | 뒷문 앞에 |
| 기분(주모) | 경계 | 분노 |
| 척후의 시야 | — | "계산대 쪽에서 쇠 긁는 소리가 났다" (소리만 들었다) |

### 엔진이 멈추는 곳 [제안]

| 멈춤 | 예 |
| --- | --- |
| 단계의 전제가 거짓이다 | 예시 A의 잠긴 문 |
| 판정이 필요하다 | 예시 B. 버튼을 낸다 |
| 다른 인물이 반응할 수 있다 | 주모가 막아선다 |
| PC가 무언가를 새로 지각했다 | 문을 여니 골목에 사람이 서 있다 |
| 되돌릴 수 없는 일인데 유저가 말하지 않았다 | 자물쇠를 부숴야 열린다 → 확인을 묻는다 |
| 뜻이 모호하다 | 되묻는다 |

### 따르는 행동과 없는 선택 [확정]

| | 예 | 처리 |
| --- | --- | --- |
| 선언에 **따르는** 행동 | 철사를 꺼낸다, 물병 뚜껑을 연다 | 엔진이 채우고, 서술해도 된다 |
| 선언에 **없는 선택** | 멈춘다, 망설인다, 주위를 살핀다, 무기를 고쳐 쥔다 | 채우지 않는다 |

- 기준: 그 행동 없이는 선언한 행동이 성립하지 않는가.

## 6. 판정 [뼈대만 제안 — 다시 연구하기로 함]

지금의 뼈대:

- 뻔한 일에는 굴리지 않는다.
- 심판은 "얼마나 어려운가"와 "방법이 얼마나 좋은가"만 판단한다.
- 능력, 숙련, 장비, 상태는 코드가 장부에서 직접 센다. 같은 사실이 두 번 반영되지 않는다.
- 성공하면 얼마나 이루고 실패하면 무엇을 잃는지는 굴리기 **전에** 정한다.
- 플레이어의 추측과 추리는 판정하지 않는다.

사용자가 정한 것과 방향:

| 내용 | 상태 |
| --- | --- |
| 플레이어가 버튼을 직접 눌러 굴린다 | 확정 |
| 한 턴에 판정이 둘 필요하면 **버튼을 연달아 낸다** | 확정 |
| 두 능력치를 결합한 판정도 만들 수 있다 | 확정(방향) |
| 같은 턴 안의 기술적 재시도에서는 눈을 유지한다. 되감으면 다시 굴린다 | 확정 |
| **지금의 판정 시스템보다 더 나은 것을 만든다** | 확정(과제) — 아직 연구하지 않았다 |

## 7. 인물 [제안 · 잠정]

### 주목과 정산

> 엔진은 **주목 안**에 있는 것만 세밀하게 다루고, 주목 밖의 것은 **주목이 돌아올 때 정산**한다.

- 심판이 턴마다 주목을 정한다. PC가 상대하는 인물과, 무언가를 걸고 있는 인물. 보통 하나에서 셋.
- 주목 안의 인물은 심판이 움직인다. 결정의 순간에만 그 인물을 따로 부른다.
- 주목 밖의 인물은 무리로 남는다. 객잔에 손님이 서른이어도 서술은 주모와 삿갓 쓴 사내를 따라간다.

정산의 예:

> 강호민이 주모와 실랑이하는 세 턴 동안 척후는 주목 밖에 있었다.
> 강호민이 구석 탁자를 돌아본다. 주목이 돌아왔다.
> 엔진이 정산한다: 척후의 목표는 "들키면 싸우지 않고 빠져나간다"였다. 그 사이 소란이 있었고 뒷문은 주모가 막고 있다.
> → 척후는 이미 자리를 떴다. 탁자에는 손대지 않은 술잔만 남아 있다.
> 단, 그 세 턴의 서술에 "구석의 사내는 여전히 앉아 있다"고 쓴 적이 있다면 그것과 어긋나면 안 된다.

### 세 해상도

| 해상도 | 무엇이 있는가 | 누가 움직이는가 |
| --- | --- | --- |
| 배경 | 서술 한 줄 ("손님 서넛이 술을 마신다") | 서술만 |
| 단역 | 개체. 역할, 겉모습 | 심판 |
| 주요 | 자기 시야, 목표, 감정, 기억 | 심판, 결정의 순간에는 자기 호출 |

- 플레이어가 지목하면 배경이 단역이 되고, 관계가 생기거나 여러 번 상대하면 주요가 된다.
- 올라갈 때 채우는 순서: 이미 전달된 것(외모, 한 말)이 먼저 굳는다 → 역할에서 물려받는다 → 빈칸은 열린 범위에서만 채운다.
  세력 소속이나 비밀처럼 닫힌 것은 지어낼 수 없다.

### 측정으로 가를 것

인물을 누가 움직이는가는 세 방식을 돌려 보고 정한다: 심판이 전부 / 결정의 순간에만 따로 / 주목 안의 인물마다 따로.
지금의 잠정안은 가운데 것이다.

## 9. 화면 밖의 세계 [제안 — 핵심이 보류 중]

- 줄거리를 쓰지 않는다. **자기 목표를 가진 세력과 인물**을 쓴다. 유저가 가만히 있어도 그들의 계획은 진행된다. **[조건부 수용]**

```
계획: 흑풍채의 상단 습격
  단계: 정탐 → 호위 수 확인 → 길목 선정 → 매복 → 습격
  지금: 호위 수 확인 (척후가 객잔에서 주모에게 듣는 중)
```

- 강호민이 객잔에서 소란을 일으켜 척후가 정보를 못 얻고 떠나면, 이 계획의 단계가 늦춰진다.
- 완급은 **연출가**가 조절한다. 연출가는 새 사건을 지어내지 않고, 이미 세계에 대기 중인 결과가 언제 드러날지만 고른다. LLM이 아닌 코드다. **[제안]**
- 계획이 **어떻게** 시간에 따라 진행되는가(예약, 관측할 때 정산)는 **[보류]**다.

## 10. 시나리오를 쓴다는 것

저작자가 쓰는 것의 실제 모습:

```
주모:
  표지: [인물]
  사실:
    - 위치(이것 → 계산대) = 뒤에
    - 역할(이것) = 객잔 주인
    - 외양(이것) = "쉰 줄의 여인. 소매를 걷어붙였고 손등에 오래된 화상 자국이 있다."
    - 성격(이것) = "셈이 빠르고 의심이 많다. 약한 사람에게는 무르지만 캐묻는 사람은 싫어한다."
    - 말투(이것) = "반말 섞인 장삿말. 경계하면 말수가 준다."
    - 목표(이것) = "오늘 밤을 조용히 넘긴다. 동생이 보낸 사내가 볼일을 마치고 뒷문으로 나가게 한다."
    - 비밀(이것) = "흑풍채 두목이 친동생이다."
```

- 대부분은 공용 사전의 속성을 **골라 값을 채우는** 일이다.
- 인물 200명을 같은 깊이로 쓰지 않는다. 틀에서 물려받고, 그 인물만의 것만 쓴다. (통하는지는 증명되지 않았다)
- **검사기**가 플레이 전에 잡아 준다: 정의에 없는 속성, 가리키는 곳이 없는 참조, 값이 정해질 수 없는 변수.

| 구 프로젝트 실측 | 턴당 50~66원. 세계 전체를 읽는 호출 하나가 약 18원·9초 | 관찰 |
| 캐시 | 없어도 도는 구조가 기본. 큰 시나리오에서는 심판에만 세계 전체를 캐시로 준다 | 제안 |
| 문맥의 크기 | 세계가 커져도 그대로, 장면의 인물 수에는 제곱으로 늘었다 (최소 구현 실험) | 관찰 |

실패에 대한 원칙 **[제안]**:

1. 어떤 실패도 세계를 반쯤 바꾼 채 남기지 않는다.
2. 이미 한 일은 다시 하지 않는다.
3. 덜 중요한 역할의 실패가 턴을 막지 않는다. 인물 호출이 실패하면 심판의 판단으로, 서술자가 끝내 실패하면 되읽기 한 줄과 확정된 사실만 전한다.
4. 플레이어는 언제나 지금 무슨 일이 벌어지는지 안다.

# 3부. 지금 어디까지 왔는가

## 12. 실제로 만든 것과 종이 위의 것

| | 상태 |
| --- | --- |
| 장부(개체, 사실, 정의, 시야, 사건), 위치 사슬, 계승, 되감기 | **코드로 만들었고 시험이 통과한다** |
| 세션 개설과 변수 | 코드 있음 |
| 조건의 계산과 되읽기 | 코드 있음 |
| 제안의 검사 (없는 속성, 없는 등급, 없는 장소, PC의 내면) | 코드 있음 |
| 정보 격리 (인물과 서술자의 문맥에 비밀이 없다) | 코드 있음, 시험으로 확인 |
| 한 턴의 흐름 | 코드 있으나 **옛 흐름**(인물마다 호출)이다. 이 문서와 다르다 |
| 단계 계획, 주목과 정산, 닫힌 범위, 호칭, 틀, 기제의 실행, 규칙의 실행, 연출가, 판정 체계, 실패 대응, 캐시 | **종이 위에만 있다** |
| 실제 LLM으로 돌려 본 것 | **없다.** Gemini 키를 넣지 못했다 |

- 따라서 품질, 실제 비용, 실제 대기 시간은 하나도 확인되지 않았다.

## 13. 상태 한눈에

**확정**

- 대목표: 매력적인 소설의 등장인물이 된 듯한 경험. 세 가치: 자유도 100%, 확장성, 개연성
- 주권의 분리, 선언은 자유·결과는 판정, 묘사는 PC의 인지 범위 안에서, 전달된 것은 철회되지 않는다
- 엔진은 모든 장르를 알고 시나리오는 고르고 고치고 더한다. 봇이 전적으로 마스터다
- 대기의 정의와 15초, 판정 버튼, 버튼을 연달아 냄, 주사위 눈의 유지와 재굴림
- 서술의 지향, 턴은 짧아도 된다, 따르는 행동만 채운다
- 소급 선언 없음, 생성 권한의 등급, 비용 50원, 실패에 대응한다
- 이미 기획된 것은 매몰비용이다

**수용**

- 장부의 여섯 요소와 기본 기제, 세부는 필요할 때 생겨 정본이 된다(틀에서 고르고 채우는 방식), 사건 틀의 엔진 공용화, 측정할 수 있는 엔진

**제안 (판단 대기)**

- 단계 계획, 판정의 뼈대, 주목과 정산, 세 해상도, 닫힌 범위, 호칭, 조건 언어, 연출가, 캐시, 실패 대응

**보류**

- 서술이 지어낸 세부의 기록 방식
- 두 층위(세계 데이터와 세션 세계)의 뜻
- 사건 기록의 방식과 예약
- 무른 사실
- 세계의 신호와 압박의 출처

**열린 문제**

- 더 나은 판정 시스템
- 심판 한 호출의 부담
- 위치가 아닌 물리 관계(부품, 연결, 제어)
- 붐비는 장면, 장면에 없는 것에 대한 언급을 찾아오기
- 세력의 계획이 부서졌을 때의 재계획
- 아직 설계하지 않은 영역: 전투, 캐릭터 생성, 결말, 디스코드 화면, 과금

## 14. 용어

| 말 | 뜻 |
| --- | --- |
| 장부 | 세계의 현재 상태를 적은 것 전체 |
| 개체 | 정체성을 가진 모든 것 |
| 사실 | `속성(주체) = 값` 한 줄 |
| 정의 | 속성의 어휘와 행동 |
| 공용 사전 | 엔진이 모든 시나리오에 주는 정의, 원형, 틀 |
| 시야 | 누군가(또는 무언가)가 알고 있는 것 |
| 틀 | 빈칸을 채워 찍어내는 묶음 |
| 원형 / 실물 | 종류 / 세계에 실제로 있는 하나 |
| 분류 헤드 | 장소가 아니면서 속성을 물려주는 머리 |
| 계승 | 값이 없으면 가까운 위에서 가져오는 것 |
| 제안 | LLM이 내는 "이렇게 바꾸자". 코드가 검사한다 |
| 심판 / 인물 / 서술자 | LLM의 세 역할 |
| 단계 | 선언을 쪼갠 낱낱의 행동 |
| 주목 | 이번 턴에 세밀하게 다룰 대상 |
| 정산 | 주목 밖에 있던 것의 그동안을 한 번에 정하는 일 |
| 대기 | 플레이어의 마지막 행동부터 다음 버튼이나 묘사 시작까지 |
| 되읽기 | 선언을 어떻게 이해했는지 알려 주는 첫 줄 / 조건을 한국어로 풀어 보여 주는 일 |
